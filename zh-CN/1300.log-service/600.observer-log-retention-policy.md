# OBServer 日志保留策略

本节为您介绍 OBServer 的日志保留策略，包括 OBServer 自身的日志保留策略，以及 OCP 的全局日志保留策略。

## OBServer 自身日志保留策略

OceanBase 数据库中通过 `enable_syslog_recycle` 和 `max_syslog_file_count` 两个参数来控制系统运行日志的保留情况。

|  参数  |  说明  |  是否重启生效  |
|--------|---------|--------------|
| `enable_syslog_recycle`  | 该配置项用于控制是否开启日志自动清理，默认为 FALSE，表示不开启日志自动清理。     |  否 |
| `max_syslog_file_count`  | 该配置项用于控制保留的日志文件个数，默认为 0，表示不限制日志文件的个数。每个日志文件最大为 256 MB，如果磁盘空间不足，可以适当调小该配置项。<li>OceanBase 数据库 V4.2.1 BP4（oceanbase-4.2.1.4-104000062024022914）之前的 V4.x 版本：`max_syslog_file_count` 参数会独立控制各种类型日志的保留数量。当该值设定得较大并且启用全链路诊断功能时，会加大用户日志盘爆的风险。</li><li>OceanBase 数据库 V4.2.1 BP4（oceanbase-4.2.1.4-104000062024022914）及其之后的 V4.2.1.x / V4.2.3 / V4.3.x 版本：`max_syslog_file_count` 调整为控制所有日志累加的保留上限。</li>   |  否 |

<main id="notice" type='explain'>
<h4>说明</h4>
<p>如果 <code>trace.log</code> 日志生成的速度过快过多，可能会抢占 OBServer 日志文件的空间，导致 OBServer 日志被较早地清理。针对这种情况，建议用户调整全链路诊断的级别，以确定适合的日志量。</p>
</main>

## OCP 全局日志保留策略

OCP 提供了自动清理 OceanBase 数据库系统运行日志的功能，功能开关由 `ocp.agent.ob.log-cleaner.enabled` 参数控制。功能开启后，具体的清理策略如下：

* 日志盘使用率小于等于阈值时（默认为 80%），不清理。
* 日志盘使用率大于阈值时，首先根据保留天数，清理超过指定时间之前的日志。
* 如果清理后日志盘使用率小于阈值则清理结束。
* 如果当前日志盘仍然超过阈值，则按照保留百分比删除多余的日志。

您可在 **系统管理** > **系统参数** 中，通过如下参数修改日志清理的相关配置。

|  参数  |  说明  |  是否重启生效  |
|--------|---------|-----------|
| `ocp.agent.ob.log-cleaner.enabled`  | log-cleaner 全局开关，默认为 true，表示开启日志自动清理。该参数在 OceanBase 数据库创建好后通过配置下发 Agent 生效后开启 log-cleaner。  |  否  |
| `ocp.agent.ob.log-cleaner.config`  | log-cleaner 配置。<li>disk_threshold：当磁盘超过此阈值时开始清理日志，默认值为 80。</li><li>file_reg：日志文件名称匹配规则，可通过该字段配置待清理的日志文件。默认清理的日志文件如下：<ul><li>`observer.log`、`rootservice.log`、`election.log`、`trace.log` 日志文件。</li><li>带有 `.zst` 后缀的压缩日志文件。</li><li>带有 `.wf` 后缀的 WARNING 日志文件，即 `observer.log.wf`、`election.log.wf`、`rootservice.log.wf`。</li></ul></li><li>retention_days：日志保留天数，默认值为 30。</li><li>keep_percentage：日志保留百分比，默认值为 80。当按照天数清理后仍然超过阈值，则按照此比例保留近期日志。</li> |  否  |
| `ocp.agent.ob.log-cleaner.run.internal` | log-cleaner 运行时间间隔，默认为 5min。 |  否  |
