# ob_tenant_tde_kms_cmk_info_not_exist 租户 TDE 密钥信息在当前 OCP 中不存在，请及时更新租户 TDE 密钥

## 告警描述

该告警检测租户的 TDE 密钥信息在当前 OCP 中是否存在。即能否通过 `GV$OB_PARAMETERS` 视图中对应租户 `external_kms_info` 参数，在当前 OCP MetaDB 的 `kms_cmk_info` 表中查到对应 KMS TDE 密钥信息记录。

## 告警原理

| 参数       | 值       |
| ---------- | ------------ |
| 监控指标   | ob_tenant_kms_cmk_info_exist_status，该指标表示租户 TDE 密钥信息在当前 OCP 中是否存在，值为 `0` 时表示存在；值为 `1` 时表示不存在，并触发告警。 |
| 数据来源   | 由 OCP-Server 定时查询 `GV$OB_PARAMETERS` 视图中对应租户 `external_kms_info` 参数，根据参数查找 `kms_cmk_info` 表中是否存在对应密钥信息记录，如果不存在则发出告警。 |
| 采集指标   | ob_tenant_kms_cmk_info_exist_status |
| 监控表达式 | max(ob_tenant_kms_cmk_info_exist_status{@LABELS}) by (@GBLABELS) |
| 采集周期   | 5 秒 |

## 规则信息

| 监控表达   | 默认阈值     | 持续时间 | 检测周期 | 消除周期 |
| ---------- | ----------- | -------- | -------- | -------- |
|  ob_tenant_kms_cmk_info_exist_status     |  1         |  120 秒    |   60 秒   |  5 分钟  |

## 告警信息

| 告警触发方式 | 告警等级 | 范围   |
| ------------ | -------- | ------ |
| 基于监控指标的表达式 | 严重     | 租户 |

## 告警模板

* 告警概述

  * 模板：${alarm_target} ${alarm_name}
  * 样例：alarm_template_id=0:ob_cluster=xxx:tenant_name=xxx 租户 TDE 密钥信息在当前 OCP 中不存在，请及时更新租户 TDE 密钥

* 告警详情

  * 模板：OceanBase 集群 ${ob_cluster_name} 中租户 ${tenant_name} 的 TDE 密钥信息在当前 OCP 中不存在，请及时更新租户 TDE 密钥。
  * 样例：OceanBase 集群 Test 中租户 xxx 的 TDE 密钥信息在当前 OCP 中不存在，请及时更新租户 TDE 密钥。

* **告警恢复**

  * 模板：告警：${alarm_name}，租户 TDE KMS 信息在当前 OCP 是否存在：\${value}
  * 样例：告警：租户 TDE 密钥信息在当前 OCP 中不存在，请及时更新租户 TDE 密钥，租户 TDE KMS 信息在当前 OCP 是否存在：0

## 对系统的影响

添加 OBServer、新建备租户及新建加密表空间等功能将不可用。

## 可能原因

* 黑屏修改了当前 OCP MetaDB 的 `kms_cmk_info` 表中 `cmd_id` 或 `kms_endpoint` 数据。
* 黑屏修改了 `GV$OB_PARAMETERS` 视图中相应租户的 `external_kms_info` 参数的 `access_key_id` 值。
* 迁出并接管集群后未及时完成相关租户 TDE 加密配置。

## 处理方法

* 方式一：进入告警对应集群概览模块，根据页面提示信息单击 **修改加密**，进入 **安全配置** > **TDE 透明加密** 修改对应租户的 TDE 加密信息。
* 方式二：在租户所属集群中，进入 **安全配置** > **TDE 透明加密**，修改对应租户的 TDE 加密信息。
