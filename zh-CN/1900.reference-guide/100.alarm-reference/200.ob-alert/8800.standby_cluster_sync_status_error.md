# standby_cluster_sync_status_error 备集群同步状态异常

## 告警描述

备集群的同步状态有异常，则触发该告警。

## 告警原理

| 参数      | 值        |
|-----------|-------------|
| 监控指标  | standby_cluster_restore_status_code  |
| 指标来源  | 检查 `V$OB_STANDBY_STATUS` 中备集群的 synchronization_status 字段  |
| 采集指标  | standby_cluster_restore_status_code  |
| 监控表达式  | sum(standby_cluster_restore_status_code{@LABELS}) by (@GBLABELS)  |
| 采集周期  | 1 分钟  |

## 规则信息

| 监控表达式  | 默认阈值  | 持续时间  | 检测周期  | 消除周期  |
|-------------|-------------|-----------|-------------|-------------|
| standby_cluster_restore_status_code  | 1  | 0 秒  | 60 秒  | 5 分钟  |

## 告警信息

| 告警触发方式  | 告警等级  | 范围  |
|-----------|-------------|----------|
| 基于监控指标的表达式  | 警告  | 集群  |

## 告警模板

* **告警概述**

  * 模板：${alarm_target} ${alarm_name}
  * 样例：alarm_template_id=0:ob_cluster=cluster01-5 备集群同步状态异常

* **告警详情**

  * 模板：OceanBase 集群 ${ob_cluster_name}:${ob_cluster_id} 同步状态异常，当前同步状态为 ${cluster_synchronization_status}
  * 样例：OceanBase 集群 cluster01:5 同步状态异常，当前同步状态为 NOT AVAILABLE

* **告警恢复**

  * 模板：告警：${alarm_name}, 备集群同步状态是否正常：${value_down}
  * 样例：告警：备集群同步状态异常，备集群同步状态是否正常: 0

## 对系统的影响

根据不同的原因存在不同的影响：

* 若 OCP MetaDB 与 OceanBase 集群信息不一致，可能影响后续 OCP 运维操作。
* 若 OceanBase 集群故障导致的无法同步，可能影响用户服务。

## 可能原因

* OceanBase 集群维护的 IDC/Region 信息与 OCP MetaDB 维护的 IDC/Region 信息不一致。
* OceanBase 集群故障导致的无法同步，会同时产生 ob_cluster_status_check_failed 告警。

## 处理办法

根据告警中的失败原因，排除故障，故障排除后 OCP 应恢复集群同步。

1. 执行如下命令确认备集群同步状态。当 synchronization_status 返回值为 OK 时为同步成功，否则即为同步失败，此时将产生告警。

   ```sql
   select cluster_id, cluster_name, cluster_role, cluster_status, current_scn, rootservice_list, synchronization_status from FROM V$OB_STANDBY_STATUS
   ```

   <main id="notice" type='explain'>
   <h4>说明</h4>
   仅 OceanBase V2.2.77 及以上版本支持 synchronization_status 字段。
   </main>

2. 确认是否为 OceanBase 集群故障导致的无法同步。

   此情况下 OCP 会同时上报 ob_cluster_status_check_failed 告警。您可先参照 [ob_cluster_status_check_failed OceanBase 集群状态检测失败](300.ob_cluster_status_check_failed.md) 告警的处理方法进行排查，等待 5 分钟后，观察告警是否继续上报。

    * 若告警继续上报，请执行下一步。
    * 若告警消除，则问题解决。

3. 检查 OceanBase 集群内 Zone 的 IDC/Region 信息在 OCP MetaDB 中是否存在、以及集群内 IDC/Region 的关联关系与 OCP MetaDB 是否一致，您可参考如下信息进行检查。

   * OCP 维护主机/Region/IDC 的数据表如下：

     * compute_host：主机
     * compute_idc：机房
     * compute_region：区域

   * 执行如下命令查询 OCP MetaDB 中所有 Region/IDC 信息：

      ```sql
      -- 查询 OCP metadb 维护的 IDC 和 Region 信息
      SELECT r.`name` AS region, i.`name` AS idc 
      FROM compute_region r JOIN compute_idc i 
      ON r.id=i.region_id;
      ```

   * 执行如下命令查询 OceanBase 集群内 Zone 的 IDC/Region 信息：

      ```sql
      -- 查询 OceanBase 集群内 Zone 的 IDC 和 Region 信息
      SELECT `zone`,
      MAX(CASE `name` WHEN 'region' THEN `info` ELSE '' END ) `region`, 
      MAX(CASE `name` WHEN 'idc' THEN `info` ELSE '' END ) `idc`       
      FROM oceanbase.__all_zone WHERE `zone` <> '' GROUP BY `zone` ;
      ```

    当 OCP MetaDB 中维护的 Region/IDC 关联关系与 OceanBase 集群内 Zone 的 Region/IDC 关联关系存在不一致时，请执行下一步。

    <main id="notice" type='explain'>
    <h4>说明</h4>
    当 OceanBase 集群内 Zone 的 IDC 设置为空时，不影响集群同步。
    </main>

4. OceanBase 集群内 Zone 的 IDC/Region 等是逻辑上的划分，当 OceanBase 集群中的 IDC/region 信息发生变动之后，需要在 OCP MetaDB 中手动进行同步。以下方信息为例：

   * IDC 修改前的名称为 `old idc`，修改后的名称为 `zue`。
   * Region 修改前的名称为 `old region`，修改后的名称为 `SHANGHAI`。

   操作步骤如下：

   1. 使用 OCP MetaDB（集群名默认为 obcluster）的 ocp_meta 租户的 root 用户登录 ocp_meta 数据库，查询是否存在修改记录。

      1. 查询是否存在名称为 `SHANGHAI` 的 Region：

         ```sql
         select * from compute_region where name='SHANGHAI';
         ```

      2. 查询是否存在名称为 `zue` 的 IDC：

        ```sql
        select * from compute_idc where name='zue';
        ```

      若不存在，执行如下命令新增 Region 和 IDC；若存在，则执行下一步。

      ```sql
      -- 新增 Region
      insert into compute_region (`name`, `description`) values ('SHANGHAI', 'SHANGHAI region');
      -- 新增 IDC
      insert into compute_idc (`name`, `description`, `region_id`) select 'zue', 'zue idc', id from compute_region where name='SHANGHAI';
      ```

   2. 修订 OCP Zone 的 Region 和 IDC 信息。

      ```sql
      update ob_zone set idc_id = (select id from compute_idc where name='zue') where name='your zone name' and cluster_id= your cluster id in ocp;
      ```

   3.修订 OCP compute_host 的 Region 和 IDC 信息。

      ```sql
      update compute_host set idc_id = (select id from compute_idc where name='zue') where inner_ip_address in (ips of the hosts);
      ```

<main id="notice" type='notice'>
<h4>注意</h4>
OCP MetaDB 中已存在的 Region、IDC 数据可能会被其他 OceanBase 集群所引用。如果您黑屏修改了 OceanBase 集群中的 Region 和 IDC 信息，请先在 OCP MetaDB 中新增该 Region 和 IDC 信息，并关联到该集群的 Zone 和主机数据中。请不要更改 OCP MetaDB 中已存在的 Region 和 IDC 记录，避免导致其他集群关联到错误的 Region 和 IDC，从而出现故障。
</main>
