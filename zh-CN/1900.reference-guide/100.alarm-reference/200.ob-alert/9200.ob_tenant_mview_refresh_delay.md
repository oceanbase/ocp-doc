# ob_tenant_mview_refresh_delay 物化视图自动刷新不及时

## 告警描述

<main id="notice" type='explain'>
<h4>说明</h4>
<li>此告警仅针对 V4.3.5.0 及以上版本的 OceanBase 集群生效。</li>
<li>当租户存在主备关系时，仅允许主租户上报告警。</li>
</main>

该告警监测租户下数据库中的物化视图刷新是否延迟。若存在延迟，则上报告警。

## 告警原理

1. OCP 定时任务在所有集群 sys 租户下执行如下 SQL 采集对应物化视图自动刷新不及时的数据，并将数据存储到 OCP MonitorDB 的 `sql_aggregate_data` 表中，定时任务每 60s 执行一次。

   ```sql
    SELECT E.tenant_id, E.tenant_name, A.database_name, B.table_name AS mview_name, C.last_refresh_date, D.next_date
    FROM oceanbase.__all_virtual_database A, oceanbase.__all_virtual_table B, oceanbase.__all_virtual_mview C, oceanbase.__all_virtual_tenant_scheduler_job D, oceanbase.DBA_OB_TENANTS E
    WHERE A.tenant_id = B.tenant_id
      AND B.tenant_id = C.tenant_id
      AND C.tenant_id = D.tenant_id
      AND D.tenant_id = E.tenant_id
      AND A.database_id = B.database_id
      AND B.table_id = C.mview_id
      AND C.refresh_job = D.job_name
      AND C.refresh_job IS NOT NULL
      AND D.job != 0
      AND D.next_date < Now()
      AND E.tenant_type <> 'META'
      AND E.tenant_name IS NOT NULL
      AND E.tenant_role = 'PRIMARY';
   ```

2. 通过 OCP 告警检测任务，识别告警项是否为 SQL_AUDIT 类型。若是，则执行如下命令扫描 `sql_aggregate_data` 中的异常数据，并根据告警检测的规则配置，产生对应告警。

   ```sql
   select * from sql_aggregate_data where tags like '%mview_stat%' order by timestamp desc
   ```

## 规则信息

| 监控指标 | 默认阈值 | 持续时间 | 检测周期 | 消除周期  |
|----------|----------|---------|----------|-----------|
| NA       | NA       | 0 秒    | NA       | 5 分钟  |

## 告警信息

| 告警触发方式 | 告警等级 | 范围  |
|--------------|---------|--------|
| 基于定时任务触发 | 警告 | 租户  |

## 告警模板

* **告警概述**

  * 模板：${alarm_target} ${alarm_name}
  * 样例：alarm_template_id=0:ob_cluster=test471-11:tenant_name=mysqlTes:database=test:mview_name=test_mv_refresh_retry_mv2 物化视图刷新不及时

* **告警详情**

  * 模板：OceanBase 集群 ${ob_cluster_name} 中租户 ${tenant_name} 中数据库 ${database} 中物化视图 ${mview_name} 自动刷新不及时，预期刷新时间 ${next_date}。
  * 样例：OceanBase 集群 test471 中租户 mysqlTes 中数据库 test 中物化视图 test_mv_refresh_retry_mv2 自动刷新不及时，预期刷新时间 2025-11-14T16:13:55.026383+08:00。

## 对系统的影响

物化视图的时效性将无法保障。

## 可能原因

增量数据太多或刷新计划不优。

## 处理方法

1. 使用 sys 租户执行如下命令查询物化视图相关会话：

    ```sql
    select id, svr_ip, svr_port,tenant_id, time, info
    from oceanbase.__all_virtual_processlist
    where info like '%mview_name%'\G
    ```

    其中，`mview_name` 需根据实际异常的物化视图名称进行填写。

2. 若存在执行时长过久的会话，可进一步查看当前正在执行的计划：

    ```sql
    select dbms_xplan.display_active_session_plan(id, 'all', svr_ip, svr_port)\G
    ```

    其中，`id`、`svr_ip`、`svr_port` 需根据上一步骤查询的结果进行填写。

3. 分析计划信息，排查刷新耗时过长的问题。如有必要可联系 OCP 技术支持协助排查。
