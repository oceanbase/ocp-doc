# binlog_process_stop Binlog Server 进程停止

## 告警描述

该告警监测 Binlog Server 进程是否停止，若停止则上报告警。

OCP-Agent 进程监控 OceanBase 相关组件进程的启动时间戳，如果时间戳发生变动就可以认为进程发生停止或重启。这个告警只代表进程停止过，并不能说明进程长时间停止运行。如果进程长时间停止，会有其它状态类告警。

相关进程包括：

* observer：告警项为 observer_process_stop
* obproxy：告警项为 obproxy_process_stop
* obproxyd.sh：告警项为 obproxyd_process_stop
* ocp_agentd：告警项为 agentd_process_stop
* ocp_mgragent：告警项为 mgragent_process_stop
* ocp_monagent：告警项为 monagent_process_stop
* logproxy：告警项为 binlog_process_stop

## 告警原理

下表列出了该告警监控逻辑中涉及的关键参数。

|  参数      |    值     |
|------------|-----------|
| 监控指标   | binlog_boot_time_delta_seconds，该指标表示 Binlog Server 进程启动时间戳变化，当指标值大于阈值时表示进程停止，并触发告警。   |
| 指标来源   | 系统的 boot time + 进程距离系统重启的时间差值即为进程的启动时间。其中，系统的 boot time 等于命令 `cat /proc/stat` 返回结果的 btime 值；进程距离系统重启的时间差值等于命令 `cat /proc/pid/stat` 返回结果的第 22 列数字除以 100 后的值。 |
| 采集指标   | process_boot_time_seconds     |
| 监控表达式 | ```max(delta(process_boot_time_seconds{name="logproxy",@LABELS}[@INTERVAL])) by (@GBLABELS)```     |
| 采集周期   | 5 秒    |

## 规则信息

|          监控指标              | 默认阈值（单位：秒） | 持续时间 | 检测周期 | 消除周期 |
|--------------------------------|----------|----------|----------|----------|
| binlog_boot_time_delta_seconds   | 10       | 0 秒      | 20 秒     | 5 分钟  |

## 告警信息

|   告警触发方式       | 告警等级 | 范围  |
|---------------------|----------|--------|
| 基于监控指标的表达式 | 严重     | 主机 |

## 告警模板

* **告警概述**

  * 模板：${alarm_target} ${alarm_name}
  * 样例：alarm_template_id=0:binlog_cluster=binlog02-2000005:host=xxx.xxx.xxx.xxx Binlog 进程停止

* **告警详情**

  * 模板：Binlog 集群：${binlog_cluster}，主机：${host}，告警：${alarm_name}。
  * 样例：Binlog 集群：binlog02，主机：xxx.xxx.xxx.xxx，告警：Binlog 进程停止。

* **告警恢复**

  * 模板：告警：${alarm_name}，Binlog Server 进程启动时间戳变化：${recover_value}
  * 样例：告警：Binlog Server 进程停止，Binlog Server 进程启动时间戳变化：0 秒

## 对系统的影响

Binlog Server 进程负责管理 Binlog 实例，若进程长时间停止，会对 Binlog 实例的管理产生影响。

## 可能原因

Binlog 的 MetaDB 不可用。

## 处理方法

1. 登录主机，观察 logproxy 进程是否存在。

2. 若 Binlog Server 进程意外停止，可尝试手动拉起进程。

   1. 登录 OCP。
   2. 进入对应 Binlog 集群的概览页面，在 **Binlog Server 列表** 中选择对应的节点，先执行 **停止**，再执行 **启动**，进行重启操作。

3. 若手动拉起进程失败，请收集 Binlog Server 进程的日志信息，并联系 OCP 技术支持协助排查。
