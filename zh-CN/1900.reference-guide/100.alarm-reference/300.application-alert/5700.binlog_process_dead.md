# binlog_process_dead Binlog Server 进程不存在

## 告警描述

该告警监测 Binlog Server 进程是否存在，若不存在则上报告警。

## 告警原理

下表列出了该告警监控逻辑中涉及的关键参数。

|  参数      |    值     |
|------------|-----------|
| 监控指标   | binlog_process_exists   |
| 指标来源   | `ps -ef\|grep -w logproxy\|grep -v grep\|wc -l`，该告警的指标来源相对特殊，由 OCP-Agent 执行上述 Linux 指令检查 Binlog Server 进程是否存在。 |
| 采集指标   | binlog_process_exists     |
| 监控表达式 | process_exists{name="logproxy",@LABELS}     |
| 采集周期   | 1 秒    |

## 规则信息

|          监控指标          | 监控指标含义                      |  默认阈值 | 检测周期 | 消除周期 |
|----------------------------|-----------------------------------|----------|----------|----------|
| binlog_process_exists == 0 | 当监控指标等于 0 时，表示进程不存在。  | 1        | 10 秒     | 5 分钟  |

## 告警信息

|   告警触发方式       | 告警等级 | 范围  |
|---------------------|----------|--------|
| 基于监控指标的表达式 | 停服     | Binlog |

## 告警模板

* **告警概述**

  * 模板：${alarm_target} ${alarm_name}
  * 样例：alarm_template_id=0:binlog_cluster=binlog02-2000005:host=xxx.xxx.xxx.xxx Binlog 进程不存在

* **告警详情**

  * 模板：Binlog 集群：${binlog_cluster}，主机：${host}，告警：${alarm_name}。
  * 样例：Binlog 集群：binlog02，主机：xxx.xxx.xxx.xxx，告警：Binlog 进程不存在。

* **告警恢复**

  * 模板：告警：${alarm_name}，Binlog Server 进程存活状态：${recover_value}
  * 样例：告警：Binlog Server 进程不存在，Binlog Server 进程存活状态：1

## 对系统的影响

Binlog Server 进程负责管理 Binlog 实例，在单节点部署的场景下，会丧失 Binlog 实例的管理能力。

## 可能原因

Binlog 的 MetaDB 不可用。

## 处理方法

1. 查看 OCP 是否已重新拉起 Binlog Server 进程。

   该告警会触发执行 OCP 中默认的自动拉起 Binlog Server 进程预案，您可检查预案是否成功执行，并查看 Binlog Server 进程是否恢复正常运行。

2. 若 OCP 拉起 Binlog Server 进程失败，可参考如下流程进行排查：

   1. 检查 Binlog 服务的 MetaDB 是否可用。当 MetaDB 持续不可用时，可能会导致 Binlog Server 进程异常退出。
   2. 收集 Binlog Server 进程的错误日志、coredump 文件及 Binlog Server 进程的运行日志 `log/logproxy.log` 等信息，并联系 OCP 技术支持协助排查。
