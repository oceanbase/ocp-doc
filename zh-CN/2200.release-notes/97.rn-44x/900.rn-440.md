  在监控告警、容灾管理、备份恢复、预案管理等模块进行深度优化，显著提升操作便捷性与易用性，助力用户轻松驾驭数据库运维工作流。

### 关键特性解读

#### 实时监控

为应对分布式数据库环境下全链路性能监控与故障定位的复杂性，OCP 创新推出全链路实时监控解决方案，构建覆盖 OBProxy > OceanBase 集群 > 租户 > 主机> Unit 的五级监控体系，通过三大核心能力重塑运维体验：

* **3D 拓扑可视化，透视架构全貌**：采用动态 3D 可视化引擎，立体呈现 OBProxy 与集群、集群与主机、租户与 OBServer 间的逻辑关系与物理部署。支持拓扑层级钻取，从全局架构到单个 Unit 的逐层下钻，直观展现资源分布与依赖关系，让分布式架构的 “黑盒” 运行状态透明化。

* **全维度指标监控，秒级定位异常**：实时汇聚 QPS、TPS、RT、连接数、CPU/内存使用率等 10+ 核心性能指标，结合性能监控趋势对比分析，精准识别性能拐点。支持在拓扑图上直接查看关联告警数以及跳转至告警中心，实现从指标异常到故障根源的一键追溯，提升故障定位效率。

* **双模数据呈现，满足多维运维场景**：提供结构化表格数据视图，通过图形化与数字化的信息互补，既满足管理者全局态势感知需求，又为技术人员提供深度分析的数据支撑，有效降低分布式系统的认知与管理门槛。

通过全链路实时监控方案，无论是日常运维、故障排查以及大屏展示，用户可以更好地管理和优化系统性能，提高系统的稳定性和可靠性。

#### KMS TDE 加密

OceanBase 数据库的 TDE 功能是一项强大的数据保护措施，旨在确保存储在磁盘上的数据的安全性。通过无感知的加密机制，TDE 在数据写入存储设备的过程中自动进行加密，并在数据读取时自动解密。这一过程对用户完全透明，有效防止黑客和恶意用户从数据文件、数据库备份或磁盘中读取到敏感数据。

OceanBase 的 TDE 功能采用两级密钥体系来实现加解密。首先，加密的最小粒度为数据库中的一个表，但表必须位于一个加密的表空间中。表空间可以理解为是一组表的集合，是 OceanBase 为了兼容 Oracle 数据库而设计的概念。表空间的加密单位意味着每个加密的表空间都设置有特定的加密算法和对应的数据密钥，用于加密该表空间中的数据。此外，每个租户都有一个主密钥，该主密钥用于对表空间的数据密钥进行加密。为了防止未经授权的解密操作，主密钥通常存储于专门的 Keystore 中。

KMS 支持密钥的生成、存储、备份、恢复和销毁等一系列管理功能。通过 KMS，用户可以方便地管理其数字资产的访问权限，确保只有授权用户才能访问特定的数据资源。此外，KMS 还可以帮助用户避免密钥丢失或遗忘带来的安全风险。

为了统一对密钥进行管理，OCP 作为 KMS 服务的代理，提供统一的密钥管理服务和接口，对 OceanBase 屏蔽不同云厂商 KMS 服务的差异。用户只需提供阿里云或腾讯云等厂商的访问域名、AK、SK 以及主密钥 ID，即可轻松开启租户的 KMS TDE 加密功能。

### 新功能

#### 基础运维

1. **集群管理**：在集群升级时，自动提示已开启动态分区功能，避免因升级过程中禁止 DDL 操作而导致影响业务或中断业务。支持的 OceanBase 版本范围为 [V4.2.5 BP2, +∞)。
2. **集群管理**：在 OceanBase 安装部署或升级过程中，若检测到主机不支持 AVX 指令集，将自动停止相关操作，避免出现潜在的兼容性问题。支持的 OceanBase 版本范围为 [V4.2.5, V4.2.5 BP2)、[4.3.5, 4.3.5 BP4)。
3. **集群管理**：支持展示租户级别主备、合并和数据备份信息，方便用户快速了解集群现状。
4. **租户管理**：支持创建 MySQL 租户时设置变量 `ob_compatibility_control`。支持的 OceanBase 版本范围为 [V4.2.3, V4.3.0)、[V4.3.2, V4.3.5 BP3)。
5. **租户管理**：支持自定义租户连接串，方便用户根据不同的域名访问数据库。
6. **租户管理**：支持在 MySQL 租户下赋予用户 `Create routine` 权限。支持的 OceanBase 版本范围为 [V4.2.2, V4.3.0)、[V4.3.1, +∞)。

#### 监控告警

1. 支持 OceanBase V2.x/V3.x 主备集群同步状态（SYNCHRONIZATION_STATUS）告警。
2. 新增 8 个租户级别监控指标：Memstore 读锁申请成功率、Memstore 写锁申请成功率、RPC 请求成功率、GTS 请求数、事务回滚比例、fuse 行缓存命中率、schema 缓存命中率、临时页缓存命中率。
3. 新增 2 个集群级别监控指标：采样周期内 RPC 网络延迟、采样周期内 RPC 交付失败。
4. 支持展示 OBProxy 集群监控时间范围内监控指标的最大值、平均值以及当前值。

#### 容灾管理

1. 主备租户支持一主多备以及级联等容灾场景下备租户自由切换同步源端，方便用户做异地切换演练。
2. 支持创建备租户（主备同步方式为基于归档）时，通过参数 `ocp.standby.tenant.restore.advance.seconds` 控制备租户的恢复时间点（默认值为当前时间减去 60 秒）。
3. 租户概览页支持展示租户主备关系。

#### 预案管理

1. 当一主一备两个租户且主备租户设置了相同的服务名，支持用户在备租户服务异常时将备租户读流量自动切流至主租户。
2. 支持 Binlog 进程（OBM）Crash 后自动拉起 Binlog 进程，30 分钟内仅生效一次。

#### Binlog 管理

支持创建 Binlog 实例时通过位点设置 Clog 解析起始点，方便下游系统按需订阅。

#### 备份恢复

1. 支持全量恢复时用户依据实际业务情况开启/禁用动态分区功能，避免因本功能造成分区数据丢失。支持的 OceanBase 版本范围为 [V4.3.5 BP2, +∞)。
2. 支持快速恢复租户：恢复完的租户处于只读状态，不支持合并和数据备份。支持的 OceanBase 版本范围为 [V4.3.3, +∞)。
3. 支持在集群级别备份策略中进行备份时默认跳过已锁定租户。
4. 支持对于 S3 兼容协议的对象存储类型设置高级选项：
   * delete_mode=delete（默认）/tagging，支持的 OceanBase 版本范围为 [V4.2.3.0, V4.2.5.0)、[V4.3.0, +∞)。
   * checksum_type=md5（默认）/crc32，支持的 OceanBase 版本范围为 [V4.2.1.6, V4.2.2.0)、[V4.2.3.0, +∞)。
   * addressing_model=virtual_hosted_style（默认）/path_style，支持的 OceanBase 版本范围为 [V4.2.1.9, V4.2.2.0)、[V4.2.5.1, V4.3.0.0)、[V4.3.5.0, +∞)。

### 产品优化

#### 集群管理

1. 资源管理页签新增 CPU、内存、日志盘及数据盘剩余空间的可视化展示，帮助用户实时掌握资源使用情况，提升运维效率。
2. 当集群下的 Zone 内仅有一个 OBServer 节点且节点上存在副本时，不允许重装 OBServer 节点。

#### 租户管理

租户规格支持按 Unit 规格名称进行搜索，解决租户规格名称较多时的查询效率问题。

#### 主机管理

主机列表的操作列支持查看主机标准化报告功能。

#### 备份恢复

1. sys 租户作为系统管理租户不支持备份恢复功能，现已移除其备份恢复页面，以避免用户混淆和误操作。支持的 OceanBase 版本范围为 [V4.0, +∞)。
2. 在恢复租户时，新增支持用户自主选择操作路径：可选择进入任务中心查看任务进度，或停留在发起恢复页面继续操作。

#### 其他

1. **AI 助手** 在未配置大模型的业务场景下，提供普通对话能力，实现文档搜索能力。
2. 去除集群/租户/OBProxy/主机详情页的标签展示字数限制。
3. **操作审计** 支持展示访问数据库的客户端 IP 地址。

### 产品行为变更

1. 因腾讯云 COS 产品行为变更可能导致数据库日志备份异常，建议使用 S3 协议替代 COS 协议。支持的 OceanBase 版本范围为 [V4.2.1.9, V4.2.2)、[V4.2.5.0, V4.3.0)、[V4.3.3.0, V4.4.0)，且 OceanBase V4.4.0 及之后版本不再支持 COS 协议。
2. 取消 Binlog 服务独占主机限制，支持多产品共用同一主机（仅建议用于测试环境），有效降低部署与运维成本。
