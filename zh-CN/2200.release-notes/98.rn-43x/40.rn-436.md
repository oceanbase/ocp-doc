# OCP V4.3.6

OCP V4.3.6 版本重磅发布！本次升级聚焦 **智能化**、**安全加固** 与 **基础能力跃升**，全面赋能企业数据库运维管理。

* **智能运维助手**：全新推出 OceanBase AI 助手，深度融合大模型与数据库原生能力，打造覆盖 OceanBase 全生态的智能问答服务，实现运维问题的高效精准解答。
* **安全能力升级**：新增 OceanBase TDE（透明数据加密）及全链路 SSL 加密功能，从数据存储到传输全程防护，筑牢数据库安全防线。
* **网络架构适配**：支持 IPv6 全场景部署，实现对 IPv6 地址 OceanBase 集群的全生命周期管理，满足合规要求与网络演进需求。
* **30 + 功能优化**：在性能监控、主备库管理、备份恢复、告警中心、巡检服务等核心模块进行深度优化，显著提升操作便捷性与管理效率，助力用户轻松驾驭数据库运维工作流。

## 版本信息

* **版本号：** V4.3.6

* **前置版本：** V4.3.5 BP4

* **版本发布日期：** 2025 年 6 月 21 日

* **支持的升级路径：**

  * 目前仅支持从 OCP V3.2.4 及之后版本直接升级到当前版本。

  * 对于 OCP V2.3.x 及之后、V3.2.4 之前的版本，需先升级至 OCP V3.3.4 版本。

  * 对于 OCP V2.3.0 之前版本，需先升级至 OCP V2.3.x 版本，再升级到 OCP V3.3.4 版本。

## 新功能

### 基础运维

* **集群管理**：全面支持互联网协议第六版（IPv6），可对集群内 IPv6 地址进行管控。通过无缝适配 IPv6 网络环境，满足政府、金融等行业严格的网络安全监管要求。
  * 支持的 OceanBase 版本范围为 [V4.2.5 BP3 Hotfix3, V4.3.0)、[4.3.5 BP2 Hotfix1, +∞)。
  * 支持的 OBClient 版本范围为 [V2.2.9, +∞)。
  * 支持的 OBProxy 版本范围为 [V4.3.4, +∞)。
* **集群管理**：安全配置支持设置 TDE 透明加密，防止攻击者绕过数据库直接从存储层读取敏感信息，保障用户数据安全。支持的 OceanBase 版本范围为 [V4.0.0, +∞)。
* **集群管理**：安全配置支持设置 SSL 链路加密（TCP 和 RPC），防止通信数据在传输过程被篡改造成安全风险，提升系统的安全性。支持的 OceanBase 版本范围为 [V4.0.0, +∞)。
* **OBProxy**：安全配置支持设置 SSL 链路加密（TCP 和 RPC），防止通信数据在传输过程被篡改造成安全风险，提升系统的安全性。支持的 OBProxy 版本范围为 [V2.0.0, +∞)。
* **租户管理**：支持批量锁定和解锁普通用户，提升数据迁移、数据导入导出等场景下的用户运维效率。
* **租户管理**：支持用户通过复制主租户备份集的方式搭建备租户，完善容灾管理方案。
* **主机管理**：支持地域、机房、机型的管理能力，但暂不支持删除存在关联主机的对象。

### 监控告警

* 支持展示监控时间范围内监控指标的最大值（max）、平均值（avg）以及当前值（current）。
* 支持在 QPS 和响应时间中增加 Commit、Rollback 等监控项。支持的 OceanBase 版本范围为 [V4.2.5 BP3, V4.3.0)、[V4.3.5 BP2, +∞)。
* 支持通过查询 `/var/log/messages` 进行硬件监控，方便用户及时发现硬件相关故障。

### 巡检服务

支持巡检同一集群下 OBServer 的时钟源设置，避免因时钟源设置不一致造成合并异常。

### Binlog 管理

* 支持开通 Binlog 服务时设置实例副本数，Binlog 服务会基于集群 Binlog Server 数量自动分布实例副本。
* Binlog 实例支持新增实例副本功能，单个业务租户最大支持 5 个实例副本。
* 支持管理 Binlog 备实例，包括启动、停止、限流、重启、删除、切主等操作。
* 支持删除 Binlog 主实例。
* 实现禁止对 Binlog 服务的 MetaDB 进行运维操作的提示，避免因误操作造成 Binlog 服务异常。

### 备份恢复

* 支持设置 Zone、Region、IDC 备份属性，降低多地域或多机房部署场景下的跨区网络流量，提升备份速度。
* 恢复租户时支持设置 Zone 优先级为 Random。

### 平台功能

* **AI 助手**：基于 LLM + PowerRAG + 内置 OceanBase 知识库，提供关于 OceanBase 及其相关产品的智能问答服务。
* **运维管理**：报告中心支持创建和下载 OceanBase 集群/租户/OBProxy 集群/主机/Binlog 服务/仲裁服务等资源信息报告，并支持通过 `ocp.report.center.report.retention.days` 参数修改报告保留时长。
* **参数模板**：支持导入导出 yaml 格式的 OceanBase 集群/租户/OBProxy 集群/Binlog 服务的参数模板。
* **集群管理** > **运维配置**：新增 5 个采集指标开关控制是否收集 Waitevent、Cache 命中率、分区数等信息。

## 产品优化

### 集群管理

* 仅处于已停止/不可用/已废弃/已迁出等状态的集群支持直接删除。
* 支持 Unit 迁移场景下对 CPU、内存、日志盘及数据盘进行预检查，避免因资源不足造成迁移异常。
* 支持开启/关闭 Cgroup 时无需重启集群。支持的 OceanBase 版本范围为 [V4.2.5 BP2, V4.3.0)、[V4.3.5, +∞)。

### 租户管理

* 合并管理功能支持按 Unit 维度展示 MEMStore 使用率、MEMStore 使用大小、CPU 使用率及内存使用率监控指标，方便用户观察合并期间的资源消耗。
* 优化统计信息管理属性，变更 **变更 Top10 表** 的数据统计逻辑。支持的 OceanBase 版本范围为 [V4.2.5 BP2, V4.3.0)、[V4.3.5, +∞)。
* 仅允许直接删除已锁定状态的主租户，通过状态校验机制规避误操作风险。
* 支持创建用户时将权限按照通用、管理员等类型进行分组，帮助用户快速创建数据库用户。
* 支持对于 Oracle 租户下角色权限进行批量设置。

### OBProxy 管理

仅处于已停止/不可用/空集群等状态的主集群支持直接删除，避免误操作。

### 其他

* **平台功能**：支持通过系统参数 `ocp.iam.password.validity.period.days` 和 `ocp.iam.password.reuse.times` 设置用户的密码有效期和密码重复使用次数，保障用户密码安全。
* **平台功能**：支持在操作系统 debian11 及其以上版本通过系统参数 `ocp.agent.home.path.prefix` 自定义 ocp_agent 安装目录。
* **告警中心**：支持告警恢复详情中展示告警恢复时的监控指标数据。
* **告警中心**：支持在告警详情页单击告警规则后跳转至新页面。

## 产品行为变更

主机管理和接管集群时不再支持容器类型的主机。

## 关键特性解读

### AI 助手（实验特性）

OceanBase AI 助手通过深度整合大语言模型（LLM）、检索增强生成技术（PowerRAG），并融合内置的 OceanBase 知识库及数据库原生的向量与全文索引能力，打造智能问答核心引擎。基于 PowerRAG 的多轮检索机制，LLM 可精准调用知识库中沉淀的技术文档、最佳实践及故障案例，针对系统配置调优、故障诊断修复、性能瓶颈分析等数据库运维核心场景，输出体系化、专业化解决方案。

在大模型配置层面，OCP 支持通过 **系统管理** > **外部集成** > **AI 模型** 功能模块，灵活接入阿里云通义千问、字节跳动豆包、DeepSeek 等第三方大模型服务，或部署自建大模型。用户可自主配置 LLM + 嵌入模型 + Rerank 重排序模型（可选），快速激活 AI 助手能力。同时，OCP 支持导入企业专属的最佳实践、标准操作流程（SOP）等专业知识，持续扩展知识库的行业适配性。

### SSL（Secure Sockets Layer）链路加密

在数字化转型加速的当下，数据传输安全成为核心诉求。OBProxy 与 OceanBase 具备 SSL 链路加密功能，通过在传输层建立加密通信通道，为网络连接提供端到端保护，有效抵御数据窃取、篡改风险，确保通信过程的机密性与完整性，从底层夯实数据传输安全防线。

作为全链路运维管理中枢，OCP（OceanBase Cloud Platform）提供覆盖证书全生命周期的管理能力：

* **便捷证书操作**：支持一键上传、删除证书，简化证书管理流程。
* **深度安全配置**：集成 OBProxy 与 OceanBase 的 SSL 加密配置功能，支持证书更新策略定制，保障加密链路的持续有效性。
* **多格式证书支持**：提供业务应用访问所需的 p7b/PEM/JKS 等标准格式证书下载，满足不同技术栈的安全接入需求。

通过 OCP 的统一管理，用户可轻松实现业务应用 > OBProxy > OBServer 全链路安全通信以及 OBServer 之间 RPC 安全通信的部署与监控，确保数据在业务接入、代理转发、节点交互等关键环节的安全传输，为数据库稳定运行构建全方位安全屏障。

<main id="notice" type='notice'>
<h4>注意</h4>
<p><li>开启 SSL 链路加密后，实例性能将有轻微下降（证书加解密需要消耗一定的计算资源），建议仅有传输加密需求的时候开启实例 SSL 链路加密。</li>
<li>若启用同一集群内 SSL 链路加密，请确保本集群内 OceanBase 和 OBProxy 的根证书 <code>ca.pem</code> 保持一致。</li>
<li>支持的 OceanBase 版本范围为 [V4.0.0, +∞)。</li></p>

## 版本使用限制

### 硬件要求

OCP-Server 可以安装在物理机上，也支持安装运行在 Docker 容器中。OCP-Server 支持多节点高可用部署模式。

OCP-Server 节点最低硬件要求如下表所示。

| 硬件 | 要求                 |
|-------|------------------------------------|
| CPU  | <li>X86_64，8 核</li><li>ARM aarch 64 架构，8 核</li> |
| 内存 | 可用内存 16 GiB             |
| 网卡 | 万兆网卡                |

OCP-Agent 自身占用资源很少，对安装节点硬件资源没有特别要求。
