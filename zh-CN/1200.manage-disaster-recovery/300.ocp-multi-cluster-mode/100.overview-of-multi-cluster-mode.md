# 多集群模式概述

OCP 支持多集群模式，实现双机房高可用容灾架构，为您提供更可靠的集群管理和监控服务。

<main id="notice" type='notice'>
<h4>功能适用性</h4>
<p>该内容仅适用于 OCP 企业版，OCP 社区版不提供此功能。</p>
</main>

## 功能介绍

OCP 多集群模式专为 OceanBase 异地容灾场景设计，提供跨地域主备库的集中管理能力。该模式支持完整的运维生命周期管理，包括主备库的创建、解耦、升级、日常切换、容灾演练等关键操作，确保业务连续性和数据安全性。

OCP 的多集群管理功能主要面向跨 OCP 集群的主备库统一容灾管理，其核心作用是实现主备库之间的拓扑信息的数据同步，确保在机房级故障发生时能够快速进行容灾切换和业务恢复。需要明确的是，这一功能并非自动故障接管机制。当主 OCP 集群发生宕机时，备 OCP 集群不会自动接管主 OCP 所管理的 OceanBase 集群资源。在主备 OCP 架构中，MetaDB（元信息数据库）之间未配置数据同步链路，两者在数据层面保持独立存储，它们的关系主要通过应用层的数据传输和业务逻辑进行协同。

<main id="notice" type='explain'>
<h4>说明</h4>
<p>OceanBase 数据库在 V4.1.0 版本之前，主备库的产品形态为集群级主备。从 V4.1.0 版本开始，主备库的产品形态变更为租户级主备，即主或备的角色信息属于租户，分为主租户和备租户，集群不再有主备角色的概念，而只是承载租户的容器。</p>
</main>

## 多集群模式架构

OCP 多集群容灾切换主要应用于跨城双机房、跨城三机房等场景。原理如下：

### 跨城双机房

在跨城主备库部署场景下，可采用 OCP 集群的跨城双机房部署方案。当某一城市的 OCP 集群及其管理的 OceanBase 集群发生故障时，备用城市的 OCP 集群需要被切换为主集群，并通过主备库容灾切换机制，接管 OceanBase 数据库的运维、监控和告警功能，确保数据库服务在最短时间内恢复可用。

OCP 的主备集群分别部署在城市 1 和城市 2 中，其中城市 1 中的 OCP 集群为主集群，城市 2 中的 OCP 集群为备集群。OCP 主备集群中分别管理着多个 OceanBase 集群。

当网络故障导致两地网络连接断开时，可通过容灾切换，将城市 2 中的备 OCP 集群切换为主集群。此时城市 1 的原主 OCP 集群会成为一个独立的废弃集群，建议删除该废弃集群并重新为城市 1 搭建新的主集群。城市 2 中的主 OCP 集群会对 OceanBase 数据库正常进行运维和监控，对于主库不在其下管理的备库，会进行容灾切换或迁出，详情参见 [容灾切换 OCP 集群](600.switch-an-ocp-cluster-in-a-failover.md)。

针对 V4.1.0 之前版本的 OceanBase 集群，业务通过关联 OBProxy 访问 OceanBase 集群，对于跨 OCP 集群的 OceanBase 主备集群，每个 OceanBase 集群绑定一个 OBProxy，当 OBProxy 绑定在业务集群备库时，可访问业务集群备库。当 OCP 主备集群出现网络故障时，业务可通过 OceanBase 备集群绑定的 OBProxy 继续访问 OceanBase 集群。

<main id="notice" type='explain'>
<h4>说明</h4>
<p>如果 OBProxy 只绑定了 OceanBase 备集群，通过 proxy 访问的时候，用户名需带上备集群 ID，如 <code>mysql -h xxx.xxx.xxx.xxx -P 2881 -u&lt;用户名称&gt;@&lt;租户名词#集群名称&gt;:1000 -p ****</code>。OCP 上集群的连接串上也会显示集群 ID，去掉 ID 后，无法连接该业务集群备库。</p>
</main>

当网络恢复后，两个主集群依然作为独立的 OCP 集群运转，可将其中一个主集群设置为备集群，通过注册 OCP 集群的方式将两个集群绑定，详情参见 [注册 OCP 集群](200.register-an-ocp-cluster.md)。

![1](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/4137375261/p292705.png)

### 跨城三机房

以跨城三机房为例，在城市 1 与 城市 2 中分别部署 OCP 集群，其中城市 1 中部署一个 OCP 集群为主集群，城市 2 中部署两个 OCP 为备集群。OCP 主备集群中分别管理着多个 OceanBase 集群。

当网络故障导致两地网络连接断开时，可通过容灾切换，将其中一个备 OCP 集群切换为主集群。此时城市 1 存在一个 OCP 主集群，城市 2 中存在一个 OCP 主集群，一个 OCP 备集群。

每个 OCP 主集群会继续对自己管理的 OceanBase 数据库进行运维监控，若存在备库所对应的主库不在当前 OCP 主集群中，则需对该备库数据进行清理，详情参见 [容灾切换 OCP 集群](600.switch-an-ocp-cluster-in-a-failover.md)。

针对 V4.1.0 之前版本的 OceanBase 集群，业务通过关联 OBProxy 访问 OceanBase 集群，对于跨 OCP 集群的 OceanBase 主备集群，每个 OceanBase 集群绑定一个 OBProxy，当 OBProxy 绑定在业务集群备库时，可访问业务集群备库。当 OCP 主备集群出现网络故障时，业务可通过 OceanBase 备集群绑定的 OBProxy 继续访问 OceanBase 集群。

<main id="notice" type='explain'>
<h4>说明</h4>
<p>若 OBProxy 只绑定了 OceanBase 备集群，通过 proxy 访问的时候，用户名需带上备集群 ID，如 <code>mysql -h xxx.xxx.xxx.xxx -P 2881 -u&lt;用户名称&gt;@&lt;租户名词#集群名称&gt;:1000 -p ****</code>。OCP 上集群的连接串上也会显示集群 ID，去掉 ID 后，无法连接该业务集群备库。</p>
</main>

当网络恢复后，在城市 1 的 OCP 集群列表中会出现城市 2 中的备库，但此时该备库的主库为城市 2 中的主库。可通过解除绑定的方式将备库移除，详情参见 [删除 OCP 集群](700.delete-an-ocp-cluster.md)。

如果需要原主库重新接入 OCP 集群，需要将原主库中的数据清除。
