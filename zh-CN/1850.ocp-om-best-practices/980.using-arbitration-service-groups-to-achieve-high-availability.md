# 通过仲裁服务组实现高可用

## 应用场景

OceanBase V4.1 开始提供仲裁服务能力，实现低成本的两副本双机房高可用能力（2F1A）。但在此种部署模式下，A 副本本身的高可用无法得到保障，如果 A 副本由于进程异常或机器宕机发生不可用，OceanBase 将无法保持高可用的运行状态。针对此问题，OCP V4.3.5 开始推出仲裁服务组高可用能力。

**什么是仲裁服务组？**

仲裁服务组中包含多个仲裁服务，当检测到某个仲裁服务不可用时，OCP 自动将其关联集群切换到组内其他仲裁服务。

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/01232128.png)

仲裁服务组由两部分组成：**仲裁服务列表** 和 **切换策略**。

* 仲裁服务组内的仲裁服务具有优先级属性，当其关联的 OceanBase 集群触发切换策略时，会优先切换到优先级高的仲裁服务上。若第一优先级资源不足，会将部分 OceanBase 集群转移到下一优先级的仲裁服务。

* 切换策略分为两部分：**Unit 失连策略** 和 **持续时间**。

  * Unit 失连策略包含以下三种：

    1. 默认策略：当 OceanBase 集群中存在租户的半数副本与仲裁服务失连时。
    2. Unit 个数：当 OceanBase 集群中存在指定个数的 Unit Server 与仲裁服务失连时。
    3. Unit 百分比：当 OceanBase 集群中指定百分比的 Unit Server 与仲裁服务失连时。

  * 持续时间：OceanBase 集群触发 Unit 失连策略多久才实施切换。

## 前置条件

1. OCP 中至少存在一个仲裁服务。
2. 创建仲裁服务组时，其中指定的仲裁服务必须为 **正常运行** 状态。
3. 仲裁服务组中的仲裁服务版本必须保持一致。

## 技术原理

仲裁服务状态检查与切换架构图如下：

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1144.png)

**OCP Agent 上报规则**：集群 RS 节点的 monagent 进程将集群与仲裁服务的连接状态上报到 MonitorDB，频率为 5s 上报一次。

**OCP Server 检查规则**：

   1. 按照仲裁服务组分片，每个 OCP-Server 检测自己分片内的仲裁服务组。
   2. 每 10s 查询 MonitorDB，获取所有与仲裁服务失连的 Server 列表。并按照用户定义的切换策略，判断集群 Unit 失连个数是否满足切换条件。

## 注意事项

* 当集群处于异常状态或者运维状态时，OCP 不会发起仲裁服务自动切换。

* 仲裁服务组内至少额外存在一台正常运行、资源充足且与 OceanBase 集群网络畅通的仲裁服务，否则 OCP 不会发起自动切换。资源充足的量化分析方式如下：

    1. 目标仲裁服务机器的内存使用率需要 ≤ 90%。
    2. 目标仲裁服务机器磁盘需满足 2F/4F 的要求：2F 租户占用 12 MiB、4F 租户占用 24 MiB，检查若迁移到该仲裁机器时，资源是否足够。

## 操作步骤

1. 登录 OCP。

2. 在左侧导航栏单击 **集群**，并进入 **仲裁服务** 页签。

3. 单击 **服务组** 页签，进入 **服务组** 列表页面。

4. 单击右上角 **新建服务组**。

5. 在 **新建服务组** 面板中，设置仲裁服务组的基础信息。
