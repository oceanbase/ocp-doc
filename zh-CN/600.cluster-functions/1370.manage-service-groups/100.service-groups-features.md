# 服务组概述

OceanBase V4.1 版本提供仲裁服务能力，仲裁服务凭借其低资源消耗的显著优势，以及对多集群的强大支持特性，成功打造出成本更为低廉的 OceanBase 数据库高可用解决方案，如 2F1A/4F1A 架构。通过这种架构，企业能够在有效控制资源成本的同时，确保数据库系统具备出色的高可用性，极大地提升了系统的性价比。

然而，不可忽视的是：仲裁服务在运行过程中存在单点故障隐患。一旦仲裁服务出现故障，在故障持续期间，OceanBase 集群的高可用性将不可避免地出现降级情况，这可能会对业务的连续性和稳定性产生负面影响。

为有效应对这一挑战，OceanBase 通过构建仲裁服务组，实现当某个仲裁服务节点发生异常时，能够秒级时间内将相关集群快速切换至其他健康的仲裁服务节点，最大程度地保障了 OceanBase 集群在各种复杂情况下都能稳定运行，确保业务不受影响。

## 什么是仲裁服务组

仲裁服务组中包含多个仲裁服务，当检测到某个仲裁服务不可用时，OCP 自动将其关联集群切换到组内其他仲裁服务。

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/01232128.png)

如上图所示，仲裁服务组由两部分组成: **仲裁服务列表** 和 **切换策略**。

### 仲裁服务列表

仲裁服务组内的仲裁服务有优先级属性，当其关联的 OceanBase 集群触发切换策略时，会优先切换到优先级高的仲裁服务上。若第一优先级资源不足，会将部分 OceanBase 集群转移到下一优先级的仲裁服务。

### 切换策略

切换策略分为两部分：Unit 失连策略和持续时间。

* Unit 失连策略包含以下三种：

  * 默认策略：适用于当 OceanBase 集群中存在租户的半数副本与仲裁服务失连的场景。
  * Unit 个数: 适用于当 OceanBase 集群中存在指定 Unit Server 与仲裁服务失连的场景。
  * Unit 百分比: 适用于当 OceanBase 集群中指定百分比的 Unit Server 与仲裁服务失连时的场景。

* 持续时间: OceanBase 集群触发 Unit 失连策略多久才实施切换。

## 前提条件

请确保当前登录 OCP 的用户具备如下权限时，才可使用仲裁服务组功能：

* **仲裁服务只读** 资源权限。
* 集群 **概览** 菜单权限。

## 查看服务组列表

登录 OCP 后，单击左侧导航栏的 **集群** ，进入 **仲裁服务** 页签下，单击 **服务组** 页签，进入 **服务组列表** 页面。

仲裁服务列表页面展示了仲裁服务组的 **主机** 、**优先级** 、**服务端口** 、**备注** 、**版本** 、**关联集群** 、**异常替换条件** 、**自动执行** 、**最近一次变更时间** 和 **状态** 。其中，支持通过主机 IP 和集群名进行仲裁服务查询。

* 单击各主机的主机 IP，可以跳转到主机监控页面，详情参见 [查看主机性能](../../880.manage-performance-monitoring/100.performance-monitoring-overview/300.view-host-performance.md)、[查看主机资源](../../880.manage-performance-monitoring/100.performance-monitoring-overview/700.view-host-resources.md) 和 [查看主机进程](../../880.manage-performance-monitoring/100.performance-monitoring-overview/750.view-host-process.md)。

* 单击仲裁服务关联集群的集群名称，可以跳转到集群概览页面，详情参见 [集群详情页概述](../300.manage-a-cluster/200.overview-of-the-cluster-details-page.md)。

* 您可通过对 **状态** 进行筛选，查看服务组信息。
