# 服务组概述

OB 4.1 开始提供仲裁服务能力，实现低成本的两副本双机房高可用能力(2F1A)。客户环境预计部署 300 个OB集群，为节省成本每个OB集群只有一个 2F 的双副本租户，并采用 2F1A 的部署模式，所有集群共享同一个仲裁服务(A副本) 。客户认为当该仲裁服务节点宕机后，所有OB集群将无法保证高可用能力，要求 OB 具备仲裁服务本身的高可用解决方案。OCP 设计了一种仲裁服务节点高可用解决方案。

## 什么是仲裁服务组

仲裁服务组中包含多个仲裁服务，当检测到某个仲裁服务不可用时，OCP自动将其关联集群切换到组内其他仲裁服务。

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/01232128.png)

如上图所示，仲裁服务组由两部分组成: 仲裁服务列表和切换策略。

* 仲裁服务组内的仲裁服务有优先级属性，当其关联的OB集群触发切换策略时，会优先切换到优先级高的仲裁服务上。若第一优先级资源不足，会将部分OB集群转移到下一优先级的仲裁服务。

* 切换策略分为两部分，unit 失连策略和持续时间，其中 unit 失连策略包含以下三种：

  * 默认策略, 当 OB 集群中存在租户的半数副本与仲裁服务失连时。
  * unit个数: 当 OB 集群中存在指定 unit server 与仲裁服务失连。
  * unit 百分比: 当 OB 集群中指定百分比的 unit server 与仲裁服务失连时。

* 持续时间: OB 集群触发 unit 失连策略多久才实施切换。

## 前提条件

请确保当前登录 OCP 的用户具备如下权限：

* **仲裁服务只读** 资源权限。
* 集群 **概览** 菜单权限。

## 查看服务组列表

登录 OCP 后，单击左侧导航栏的 **集群** ，进入 **仲裁服务** 页签下，单击 **服务组** 页签，进入 **服务组列表** 页面。

仲裁服务列表页面展示了仲裁服务组的 **主机** 、**优先级** 、**服务端口** 、**备注** 、**版本** 、**关联集群** 、**异常替换条件** 、**自动执行** 、**最近一次变更时间** 和 **状态** 。其中，支持通过主机 IP 和集群名进行仲裁服务查询。

* 单击各主机的主机 IP，可以跳转到主机监控页面，详情参见 [查看主机性能](../../880.manage-performance-monitoring/100.performance-monitoring-overview/300.view-host-performance.md)、[查看主机资源](../../880.manage-performance-monitoring/100.performance-monitoring-overview/700.view-host-resources.md) 和 [查看主机进程](../../880.manage-performance-monitoring/100.performance-monitoring-overview/750.view-host-process.md)。

* 单击仲裁服务关联集群的集群名称，可以跳转到集群概览页面，详情参见 [集群详情页概述](../300.manage-a-cluster/200.overview-of-the-cluster-details-page.md)。

* 您可通过对 **状态** 进行筛选，查看服务组信息。
