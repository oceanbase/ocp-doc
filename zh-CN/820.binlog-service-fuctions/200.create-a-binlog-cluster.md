# 创建 Binlog 集群

Binlog 集群是由一个或多个 Binlog Sever 组成的统一的对外服务，在 Binlog 集群中存在多台 Binlog Server 的场景下，租户 Binlog 服务启动时，将根据负载均衡的逻辑选择合适的 Binlog Server；当任意一台 Binlog Server 故障时，将由其他正常的 Binlog Server 接管其 Binlog 服务。

您可以根据业务需要新建待管理的 Binlog 集群。

## 前提条件

当前登录 OCP 的用户为 **ADMIN** 角色或 **ORG_ADMIN** 角色。

## 操作步骤

1. 登录 OCP，在左侧导航栏单击 **<UI-TERM key="ocp-v2.src.hook.useMenu.BinlogService">Binlog 服务</UI-TERM>** 。

2. 进入 Binlog **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">集群列表</UI-TERM>** 页面，单击右上角 **<UI-TERM key="ocp-v2.Binlog.New.CreateABinlogCluster">创建 Binlog 集群</UI-TERM>** 。

3. 在 **<UI-TERM key="ocp-v2.page.Binlog.CreateABinlogCluster">创建 Binlog 集群</UI-TERM>** 页面，设置集群基本信息。

     |配置  |   描述   |
     |-----|-------|
     | **<UI-TERM key="ocp-v2.page.Binlog.BinlogClusterName">Binlog 集群名</UI-TERM>**          | 自定义待管理的 Binlog 集群名称。集群名称必须以英文字母开头、英文或数字结尾，可包含英文、数字和下划线，且长度为 2 ~ 32 字符。|
     | **<UI-TERM key="ocp-v2.OBProxy.New.SoftwareVersion">软件版本</UI-TERM>**         | 选择 Binlog 集群的软件包版本。若列表中无可用软件包，您可单击列表下方 **<UI-TERM key="ocp-v2.src.component.PackageSelect.UploadASoftwarePackage">上传软件包</UI-TERM>** 进行上传。  |
     | **<UI-TERM key="ocp-v2.Detail.Overview.Endpoint">访问地址</UI-TERM>**          | 填写 Binlog 集群的访问地址，用于 OBProxy 与当前 Binlog 集群通信的请求转发和负载均衡。   |
     | **<UI-TERM key="ocp-v2.TakeOver.Component.LoadBalancer.AccessPort">访问端口</UI-TERM>** | Binlog 集群的访问端口，默认为 **2983**，支持自定义。   |

     ![Image 175](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/431/%E5%88%9B%E5%BB%BA%E9%9B%86%E7%BE%A4-%E5%9F%BA%E6%9C%AC%E8%AE%BE%E7%BD%AE.png)

4. 配置 MetaDB 信息。

   需要您输入 MySQL 租户的相关信息，用于存储 Binlog Service 的元信息，建议您不要使用业务集群。

     |配置  |   描述   |
     |-----|-------|
     | **<UI-TERM key="ocp-v2.Cluster.Import.ClusterName">集群名</UI-TERM>**    | 选择已有的 OceanBase 集群作为 Binlog Service 的 MetaDB。|
     | **<UI-TERM key="ocp-v2.Detail.Component.CloneTenantModal.TenantName">租户名</UI-TERM>**    | 选择集群中具体的 MySQL 租户。   |
     | **<UI-TERM key="ocp-v2.Binlog.New.DatabaseUsername">数据库用户名</UI-TERM>**        | 选择 MySQL 租户下具体的用户。  |
     | **<UI-TERM key="ocp-v2.Detail.Overview.DatabaseName">数据库名称</UI-TERM>**          | 填写 MetaDB 数据库的名称，默认为 `binlog_database`，支持自定义。   |

   ![10](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/431/%E5%88%9B%E5%BB%BA%E9%9B%86%E7%BE%A4-metadb%E8%AE%BE%E7%BD%AE.png)

5. 部署 Binlog 集群。

   每个 Binlog 集群由多个 Binlog Server 组成，每个 Binlog Server 需要设置的信息及其说明如下。

   |   配置   |  描述   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.src.component.AddHostDrawer.ComputerRoom">机房</UI-TERM>**     | Binlog Server 所在的机房，一个 Binlog Server 只能存在于一个机房。  |
   | **<UI-TERM key="ocp-v2.OBProxy.New.DeployMode.Models">机型</UI-TERM>**    | 可选项。如果选择了机型，后面主机列表会根据机型进行过滤。   |
   | **<UI-TERM key="ocp-v2.Detail.TakeOver.Host">主机</UI-TERM>**  | 您可以选择多个主机，或进行添加主机的操作。   |

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/431/%E5%88%9B%E5%BB%BA%E9%9B%86%E7%BE%A4-%E9%83%A8%E7%BD%B2binlog%E9%9B%86%E7%BE%A4.png)

6. 为 Binlog 集群配置启动参数。

   * 您可通过如图 ① 处，逐个添加启动参数项并为其配置值。

   * 也可通过如图 ② 处，单击 **<UI-TERM key="ocp-v2.page.Tenant.ParameterTemplate">参数模板</UI-TERM>** ，选择一个参数模板，系统会将模板中的参数连同配置自动填充到此处。在未创建集群参数模板的情况下，您可单击 **新建 Binlog 参数模板**，为 Binlog 集群创建参数模板，详情可参考 [管理 Binlog 参数模板](500.manage-binlog-parameter-templates.md)。

   ![09161737](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/01242114.png)

   系统提供如下 5 种内置模板，模板中包含了常用的参数设置，您可直接应用该模板进行 Binlog 集群的初始化设置。

   | 模板      | 说明    |
   |-----------|---------|
   | 顶级性能参数模板  | 预计占用资源 16C 10GB，预计 RPS 20W~25W，仅 4.2.0 及以上版本适用。    |
   | 超级性能参数模板  | 预计占用资源 12C 9GB，预计 RPS 15W~20W，仅 4.2.0 及以上版本适用。 |
   | 高级性能参数模板  | 预计占用资源 8C 9GB，预计 RPS 10W~15W，仅 4.2.0 及以上版本适用。    |
   | 中级性能参数模板  | 预计占用资源 4C 8256MB，预计 RPS 8W~10W，仅 4.2.0 及以上版本适用。    |
   | 默认性能参数模板  | 预计占用资源 2C 8224MB，预计 RPS 5W~6W，仅 4.2.0 及以上版本适用。    |

7. 在 **<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.CustomSettings">自定义设置</UI-TERM>** 模块，支持您自定义软件安装路径。路径默认为 `/home/admin/binlogservice`，支持自定义。

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/431/%E8%87%AA%E5%AE%9A%E4%B9%89%E8%AE%BE%E7%BD%AE.png)

8. 单击 **<UI-TERM key="ocp-v2.Component.AddSamplingInspectStrategy.Submitted">提交</UI-TERM>** 。

9. 创建集群任务提交后，您可在 **<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">任务中心</UI-TERM>** 中查看该任务的执行进度。

## 集群列表总览

集群创建完成后，您可在 **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">集群列表</UI-TERM>** 中查看 Binlog 集群的相关信息，包括 **<UI-TERM key="ocp-v2.page.Binlog.BinlogClusterName">Binlog 集群名</UI-TERM>**、**<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.Outline.State">状态</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Binlog.AllocatedCpu">已分配 CPU</UI-TERM>**、**<UI-TERM key="ocp-v2.Resource.Component.Block.AllocatedMemory">已分配内存</UI-TERM>**、**<UI-TERM key="ocp-v2.Detail.Resource.Trend.UsedDisks">已使用数据盘</UI-TERM>**、**<UI-TERM key="ocp-v2.Binlog.Component.UpgradeBinlogModal.VersionNumber">版本号</UI-TERM>**、**<UI-TERM key="ocp-v2.Cluster.Arbitration.CreationTime">创建时间</UI-TERM>** 和 **<UI-TERM key="ocp-performance-report.ReportTables.ParameterStatInfo.ZoneParamInfoTable.ModificationTime">修改时间</UI-TERM>** 。

* 单击集群名，可跳转至 Binlog 集群概览页面，详情参见 [查看 Binlog 集群概览](300.manage-a-binlog-cluster/100.binlog-cluster-overview.md)。
* 支持通过 **<UI-TERM key="ocp-v2.Backup.SecondaryBackup.Log.State">状态</UI-TERM>** 对 Binlog 集群进行筛选。
