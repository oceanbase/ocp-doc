# Create a standalone, centralized database

OceanBase Database offers the standalone centralized architecture to simplify your database deployment. With this architecture, you only need one server to get started, and the database is ready for use immediately. However, the database does not support multi-replica deployment or scaling, making it suitable for business systems with low data security requirements and for development and testing environments.

This topic will guide you through the process of creating a standalone centralized database.

## Prerequisites

* The user logging in to OCP has the **Create Cluster** permission.

* Only OceanBase Database V4.1.0 and above are supported.

## Procedure

1. Log in to the OCP console. On the left-side navigation pane, find the entry to create a cluster based on your business scenario.

   1. If you do not have a manageable cluster, a prompt is displayed on the **<UI-TERM key="ocp-v2.Detail.Overview.Cluster.1">Cluster</UI-TERM>** page to prompt you to create a cluster. Click **<UI-TERM key="ocp-v2.page.Cluster.CreateANewCluster">Create Cluster</UI-TERM>** in the prompt.

   2. If you already have a manageable cluster, click **New Cluster** in the upper-right corner of the **<UI-TERM key="ocp-v2.component.MonitorSearch.Cluster">Cluster</UI-TERM>** page.

2. On the **Create Cluster** page, select **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>**.

3. Configure the basic information of the cluster.

    The following table describes the parameters on the **Create Cluster** page.

     | Parameter  | Description |
     |-----|-------|
     | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.ClusterName">Cluster Name</UI-TERM>**          | The name of the cluster. The name must start with an English letter and end with an English letter or a number. It can contain English letters, numbers, and underscores, and must be 2 to 32 characters long. |
     | **<UI-TERM key="ocp-v2.Cluster.Import.RootSysPassword">Root@sys Password</UI-TERM>**    | The password can be customized or randomly generated. The password must meet the following complexity requirements: <ul><li>It must be 8 to 32 characters long. </li><li>It must contain uppercase and lowercase letters, numbers, and special characters, and must contain at least two of each. </li><li> The special characters are \~!@#%\^\&\*_-+=\`\|(){}\[\]:;',.?/  </li></ul>   |
     | **<UI-TERM key="ocp-v2.Detail.Component.UpgradeModal.ObVersion">OceanBase version</UI-TERM>**         | You can select an existing OceanBase cluster version from the list or click **<UI-TERM key="ocp-v2.src.component.PackageSelect.AddVersion">Add Version</UI-TERM>** below the list to upload an OceanBase version.  |
     | **<UI-TERM key="ocp-v2.Component.AddOBServerDrawer.ZoneName">Zone Name</UI-TERM>**    | You can keep the default value or customize it. The zone name must start with an English letter and can contain uppercase and lowercase letters, numbers, and underscores, and must be 2 to 48 characters long. An OceanBase cluster with multiple zones must have a zone that has the same region as the primary zone.  |
     | **<UI-TERM key="ocp-v2.Component.AddZoneDrawer.Host">Host</UI-TERM>**  | Select a host that is consistent with the architecture of **<UI-TERM key="ocp-v2.Detail.Component.UpgradeModal.ObVersion">OceanBase version</UI-TERM>**. You can select only one host as the OBServer and rootserver. If no hosts are available in the drop-down list, you can click **<UI-TERM key="ocp-v2.page.Host.AddHost">Add Host</UI-TERM>** to add a host.   |

     ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E5%88%9B%E5%BB%BA%E9%9B%86%E7%BE%A4.png)

4. Click **<UI-TERM key="ocp-v2.Component.RuleForm.ParameterConfiguration">Parameter Configurations</UI-TERM>** to open the parameter configuration module and configure the cluster parameters.

    * You can add parameters and configure their values one by one as shown in Figure ①.

    * Alternatively, you can click **<UI-TERM key="ocp-v2.component.ParameterTemplate.ParameterTemplateDropdown.SelectAParameterTemplate">Select Parameter Template</UI-TERM>** as shown in Figure ② to browse and select a parameter template. The parameters in the template will be automatically filled into the parameter configuration module.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>If OceanBase Version is V2.2.77, we recommend that you use the built-in <strong>2.2.77 Version Parameter Template</strong>. This template contains common parameter settings for OceanBase Database V2.2.77. You can apply this template to initialize the cluster. </li>
    <li>If no cluster parameter template has been created, you can click <strong>Create Cluster Template</strong> to create one. For more information, see <a href="../1200.cluster-parameters-template-management.md">Cluster Parameter Template Management</a>. </li>
    </ul>
    </main>

   ![09161737](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E5%8F%82%E6%95%B0%E8%AE%BE%E7%BD%AE1.png)

5. Click **Custom Configuration** to open the path and port configuration page.

   * Configure the path:
      1. In the **Path Configuration** section, customize the **<UI-TERM key="ocp-v2.Cluster.New.SoftwareInstallationPath">Software Installation Path</UI-TERM>**, **<UI-TERM key="ocp-v2.Cluster.New.DataDiskPath">Data Disk Path</UI-TERM>**, and **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.LogDiskPath">Log Disk Path</UI-TERM>** parameters as needed.
      2. After you configure the parameters, click **<UI-TERM key="ocp-v2.Settings.Credential.Cluster.Test">Test</UI-TERM>** to verify whether the paths are available. If not, you can troubleshoot the issues based on the test results or change the paths to available ones.

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>In a production environment, we recommend that you set the log disk space to be at least three times the size of the host memory space for OceanBase Database; also, to avoid performance issues, we recommend that you do not mount the data directory and log directory on the same disk. </p>
      </main>

   * Configure the port:
      1. In the **Port Configuration** section, customize the **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.SqlPort">SQL Port Number</UI-TERM>** and **<UI-TERM key="ocp-v2.Cluster.New.RpcPort">RPC Port</UI-TERM>** parameters.
      2. After you configure the parameters, click **<UI-TERM key="ocp-v2.Settings.Credential.Host.Test">Test</UI-TERM>** to verify whether the ports are available. If the ports are occupied, you need to configure other available ports.

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E8%87%AA%E5%AE%9A%E4%B9%89%E8%AE%BE%E7%BD%AE.png)

6. After the tests are successful, click **<UI-TERM key="ocp-v2.Detail.Component.AddUserDrawer.Submitted">Submit</UI-TERM>**.

7. In the right-side pane, verify the information. If the information is correct, click **<UI-TERM key="ocp-v2.component.FormEditTable.Determine">OK</UI-TERM>**.

8. In the dialog box that appears, select whether to create a tenant.

    * If you do not want to create a tenant, click **<UI-TERM key="ocp-v2.src.constant.task.SetToSuccessful">Skip</UI-TERM>**. In this case, only the cluster is created without a tenant. You can create a tenant later by referring to [Create a tenant](../../500.quickstart/600.quickstart-create-a-tenant.md).
    * If you want to create a tenant, configure the tenant. After you configure the tenant, click **<UI-TERM key="ocp-v2.Cluster.Component.NewTenant.CreateAndSubmit">Create and Submit</UI-TERM>**. You can view the execution progress of the related task in the **System Management > Tasks** page.

      The following table describes the parameters:

      | Parameter  | Description |
      |-----|-------|
      | Tenant Mode | The tenant mode. The default value is MySQL. |
      | Tenant Name | The name of the tenant. The default value is the same as the tenant mode. Custom tenant names are supported.  |
