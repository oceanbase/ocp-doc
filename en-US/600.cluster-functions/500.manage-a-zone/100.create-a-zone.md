# Add a zone

You can add zones to a cluster that you manage.

## Prerequisites

* Make sure that you have the following permissions:
  * **<UI-TERM key="ocp-v2.Auth.Role.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** menu of **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>**

  * Resource permissions: **Cluster maintenance** permission.
  * Menu permissions: Permission on the **Overview** menu of clusters.

* The target OceanBase cluster is managed in the current OceanBase Cloud Platform (OCP) cluster.

  Otherwise, you need to take over the OceanBase cluster to the current OCP cluster. For more information, see [Take over a cluster](../300.manage-a-cluster/400.take-over-a-cluster.md).

* You cannot add a zone to a **standalone centralized** database.
  
## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>**. The **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. On the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** page, find the target OceanBase cluster and click its name.

4. Go to the **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** page of the cluster and click **<UI-TERM key="ocp-v2.Topo.TopoGraph.NewZone">Create Zone</UI-TERM>** in the upper-right corner.

5. In the dialog box that appears, specify the zone information.

   By default, only one zone is added. You can click **+NewZone** to add more zones.

   The following table describes the parameters required for setting the zone information.

   |    **<UI-TERM key="ocp-performance-report.ReportTables.ParameterStatInfo.ZoneParamInfoTable.Parameter">Parameter</UI-TERM>**     | **<UI-TERM key="ocp-v2.Settings.Credential.Cluster.Description">Description</UI-TERM>** |
   |---------|------|
   | Zone Name | The name of the zone.      |
   | IDC      | The IDC where the zone is located.    |
   | Model     | Optional. If you select a model, the host list is filtered based on the model. |
   | CPU Architecture  | The CPU architecture of the zone. Valid values: `aarch64` and `x86`. <main id="notice" type='explain'><h4>Note</h4><p>You can select a CPU architecture only if the OceanBase Database RPM package for this architecture is available. </p></main>    |
   | Host      | The IP address of the host. You can select multiple IP addresses. In a production environment, we recommend that the size of the log disk be at least three times the memory size of the host. To avoid performance issues, we recommend that you do not create the data directory and the log directory on the same disk. |
   | Tenant Configuration | Settings of tenants. You can configure replicas for multiple tenants in the cluster at a time. <ul><li>You can specify the replica type, unit specification, and number of units. </li><li>Each row contains parameters of only one tenant. To configure more tenants, click **Add Tenant**. </li><li>The number of units is automatically specified based on the selected tenant and cannot be edited. </li></ul> |
   | Custom Settings  | The OS user, path, and port number of the OBServer node. For more information, see the section about custom settings in [Create a distributed cluster](../200.create-a-cluster/100.create-a-distributed-cluster.md).    |
   | Parameter Settings | The startup parameters of all OBServer nodes in the zone. For more information about the parameters, see [Overview](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001103709). <br>If you do not specify the OBServer node startup parameters, the startup parameters specified when you created the cluster are used.    |

6. Click **<UI-TERM key="ocp-v2.Detail.Monitor.Determine">OK</UI-TERM>**.

   In the dialog box that appears, you can click **<UI-TERM key="ocp-v2.Cluster.Import.ImportClusterResults.ViewTasks">View Task</UI-TERM>** to view the progress. You can also view the task progress in **<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">Task Center</UI-TERM>**.

   When the task enters the **<UI-TERM key="ocp-v2.src.constant.plan.Completed">Completed</UI-TERM>** state, and the status of the zone is displayed as **<UI-TERM key="ocp-v2.src.constant.compute.NormalOperation">Running</UI-TERM>** in the **<UI-TERM key="ocp-performance-report.pages.AWR.Zone">Zones</UI-TERM>** list on the **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** page of the cluster, the zone is created.
