# Restart a faulty OBServer node

This topic describes how to restart an OBServer node.

## Prerequisites

* Make sure that you have the following permissions:
  * **<UI-TERM key="ocp-v2.Auth.Role.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** menu of **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>**

* The target OceanBase cluster is managed in the current OCP cluster.

   Otherwise, you need to use the current OCP cluster to take over the OceanBase cluster. For more information, see [Take over a cluster](../300.manage-a-cluster/400.take-over-a-cluster.md).

* If the OBServer node to be restarted hosts the only full-featured replica of a tenant, we recommend that you restart the OBServer node during night hours when the business traffic is low.

## Procedure

1. Log on to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** to go to the **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page.

3. In the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** list on this page, find the target cluster and click its name to go to the **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">Overview</UI-TERM>** page of the cluster.

4. In the **<UI-TERM key="ocp-v2.Cluster.Component.MachineResource.NumberOfObservers">OBServers</UI-TERM>** list, find the target OBServer node, and then click **<UI-TERM key="ocp-v2.src.constant.compute.Restart">Restart</UI-TERM>** in the **<UI-TERM key="ocp-v2.Settings.Credential.Host.Operation">Actions</UI-TERM>** column.

5. In the dialog box that appears, set the following parameters and click **<UI-TERM key="ocp-v2.Cluster.Arbitration.Start">Restart</UI-TERM>**.

   * Set **<UI-TERM key="ocp-v2.Detail.Component.RestartModal.RestartMode">Restart Method</UI-TERM>** to **<UI-TERM key="ocp-v2.page.Host.Restart">Restart</UI-TERM>** or **<UI-TERM key="ocp-v2.Component.CgroupEditModal.ForceRestart">Force Restart</UI-TERM>**.

      * **<UI-TERM key="ocp-v2.src.constant.obproxy.Restart">Restart</UI-TERM>** (recommended): Business access to the database is not interrupted.

      * **<UI-TERM key="ocp-v2.Detail.Component.RestartModal.ForceRestart">Force Restart</UI-TERM>**: Business access to the database is interrupted and the business will become unavailable.

   * Specify whether to initiate a minor compaction before stopping the observer process. By default, this option is selected. A minor compaction prolongs the response time required to stop the observer process, but significantly shortens the time required to restore the OBServer node.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>If the OBServer node does not provide services, you can forcibly restart it. Otherwise, we recommend that you do not choose a force restart. In a general restart task, a pre-check is performed before the OBServer node is restarted. The OBServer node will not be restarted if it does not pass the pre-check. This way, your business is not interrupted. </p>
    </main>

6. In the dialog box that appears, click **<UI-TERM key="ocp-v2.Cluster.Import.ImportClusterResults.ViewTasks">View Task</UI-TERM>** to view the progress.

   You can also choose **System Management > Tasks** to view the progress.

   When the task enters the **<UI-TERM key="ocp-v2.src.constant.backup.Completed">Completed</UI-TERM>** state, and the status of the OBServer node is displayed as **<UI-TERM key="ocp-v2.src.constant.oceanbase.NormalOperation">Running</UI-TERM>** in the **<UI-TERM key="ocp-v2.Cluster.Component.MachineResource.NumberOfObservers">OBServers</UI-TERM>** list on the **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** page, the OBServer node is restarted.
