# View the unit distribution

You can view the unit distribution to check the physical distribution and resource usage of each tenant in OceanBase clusters.

The **<UI-TERM key="ocp-v2.Detail.Resource.UnitDistribution">Unit Distribution</UI-TERM>** page provides the **<UI-TERM key="ocp-v2.Detail.Resource.Unit.UnitView">Unit View</UI-TERM>** and **<UI-TERM key="ocp-v2.Detail.Resource.Unit.ReplicaView">Replica View</UI-TERM>** tabs.

To view the unit distribution, perform the following operations: In the left-side navigation pane, click **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>**. On the **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page, click the name of a cluster. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.src.util.menu.ResourceManagement">Resource Management</UI-TERM>**. The **<UI-TERM key="ocp-v2.Detail.Resource.UnitDistribution">Unit Distribution</UI-TERM>** page automatically appears.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>If the OceanBase Database version of the cluster is V4.0 or later, the <strong>Replica View</strong> tab is not displayed. </p>
  </main>

## Prerequisites

* To view the distribution information of units and replicas in a cluster, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Read-only** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.src.util.menu.ResourceManagement">Resource Management</UI-TERM>** menu of **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>**

* To manually migrate loads, start an OBServer node, or stop an OBServer node, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.Detail.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.Detail.Resource.ResourceManagement">Resource Management</UI-TERM>** menu of **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>**

* If the version of the OceanBase cluster is V4.0 or later, the <strong>Replica View</strong> tab is not displayed.

## Unit View

The **<UI-TERM key="ocp-v2.Detail.Resource.Unit.UnitView">Unit View</UI-TERM>** tab automatically appears and shows the distribution of resource units in a view. Each column indicates an OBServer node.

* Click **<UI-TERM key="ocp-v2.component.ZoneFormCardList.Tenant">Tenant</UI-TERM>** in the upper-right corner of the tab to select a tenant.

* Click **<UI-TERM key="ocp-v2.Component.StorageConfigCard.S3RegionName">Region</UI-TERM>** in the upper-right corner of the tab to select the physical region where the current cluster is located.

* Click **<UI-TERM key="ocp-v2.Component.OBServerList.OBServerModal.BelongsZone">Zone</UI-TERM>** in the upper-right corner of the tab to select Zone1, Zone2, or Zone3.

* Click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.IndexTable.Type">Type</UI-TERM>** in the upper-right corner of the tab to select the host type.

* Enable unit load balancing:

  * If the OceanBase Database version of the cluster is V4.x, enable **<UI-TERM key="ocp-v2.Detail.Resource.Unit.AutomaticMigration">Automatic Migration</UI-TERM>**. When the system resource usage is unbalanced, resource units are automatically migrated in the background to achieve load balancing. If the server is offline or in the **DELETING** state, automatic migration does not take effect.

  * If the OceanBase Database version of the cluster is V2.x or V3.x, enable **<UI-TERM key="ocp-v2.Detail.Resource.Unit.EnableMigration">Enable Migration</UI-TERM>**. When the system resource usage is unbalanced, resource units can be automatically migrated in the background or manually migrated. If the server is offline or in the **DELETING** state, automatic migration does not take effect.

* Enable **<UI-TERM key="ocp-v2.Detail.Monitor.AutomaticRefresh">Auto Refresh</UI-TERM>**. The unit view refreshes every second so that you can view the latest unit distribution.

  * Check load balancing of the cluster:

    You can view the values of **<UI-TERM key="ocp-v2.Resource.Component.Block.AllocatedMemory">Allocated Memory</UI-TERM>**, **<UI-TERM key="ocp-v2.page.Binlog.AllocatedCpu">Allocated CPU</UI-TERM>**, and **<UI-TERM key="ocp-v2.Cluster.Component.WaterLevel.DiskUsed">Data Disk Used</UI-TERM>** of each zone to check whether the usage of the same type of resource is balanced across the servers in the zone. If no, you can modify the load balancing parameters of the OceanBase cluster to implement load balancing.

  * Evaluate whether the cluster needs a scale-out:

    You can determine whether the data disk capacity is sufficient based on the value of **<UI-TERM key="ocp-v2.Detail.Resource.Trend.UsedDisks">Data Disk Used</UI-TERM>**. When the data disk usage reaches 80%, you can scale out the cluster by adding a server to ensure normal data disk usage.

  * View the resource distribution of a tenant:

    Click **<UI-TERM key="ocp-v2.page.AuditEvent.Tenant">Tenant</UI-TERM>** in the upper part of the view and select the name of the target tenant from the drop-down list. Then, click **<UI-TERM key="ocp-v2.Monitor.AddMonitor.VisualizationsTable.Ok">OK</UI-TERM>** to view the resource distribution of the tenant.

  * View the details of a tenant:

    * Hover the pointer over the name of a tenant to view its information, including the name, ID, status, zone priorities, locality, and arbitration service status.
    * A unit card next to the tenant displays the resource specifications and replica information of the tenant. Hover the pointer over the unit card to view the OBServer node information, including the unit ID, tenant name, resource pool, number of CPU cores, memory size (GB), and used space of the data disk (GB).

        <main id="notice" type='explain'>
        <h4>Note</h4>
        <p>In OceanBase Database V4.0 and later, the following OBServer node information is added to a unit card:<ul><li>The total size of the log disk (GB), IOPS, and used size of the log disk (GB). </li><li>The <b>Leader</b> label, which indicates that a leader log stream resides on the current OBServer node. </li><li>The label that indicates whether a leader exists and the replica type. Valid values: <b>FULL</b> (full-featured replica) and <b>READONLY</b> (read-only replica). </li></ul></p>
        </main>

    Click the name of the tenant to go to its **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">Overview</UI-TERM>** page. On this page, you can view the tenant details, including the replica details, zone priorities, and allowlist information.

  * Manually implement load balancing:

    If the built-in load balancing algorithms of the OceanBase cluster cannot meet your needs, you can click a unit card next to the tenant to manually migrate resources, but only within a single zone.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>We recommend that you disable the automatic load balancing feature of the OceanBase cluster before you manually implement load balancing, because the feature may migrate the unit back to the original locality. </p>
    </main>

  * View the number of units:
  
      View the number of resource units in the **<UI-TERM key="ocp-v2.Restore.SamplingStrategy.Detail.UnitQuantity">Number of Units</UI-TERM>** section. When the number of resource units is greater than the number of tenants, it indicates that some resource units are not associated with any tenant. In this case, you can drop or merge resource units that remain in the idle state for more than 1 hour.

## Replica View

Click the **<UI-TERM key="ocp-v2.Detail.Resource.Unit.ReplicaView">Replica View</UI-TERM>** tab. This tab shows the distribution of replicas in a view. Each column indicates an OBServer node.

* Click **<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.UpgradeArbitrationGroup.Tenant">Tenant</UI-TERM>** in the upper-right corner of the tab to select a tenant.

* Click **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.Region">Region</UI-TERM>** in the upper-right corner of the tab to select the physical region where the current cluster is located.

* Click **<UI-TERM key="ocp-v2.Component.OBServerList.BelongsZone">Zone</UI-TERM>** in the upper-right corner of the tab to select Zone1, Zone2, or Zone3.

* Click **<UI-TERM key="ocp-v2.page.External.CreateDrawer.Type">Type</UI-TERM>** in the upper-right corner of the tab to select the host type.

* Enable **<UI-TERM key="ocp-v2.component.MonitorSearch.AutoRefresh">Auto Refresh</UI-TERM>**. The replica view refreshes every 30 seconds so that you can view the latest replica distribution.

  * Check load balancing of the cluster:

    You can view the values of **<UI-TERM key="ocp-v2.Resource.Component.Block.AllocatedMemory">Allocated Memory</UI-TERM>**, **<UI-TERM key="ocp-v2.Resource.Component.Block.AllocatedCpu">Allocated CPU</UI-TERM>**, and **<UI-TERM key="ocp-v2.Detail.Resource.Trend.UsedDisks">Data Disk Used</UI-TERM>** of each zone to check whether the usage of the same type of resource is balanced across the servers in the zone. If no, you can modify the load balancing parameters of the OceanBase cluster to implement load balancing.

    In the following figure, ③ indicates the allocated memory on the current OBServer node, and ④ indicates the total memory on the current OBServer node.

  * Evaluate whether the cluster needs a scale-out:

    You may consider a cluster scale-out when the value of **<UI-TERM key="ocp-v2.Detail.Resource.Trend.UsedDisks">Data Disk Used</UI-TERM>** reaches 80%.

  * View the resource distribution of a tenant:

    Select the target tenant from the **<UI-TERM key="ocp-v2.page.Information.Tenant">Tenant</UI-TERM>** drop-down list, and then click **<UI-TERM key="ocp-v2.Statistics.components.ManualCollectDrawer.Ok">OK</UI-TERM>** to view the resource distribution of the tenant.

    Hover the pointer over the replica card next to the tenant to view the number of leader replicas and the total number of replicas of the tenant.

    In the following figure, ① indicates the number of leader replicas in the OBServer, and ② indicates the total number of replicas in the OBServer.

  * View the details of a tenant:

    Click the name of the tenant to go to its **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">Overview</UI-TERM>** page. On this page, you can view the tenant details, including the replica details, zone priorities, and allowlist information.

  * Stop or start an OBServer node:

    Click the host card next to a host address to start or stop the OBServer node.

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>Stopping an OBServer node will switch all its traffic and the leaders to another OBServer node. Proceed with caution. </p>
   </main>
