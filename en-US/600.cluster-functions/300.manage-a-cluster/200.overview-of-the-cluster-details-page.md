# View the details of a cluster

On the **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">Overview</UI-TERM>** page of a cluster, you can view its basic information, resource usage, alerts, system events of the last seven days, zones, and OBServer nodes, and can perform routine cluster maintenance.

## Prerequisites

Make sure that you have the following permissions:

* **<UI-TERM key="ocp-v2.Auth.Role.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Read-only** permission
* **<UI-TERM key="ocp-v2.Auth.Role.AddRole.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** menu of **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>**

## View resource usage

In the **<UI-TERM key="ocp-v2.Cluster.Component.WaterLevel.ResourceWaterLevel">Resource Usage</UI-TERM>** section, you can view the following information about the current cluster: **<UI-TERM key="ocp-v2.Cluster.Component.WaterLevel.AllocatedCpu">Allocated CPU</UI-TERM>**, **<UI-TERM key="ocp-v2.Resource.Component.Block.AllocatedMemory">Allocated Memory</UI-TERM>**, **<UI-TERM key="ocp-v2.Resource.Component.Block.AssignedLogDisk">Allocated Log Disk</UI-TERM>**, and **<UI-TERM key="ocp-v2.Detail.Resource.Trend.UsedDisks">Data Disk Used</UI-TERM>**. You can manage the cluster based on the resource usage.

## View system events in the last seven days

You can set query conditions in the **<UI-TERM key="ocp-v2.Detail.Component.Event.SystemEventsInTheLast">System Events in Last 7 Days</UI-TERM>** section to query the system events in the last seven days.

* You can specify a time range in the time selection field.

* You can filter events in the **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.EventName">Event Name</UI-TERM>** column.

* You can filter events by module.

* You can sort events in ascending or descending order by start time.

The system lists the system events that meet the foregoing conditions you specified.

## Protection modes

* Maximum performance: It protects user data and maximizes the performance of the primary cluster. In this mode, the log transfer between the primary cluster and all standby clusters is asynchronous.

* Maximum availability: Normally, the primary cluster keeps synchronous log transfer with only one standby cluster.

* Maximum protection: The primary cluster keeps synchronous log transfer with only one standby cluster, and asynchronous log transfer with other standby clusters.

## Switch between clusters
