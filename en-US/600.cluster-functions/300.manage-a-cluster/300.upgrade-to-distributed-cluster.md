# Scale a standalone system to a distributed cluster

This section will guide you on how to scale a standalone system to a distributed cluster.

## Background information

* When you scale out a standalone cluster to a multi-host cluster in a single zone, only the computing power of OceanBase Database is enhanced. The cluster does not support multi-replica high availability. This mode is suitable for development and test environments.
* When you scale out a standalone cluster to an even number of zones, the cluster cannot meet the high availability requirements and may cause data security risks. We recommend that you modify the configuration to ensure that an odd number of zones is used, or enable the arbitration service for the cluster or tenant.

## Prerequisites

* Make sure that the user who logs in to OCP has the following permissions:

  * The resource permission of **OCP:ClusterMaintenance**.
  * The permission of the **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** menu of the cluster.

* The standalone cluster to be scaled out is in the **RUNNING** state.

* Before you scale out the standalone cluster, make sure that the distributed OceanBase Database software package meets the following requirements:

  * The package name does not contain the `standalone` identifier.
  * The package version is the same as the version of the standalone cluster. For example, both the standalone and distributed OceanBase Database are V4.2.5.4.
  * The system architecture of the package is the same as that of the standalone cluster.

## Considerations

* The operation of scaling out a standalone cluster to a distributed cluster is high-risk and will interrupt business access. We recommend that you perform this operation under the technical guidance of OceanBase Database engineers.
* Before you proceed, read through the official documentation [Considerations when you scale out a standalone cluster to a distributed cluster](https://www.oceanbase.com/docs/common-oceanbase-database-standalone-1000000003360376) carefully to confirm whether the current database version supports the scaling out to a distributed cluster. If you proceed without confirmation, the cluster may become unavailable.

## Considerations

If the cluster has the cgroup enabled, and the version of the operating system kernel of the host selected for scaling out is earlier than 5.1.0, we recommend that you disable the cgroup of the cluster. Otherwise, the system performance may drop or become unstable.

## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.component.MonitorSearch.Cluster">Cluster</UI-TERM>**. The **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. On the **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** page, find the target cluster and click its name.

4. On the **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">Overview</UI-TERM>** page of the cluster, click **<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.UpgradeADistributedCluster">Extended Distributed Cluster</UI-TERM>**.

5. In the dialog box that appears, understand the operation risks. If you still want to proceed, click **Scale Out**.

6. In the panel that appears on the right, configure the following information.

    * Select the software package type. By default, it is the same as the standalone edition. If the system cannot identify the software package type of the standalone edition, you need to manually select an appropriate package based on the operating system version.

    * Configure the relevant information for scaling out.

      By default, the system scales out the cluster in **<UI-TERM key="ocp-v2.Component.AddZoneDrawer.NewZone">Create Zone</UI-TERM>** mode. You can click the **<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.AddObserver">Add OBServer Node</UI-TERM>** tab to scale out the cluster to multi-host single-zone mode. In **<UI-TERM key="ocp-v2.Topo.TopoGraph.NewZone">Create Zone</UI-TERM>** mode, you can click **<UI-TERM key="ocp-v2.Component.AddZoneDrawer.NewZone">Create Zone</UI-TERM>** to add multiple zones.

      | **Configuration**  |   **<UI-TERM key="ocp-v2.Auth.Role.Detail.Description">Description</UI-TERM>**    |
      |---------|-------|
      | Zone Name | The name of the zone. When you scale out the cluster in **<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.AddObserver">Add OBServer Node</UI-TERM>** mode, you cannot edit the zone name.    |
      | IDC      | The IDC where the zone is located. When you scale out the cluster in **<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.AddObserver">Add OBServer Node</UI-TERM>** mode, you cannot edit the IDC.     |
      | Host Type      | Optional. If you select a host type, the host list will be filtered based on the host type.   |
      | CPU Architecture  | The CPU architecture of the zone must be the same as that of the cluster. <ul><li>When you scale out the cluster in **<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.AddObserver">Add OBServer Node</UI-TERM>** mode, you cannot edit the CPU architecture.</li><li>When you scale out the cluster in **<UI-TERM key="ocp-v2.Topo.TopoGraph.NewZone">Create Zone</UI-TERM>** mode, after you select an architecture, the system checks whether an installation package is available for the CPU architecture of the standalone edition. If no installation package is available for the specified architecture, the zone cannot be added.</li></ul>   |
      | Host      | When you scale out the cluster in **<UI-TERM key="ocp-v2.Topo.TopoGraph.NewZone">Create Zone</UI-TERM>** mode, you can select only one host as an OBServer and a RootServer. When you scale out the cluster in **<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.AddObserver">Add OBServer Node</UI-TERM>** mode, you can select multiple hosts. <ul><li>If no host is available in the drop-down list, you can perform [Add Host](../../850.host-features/100.manage-a-host/200.add-a-host.md).</li><li>In a production environment, OceanBase Database recommends that the log disk space be at least three times the host memory space. To avoid performance issues, we recommend that you do not mount the data directory and log directory to the same disk.</li></ul> |
      | Tenant Configuration  | When you scale out the cluster in **<UI-TERM key="ocp-v2.Topo.TopoGraph.NewZone">Create Zone</UI-TERM>** mode, you can configure the replica information for all tenants in the cluster at a time. <ul><li>The replica information to be configured includes: replica type, unit specification, and unit quantity.</li><li>One row of information is for one tenant. If you need to configure multiple tenants, click **<UI-TERM key="ocp-v2.component.ZoneFormCardList.AddTenants">Add Tenant</UI-TERM>** to add more rows.</li><li>The unit quantity is automatically filled in based on the selected tenant and cannot be edited.</li></ul>   |

    * Perform custom settings to configure the OS user, path, and port of the OBServer node. For more information, see **Custom configuration** in [Create a distributed cluster](../200.create-a-cluster/100.create-a-distributed-cluster.md).

    * Configure the startup parameters of the OBServer. For more information, see [OceanBase parameters](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000218691).

   ![09161742](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/01251426.png)

7. Click **<UI-TERM key="ocp-v2.component.FilterDropdown.Determine">OK</UI-TERM>**.

   In the dialog box that appears, you can click **<UI-TERM key="ocp-v2.src.constant.ViewTasks">View Tasks</UI-TERM>** to view the task progress. You can also view the task progress in **<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">Task Center</UI-TERM>**.
