# Move out a cluster

This topic describes how to move out an OceanBase cluster from one OceanBase Cloud Platform (OCP) cluster to another.

<main id="notice" type='alert'>
<h4>Notice</h4>
<p>After an OceanBase cluster is moved out, it is no longer managed by the original OCP cluster. Proceed with caution. </p>
</main>

## Prerequisites

* Make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Management** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.Detail.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">Overview</UI-TERM>** menu of **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>**

* The OceanBase cluster to be moved out is in the **STOPPED**, **RUNNING**, or **UNAVAILABLE** state.

* Move out the OceanBase cluster in off-peak hours.

* When you move out an OceanBase cluster, you must first move out the standby cluster.

  * In a single-OCP scenario, you must move out the standby OceanBase cluster before the primary OceanBase cluster.

  * In a multi-OCP scenario, you must first move out the standby OceanBase cluster from its OCP cluster and then move out the primary OceanBase cluster from its OCP cluster.

* If an OceanBase cluster and an OBProxy cluster share the same host in a move-out or takeover scenario, perform the following operations in sequence. For more information, see [Migrate a cluster between IDCs in OCP](../../1850.ocp-om-best-practices/750.ocp-idc-migration.md).

   1. [Move out the OBProxy cluster](../../800.obproxy-functions/300.manage-a-obproxy-cluster/450.migrate-an-obproxy-cluster.md).
   2. Move out the OceanBase cluster.
   3. [Take over the OceanBase cluster](400.take-over-a-cluster.md).
   4. [Take over the OBProxy cluster](../../800.obproxy-functions/400.manage-a-obproxy-server/200.take-over-an-obproxy.md).

* If other services are deployed on the host where the OceanBase cluster is deployed, you cannot delete this host from OCP when you move out the OceanBase cluster.
  
## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>**. The **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. On the **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page, find the target cluster and click its name.

4. On the **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** page of the cluster, click the **...** icon in the upper-right corner and select **<UI-TERM key="ocp-v2.Detail.Overview.MoveOutOfTheCluster.1">Migrate Cluster</UI-TERM>**.

5. In the dialog box that appears, perform the following operations:

   1. **Export credentials**: Enter the credential file encryption key and click **<UI-TERM key="ocp-v2.Credential.Component.ExportModal.ExportCredentials">Export Credential</UI-TERM>**. Then, click **<UI-TERM key="ocp-v2.Cluster.Import.Next">Next</UI-TERM>**.

      We recommend that you export the credentials so that you can directly import them after taking over the OceanBase cluster. After you click **<UI-TERM key="ocp-v2.Credential.Component.ExportModal.ExportCredentials">Export Credential</UI-TERM>**, the system will export the credentials of the cluster to be moved out. After the OceanBase cluster is taken over to the new OCP cluster, you can import its credentials in batches for future use. For more information, see [Import a credential](../../1600.system-management-features/100.manage-password-box/300.import-a-credential.md).

   2. **Move out the OceanBase cluster**:

      1. Select the host where the OceanBase cluster is deployed, and delete it from the original OCP cluster before you take over the OceanBase cluster to the new OCP cluster. You can also delete the host on the **<UI-TERM key="ocp-v2.page.Host.HostList">Hosts</UI-TERM>** page. For more information, see [Delete a host](../../850.host-features/550.delete-a-host.md).

         <main id="notice" type='alert'>
         <h4>Notice</h4>
         <p>If no other services are deployed on the host, we recommend that you delete the host. If you choose to retain the host and deploy other clusters on this host, adverse effects can be caused on the original cluster. Exercise caution when you choose to retain the host, and understand the risks in advance. </p>
         </main>

      2. Specify whether to retain information about the OceanBase cluster to be moved out. If you enable **<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step2.WhetherToRetainClusterInformation">Retain Cluster Information</UI-TERM>**, information about the OceanBase cluster is retained in the original OCP cluster for the config server. This way, business applications can still connect to the OceanBase cluster by using OBProxy.

      3. Enter **move out** in the textbox and click **<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step2.MoveOut">Move Out</UI-TERM>** to submit a task to move out the OceanBase cluster.

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/432/move-out.png)

6. In the dialog box that appears, click **<UI-TERM key="ocp-v2.Detail.Report.ViewTasks">View Task</UI-TERM>** to view the progress.

   If the task status is **<UI-TERM key="ocp-v2.src.constant.backup.Completed">Completed</UI-TERM>**, and the status of this OceanBase cluster on the **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page is **<UI-TERM key="ocp-v2.src.constant.oceanbase.MovedOut">Moved Out</UI-TERM>**, the cluster is successfully moved out.

7. On the **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page, delete the cluster.
