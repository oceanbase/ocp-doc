# Take over a cluster

You can take over a cluster created by using CLI or OCP on the command line interface (CLI) to the current OCP console, and continue to maintain and manage the cluster on the current OCP console.

## Prerequisites

* You are logged in to OCP as a user with the **ADMIN** or **ORG_ADMIN** role.

* All OBServer nodes of the OceanBase cluster to be taken over are running normally.

* When you take over an OceanBase cluster, follow the principle of taking over the primary cluster first:

  * If you are in a single OCP scenario, take over the primary OceanBase cluster first, and then take over the standby OceanBase cluster.

  * If you are in a multi-OCP scenario, take over the primary OceanBase cluster in one OCP first, and then take over the standby OceanBase cluster in any OCP.

* The service name of each tenant in the OceanBase cluster to be taken over must be unique, and the service name must also be unique in the system. Otherwise, after the takeover, the service name of the tenant in the OceanBase cluster will be set to **Invalid**. For more information about service names, see [Manage service names](../../700.tenant-functions/600.manage-a-tenant/800.manage-service-name.md).

* If the OceanBase cluster to be taken over is deployed by using obd, check whether the cluster meets the takeover conditions by referring to [Take over an obd-deployed cluster in OCP](https://www.oceanbase.com/docs/community-obd-cn-1000000001477802) before the takeover.

## Considerations

* After an OceanBase cluster is taken over, it cannot be maintained and monitored in the original OCP cluster. Therefore, assess the impact before the takeover.
* If the OceanBase cluster to be taken over has been configured with a load type, you must configure the load type again on the **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">Overview</UI-TERM>** page of the cluster after the takeover.
* When you take over an OceanBase cluster, OCP will also take over the corresponding host of each OBServer node in the cluster for unified management.
  * If the credentials used by the hosts are the same, OCP can take over the hosts in the **Precheck** step.
  * If the credentials used by the hosts are different, you must add the hosts to OCP by using the [Add Host] feature before you take over the cluster.

## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.src.constant.alarm.Cluster">Cluster</UI-TERM>**. The **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. On the **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page, click **<UI-TERM key="ocp-v2.page.Cluster.TakeOverTheCluster">Take over Cluster</UI-TERM>** in the upper-right corner.

4. Connect to the cluster by using **<UI-TERM key="ocp-v2.Cluster.Import.DirectlyConnected">Direct Connection</UI-TERM>** or **OBProxy**.

   * **Direct Connection**: Enter the **<UI-TERM key="ocp-v2.page.OBProxy.Endpoint">Access URL</UI-TERM>** and **<UI-TERM key="ocp-v2.Scan.ReportTable.ServerInfoTable.Port">Port</UI-TERM>** of the cluster, as well as the **<UI-TERM key="ocp-v2.Cluster.Import.RootSysPassword">Root@sys Password</UI-TERM>**. You can also choose to **Enter proxyro Password**. Click **<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step1.NextStep">Next</UI-TERM>**.

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>The password of the proxyro account is used by OBProxy to access the OceanBase cluster. You can enter the password here to ensure consistency of the proxyro password. For more information about the proxyro account, see <a href="../../800.obproxy-functions/300.manage-a-obproxy-cluster/900.proxyro-user-management.md">Manage proxyro accounts</a>. </p>
      </main>

      ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/420/%E6%8E%A5%E7%AE%A1%E9%9B%86%E7%BE%A4-%E7%9B%B4%E8%BF%9E.png)

   * **OBProxy**: Enter the **<UI-TERM key="ocp-v2.MultiCluster.Detail.Endpoint">Access URL</UI-TERM>** and **<UI-TERM key="ocp-v2.Cluster.Import.Port">Port</UI-TERM>** of the cluster, as well as the **<UI-TERM key="ocp-v2.Detail.Component.SwitchModal.ClusterName">Cluster Name</UI-TERM>**, **<UI-TERM key="ocp-v2.Cluster.Import.ClusterIdOptional">Cluster ID (Optional)</UI-TERM>**, and **<UI-TERM key="ocp-v2.Cluster.Import.RootSysPassword">Root@sys Password</UI-TERM>**. You can also choose to **Enter proxyro Password**. Click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>**.

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p><ul><li>If the cluster to be taken over is a standby cluster, the cluster ID is required. If both the primary and standby clusters need to be taken over, take over the primary cluster first, and then the standby cluster. </li><li>The password of the proxyro account is used by OBProxy to access the OceanBase cluster. You can enter the password here to ensure consistency of the proxyro password. For more information about the proxyro account, see <a href="../../800.obproxy-functions/300.manage-a-obproxy-cluster/900.proxyro-user-management.md">Manage proxyro accounts</a>. </li></ul></p>
      </main>

      ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/420/%E6%8E%A5%E7%AE%A1%E9%9B%86%E7%BE%A4-obproxy.png)

5. After the cluster is connected, go to the precheck page.

   * If the precheck passes, you can enter the corresponding information and take over the hosts that correspond to the OBServer nodes that are not managed by OCP.

   * If the precheck fails, modify the OBServer node configurations as prompted and click **<UI-TERM key="ocp-v2.Cluster.Import.ReCheck">Recheck</UI-TERM>** after the modification.

   ![09010928](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E6%8E%A5%E7%AE%A1%E9%9B%86%E7%BE%A41.png)

6. Click **<UI-TERM key="ocp-v2.Settings.Component.ModifyUserInfoDrawer.Submit">Submit</UI-TERM>**.

   After the task is submitted, you can view the task execution progress on the submission result page or return to the cluster overview page.
