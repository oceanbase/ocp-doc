# Take over a cluster

You can take over a cluster that was created by using the CLI or another OCP console to the current OCP console. After the takeover, you can continue to manage and maintain the cluster in the current OCP console.

## Prerequisites

* The current login user is the **ADMIN** or **ORG_ADMIN** role.

* All OBServer nodes of the target OceanBase cluster are running normally.

* When taking over the OceanBase cluster, follow the primary cluster first principle:

  * In a single OCP scenario, take over the primary OceanBase cluster first, and then the standby OceanBase cluster.

  * In a multi-OCP scenario, take over the primary OceanBase cluster first in one OCP, and then take over the standby OceanBase cluster in any OCP.

* The service names of tenants and the service names of systems in the OceanBase cluster to be taken over must be unique. Otherwise, the service name status of tenants with conflicting service names will be set to **Invalid** after the takeover. For more information about service names, see [Manage service names](../../700.tenant-functions/600.manage-a-tenant/800.manage-service-name.md).

* If the target cluster is deployed by using obd, check whether the cluster meets the takeover conditions by referring to [Take over a cluster deployed by using obd](https://en.oceanbase.com/docs/community-obd-en-10000000001957807) before the takeover.

## Considerations

* Each OceanBase cluster can be managed by only one OCP. After the takeover, the cluster cannot be properly maintained and monitored in the original OCP. Therefore, assess the takeover plan carefully before the takeover. We recommend that you migrate the cluster before the takeover. For more information, see [Migrate a cluster](650.migrate-a-cluster.md).
* If the OceanBase cluster to be migrated is shared with the OBProxy cluster on the same host, follow the sequence of operations below before the takeover. For more information, see [OCP IDC migration](../../1850.ocp-om-best-practices/750.ocp-idc-migration.md).

   1. [Migrate the OBProxy cluster](../../800.obproxy-functions/300.manage-a-obproxy-cluster/450.migrate-an-obproxy-cluster.md).
   2. Migrate the OceanBase cluster.
   3. [Take over the OceanBase cluster](400.take-over-a-cluster.md).
   4. [Take over the OBProxy cluster](../../800.obproxy-functions/400.manage-a-obproxy-server/200.take-over-an-obproxy.md).

* If the OceanBase cluster to be taken over has been configured with a load type, you need to reconfigure the load type for the cluster on the **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">Overview</UI-TERM>** page of the cluster.
* When taking over the OceanBase cluster, OCP will also take over the OBServer nodes of the cluster.
  * If the credentials of the OBServer nodes are the same, you can take over the nodes in the **Precheck** step.
  * If the credentials of the OBServer nodes are different, you need to add the nodes to OCP before you take over the cluster. For more information, see [Add a host](../../850.host-features/100.manage-a-host/200.add-a-host.md).
* After the cluster is taken over, you need to reconfigure the backup strategy based on the original backup strategy of the cluster or the tenant.

## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.src.constant.alarm.Cluster">Clusters</UI-TERM>**. The **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. On the **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page, click **<UI-TERM key="ocp-v2.page.Cluster.TakeOverTheCluster">Take over Cluster</UI-TERM>** in the upper-right corner.

4. Connect to the cluster by using **<UI-TERM key="ocp-v2.Cluster.Import.DirectlyConnected">Direct Connection</UI-TERM>** or **OBProxy**.

   * **Direct Connection:** Enter the **<UI-TERM key="ocp-v2.page.OBProxy.Endpoint">Access Address</UI-TERM>** and **<UI-TERM key="ocp-v2.Scan.ReportTable.ServerInfoTable.Port">Port</UI-TERM>** of the cluster, and **<UI-TERM key="ocp-v2.Cluster.Import.RootSysPassword">Root@sys Password</UI-TERM>**, and optionally enter the password of the proxyro account. Then, click **<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step1.NextStep">Next</UI-TERM>**.

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>The password of the proxyro account is used by OBProxy to access the OceanBase cluster. You can enter the password here to ensure the consistency of the proxyro password. For more information about the proxyro account, see <a href="../../800.obproxy-functions/300.manage-a-obproxy-cluster/900.proxyro-user-management.md">Manage proxyro accounts</a>. </p>
      </main>

   * **OBProxy:** Enter the **<UI-TERM key="ocp-v2.MultiCluster.Detail.Endpoint">Access Address</UI-TERM>** and **<UI-TERM key="ocp-v2.Cluster.Import.Port">Port</UI-TERM>** of the cluster, **<UI-TERM key="ocp-v2.Detail.Component.SwitchModal.ClusterName">Cluster Name</UI-TERM>**, **<UI-TERM key="ocp-v2.Cluster.Import.ClusterIdOptional">Cluster ID (Optional)</UI-TERM>**, and **<UI-TERM key="ocp-v2.Cluster.Import.RootSysPassword">Root@sys Password</UI-TERM>**, and optionally enter the password of the proxyro account. Then, click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>**.

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p><ul><li>If the standby cluster is to be taken over, the cluster ID is a required field. If both the primary and standby clusters are to be taken over, take over the primary cluster first, and then take over the standby cluster. </li><li>The password of the proxyro account is used by OBProxy to access the OceanBase cluster. You can enter the password here to ensure the consistency of the proxyro password. For more information about the proxyro account, see <a href="../../800.obproxy-functions/300.manage-a-obproxy-cluster/900.proxyro-user-management.md">Manage proxyro accounts</a>. </li></ul></p>
      </main>

5. After the cluster is connected, the precheck page appears.

   * If the precheck passes, and some OBServer hosts are not managed by OCP, enter the relevant information to take over the hosts.

   * If the precheck fails, modify the OBServer node configuration as prompted and click **<UI-TERM key="ocp-v2.Cluster.Import.ReCheck">Recheck</UI-TERM>** after the modification.

6. Click **<UI-TERM key="ocp-v2.Settings.Component.ModifyUserInfoDrawer.Submit">Submit</UI-TERM>**.

   After the task is submitted, you can view the task progress on the submission result page or return to the cluster overview page.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>For OCP to connect to the database, a credential string must be managed in the credential management system. After the cluster is taken over, you can import the cluster credential file obtained by using the <a href="650.migrate-a-cluster.md">Export Cluster</a> feature into this OCP instance. This way, you can batch upload the credentials of the cluster. For more information, see <a href="../../1600.system-management-features/100.manage-password-box/300.import-a-credential.md">Import Credentials</a>. </p>
    </main>
