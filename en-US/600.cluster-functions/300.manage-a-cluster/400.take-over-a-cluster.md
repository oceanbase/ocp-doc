# Take over a cluster

You can take over a cluster created by using CLI or OCP in a previous version to the current OCP. After the cluster is taken over, you can continue to maintain and manage the cluster in the current OCP.

## Prerequisites

* You are logged in to the OCP console as a user with the **ADMIN** or **ORG_ADMIN** role.

* All OBServer nodes in the OceanBase cluster to be taken over are running normally.

* When you take over an OceanBase cluster, you must follow the principle of taking over the primary cluster first:

  * In a single OCP scenario, you must first take over the primary OceanBase cluster and then the standby OceanBase cluster.

  * In a multi-OCP scenario, you must first take over the primary OceanBase cluster in one OCP console and then take over the standby OceanBase cluster in any OCP console.

* The service name of each tenant in the OceanBase cluster to be taken over must be unique, and the service name of each tenant in the system must also be unique. Otherwise, the service name status of the tenant with conflicting service names will be set to **Invalid** after the takeover. For more information about service names, see [Manage service names](../../700.tenant-functions/600.manage-a-tenant/800.manage-service-name.md).

* If the OceanBase cluster to be taken over is deployed by using obd, check whether the cluster meets the takeover conditions by referring to [Take over an obd-deployed cluster in the OCP console](https://www.oceanbase.com/docs/community-obd-cn-1000000001477802) before the takeover.

## Considerations

* After you take over an OceanBase cluster, you cannot maintain and monitor the cluster in the original OCP cluster. Before the takeover, assess the situation carefully.
* If the OceanBase cluster to be taken over is configured with a load type, you must reconfigure the load type on the **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">Overview</UI-TERM>** page after the takeover.
* When you take over an OceanBase cluster, OCP will also take over the OBServer host of the cluster for unified management.
  * If the credentials of the hosts are the same, you can take over the hosts in the **Precheck** step.
  * If the credentials of the hosts are different, you must first add the hosts to OCP by using the [Add Host] feature and then take over the cluster.
* After you take over the cluster, reconfigure the backup strategy based on the original cluster or tenant backup strategy.

## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, select **<UI-TERM key="ocp-v2.src.constant.alarm.Cluster">Cluster</UI-TERM>**. The **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. On the **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page, click **<UI-TERM key="ocp-v2.page.Cluster.TakeOverTheCluster">Take over Cluster</UI-TERM>** in the upper-right corner.

4. Connect to the cluster by using **<UI-TERM key="ocp-v2.Cluster.Import.DirectlyConnected">Direct Connection</UI-TERM>** or **OBProxy**.

   * **Direct Connection**: Enter the **<UI-TERM key="ocp-v2.page.OBProxy.Endpoint">Access URL</UI-TERM>** and **<UI-TERM key="ocp-v2.Scan.ReportTable.ServerInfoTable.Port">Port</UI-TERM>** of the cluster, as well as the **<UI-TERM key="ocp-v2.Cluster.Import.RootSysPassword">Root@sys Password</UI-TERM>**, and optionally enter the password of the **proxyro** account. Then, click **<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step1.NextStep">Next</UI-TERM>**.

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>The password of the **proxyro** account is used for OBProxy to access the OceanBase cluster. You can enter it here to ensure the consistency of the proxyro password. For more information about the **proxyro** account, see <a href="../../800.obproxy-functions/300.manage-a-obproxy-cluster/900.proxyro-user-management.md">Manage proxyro accounts</a>. </p>
      </main>

      ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/420/%E6%8E%A5%E7%AE%A1%E9%9B%86%E7%BE%A4-%E7%9B%B4%E8%BF%9E.png)

   * **OBProxy**: Enter the **<UI-TERM key="ocp-v2.MultiCluster.Detail.Endpoint">Access URL</UI-TERM>** and **<UI-TERM key="ocp-v2.Cluster.Import.Port">Port</UI-TERM>** of the cluster, as well as the **<UI-TERM key="ocp-v2.Detail.Component.SwitchModal.ClusterName">Cluster Name</UI-TERM>**, **<UI-TERM key="ocp-v2.Cluster.Import.ClusterIdOptional">Cluster ID (Optional)</UI-TERM>**, and **<UI-TERM key="ocp-v2.Cluster.Import.RootSysPassword">Root@sys Password</UI-TERM>**, and optionally enter the password of the **proxyro** account. Then, click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>**.

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p><ul><li>If the cluster to be taken over is a standby cluster, the cluster ID is required. If both the primary and standby clusters need to be taken over, take over the primary cluster first, and then the standby cluster. </li><li>The password of the **proxyro** account is used for OBProxy to access the OceanBase cluster. You can enter it here to ensure the consistency of the proxyro password. For more information about the **proxyro** account, see <a href="../../800.obproxy-functions/300.manage-a-obproxy-cluster/900.proxyro-user-management.md">Manage proxyro accounts</a>. </li></ul></p>
      </main>

      ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/420/%E6%8E%A5%E7%AE%A1%E9%9B%86%E7%BE%A4-obproxy.png)

5. After the cluster is connected, go to the precheck page.

   * If the precheck passes, and some OBServer hosts in the cluster are not managed by OCP, enter the required information and take over the hosts.

   * If the precheck fails, modify the OBServer node configuration as prompted, and then click **<UI-TERM key="ocp-v2.Cluster.Import.ReCheck">Recheck</UI-TERM>**.

   ![09010928](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E6%8E%A5%E7%AE%A1%E9%9B%86%E7%BE%A41.png)

6. Click **<UI-TERM key="ocp-v2.Settings.Component.ModifyUserInfoDrawer.Submit">Submit</UI-TERM>**.

   After the task is submitted, you can view the task progress on the task submission result page or go back to the cluster overview page.

    <h4>Note</h4>

For more information, see <a href="../../1600.system-management-features/100.manage-password-box/300.import-a-credential.md">Import Credentials</a>. </p>
