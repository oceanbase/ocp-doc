# Manage TDE

<main id="notice" type='notice'>
<h4>Applicability</h4>
<p>This topic applies only to OCP Enterprise Edition. OCP Community Edition does not support this feature.</p>
</main>

OceanBase Database supports transparent data encryption (TDE) at the data storage layer.

TDE encrypts sensitive data stored on disks. Data is automatically encrypted before being written to storage devices and automatically decrypted when read. This process is transparent to users, and authenticated users can access the data without restrictions. If a storage medium is stolen, TDE ensures that sensitive data on the medium cannot be accessed by unauthorized users. Even if the storage medium is lost, the data remains secure and will not be lost, maximizing the protection of user data.

This topic describes how to enable TDE and create a tablespace for a tenant.

## Enable TDE<a id="parameter"></a>

This topic describes how to enable TDE for a cluster.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>After TDE is enabled, it cannot be disabled. Enabling TDE may degrade database performance. To decrypt data, you must move the tables out of the encrypted tablespace and perform a major compaction. </p>
</main>

### Prerequisites

* You have logged in to the OCP console as the **ADMIN** or **ORG_ADMIN** user.
* The status of the tenant to be encrypted is **Running**.
* If you use the key provided by OCP, the OceanBase Database cluster must be of V4.x or later.
* If you use the key provided by a third-party vendor, the OceanBase Database cluster must be of the following versions:
  * [V4.2.5.4, V4.3.0)
  * [V4.3.5.2, +∞)
* If you use the key provided by **Koal**, you must configure the following parameters based on the service type:
  * **Standard**: Set the values of <code>ocp.kms.tde.koal.useTLS.enabled</code> and <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> to false.
  * **Password**: Set the values of <code>ocp.kms.tde.koal.useTLS.enabled</code> and <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> to true.
  For more information about the parameters, see **Parameters**.

### Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.Detail.Component.UpgradeModal.Cluster">Cluster</UI-TERM>**. The **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. On the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** page, find the target cluster and click its name to go to the **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** page.

4. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.src.hook.useMenu.SecurityConfiguration">Security Configuration</UI-TERM>**.

5. On the page that appears, click the **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">Transparent Data Encryption</UI-TERM>** tab.

6. Select the tenant for which you want to enable TDE and click **<UI-TERM key="ocp-v2.src.constant.security.TurnOnEncryption">Enable Encryption</UI-TERM>** in the Actions column.

7. In the dialog box that appears, select the key type.

   * Use the key provided by OCP: The key automatically generated by OCP. In this case, the `tde_method` parameter is set to internal, indicating that the master key is stored in the internal table of OceanBase Database.
   * Use the key provided by a third-party vendor: The key managed by KMS. You need to configure the following key information.

      | Parameter | Description |
      |-----------|---------|
      | Vendor | The value can be **<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.AlibabaCloud">Alibaba Cloud</UI-TERM>**, **<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.TencentCloud">Tencent Cloud</UI-TERM>**, or **Koal**.  |
      | Service Type | The service type of KMS. This parameter is required only when the vendor is **Koal**.<ul><li>**Standard**: The KMS standard service version must be 2.0 or later. </li><li>**<UI-TERM key="ocp-v2.Alarm.Channel.Detail.Password">Password</UI-TERM>**: The KMS password service version must be 3.2.0 or later.   |
      | Access Domain | The endpoint of KMS.  |
      | AK | The access_key_id for signature authentication. |
      | SK | The access_key_secret for signature authentication. |
      | SK Version | The specific version number of SK. This parameter is required only when the vendor is **Koal** and the service type is **<UI-TERM key="ocp-v2.Channel.FormComponent.EMailForm.Password">Password</UI-TERM>**.   |
      | Master Key ID | The ID of the master key.   |
      | Region | The region of KMS. This parameter is required only when the vendor is **<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.TencentCloud">Tencent Cloud</UI-TERM>**.  |

8. Click **<UI-TERM key="ocp-v2.Detail.Overview.Enable">Enable</UI-TERM>**.

### Parameters

| Parameter  | Description  | Effective only after restart  |
|-------|-------|--------------------|
| <code>ocp.kms.tde.koal.useTLS.enabled</code>  | Specifies whether to use the TLS (Transport Layer Security) protocol for Koal KMS encryption. This parameter is stored in the <code>config_properties</code> table of the OCP MetaDB database. The default value is <code>false</code>. If the endpoint is <code>https</code>, set the value to <code>true</code>.  | No  |
| <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> | Specifies whether to use the kcsp version for Koal KMS encryption. You can configure this parameter on the **<UI-TERM key="ocp-v2.Detail.Overview.SystemParameter">System Parameters</UI-TERM>** page of the OCP console. The default value is <code>true</code>.  | No  |

## Create a tablespace

OceanBase Database allows you to enable transparent data encryption (TDE) at the tablespace level to ensure data security.

### Prerequisites

* You have logged in to the OCP console as the **ADMIN** or **ORG_ADMIN** role.
* The OceanBase cluster is of V4.x or later.
* TDE is enabled. For more information, see [Enable TDE](#parameter).

### Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.component.alarm.Search.Cluster">Cluster</UI-TERM>**. The **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. In the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** list, find the target cluster and click its name to go to the **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">Overview</UI-TERM>** page.

4. In the left-side navigation pane of the displayed page, click **<UI-TERM key="ocp-v2.src.hook.useMenu.SecurityConfiguration">Security Configuration</UI-TERM>**.

5. Click the **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">Transparent Data Encryption</UI-TERM>** tab.

6. In the left-side navigation pane, select the target tenant and click **<UI-TERM key="ocp-v2.src.constant.security.CreateATablespace">Create Tablespace</UI-TERM>** in the Actions column.

7. In the dialog box that appears, specify the following information.

   | Parameter | Description |
   |--------|---------|
   | Tablespace Name  | You can create multiple encrypted tablespaces in the same tenant. Each tablespace name must be unique. The name must start with a letter and can contain letters, digits, and underscores. The length must be 2 to 30 characters.  |
   | Encryption Algorithm      | After you set the encryption algorithm, you cannot modify it or convert it to another type. OceanBase Database of different versions support different encryption algorithms. For more information, see the official documentation of OceanBase Database.  |

8. Specify the tablespace name and encryption algorithm, and click **<UI-TERM key="ocp-v2.SecurityCard.TDE.CreateTableSpace.Create">Create</UI-TERM>**.

9. After you enable TDE and create an encrypted tablespace, you need to perform a DDL operation to create an encrypted table before you can encrypt data. The DDL operation is as follows:

   ```sql
   CREATE TABLE t1 (id int,id2 int) TABLESPACE sectest_ts1;
   ```

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>After you add a historical table to an encrypted tablespace, you must perform a major compaction to persist the encrypted data. Otherwise, the data in the historical table cannot be encrypted. </p>
   </main>

10. You can click the name of the encrypted tablespace to view details of the encrypted table, including the tenant, table name, encryption status, and encryption progress. The encryption progress indicates the percentage of data blocks that have been encrypted in the current table.
