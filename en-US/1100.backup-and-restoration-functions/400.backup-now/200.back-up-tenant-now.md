# Perform tenant backup immediately

This topic describes how to perform an immediate backup of a tenant.

You can perform a tenant backup through the following two methods:

* **Method 1**: Log in to the OCP console, choose **Backup & Recovery > Backups** on the tab that appears, and select **<UI-TERM key="ocp-v2.src.constant.backup.BackUpNow">Back up Now</UI-TERM>** from the drop-down list in the upper-right corner of the page. On the dialog box that appears, select **<UI-TERM key="ocp-v2.Backup.BackupTenant">Back up Tenant</UI-TERM>**.

* **Method 2**: Log in to the OCP console, go to the **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** page of the target tenant, and select **<UI-TERM key="ocp-v2.Backup.BackupStrategy.New.BackupAndRestoration">Backup & Recovery</UI-TERM>** in the left-side navigation pane. On the dialog box that appears, click **<UI-TERM key="ocp-v2.Backup.Component.BackupNowDrawer.BackUpNow">Back up Now</UI-TERM>**.

## Prerequisites

* If you want to back up a tenant immediately by using **Method 1**, make sure that the user who is logged in to OCP has the following permissions:

  * The **Cluster Maintenance** or **Tenant Maintenance** resource permission.
  * The **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.Backup">Backup</UI-TERM>** menu permission under **Backup & Recovery**.

* If you want to back up a tenant immediately by using **Method 2**, make sure that the user who is logged in to OCP has the following permissions:

  * The **Cluster Maintenance** or **Tenant Maintenance** resource permission.
  * The **<UI-TERM key="ocp-v2.src.constant.compute.BackupAndRestoration">Backup & Recovery</UI-TERM>** menu permission.

* OceanBase Database supports tenant backup only for tenants of OceanBase Database V3.2.2-20220304134610 and later.
* OceanBase Database does not support backing up a locked tenant.

## Procedure

The following steps use **Method 1** as an example.

1. Log in to the OCP console.

2. In the left-side navigation pane, choose **<UI-TERM key="ocp-v2.src.constant.compute.BackupAndRestoration">Backup & Recovery</UI-TERM>** **\>** **<UI-TERM key="ocp-v2.src.constant.backup.Backup">Backups</UI-TERM>**. In the upper-right corner of the page, select **<UI-TERM key="ocp-v2.Detail.Backup.BackUpNow">Back up Now</UI-TERM>**.

3. Select the backup object.

   In the **<UI-TERM key="ocp-v2.Backup.Backup.BackupTenant">Back Up Tenant</UI-TERM>** drop-down list, select the object to be backed up. The system automatically identifies the **<UI-TERM key="ocp-v2.Cluster.New.ObVersion">OceanBase version</UI-TERM>** and **<UI-TERM key="ocp-v2.Backup.Backup.Log.BackupMethod">Backup Method</UI-TERM>** of the tenant and automatically fills in the **<UI-TERM key="ocp-v2.Backup.Service.Detail.StorageConfiguration">Storage Configuration</UI-TERM>**.

4. Fill in the storage configuration.

   * If the tenant to be backed up has a backup strategy, the storage configuration will be automatically filled in.

   * If the tenant to be backed up does not have a backup strategy, you need to manually fill in the storage configuration. You can fill in the information as prompted on the page, or follow Step 4 in [Create a tenant-level backup strategy](../500.regular-backup/200.manage-tenant-backup-strategy/100.creat-a-tenant-backup-stategy.md).

     After you fill in the information, click **<UI-TERM key="ocp-v2.Cluster.New.Test">Test</UI-TERM>** to test the storage configuration.

5. (Optional) Enable the custom backup scope feature.

    <main id="notice" type='notice'>
    <h4>Notice</h4>
    <ul>
    <li>Currently, OceanBase Database of the following versions support the custom backup scope feature: [4.2.1.11, 4.2.0) and [4.2.5.2, 4.3.0). </li>
    <li>If a tenant-level backup strategy exists, the custom backup scope feature is unavailable for the immediate backup. </li>
    <li>Data backup reads backup data from the follower replica by default, and log backup reads backup data from the leader replica by default. </li>
    <li>When you select the zones to be backed up, you must prioritize the zones. Otherwise, the backup may fail or generate cross-region traffic. </li>
    <li>When you enable the custom backup scope feature, we recommend that you do not set the primary zone to random. </li>
    </ul>
    </main>

   1. Select the data backup type: zone, region, or IDC, and use the shuttle box to set the priority of the zones, regions, or IDCs.

   2. Select the log backup type: zone, region, or IDC, and use the shuttle box to set the priority of the zones, regions, or IDCs.

6. Select the data backup method.

   If you choose physical backup, you need to select the data backup method. If you choose logical backup, you can only choose full backup.

    <main id="notice" type='notice'>
    <h4>Notice</h4>
    <ul>
    <li>Before incremental backup, you must perform a full data backup when you choose physical backup. Otherwise, the <code>Check if ready to data backup</code> step will report an error indicating that a full data backup is needed before incremental data backup. </li>
    <li>If the <code>Start cluster compact if necessary</code> step reports an error indicating that a cluster compaction is needed before full data backup when you choose full backup, you can try to perform a major compaction and then click the <strong>Retry</strong> button to continue the backup. For more information, see <a href="../../600.cluster-functions/1100.manage-cluster-merge/200.cluster-perform-merge.md">Perform a major compaction</a>. </li>
    </ul>
    </main>

7. Click **<UI-TERM key="ocp-v2.Detail.Backup.BackUpNow">Back up Now</UI-TERM>**.
