# Create a tenant-level backup strategy

OCP allows you to configure personalized backup and restore strategies for each tenant. After you create a tenant-level backup strategy for a tenant, the tenant is no longer affected by the cluster-level backup strategy.

You can create a tenant-level backup strategy by using the following two methods:

* **Method 1**: Log in to the OCP console. In the left-side navigation pane, choose **Backup > Backup**. The **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.Backup">Backup</UI-TERM>** page appears.

* **Method 2**: Log in to the OCP console. On the **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** page of the tenant, click **<UI-TERM key="ocp-v2.Backup.BackupStrategy.Edit.BackupAndRestoration">Backup & Recovery</UI-TERM>** in the left-side navigation pane. The **<UI-TERM key="ocp-v2.src.util.menu.BackupAndRestoration">Backup & Recovery</UI-TERM>** details page appears.

<main id="notice" type='explain'>
<h4>Note</h4>
<p>If a cluster-level backup strategy exists for the cluster to which the tenant belongs, the content of the cluster-level backup strategy is automatically filled in when you create a tenant-level backup strategy. </p>
</main>

## Prerequisites

* When you create a tenant-level backup strategy by using **Option 1**, make sure that the user who logs in to OCP has the following permissions:

  * The **Cluster Maintenance** or **Tenant Maintenance** resource permission.
  * The **<UI-TERM key="ocp-v2.src.constant.compute.Backup">Backup</UI-TERM>** menu permission under Backup and Restore.

* When you create a tenant-level backup strategy by using **Option 2**, make sure that the user who logs in to OCP has the following permissions:

  * The **Cluster Maintenance** or **Tenant Maintenance** resource permission.
  * The **<UI-TERM key="ocp-v2.src.util.menu.BackupAndRestoration">Backup & Recovery</UI-TERM>** menu permission under Backup and Restore.

* A tenant can be created only in a cluster of V4.0.0 or later.

* OceanBase Database does not support backing up a locked tenant.

* The sys tenant does not support creating a tenant-level backup strategy.

## Procedure

The following steps use **Option 1** as an example.

1. In the left-side navigation pane, choose **Backup and Recovery > Backup**.

2. On the **<UI-TERM key="ocp-v2.src.constant.compute.Backup">Backup</UI-TERM>** page, hover the pointer over **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.CreateABackupPolicy">New Backup Strategy</UI-TERM>** and click **<UI-TERM key="ocp-v2.Backup.BackupStrategy.New.CreateATenantLevelBackupPolicy">Create Tenant-level Backup Strategy</UI-TERM>**.

3. In the drop-down list, select a tenant to back up.

   * If the version of the cluster to which the tenant belongs is earlier than V2.2.60, the backup method is **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.LogicalBackup">Logical Backup</UI-TERM>**.

   * If the version of the cluster to which the tenant belongs is V2.2.60 or later, the backup method is **<UI-TERM key="ocp-v2.src.constant.backup.PhysicalBackup">Physical Backup</UI-TERM>**.

4. Set the storage configuration and click **<UI-TERM key="ocp-v2.Component.StorageConfigCard.Test">Test</UI-TERM>**.

   * For logical backup, select the storage configuration configured in [Install a service](../../1000.manage-backup-and-recovery-service/200.installation-services.md).

     If no backup service is installed, you must install one. For more information, see [Install a service](../../1000.manage-backup-and-recovery-service/200.installation-services.md).

   * For physical backup, you can customize or select an existing storage configuration. If you customize the configuration, you must set the parameters as described in the following table. If you select an existing configuration, the parameters in the following table will be automatically populated after you click **<UI-TERM key="ocp-v2.Backup.Component.StorageConfigDropdown.SelectAnExistingConfiguration">Select Existing Configuration</UI-TERM>**.

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>If native Alibaba Cloud OSS or Tencent Cloud COS is available, we recommend that you use it for configuration. </p>
      </main>

      * **File**: local file storage, which is usually NFS.

         | Parameter  |  Description  |
         |--------|-------|
         |  Storage Directory  |  The storage directory for backup files on the current media. If a backup recovery strategy already exists for the tenant's cluster, we recommend that you set this directory to be consistent with the cluster. Otherwise, it may affect the statistics of tenant backup data.  |
         |  Backup Storage Capacity Alarm Threshold  |  The alarm threshold for backup storage capacity. The default value is 80%.  |

      * **OSS**: Alibaba Cloud OSS, which is supported only by OceanBase Database V2.2.76 and later.

         | Parameter  |  Description  |
         |--------|-------|
         |  Storage Directory  |  The storage directory for backup files on the current media. If a backup recovery strategy already exists for the tenant's cluster, we recommend that you set this directory to be consistent with the cluster. Otherwise, it may affect the statistics of tenant backup data.  |
         |  Access Domain Name  |  The domain name for accessing the Alibaba Cloud storage endpoint. Example: `oss-cn-hangzhou.aliyuncs.com`.  |
         |  Access User  |  The user for accessing the Alibaba Cloud storage endpoint.  |
         |  Access Secret  |  The user secret for accessing the Alibaba Cloud storage endpoint.  |

      * **COS**: Tencent Cloud COS, which is supported only by OceanBase Database V2.2.76 and later, V4.0 and earlier, or V4.2.1 and later.

         | Parameter  |  Description  |
         |--------|-------|
         |  Storage Directory  |  The storage directory for backup files on the current media. If a backup recovery strategy already exists for the tenant's cluster, we recommend that you set this directory to be consistent with the cluster. Otherwise, it may affect the statistics of tenant backup data.  |
         |  Access Domain Name  |  The domain name for accessing the objects in the Tencent Cloud COS bucket. Example: `cos.ap-beijing.myqcloud.com`.  |
         |  Resource Identifier (APPID)  |  The unique resource identifier at the user level for accessing the COS service. You can obtain it on the API key management page of the corresponding service.  |
         |  Project Identity ID  |  The project identity ID of the developer. You can obtain it on the API key management page of the corresponding service.  |
         |  Project Identity Secret  |  The project identity secret of the developer. You can obtain it on the API key management page of the corresponding service.  |

      * **S3**: a storage medium that is compatible with the AWS S3 protocol, including native AWS S3, Huawei Cloud OBS, China Telecom Cloud OBS, and Google GCS. OceanBase Database V4.2.1-BP7 and V4.2.3-BP1 (and later) support this feature. For more information about storage media that is compatible with the AWS S3 protocol, see [Overview of the S3 protocol](../../../2100.appendix/900.s3-overview.md).

         | Parameter  |  Description  |
         |--------|-------|
         |  Storage Directory  |  The storage directory for backup files on the current media. If a backup recovery strategy already exists for the tenant's cluster, we recommend that you set this directory to be consistent with the cluster. Otherwise, it may affect the statistics of tenant backup data.  |
         |  Access Domain Name  |  The domain name for accessing the objects in the S3 storage space (bucket). Example: `s3.us-west-2.amazonaws.com`.  |
         |  AK  |  The secret ID of the S3 storage space.  |
         |  SK  |  The access secret of the S3 storage space.  |
         |  Region  |  The region of the S3 storage space.  |

         <main id="notice" type='notice'>
         <h4>Notice</h4>
         <p>If the storage medium is AWS S3, the <b>Region</b> field is a required field. If the storage medium is Huawei Cloud OBS, China Telecom Cloud OBS, or Google GCS, this field is not required. </p>
         </main>

     ![Image 147](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/431/%E5%AD%98%E5%82%A8%E9%85%8D%E7%BD%AE-%E7%A7%9F%E6%88%B7.png)

5. (Optional) Enable the custom backup scope feature.

    <main id="notice" type='notice'>
    <h4>Notice</h4>
    <ul>
    <li>Custom backup scope is supported in OceanBase Database V4.2.1.11, V4.2.0, V4.2.5.2, and V4.3.0. </li>
    <li>When a tenant-level backup policy exists, custom backup scope is not supported. </li>
    <li>Data backup reads backup data from the follower replica by default. Log backup reads backup data from the leader replica by default. </li>
    <li>When you select a zone for backup, you must prioritize the zones. Otherwise, backup may fail or cross-region traffic may be generated. </li>
    <li>When you enable the custom backup scope feature, we recommend that you do not set the primary zone to random. </li>
    </ul>
    </main>

   1. Select the data backup type: zone, region, or IDC, and use the shuttle box to set the priority of the zone, region, or IDC.

   2. Select the log backup type: zone, region, or IDC, and use the shuttle box to set the priority of the zone, region, or IDC.

      ![Image 49](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/%E8%87%AA%E5%AE%9A%E4%B9%89%E5%A4%87%E4%BB%BD%E8%8C%83%E5%9B%B4.jpg)

6. Set the scheduling configuration.

   * Scheduling Cycle: The backup schedule is performed on a weekly or monthly basis. If the backup schedule is performed on a monthly basis, you can select at most 10 days.

   * If you disable log backup for physical backup, the system will start log backup before data backup and disable log backup after data backup is completed.

   ![Image 37](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/%E8%B0%83%E5%BA%A6%E9%85%8D%E7%BD%AE.png)

7. Set the backup cleanup scheduling configuration.

   ![Image 52](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/1307669461/p428171.png)

8. Set the alarm threshold. You can configure the data backup timeout alarm threshold, log backup latency alarm threshold, and number of days without successful data backup. After the configuration is successful, an alert will be triggered when the actual output exceeds the threshold.

   ![Image 53](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E6%8A%A5%E8%AD%A6%E9%98%88%E5%80%BC%E9%85%8D%E7%BD%AE.png)

9. (Optional) Set the secondary backup configuration.

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>Secondary backup is not supported in OceanBase Database V4.x.
   </p>
   </main>

   You can choose to back up the backup data files and log files to another directory. To enable secondary backup, turn on the **<UI-TERM key="ocp-v2.Component.BackupStrategyDetail.SecondaryBackup">Second Backup</UI-TERM>** switch.

   1. Set the storage configuration for secondary backup.

      ![Image 54](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/1307669461/p428178.png)

   2. Set the scheduling configuration for secondary backup.

      ![09221429](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/2859542361/p328243.png)

10. Click **<UI-TERM key="ocp-v2.src.constant.alarm.Create">Create</UI-TERM>** to create the tenant-level backup policy.
