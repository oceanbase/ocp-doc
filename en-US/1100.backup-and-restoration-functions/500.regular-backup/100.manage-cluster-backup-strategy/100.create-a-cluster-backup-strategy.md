# Create a cluster-level backup strategy

A cluster-level backup strategy takes effect only for tenants that have not configured a tenant-level backup strategy. You can create a cluster-level backup strategy for such tenants to manage their backups.

You can create a cluster-level backup strategy through the following three methods:

* **Method 1**: Log in to the OCP console, choose **Backup and Restore > Backup**. In the upper-right corner of the page, click **<UI-TERM key="ocp-v2.Backup.Overview.Welcome.CreateABackupPolicy">New Backup Strategy</UI-TERM>** and select **<UI-TERM key="ocp-v2.Backup.BackupStrategy.New.CreateAClusterLevelBackupPolicy">Create Cluster-level Backup Strategy</UI-TERM>** from the drop-down list.

* **Method 2**: Log in to the OCP console, go to the **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** page of the cluster, and in the left-side navigation pane, select **<UI-TERM key="ocp-v2.src.constant.package.BackupAndRestoration">Backup & Recovery</UI-TERM>**. Click **<UI-TERM key="ocp-v2.Detail.Backup.CreateAClusterLevelBackupPolicy">Create Cluster-level Backup Strategy</UI-TERM>**.

* **Method 3**: Log in to the OCP console, go to the **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** page of the tenant, and in the left-side navigation pane, select **<UI-TERM key="ocp-v2.Backup.Guide.BackupAndRestoration">Backup & Recovery</UI-TERM>**. Click **<UI-TERM key="ocp-v2.Backup.BackupStrategy.New.CreateAClusterLevelBackupPolicy">Create Cluster-level Backup Strategy</UI-TERM>**.

<main id="notice" type='explain'>
<h4>Note</h4>
<p>You can use <b>Method 3</b> to create a cluster-level backup strategy only when no backup strategy exists for the tenant and its cluster.</p>
</main>

## Prerequisites

* If you create a cluster-level backup strategy by using **Option 1**, make sure that the user who is logged in to OCP has the following permissions:

  * The **Cluster Maintenance** or **Tenant Maintenance** resource permission.
  * The **<UI-TERM key="ocp-v2.Component.BackupStrategyDetail.Backup">Backup</UI-TERM>** menu permission under Backup and Restore.

* If you create a cluster-level backup strategy by using **Option 2**, make sure that the user who is logged in to OCP has the following permissions:

  * The **Cluster Maintenance** resource permission.
  * The **<UI-TERM key="ocp-v2.src.util.menu.BackupAndRestoration">Backup & Recovery</UI-TERM>** menu permission under the cluster.

* If you create a cluster-level backup strategy by using **Option 3**, make sure that the user who is logged in to OCP has the following permissions:

  * The **Cluster Maintenance** or **Tenant Maintenance** resource permission.
  * The **<UI-TERM key="ocp-v2.Backup.Guide.BackupAndRestoration">Backup & Recovery</UI-TERM>** menu permission under the tenant.

* OceanBase Database does not support backing up a tenant that is in a locked state.

## Procedure

The following example describes the procedure for **entry 1**.

1. In the left-side navigation pane, choose **<UI-TERM key="ocp-v2.Detail.Backup.BackupAndRestoration">Backup & Recovery</UI-TERM>** **\>** **<UI-TERM key="ocp-v2.src.constant.backup.Backup">Backup</UI-TERM>**.

2. On the **<UI-TERM key="ocp-v2.Component.BackupStrategyCard.Backup">Backup</UI-TERM>** page, hover the pointer over **<UI-TERM key="ocp-v2.src.constant.backup.CreateABackupPolicy">New Backup Strategy</UI-TERM>** and click **<UI-TERM key="ocp-v2.Backup.AddClusterStrategy.CreateAClusterLevelBackupPolicy">Create Cluster-level Backup Strategy</UI-TERM>**.

3. Select a backup cluster from the drop-down list.

   * If the version of the backup cluster is earlier than V2.2.60, the backup method is **<UI-TERM key="ocp-v2.Backup.Component.BackupNowDrawer.LogicalBackup">Logical Backup</UI-TERM>**.

   * If the version of the backup cluster is V2.2.60 or later, the backup method is **<UI-TERM key="ocp-v2.src.constant.backup.PhysicalBackup">Physical Backup</UI-TERM>**.

4. Specify the following parameters to set the storage configuration and click **<UI-TERM key="ocp-v2.src.component.ArchiveForm.Test">Test</UI-TERM>**.

   * For logical backup, select the storage configuration configured in [Install a backup service](../../1000.manage-backup-and-recovery-service/200.installation-services.md).

     If no backup service is installed, install one first. For more information, see [Install a backup service](../../1000.manage-backup-and-recovery-service/200.installation-services.md).

   * For physical backup, you can select an existing storage configuration or specify a custom one. If you select an existing configuration, the following parameters will be automatically populated when you click **<UI-TERM key="ocp-v2.Backup.Component.StorageConfigDropdown.SelectAnExistingConfiguration">Select Existing Configuration</UI-TERM>**.

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>If native Alibaba Cloud OSS or Tencent Cloud COS is available, we recommend that you use it for configuration. </p>
      </main>

      * **File**: local file storage, generally NFS.

         | Parameter  |  Description  |
         |--------|-------|
         | Storage Directory  |  The storage directory for backup files on the current media.  |
         | Backup Storage Capacity Alert Threshold  |  The alert threshold for backup storage capacity. The default value is 80%.  |

      * **OSS**: Alibaba Cloud OSS. OceanBase Database V2.2.76 and later support this option.

         | Parameter  |  Description  |
         |--------|-------|
         | Storage Directory  |  The storage directory for backup files on the current media.  |
         | Access Domain Name  |  The domain name for accessing Alibaba Cloud storage. Example: `oss-cn-hangzhou.aliyuncs.com`.  |
         | Access User  |  The user for accessing Alibaba Cloud storage.  |
         | Access Key  |  The user key for accessing Alibaba Cloud storage.  |

      * **COS**: Tencent Cloud COS. OceanBase Database V2.2.76 and later, versions earlier than V4.0, or V4.2.1 and later support this option.

         | Parameter  |  Description  |
         |--------|-------|
         | Storage Directory  |  The storage directory for backup files on the current media.  |
         | Access Domain Name  |  The domain name for accessing objects in the Tencent Cloud COS storage bucket. Example: `cos.ap-beijing.myqcloud.com`.  |
         | Resource Identifier (APPID)  |  The unique resource identifier for the user dimension when developers access the COS service. You can obtain it on the API key management page of the corresponding service.  |
         | Project Identity ID  |  The project identity ID of the developer. You can obtain it on the API key management page of the corresponding service.  |
         | Project Identity Key  |  The project identity key of the developer. You can obtain it on the API key management page of the corresponding service.  |

      * **OBS**: Huawei Cloud OBS. OceanBase Database V3.2.3.2-105000062022090916 and later, and versions earlier than V4.0.0.0 support this option.

         | Parameter  |  Description  |
         |--------|-------|
         | Storage Directory  |  The storage directory for backup files on the current media.  |
         | Access Domain Name  |  The domain name for accessing Huawei Cloud OBS objects. Example: `obs.cn-north-4.myhuaweicloud.com`.  |

      * **S3**: storage media that is compatible with the AWS S3 protocol, including native AWS S3, Huawei Cloud OBS, China Mobile Cloud OBS, and Google GCS. OceanBase Database V4.2.1-BP7 and V4.2.3-BP1 (including) and later support this option. For more information about storage media that is compatible with the AWS S3 protocol, see [Overview of the S3 protocol](../../../2100.appendix/900.s3-overview.md).

         | Parameter  |  Description  |
         |--------|-------|
         | Storage Directory  |  The storage directory for backup files on the current media.  |
         | Access Domain Name  |  The domain name for accessing objects in the S3 storage space (Bucket). Example: `s3.us-west-2.amazonaws.com`.  |
         | AK  |  The secret ID of the S3 storage space.  |
         | SK  |  The access key of the S3 storage space.  |
         | Region  |  The region information of the S3 storage space.  |

         <main id="notice" type='notice'>
         <h4>Notice</h4>
         <p>If the storage media is AWS S3, the <b>Region</b> field is a required field. For other storage media such as Huawei Cloud OBS, China Mobile Cloud OBS, or Google GCS, this field is not required. </p>
         </main>

5. Set the scheduling configuration.

   * Scheduling Cycle: You can set the scheduling cycle to a week or a month. If you set the scheduling cycle to a month, you can select at most 10 days.

   * After you disable log backup for physical backup, the system will start log backup before data backup and disable log backup after data backup is completed.

   ![Image 37](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/%E9%9B%86%E7%BE%A4-%E8%B0%83%E5%BA%A6%E9%85%8D%E7%BD%AE.png)

6. Set the backup cleanup scheduling configuration.

   ![Image 52](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/1307669461/p428171.png)

7. Set the alert threshold. You can set the data backup timeout alert threshold, log backup latency alert threshold, and the number of days without successful data backup. After the configuration is completed, an alert will be triggered when the actual output exceeds the threshold.

   ![Image 53](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E6%8A%A5%E8%AD%A6%E9%98%88%E5%80%BC%E9%85%8D%E7%BD%AE.png)

8. (Optional) Set the secondary backup configuration.

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>Secondary backup is not supported in OceanBase Database V4.x.
   </p>
   </main>

   You can choose to back up the backup data files and log files to another directory. To enable secondary backup, turn on the **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.SecondaryBackup">Second Backup</UI-TERM>** switch.

   1. Set the storage configuration for secondary backup.

      ![Image 54](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/1307669461/p428178.png)

   2. Set the scheduling configuration for secondary backup.

      ![09221429](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/2859542361/p328243.png)

9. Click **<UI-TERM key="ocp-v2.src.constant.alarm.Create">Create</UI-TERM>** to create the cluster-level backup policy.
