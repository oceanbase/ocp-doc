# View sampling tasks

This topic describes how to view sampling tasks. 

## Prerequisites

Make sure that you have the following permissions:

* **<UI-TERM key="ocp-v2.Auth.Role.Detail.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Read-only** or **Tenant Read-only** permission
* **<UI-TERM key="ocp-v2.Auth.Role.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **Restore** menu of **<UI-TERM key="ocp-v2.src.constant.package.BackupAndRestoration">Backup & Recovery</UI-TERM>**

## Procedure

1. Log on to the OceanBase Cloud Platform (OCP) console. 

2. In the left navigation pane, choose **<UI-TERM key="ocp-v2.Backup.BackupStrategy.Edit.BackupAndRestoration">Backup & Recovery</UI-TERM>** **\>** **<UI-TERM key="ocp-v2.src.constant.backup.Recovery">Recovery</UI-TERM>**. The **<UI-TERM key="ocp-v2.Backup.Restore.Recovery">Recovery</UI-TERM>** page automatically appears.

3. Click the **<UI-TERM key="ocp-v2.Backup.Restore.SamplingTask">Sampling Tasks</UI-TERM>** tab. You can filter the tasks by time and view the sampling task information.

   * The tab displays task information in the following columns: **<UI-TERM key="ocp-v2.Session.Deadlock.DeadlockHistoryTable.Id">ID</UI-TERM>**, **<UI-TERM key="ocp-v2.Backup.Component.BackupNowDrawer.BackupCluster">Backup Cluster</UI-TERM>**, **<UI-TERM key="ocp-v2.Backup.Restore.RestoreTask.BackupTenant">Backup Tenant</UI-TERM>**, **<UI-TERM key="ocp-v2.Restore.SamplingStrategy.BackupMethod">Backup Method</UI-TERM>**, **<UI-TERM key="ocp-v2.Backup.Restore.RestoreTask.TargetCluster">Destination Cluster</UI-TERM>**, **<UI-TERM key="ocp-v2.Backup.Restore.RestoreTask.TargetTenant">Destination Tenant</UI-TERM>**, **Object to Restore**, **<UI-TERM key="ocp-v2.Backup.Backup.Log.StartTime">Started At</UI-TERM>**, **<UI-TERM key="ocp-v2.Backup.Restore.RestoreTask.RecoveryDuration">Restore Duration</UI-TERM>** and **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.Status">Status</UI-TERM>**. You can filter the backup tasks by status. You can click **Clean Up** in the Actions column to release the resources occupied by failed restore tasks.

   * You can click **<UI-TERM key="ocp-v2.src.constant.backup.ViewReasons">View Cause</UI-TERM>** in the Actions column to view the cause of a failed sampling task.

   * In the upper-right corner of the tab, you can select **Last 1 Hour, Last 24 Hours, Last 7 Days**, or **<UI-TERM key="ocp-v2.src.constant.backup.NearlyDays">Last 30 Days</UI-TERM>**, or select **<UI-TERM key="ocp-v2.component.RangeTimeDropdown.CustomTime">Custom Time</UI-TERM>** and specify a time range, to view the tasks in the specified time range.

   | --- | --- |
   | ID | The unique identifier of the restore task.  |
   | Backup Cluster | The cluster that is backed up. You can restore the data of the cluster to another cluster.  |
   | Backup Tenant | The tenant that has been backed up in the backup cluster. You can restore the data of the tenant to another tenant in the same or another cluster.  |
   | Backup Method | The backup mode of the cluster and tenant. Valid values: Logical Backup and Physical Backup.  |
   | Destination Cluster | The cluster to which the data of the backup cluster is restored.  |
   | Destination Tenant | The tenant to which the data of the backup tenant is restored.  |
   | Object to Restore | The type of the object to be restored.  |
   | Started At | The start time of the restore task.  |
   | Restore Duration | The execution duration of the restore task.  |
   | Status | You can filter tasks by status. <ul><li>For a physical backup task, the options of task status include **Creating Tenant**, **<UI-TERM key="ocp-v2.src.constant.backup.RestoringSystemReplica">Recovering System Replicas</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.backup.PreUpgradeCheck">Pre-upgrade Check</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.backup.PostUpgradeCheck">Post-upgrade Check</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.backup.SchemaModification">Modifying Schemas</UI-TERM>**, **The user partitions are being created**, **<UI-TERM key="ocp-v2.src.constant.backup.RestoringUserReplicas">Recovering User Replicas</UI-TERM>**, **The index is being created**, **<UI-TERM key="ocp-v2.src.constant.backup.InProgress">In Progress</UI-TERM>**, **<UI-TERM key="ocp-v2.Compaction.Detail.Completed">Completed</UI-TERM>**, and **<UI-TERM key="ocp-v2.src.constant.backup.Failed">Failed</UI-TERM>**. </li><li>For a logical backup task, the options of task status include **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.Start">Start</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.tenant.Recovering">Restoring</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Statistics.utils.Canceled">Canceled</UI-TERM>**, **<UI-TERM key="ocp-v2.Layout.BasicLayout.Failed">Failed</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.backup.Completed">Completed</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.backup.RestoringData">Recovering Data</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.backup.RestoringLogs">Recovering Logs</UI-TERM>**, **An error occurred while recovering data**, and **Failed to recover logs**. </li></ul> |
   | Actions | You can clean up failed tasks or view their failure causes.  |
