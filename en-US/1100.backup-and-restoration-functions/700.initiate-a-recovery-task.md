# Initiate a restore task

You can initiate a restore task for a cluster that has been backed up.

You can initiate a restore task by using the following methods:

* **Method 1**: Log in to the OceanBase Cloud Platform (OCP) console. In the left-side navigation pane, choose **<UI-TERM key="ocp-v2.Backup.BackupStrategy.Edit.BackupAndRestoration">Backup & Recovery</UI-TERM>** > **<UI-TERM key="ocp-v2.src.constant.compute.Recovery">Recovery</UI-TERM>**. On the **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.BackupAndRestoration">Backup & Recovery</UI-TERM>** page of the target cluster, click **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.InitiateRecovery">Initiate Recovery</UI-TERM>**.

* **Method 2**: Log in to the OCP console and go to the **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">Overview</UI-TERM>** page of the target cluster. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.src.constant.auditEvent.BackupAndRestoration">Backup & Recovery</UI-TERM>**. On the **<UI-TERM key="ocp-v2.src.constant.auditEvent.BackupAndRestoration">Backup & Recovery</UI-TERM>** page of the target cluster, click **<UI-TERM key="ocp-v2.Backup.Restore.RestoreNow.InitiateRecovery">Initiate Recovery</UI-TERM>**.

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>You cannot restore a cluster by using Method 2 in the following circumstances:<ul><li>The cluster is not in the <b>Running</b> state. </li><li>The cluster does not have a backup strategy. </li></ul></p>
   </main>

* **Method 3**: Log in to the OCP console and go to the **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** page of the target tenant. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.src.util.menu.BackupAndRestoration">Backup & Recovery</UI-TERM>**. On the **<UI-TERM key="ocp-v2.src.constant.compute.BackupAndRestoration">Backup & Recovery</UI-TERM>** page of the target tenant, click **<UI-TERM key="ocp-v2.Backup.Restore.RestoreNow.InitiateRecovery">Initiate Recovery</UI-TERM>**.

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>You cannot restore a tenant by using Method 3 in the following circumstances:<ul><li>The tenant is not in the <b>Running</b> state. </li><li>The tenant does not have a backup strategy. </li></ul></p>
   </main>

## Prerequisites

* To initiate a restore task by using **Method 1**, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** or **Tenant Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.Detail.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **Restore** menu of **<UI-TERM key="ocp-v2.Backup.Guide.BackupAndRestoration">Backup & Recovery</UI-TERM>**

* To initiate a restore task by using **Method 2**, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.BackupAndRestoration">Backup & Recovery</UI-TERM>** menu of **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>**

* To initiate a restore task by using **Method 3**, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** or **Tenant Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.Detail.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.Backup.BackupStrategy.Edit.BackupAndRestoration">Backup & Recovery</UI-TERM>** menu of **<UI-TERM key="ocp-v2.Tenant.New.Tenant">Tenants</UI-TERM>**

* You have backed up the cluster to be restored. For more information, see [Back up now](400.backup-now/100.back-up-cluster-now.md).

* When you restore a OceanBase cluster that is physically backed up, you cannot restore its data to a cluster of an earlier version.

## Procedure

The procedure of **Method 1** is described as follows:

1. Log in to the OCP console.

2. In the left-side navigation pane, choose **<UI-TERM key="ocp-v2.Detail.Backup.BackupAndRestoration">Backup & Recovery</UI-TERM>** > **<UI-TERM key="ocp-v2.src.constant.backup.Recovery">Recovery</UI-TERM>**.

3. On the **<UI-TERM key="ocp-v2.Backup.Restore.Recovery">Recovery</UI-TERM>** page, click **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.InitiateRecovery">Initiate Recovery</UI-TERM>** in the upper-right corner.

4. (Optional) If you use Method 1, configure a custom storage configuration or use an existing configuration. If you choose to configure a custom configuration, configure the parameters based on the following tables. If you choose to select an existing configuration, click **<UI-TERM key="ocp-v2.Backup.Component.StorageConfigDropdown.SelectAnExistingConfiguration">Select Existing Configuration</UI-TERM>**. Then, the system automatically populates the following parameters.

5. Specify the restore source.

   * Restore a tenant

      | Parameter | Description |
      |-------|-------------------------------|
      | Source Cluster     | If you initiate a restore task from the O&M page of a cluster, the cluster is the source cluster by default, and you do not need to specify this parameter. |
      | Source Tenant     | Select the tenant to restore.                    |
      | Object to Restore | Select **<UI-TERM key="ocp-v2.component.ParameterTemplate.DetailDrawer.Tenant">Tenant</UI-TERM>**.                    |
      | Recovery Date | Select a date within the specified restorable time range.                 |
      | Restore Point in Time | Select a point in time within the specified time range.            |

   * Restore databases

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>This feature is supported only in OceanBase Database V4.x. </p>
      </main>

     If you use Method 3 to restore a tenant, you can restore databases in the tenant.

      | Parameter | Description |
      |-------|-------------------------------|
      | Source Cluster   | The source cluster to restore the tables. The default value is the cluster to which the current tenant belongs. |
      | Source Tenant   | The source tenant to restore the tables. The default value is the current tenant.                    |
      | Object to Restore | Select **<UI-TERM key="ocp-v2.TraceDetail.TraceContent.Database">Database</UI-TERM>**.                    |
      | Recovery Date | Select a date within the specified restorable time range.                 |
      | Restore Point in Time | Select a point in time within the specified time range.     |
      | Restore Database Object | Select the databases to be restored in the **Restorable Objects** list on the left and click **>** to add them to the **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.SelectedObjects">Selected Objects</UI-TERM>** list on the right. The database names must be unique. OCP allows you to rename databases, as shown in the following figure.  |

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>You can select at most 200 database objects. </p>
      </main>

   * Restore tables

      <main id="notice" type='explain'>

      </main>

      | Parameter | Description |

6. Specify the restore target.

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>During a database or table restore, you need to create an auxiliary tenant in the target cluster. We recommend that the specifications of the auxiliary tenant be consistent with those of the source tenant, and that the target cluster have sufficient CPU, memory, and disk resources. If the resources are insufficient, the restore may be slow or fail. After the restore is completed, the system will delete the auxiliary tenant by default. </p>
      </main>

      | Parameter | Description |
      |-------|-------------------------------|
      | Destination Cluster | Select a target cluster. |
      | Destination Tenant | Select a target tenant.                    |

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>The following types of clusters cannot be used as the restore target:<ul><li>Clusters in primary/standby mode </li><li>Clusters in the Unavailable state </li><li>Clusters of an OceanBase Database version earlier than that of the source cluster </li></ul></p>
   </main>

7. Specify the following zone-related parameters and set the priorities of the zones.

   | Parameter | Description |
   |---------|---|
   | Replica Type | Valid values: <ul><li>**<UI-TERM key="ocp-v2.src.constant.oceanbase.AllPurposeReplica">Full-featured Replica</UI-TERM>**: A standard replica that contains all the data categories and all the features, including MemTables, SSTables, and transaction logs. A full-featured replica can switch to the leader role efficiently to provide services. </li><li>**<UI-TERM key="ocp-v2.src.constant.oceanbase.LogCopy">Log Replica</UI-TERM>**: A replica that contains only logs. It does not have a MemTable or an SSTable. It provides log services for external applications and participates in log voting. It can facilitate the restore of other replicas, but it cannot become the leader to provide database services.   </li><li>**<UI-TERM key="ocp-v2.src.constant.oceanbase.ReadOnlyCopy">Read-only Replica</UI-TERM>**: A replica that contains full logs, MemTables, and SSTables. You can select this type of replica for applications that does not require high consistency in data reading. </li></ul> |
   | Unit Specification | The specifications of the resources that the replica occupies. <ul><li>You can select an existing specification. </li><li>You can also create a specification as needed and select the created specification. </li></ul>  |
   | Units | The number of resource units occupied by the replica. <blockquote>**Notice**</br>If the version of the target cluster is V4.0 or later, you can only set the same number of units for all zones. In other words, the number of units that you specify on this page applies to all zones under the restored tenant. </blockquote>|

8. Click **<UI-TERM key="ocp-v2.Detail.Backup.InitiateRecovery">Initiate Recovery</UI-TERM>**.
