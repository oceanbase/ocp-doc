# Create an SSO integration

OCP provides an account system. You can configure an external integration service in OCP and log in to the OCP console by using SSO.

## Prerequisites

* The user logged in to OCP must be of the **ADMIN** role.
* The authorization service has been deployed.

## Considerations

* OAUTH/OIDC integration supports only the authorization code mode.
* When you log out from OAUTH/OIDC, only the login state of the OCP application is cleared, and the login state of the SSO system is not cleared.

## Procedure

### Configure OAuth2

Example: Integrate a third-party application with OCP by using the OAuth2 type to authorize access to OCP through the third-party account.

1. Log in to the OCP console.

2. In the left-side navigation pane, choose **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** > **<UI-TERM key="ocp-v2.src.hook.useMenu.ExternalIntegration">External Integration</UI-TERM>** to go to the **<UI-TERM key="ocp-v2.page.External.SsoIntegrationList">SSO Integration List</UI-TERM>** page.

3. In the upper-right corner of the page, click **<UI-TERM key="ocp-v2.page.External.CreateSsoIntegration">Create SSO Integration</UI-TERM>**. In the dialog box that appears, configure the gateway authentication parameters.

    The following table describes the parameters of the OAuth2 type.

    | **<UI-TERM key="ocp-v2.component.ParameterTemplate.Parameter">Parameter</UI-TERM>** | **<UI-TERM key="ocp-v2.component.alarm.RuleDetail.Description">Description</UI-TERM>** |
    |---------|---------|
    | Configuration Name | The configuration name will be used as the custom login name. It must start with an English letter, end with an English letter or a number, and can contain English letters, numbers, and underscores. The length must be between 2 and 32 characters. |
    | Type | OAuth2 |
    | Enable Local Login Mode | Specifies whether to support the local username and password login mode. |
    | Client ID | The application identifier, which must be consistent with the configuration when the authorization server is registered. |
    | Client Secret | The application key. |
    | Auth URL | The URL provided by the authorization server to obtain the grant-code. |
    | User Info URL | The URL provided by the authorization server to obtain the user information. |
    | Token URL | The URL provided by the authorization server to obtain the access token. |
    | Redirect URL | The URL provided by the authorization server to callback to the OCP service.<main id="notice" type='notice'><h4>Notice</h4><p>If the SSO has a callback whitelist, you need to add the URL to the whitelist. </p></main>  |
    | Scope | The authorization scope of the application. Multiple scopes are separated by spaces. We recommend that you set the value to profile.<main id="notice" type='notice'><h4>Notice</h4><p>When you configure SSO through a third-party application, you must specify the Scope. </p></main> |
    | jwkSet URL | Optional. The URL provided by the authorization server to obtain the public key for authentication. |
    | userNameAttribute | Optional. The user name field. |
    | Client Authentication Method | Optional. The authentication method used to authenticate the client to the authorization server. |
    | Authorization Grant Type | Optional. The authorization method of OAuth2. |
    | User Info Authentication Method | Optional. The authentication method used to authenticate the access token when you send a resource request to the resource server. |

4. Click **<UI-TERM key="ocp-v2.page.External.CreateDrawer.TestConnection">Test Connection</UI-TERM>**. The third-party authorization login page appears.

5. Enter the account and password of the third-party account, and click **Third-party Login** to authorize access to OCP.

6. After the test connection is successful, the system returns the structure of the user information API. Fill in the user field mapping parameters based on the returned information.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>The structure of the user information API varies for different third-party applications. To map the user information of the third-party application to the OCP user fields, you need to fill in the user information mapping form. User field mapping is used to identify the identifier of the OCP account associated with the OAuth2 login. </p>
    </main>

7. Click **<UI-TERM key="ocp-v2.Monitor.AddMonitor.AddMonitorDrawer.Save">Save</UI-TERM>** to complete the creation of the SSO integration.

8. For information about how to enable or disable an SSO integration, see [Enable or Disable an SSO Integration](200.create-sso-integration.md). In the **<UI-TERM key="ocp-v2.page.External.SsoIntegrationList">SSO Integration List</UI-TERM>** page, enable the created SSO integration.

### Configure an OIDC integration

Example: Integrate a third-party application to OCP by using the OIDC type, so that you can log in to OCP by using a third-party account.

1. Log in to the OCP console.

2. In the left-side navigation pane, choose **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** > **<UI-TERM key="ocp-v2.page.External.ExternalIntegration">External Integration</UI-TERM>**. The **<UI-TERM key="ocp-v2.page.External.SsoIntegrationList">SSO Integration List</UI-TERM>** page automatically appears.

3. In the upper-right corner of the page, click **<UI-TERM key="ocp-v2.page.External.CreateSsoIntegration">Create SSO Integration</UI-TERM>**. In the dialog box that appears, configure the parameters related to gateway authentication.

    The following table describes the parameters of the OIDC type.

    | **<UI-TERM key="ocp-v2.Transaction.Detail.Procedure">Steps</UI-TERM>** | **Description** |
    |----------|-----------|
    | Configuration Name | The name of the configuration, which will be used as the custom login name. It must start with a letter and end with a letter or a number. It can contain letters, numbers, and underscores, and must be 2 to 32 characters in length. |
    | Type | OIDC. |
    | Enable Local Login | Specifies whether to support the local username and password login mode. |
    | Client ID | The application identifier, which must be consistent with the configuration when the authorization server is registered. |
    | Client Secret | The application key, which must be consistent with the configuration when the authorization server is registered. |
    | Auth URL | The URL provided by the authorization server to obtain the grant code. |
    | User Info URL | The URL provided by the authorization server to obtain the user information. |
    | Token URL | The URL provided by the authorization server to obtain the access token. |
    | Redirect URL | The URL provided by the authorization server to callback to the OCP service. <main id="notice" type='notice'><h4>Notice</h4><p>If the SSO has a callback allowlist, you must add the URL to the allowlist. </p></main>  |
    | Scope | The authorization scope of the application. Multiple scopes are separated by spaces. We recommend that you set the scope to profile. <main id="notice" type='notice'><h4>Notice</h4><p>When you configure an SSO by using a third-party application, you must specify the scope. </p></main> |
    | jwkSet URL | Optional. The URL provided by the authorization server to obtain the public key for authentication. |
    | Issue URL | The URL of the authentication service. |
    | Client Authentication Method | Optional. The authentication method used to authenticate the client to the authorization server. |
    | Authorization Grant Type | Optional. The OAuth2 authorization type. |
    | User Info Authentication Method | Optional. The authentication method used to authenticate the client to the resource server when you send a resource request with the access token. |

4. To test the connection, you must add the callback URL to the allowlist. Manually add the URL to the allowlist as prompted on the page, and then click **<UI-TERM key="ocp-v2.page.External.CreateDrawer.TestConnection">Test Connection</UI-TERM>**.

5. Enter the account and password of the third-party application, and click **Third-party Login** to authorize access to OCP.

6. After the connection is tested, the system returns the structure of the user information API. Fill in the parameters related to the user field mapping based on the returned information.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>The structure of the user information API varies for different third-party applications. To map the user information of the third-party application to the user fields of OCP, you need to fill in the user information mapping form. The user field mapping is used to identify the identifier of the OCP account associated with the OAuth2 login. </p>
    </main>

7. Click **<UI-TERM key="ocp-v2.Monitor.AddMonitor.AddMonitorDrawer.Save">Save</UI-TERM>** to complete the creation of the SSO integration.

8. For information about how to enable or disable an SSO integration, see [Enable or disable an SSO integration](200.create-sso-integration.md). In the **<UI-TERM key="ocp-v2.page.External.SsoIntegrationList">SSO Integration List</UI-TERM>** page, enable the created SSO integration.
