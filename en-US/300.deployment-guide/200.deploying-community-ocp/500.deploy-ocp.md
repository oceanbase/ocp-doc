# Deploy OCP by using the graphical interface

This topic describes how to deploy OCP by using OceanBase Deployer (OBD).

MetaDB is an important component of OCP. MetaDB provides the underlying storage capability for OCP to manage metadata and monitoring data. OCP-Server provides the full lifecycle management service of OceanBase Database by calling the data in MetaDB. You can deploy OCP by using the following MetaDB configuration methods:

* (Recommended) Create a new OceanBase Database instance as the MetaDB of OCP.

* Use an existing OceanBase Database instance as the MetaDB of OCP.

## Prerequisites

* Only OCP-CE V4.0.3 and later versions are supported.

* Java is installed and configured. Only JDK1.8 is supported, and the build version must be at least 161.

* If the decompressed directories of previous versions of OCP software packages exist on the OCP host, to avoid confusion with the decompressed directories of the new version, you need to rename or delete the old directories.

* You have obtained the `ocp-all-in-one-4.4.0-YYYYMMDDhhmmss.el7.x86_64.tar.gz` package as described in [Installation Preparation](400.installation-preparation.md), uploaded the package to any directory on the OCP host, and executed the following command to decompress it.

    ```bash
    tar zxf ocp-all-in-one-4.4.0-YYYYMMDDhhmmss.el7.x86_64.tar.gz
    ```

## (Recommended) Create a new OceanBase database as the MetaDB of OCP

### Step 1: Start the obd tool

1. Log in to the OCP host.

2. Run the following command to go to the `bin` directory of the decompressed software package and install the deployment program.

    ```bash
    cd ocp-all-in-one/bin && bash install.sh
    ```

3. Run the following command to make the environment variables take effect.

    ```bash
    source ~/.oceanbase-all-in-one/bin/env.sh
    ```

4. Run the `obd web install` command. In the returned information, obtain the IP address of the deployment wizard page.

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/install.png)

### Step 2: Go to the OCP deployment wizard page

1. Access the IP address obtained in **Step 1** in a browser to go to the deployment wizard page, and click **Start Your Trial**.

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E9%83%A8%E7%BD%B2%E5%90%91%E5%AF%BC%E9%A1%B5%E9%9D%A2.png)

2. Select the **OCP** product, and click **<UI-TERM key="ocp-v2.Detail.Monitor.Determine">OK</UI-TERM>**.

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E9%80%89%E6%8B%A9%E5%AE%89%E8%A3%85%E4%BA%A7%E5%93%81.png)

3. Select **Create a new OceanBase cluster** to use it as the MetaDB of OCP, and click **<UI-TERM key="ocp-v2.page.Information.Ok">OK</UI-TERM>**.

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E5%88%9B%E5%BB%BA%E6%96%B0%E7%9A%84metadb.png)

### Step 3: Configure the deployment information

1. Specify the name of the OceanBase cluster to be managed.

    The name must be unique, start with an English letter, and end with an English letter or a digit. The length must be 2 to 32 characters.

2. Select the product version to be deployed.

    The versions of OceanBase Database and OBProxy are related. For example, if you select to deploy OceanBase Database V4.1.0 or later, you can deploy only OBProxy V4.1.0 or later.

![Alt text](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/440/%E9%83%A8%E7%BD%B2%E9%85%8D%E7%BD%AE.png)

### Step 4: Configure MetaDB

    |  SSH Port | The SSH port of the host. The default value is `22`. You can specify a custom port.     |
    |  Use the running user | (Optional) Configure a dedicated operating system user for running OCP services. |

2. Configure the OCP node.

    Select the host on which you want to deploy OCP. You can configure multiple hosts.

    <main id="notice" type='notice'>

    |---------|----------|

    |  OBServer Node   |  Select the host on which you want to deploy MetaDB. You can configure multiple hosts.  |
    |  RootServer Node   | Select an IP address as the host where RootService is located. In an OceanBase cluster with multiple replicas, you must specify a RootServer for each zone.   |

If you want to deploy a cluster with less than one zone, you can click the delete icon in the right-side column of the zone.

4. Configure the cluster information.

    |  Parameter   |   Description   |
    |---------|----------|
    |  root@sys Password   | You can specify a custom password or generate a random password. The password must meet the following complexity requirements:<ul><li>Length: 8 to 32 characters</li><li>At least three of the following four types: digits (0\~9), uppercase letters (A\~Z), lowercase letters (a\~z), and special characters.     |  Software Path   | The installation path of MetaDB. The default value is `/Deployment User/oceanbase`. You can specify a custom path. You must have read and write permissions for the specified path.    |
    |  Data Path   | The data storage path of MetaDB. The default value is `/data/1`. You can specify a custom path. You must have read and write permissions for the specified path, and the specified path must be empty.     |
    |  Log Path   | The log storage path of MetaDB. The default value is `/data/log1`. You can specify a custom path. You must have read and write permissions for the specified path, and the specified path must be empty.   |
    |  SQL Port   | The SQL port of MetaDB. The default value is  `2881`. You can specify a custom port (1024~65535). You must ensure that the specified port is not occupied.    |
    |  RPC Port   | The RPC port of MetaDB. The default value is  `2882`. You can specify a custom port (1024~65535). You must ensure that the specified port is not occupied.    |
    |  More Configurations   | (Optional) Click this parameter to view and configure the parameters of the OceanBase cluster. For more information about the parameters of the OceanBase cluster, see [View the parameter list](../../600.cluster-functions/1300.manage-cluster-parameters/200.view-the-parameters-list.md).  |

    <main id="notice" type='notice'>

    </main>

5. Configure the OBProxy information.

    |  Parameter   |   Description   |
    |---------|----------|
    |  OBProxy Node   |  Select the host on which you want to deploy OBProxy. You can configure only one IP address. This indicates that only a single-node OBProxy installation is supported.   |
    |  SQL Port   | The SQL port of OBProxy. The default value is `2883`. You can specify a custom port (1024~65535). You must ensure that the specified port is not occupied.    |
    |  Exporter Port   | The Prometheus listening port of OBProxy. The default value is `2884`. You can specify a custom port (1024~65535). You must ensure that the specified port is not occupied.    |
    |  Software Path   | The installation path of OBProxy. The default value is `/Deployment User/obproxy`. You can specify a custom path. You must have read and write permissions for the specified path.    |
    |  More Configurations   | (Optional) Configure the parameters of the OBProxy cluster. For more information about the parameters, see [OBProxy parameters](../../800.obproxy-functions/900.obproxy-parameters-description.md).  |

### Step 5: Configure OCP

This step is used to configure OCP service and tenant information.

1. Configure OCP service.

    |  Parameter   |   Description   |
    |---------|----------|
    |  Admin Password   | The password of the OCP administrator account. The password must meet the following complexity requirements:<ul><li>Length: 8 to 32 characters</li><li>At least three of the following four types: digits (0\~9), uppercase letters (A\~Z), lowercase letters (a\~z), and special characters. The supported special characters are <code>~^*{}[]_-+</code>.</li></ul>  |
    |  Software Path   | The installation path of OCP. The default value is `/Deployment User/ocp`. You can customize the software path. You must have read and write permissions for the corresponding directory, and ensure that the disk space of this path is sufficient.  |
    |  Log Path   | The log storage path of OCP. The default value is `/home/Deployment User/logs`. You can customize the log path. You must have read and write permissions for the corresponding directory, and ensure that the disk space of this path is sufficient.  |
    |  Software Package Path   | The installation path of the OCP Agent. The default value is `/home/Deployment User/software`. You can customize the software package path. You must have read and write permissions for the corresponding directory, and ensure that the disk space of this path is sufficient.  |
    |  ocp.site.url   | The URL for accessing the OCP website. The URL must start with `http/https`, contain the VIP address, domain name, or port, and not end with a slash (/). For example, `http://localhost:8080`.<br>After you set this parameter, you can click **Verify** to test the URL connectivity. If the verification fails, you need to modify the URL based on the prompt.  |
    |  Service Port   | The service listening port of OCP. The default value is `8080`. You can customize the port (only 1024~65535 is supported). Ensure that the port is not occupied.  |

2. Plan resource allocation.

    OCP service has a large amount of computing and storage overhead during operation. Therefore, you need to plan resources based on the scale of the objects to be managed. At the same time, OCP needs to configure necessary tenants in MetaDB to implement the full lifecycle management of OceanBase Database. After the configuration is completed, the system will automatically create the **meta tenant** and **monitoring data tenant**.

    1. Specify the number of hosts to be managed.

        The system manages up to 10 hosts by default. You can modify this parameter based on your actual situation.

    2. Configure memory resources.

        The default memory size is 16 GiB. The memory resource configuration is related to the number of hosts to be managed. For more information about the host resource planning of OCP, see [Host planning](300.installation-planning/200.host-planning.md).

    3. Configure the meta tenant information.

        |  Parameter   |   Description   |
        |---------|----------|
        | Tenant Name | The name of the meta tenant. The default value is `ocp_meta`. You can customize the value.  |
        | Password   | The password of the meta tenant account. The password can be randomly generated or customized. If you customize the password, it must meet the following complexity requirements:<ul><li>Length: 8 to 32 characters</li><li>At least three of the following four types: digits (0\~9), uppercase letters (A\~Z), lowercase letters (a\~z), and special characters. The supported special characters are <code>~!@#%^&*_-+=\|(){}[]:;,.?/</code>.</li></ul> |
        | CPU | The number of CPU cores allocated to the meta tenant. The default value is 1 VCPU. You can modify the value.|
        | Memory | The size of memory allocated to the meta tenant. The default value is 2 GiB. You can modify the value.|

    4. Configure the monitoring data tenant information.

        |  Parameter   |   Description   |
        |---------|----------|
        | Tenant Name | The name of the monitoring data tenant. The default value is `ocp_monitor`. You can customize the value. |
        | Password   | The password of the monitoring data tenant account. The password can be randomly generated or customized. If you customize the password, it must meet the following complexity requirements:<ul><li>Length: 8 to 32 characters</li><li>At least three of the following four types: digits (0\~9), uppercase letters (A\~Z), lowercase letters (a\~z), and special characters. The supported special characters are <code>~!@#%^&*_-+=\|(){}[]:;,.?/</code>. </li></ul> |
        | CPU | The number of CPU cores allocated to the monitoring data tenant. The default value is 2 VCPUs. You can modify the value.|
        | Memory | The size of memory allocated to the monitoring data tenant. The default value is 4 GiB. You can modify the value.|

### Step 6: Precheck the environment

After you configure the OCP installation information, you need to check and confirm the configuration information. Then, you can perform a precheck.

* If the configuration is incorrect, click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.PreviousStep">Previous</UI-TERM>** to go back to the configuration page and modify the configuration.

    ![Alt text](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E9%A2%84%E6%A3%80%E6%9F%A5.png)

* If the configuration is correct, click **<UI-TERM key="ocp-v2.Detail.TakeOver.Precheck">Precheck</UI-TERM>**. The system will verify whether your environment meets the minimum requirements for installing and configuring MetaDB and OCP.

    * If the precheck fails for some items, OCP provides repair solutions. You can refer to the repair solutions to troubleshoot and fix the issues. For check items that can be automatically repaired, you can click **<UI-TERM key="ocp-v2.page.Host.AutomaticRepair.1">Auto Repair</UI-TERM>** to repair the issues.

        After the repair is completed, you can click **<UI-TERM key="ocp-v2.Cluster.Import.ReCheck">Recheck</UI-TERM>** to re-execute the precheck.

   * If the precheck passes, click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>**.

    ![Alt text](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E9%A2%84%E6%A3%80%E6%9F%A5-%E6%96%B0%E5%BB%BAmetadb.png)

### Step 7: Deploy OCP

During the OCP deployment, you can view the detailed installation logs in the **Deployment Log** module.

* If the deployment fails, view the log information to obtain the failure cause and contact technical support for assistance. After you locate the cause of the installation failure and fix the issue, click **Redeploy**. The system will clear the failed OCP installation environment and re-execute the installation program.

* If the deployment succeeds, click **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">Complete</UI-TERM>** to exit the deployment program. Before you exit the program, you can copy the access URL and account password to log in to the deployed OCP platform.

![Alt text](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E5%AE%89%E8%A3%85%E6%88%90%E5%8A%9F.png)

### Step 7: Deploy OCP

During the OCP deployment, you can view the detailed logs in the **Deployment Logs** module.

* If the deployment fails, check the log information to identify the cause of the failure. Contact technical support for assistance. After the issue is resolved, click **Redeploy**. The system will clean up the failed OCP installation environment and re-execute the installation process.

* If the deployment is successful, click **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">Complete</UI-TERM>** to exit the deployment program. Before exiting, you can copy the access address and account credentials to log in to the deployed OCP platform.
