# Initialize system parameters

After OCP is installed, you need to confirm and modify the following system parameters:

|  Parameter name        |   Description    |     Initial value   | Is it supported to modify it in the GUI?  |
|----------------|-----------|-------------|-------------------|
| **server.port**     | The port number for the application server. This parameter takes effect after OCP-Server is restarted.  | 8080    | No |
| **ocp.site.url**    | The URL for external access to the OCP website. The OCP-managed host must also be accessible to ocp-server through this URL. The URL must start with HTTP (HTTPS is not supported), contain the VIP address, domain name, or port, and must not end with a slash (/). | `http://localhost:8080` | Yes |
| **ocp.config-url.site.url**   | The URL for external access to the OCP config url service. The default value is empty, indicating that the same value as `ocp.site.url` will be used. If the config url service is deployed separately, a different value from `ocp.site.url` must be configured.   | Default value is empty   | Yes |

For parameters that support GUI modification, you can refer to [Modify system parameters](../../../../../1600.system-management-features/500.manage-system-parameter/200.modify-system-parameters.md) for details.

<main id="notice" type='explain'>
<h4>Note</h4>
<ul>
<li>In the Docker image installation scenario, a built-in OBProxy is provided for OCP to manage the OceanBase cluster. Therefore, you do not need to modify the <code>ocp.system.obproxy.address</code> and <code>ocp.system.obproxy.port</code> parameters. If you do not want to use the built-in OBProxy, you can specify the required OBProxy cluster using these parameters.</li>
<li>In the RPM installation scenario, you need to install the OBProxy for OCP to manage the OceanBase cluster yourself, and also modify the <code>ocp.system.obproxy.address</code> and <code>ocp.system.obproxy.port</code> parameters.</li>
</ul>
</main>

If you do not connect to the OceanBase cluster where MetaDB is located through a load balancer during MetaDB initialization, the automatically generated MonitorDB connection parameters will also be direct connections to OceanBase. If you need to modify it to connect to MonitorDB through a load balancer (DNS or VIP address), you need to modify the following load balancing-related parameters:

|      Parameter name       |     Description     |   Is it supported to modify it in the GUI?  |
|--------------------|----------------|----------------|
| ocp.monitordb.host | The connection address of MonitorDB |   No    |
| ocp.monitordb.port | The connection port of MonitorDB |   No    |
