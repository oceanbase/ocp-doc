# View the OceanBase Autonomy Service page

OceanBase Autonomy Service integrates the routine O&M capabilities of OceanBase Cloud Platform (OCP). You can view the loads and health status of all clusters managed by OCP on the OceanBase Autonomy Service page.

<main id="notice" type='notice'>
<h4>Applicability</h4>
<p>This topic applies only to OCP Enterprise Edition. OCP Community Edition does not support this feature. </p>
</main>

## Prerequisites

To view information on the **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** page of OceanBase Autonomy Service, make sure that you have the following permissions:

* **<UI-TERM key="ocp-v2.Auth.Role.Detail.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster read-only** or **tenant read-only** permission
* **<UI-TERM key="ocp-v2.Auth.Role.AddRole.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on any menu of **<UI-TERM key="ocp-v2.page.Diagnosis.AutonomousService">OceanBase Autonomy Service</UI-TERM>**

## Exception events

Cluster exception events that occurred in the last three days are displayed on the homepage of OceanBase Autonomy Service. You can scroll the page to view the exception events, which are listed in descending order of occurrence time.

* View the information of exception events in the following columns: **<UI-TERM key="ocp-v2.Detail.Overview.ClusterName">Cluster Name</UI-TERM>**, **<UI-TERM key="ocp-v2.Oracle.Component.ModifyObjectPrivilegeDrawer.Object">Object</UI-TERM>**, **<UI-TERM key="ocp-v2.MultiCluster.Detail.Name">Name</UI-TERM>**, **Behavior**, **Current Status**, **Occurrence Time**, **<UI-TERM key="ocp-v2.Alarm.Event.Detail.RecoveryTime">Recovery Time</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Monitor.TimeRange">Duration</UI-TERM>**, and **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.Operation">Actions</UI-TERM>**.

* Click the name of a cluster to go to the overview page of the cluster.

* Click **<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.Outline.SqlDiagnosis">SQL Diagnostics</UI-TERM>** in the **<UI-TERM key="ocp-v2.Detail.Overview.Operation">Actions</UI-TERM>** column of an event to go to the real-time diagnostics page of the corresponding cluster. On this page, you can filter for the top SQL statements by the occurrence time and recovery time of the exception events.

## Diagnostic information

The **Diagnostic Information** section displays the SQL, transaction, and session diagnostic information and optimization history.

* **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.SqlDiagnosis">SQL Diagnostics</UI-TERM>**: displays the number of clusters with suspicious SQL statements, clusters with slow SQL statements, and clusters with high-risk SQL statements in the last 6 hours.

* **<UI-TERM key="ocp-v2.Detail.Realtime.TransactionDiagnosis">Transaction Diagnostics</UI-TERM>**: displays the number of clusters with long-running transactions and clusters with suspended transactions in real time.

* **<UI-TERM key="ocp-v2.page.Overview.SessionDiagnosis">Session Diagnostics</UI-TERM>**: displays the number of clusters with deadlocks in the last seven days.

* **<UI-TERM key="ocp-v2.page.Overview.OptimizationHistory">Optimization History</UI-TERM>**: displays the number of clusters with optimization history in the last seven days.

You can click a metric name or the number of clusters to filter clusters. The clusters that meet the filter condition are displayed in the list in the **<UI-TERM key="ocp-v2.page.Diagnosis.ClusterDetails">Cluster Details</UI-TERM>** section. As shown in the following figure, if you click **<UI-TERM key="ocp-v2.page.Diagnosis.ClustersWithSuspiciousSqlStatements">Clusters with Suspicious SQL Statements</UI-TERM>**, only the clusters with suspicious SQL statements are displayed in the list in the **<UI-TERM key="ocp-v2.page.Diagnosis.ClusterDetails">Cluster Details</UI-TERM>** section.

## Cluster details

The **<UI-TERM key="ocp-v2.page.Diagnosis.ClusterDetails">Cluster Details</UI-TERM>** section displays the SQL diagnostic information, real-time transactions, sessions, optimization history, and resource usage of each cluster.

* You can click a statistical number in the column of an SQL type to go to the corresponding details page.

* You can sort clusters by the number of suspicious SQL statements, slow SQL statements, high-risk SQL statements, long-running transactions, suspended transactions, deadlock sessions, active sessions, or optimization records or the total number of sessions in ascending or descending order.

* You can click the name of a cluster to go to the autonomy service overview page of the cluster.

* In the search window in the upper-right corner, you can search for a cluster by its name.
