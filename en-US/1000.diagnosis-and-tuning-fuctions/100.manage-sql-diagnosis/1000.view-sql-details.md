# View the details of an SQL statement

This topic describes how to view SQL details in OCP, including the SQL execution status, execution plan, bound indexes, and whether the SQL is throttled.

You can view SQL diagnostics in the following ways:

* **Method 1**: Log in to OCP and click **<UI-TERM key="ocp-v2.src.hook.useMenu.AutonomousService">OceanBase Autonomy Service</UI-TERM>** in the left-side navigation pane. Click the name of the cluster to go to the **<UI-TERM key="ocp-v2.src.hook.useMenu.RealTimeDiagnosis">Real-time Diagnostics</UI-TERM>** page of the cluster.

* **Method 2**: Log in to OCP. On the **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** page of your tenant, click **<UI-TERM key="ocp-v2.ParallelSQL.TraceDetail.SqlDiagnosis">SQL Diagnostics</UI-TERM>** in the left-side navigation pane.

<main id="notice" type='notice'>
   <h4>Applicability</h4>
   <p>SQL diagnostics is not supported in the Community Edition. You can only use <b>Method 2</b> to view SQL diagnostics. </p>
</main>

## Prerequisites

* When you view SQL details through **Access Point 1**, make sure that the logged-in user in OCP has the following permissions:

  * **Cluster Read-Only** or **Tenant Read-Only** resource permissions.
  * Permissions on the **<UI-TERM key="ocp-v2.src.hook.useMenu.RealTimeDiagnosis">Real-time Diagnostics</UI-TERM>** menu of the Autonomous Service.

* When you view SQL details through **Access Point 2**, make sure that the logged-in user in OCP has the following permissions:

  * **Cluster Read-Only** or **Tenant Read-Only** resource permissions.
  * Permissions on the **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.SqlDiagnosis">SQL Diagnostics</UI-TERM>** menu of the tenant.

* OceanBase Database V3.0 and later versions support viewing SQL execution profiles.

* For tenants of the MySQL mode, the password of the tenant is stored in the password box of the OCP user.

* For tenants of the Oracle mode, the password of the SYS tenant is stored in the password box of the OCP user.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>For the logged-in tenant to be able to bind indexes, bind execution plans, and set throttling, it must have the <strong>UPDATE</strong> permission on the tenant. </p>
  </main>

2. The system displays the **<UI-TERM key="ocp-v2.SQLDiagnosis.Digest.SqlDiagnosis">SQL Diagnostics</UI-TERM>** tab by default.

3. On the **<UI-TERM key="ocp-v2.page.Overview.SuspiciousSql">Suspicious SQL</UI-TERM>**, **TopSQL**, **SlowSQL**, **ParallelSQL**, **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.HighRiskSql">High Risk SQL</UI-TERM>**, and **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.AddSql">New SQL statement</UI-TERM>** tabs, find the target SQL.

   You can set search conditions to locate the target SQL.

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/OAS/%E6%9F%A5%E7%9C%8BSQL%E8%AF%A6%E6%83%85-1.png)

4. Click the SQL statement of the target SQL to go to the details page of the SQL.

   ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/OAS/%E6%9F%A5%E7%9C%8BSQL%E8%AF%A6%E6%83%85-2.png)

   On the **<UI-TERM key="ocp-v2.ParallelSQL.TraceDetail.SqlDetails">SQL Details</UI-TERM>** page, you can view the following details about the SQL:

   * In the **<UI-TERM key="ocp-v2.Trace.TraceDetailDrawer.SqlText">SQL Text</UI-TERM>** section, view the complete SQL statement. OCP will desensitize the SQL statement before displaying it. If the SQL statement fails to be parsed, the original SQL statement will be displayed. If you enable the option to show table schema, the statement for creating the table will be displayed.

   * In the **<UI-TERM key="ocp-v2.Component.SQLDetail.SQLTunning.OptimizationSuggestions">Optimization Suggestions</UI-TERM>** section, view the optimization suggestions for the SQL statement. For more information, see **View optimization suggestions**.

   * In the **<UI-TERM key="ocp-v2.Component.SQLDetail.ParallelSQLTraceTable.SqlExecutionProfiling">SQL Execution Profile</UI-TERM>** section, view the execution details of the SQL statement. For more information, see **View SQL execution profile**.

   * On the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.HistoricalTrends">Previous Tendency</UI-TERM>** tab, view the historical trends of the SQL statement. For more information, see **View historical trends of the SQL statement**.

   * On the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ExecutionPlan">Execution Plans</UI-TERM>** tab, view the execution plan of the SQL statement or bind an execution plan to it. For more information, see **View execution plan**.

   * On the **<UI-TERM key="ocp-v2.Capacity.Resource.Top.Index">Index</UI-TERM>** tab, view the indexes bound to the SQL statement. For more information, see **View and bind indexes**.

   * On the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.SqlThrottling">SQL Throttling</UI-TERM>** tab, view the throttling status of the SQL statement or set throttling for it. For more information, see **Set SQL throttling**.

   * On the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ExecutionPlan">Execution Plans</UI-TERM>**, **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.Index">Index</UI-TERM>**, and **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.SqlThrottling">SQL Throttling</UI-TERM>** tabs, you can click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ViewBindingRecordsInThe">View Binding Records in Last 30 Days</UI-TERM>** to view the binding records of the SQL statement.

     In the binding records, you can view the status of the bound plan. You can click **<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.Outline.Unbind">Unbind</UI-TERM>** to unbind the SQL statement from the plan or click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.BindPlan">Bind Plan</UI-TERM>** to bind them again.

## View optimization suggestions

When the SQL execution plan changes and the performance decreases, the system provides a plan binding suggestion. When the SQL index is not optimal and meets the following conditions, the system provides an index optimization suggestion:

* The average response time of the SQL query is greater than 20 ms, or the average CPU time is greater than 10 ms.
* The SQL query type is one of the following: SELECT, SELECT_FOR_UPDATE, UPDATE, or DELETE.
* The SQL query does not contain the difficult predicate "OR".
* The SQL query does not contain JOIN.

You can view the diagnostic issues and suggested solutions for this SQL query in the **<UI-TERM key="ocp-v2.Detail.Optimize.OptimizationSuggestions">Optimization Suggestions</UI-TERM>** section, and perform operations such as viewing Plan Hash, binding execution plans, and viewing diagnostic details.

* When recommending indexes, the system follows the following algorithm:

  * Equi-join columns are placed at the beginning, and can be combined in any order.

  * For range joins, the most selective range join columns are placed after the equi-join columns.

  * For SQL queries without range joins, if the elimination sort condition is met, the sorted columns are placed after the equi-join columns.

  * Columns in other predicates are placed after the index, at which point the index is a half-width index.

  * Columns in other predicates of the SQL query are placed after the index, and a covering index is constructed.

  * If the SQL query contains at most eight columns, a covering index is recommended; otherwise, a half-width index is recommended.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>Table join scenarios are currently not supported. </p>
  </main>

  The following parameters are configured:

  * `ocp.perf.sql.index-advisor-cpu-time-threshold`: the average CPU time threshold for recommending indexes. If the average CPU time of an SQL query is greater than the value of this parameter, an index is recommended for the SQL query.

  * `ocp.perf.sql.index-advisor-elapsed-time-threshold`: the average response time threshold for recommending indexes. If the average response time of an SQL query is greater than the value of this parameter, an index is recommended for the SQL query.

* When recommending historical plans, the system analyzes the execution plans of the SQL query in the last seven days. If the average CPU time of a plan is less than 80% of that of the most recent plan of the same type, the plan is recommended. Local plans are prioritized. If no local plans are available, distributed plans are recommended.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>Only suspicious SQL queries support viewing diagnostic details. </p>
  </main>

## View SQL execution profile

On the **<UI-TERM key="ocp-v2.Report.SQLTrace.SqlExecutionProfiling">SQL Execution Profile</UI-TERM>** page, you can view the operator-level SQL execution details within the collection time range, including TraceID, degree of parallelism, request time, response time, and actions.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>Only ParalleSQL supports viewing SQL execution profiles.</p>
  </main>

### View trace details

Click the TraceID to go to the **<UI-TERM key="ocp-v2.ParallelSQL.TraceDetail.TraceDetails">Trace Details</UI-TERM>** page, where you can view the execution profile, including trace basic information, schema tables, schema indexes, OBServer details, and operator execution details.

* Click **<UI-TERM key="ocp-v2.ParallelSQL.TraceDetail.DownloadTheExecutionProfileReport">Download Execution Profile Report</UI-TERM>** in the upper-right corner of the page to export the trace information as an HTML file to your local device.
* Click the triangle icon next to the Trace ID to switch traces.
* On the **<UI-TERM key="ocp-v2.TraceDetail.TraceContent.SchemaTable">Schema Table</UI-TERM>** tab, click the statement to view the details.
* On the **<UI-TERM key="ocp-v2.TraceDetail.TraceContent.SchemaIndex">Schema Index</UI-TERM>** tab, you can bind and unbind indexes.

  ![5](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/OAS/%E6%9F%A5%E7%9C%8BSQL%E8%AF%A6%E6%83%85-5.png)

### Download an execution profile report

  In the **<UI-TERM key="ocp-v2.Component.SQLDetail.ParallelSQLTraceTable.SqlExecutionProfiling">SQL Execution Profile</UI-TERM>** table on the **<UI-TERM key="ocp-v2.Backup.Restore.RestoreTask.Operation">Actions</UI-TERM>** column, click **<UI-TERM key="ocp-v2.Component.SQLDetail.ParallelSQLTraceTable.DownloadTheExecutionProfileReport">Download Execution Profile Report</UI-TERM>** to export the trace information as an HTML file to your local device.

  ![6](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/OAS/%E6%9F%A5%E7%9C%8BSQL%E8%AF%A6%E6%83%85-6.png)

## View the execution trend of an SQL statement

On the **<UI-TERM key="ocp-v2.ParallelSQL.TraceDetail.SqlDetails">SQL Details</UI-TERM>** page, click the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.HistoricalTrends">Previous Tendency</UI-TERM>** tab.

You can view the charts about the SQL execution trend and the plan generation time. If you change the statistics time in the charts, the SQL running chart and SQL plan generation time chart are updated according to the selected time period.

* SQL execution trend

  By default, the running trend chart displays the **<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.SuspiciousSQLDetail.AverageResponseTime">Average Response Time</UI-TERM>**, **<UI-TERM key="ocp-v2.TraceDetail.TraceContent.CpuTime">CPU Time</UI-TERM>**, and **<UI-TERM key="ocp-v2.SQLDiagnosis.attributes.sqlTrendsAttributes.ExecutionTime">Execution Time</UI-TERM>** metrics. You can use **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SampleStatisticCard.IndicatorManagement">Metric Management</UI-TERM>** to select the metrics that you want to display.

  ![7](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/OAS/%E6%9F%A5%E7%9C%8BSQL%E8%AF%A6%E6%83%85-7.png)

* SQL plan generation time

  The Plan Hash column indicates that a new plan is generated. The vertical axis shows the time consumed in generating the plan.

  ![8](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/OAS/%E6%9F%A5%E7%9C%8BSQL%E8%AF%A6%E6%83%85-8.png)

## View the execution plan of an SQL statement

On the **<UI-TERM key="ocp-v2.ParallelSQL.TraceDetail.SqlDetails">SQL Details</UI-TERM>** page, click the **<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.constant.ExecutionPlan">Execution Plans</UI-TERM>** tab. You can do the following operations on this tab:

* Use **<UI-TERM key="ocp-v2.component.RangeTimeDropdown.CustomTime">Custom Time</UI-TERM>** to specify the query time range and window duration.

* Click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ViewBindingRecordsInThe">View Binding Records in Last 30 Days</UI-TERM>** to view the execution plans from the last 30 days.

* Click on the value of the Plan Hash column to view the detailed execution information of this execution plan, including the basic information, execution steps, and execution status on each OBServer node.

* Click **<UI-TERM key="ocp-v2.Component.SQLDetail.SQLTunning.Bind">Bind</UI-TERM>** to bind this execution plan with the current SQL statement.

![9](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/OAS/%E6%9F%A5%E7%9C%8BSQL%E8%AF%A6%E6%83%85-9.png)

  You can filter indexes by index status and type. You can also click **<UI-TERM key="ocp-v2.Component.SQLDetail.SQLTunning.Bind">Bind</UI-TERM>** to bind the SQL statement to an index. You can create an index in a console or connect to OceanBase Developer Center (ODC) to create an index.

* Click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ViewBindingRecordsInThe">View Binding Records in Last 30 Days</UI-TERM>** to view the index binding records of the SQL statement in the last 30 days.

* Check whether the current SQL statement is throttled.

  As shown in the following figure, the SQL statement is not throttled.

  ![13](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/OAS/%E6%9F%A5%E7%9C%8BSQL%E8%AF%A6%E6%83%85-13.png)
