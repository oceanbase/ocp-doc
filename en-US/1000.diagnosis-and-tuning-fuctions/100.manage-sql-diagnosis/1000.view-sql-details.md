# View the details of an SQL statement

This topic describes how to view the details of an SQL statement in OceanBase Cloud Platform (OCP), including its execution status, execution plans, bound indexes, and throttling enabling status.

You can view the details of an SQL statement by using the following methods:

* **Method 1**: Log in to the OCP console. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.page.Diagnosis.AutonomousService">OceanBase Autonomy Service</UI-TERM>**. On the page that appears, find the target cluster and click its name to go to the **<UI-TERM key="ocp-v2.Detail.Realtime.RealTimeDiagnosis">Real-time Diagnostics</UI-TERM>** page.

* **Method 2**: Log in to the OCP console. On the **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">Overview</UI-TERM>** page of a tenant, click **<UI-TERM key="ocp-v2.Detail.Realtime.SqlDiagnosis">SQL Diagnostics</UI-TERM>** in the left-side navigation pane.

<main id="notice" type='notice'>
   <h4>Applicability</h4>
   <p>OCP Community Edition does not support OceanBase Autonomy Service. To use this service, go to the relevant page by using <b>Method 2</b>. </p>
</main>

## Prerequisites

* To view the details of an SQL statement by using **Method 1**, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Read-only** or **Tenant Read-only** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.Detail.Realtime.RealTimeDiagnosis">Real-time Diagnostics</UI-TERM>** menu of **<UI-TERM key="ocp-v2.src.hook.useMenu.AutonomousService">OceanBase Autonomy Service</UI-TERM>**

* To view the details of an SQL statement by using **Method 2**, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.Detail.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Read-only** or **Tenant Read-only** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.page.Iframe.SqlDiagnosis">SQL Diagnostics</UI-TERM>** menu of **<UI-TERM key="ocp-v2.Resource.Component.Block.Tenant">Tenants</UI-TERM>**

* The version of OceanBase Database is later than 3.0, if you want to view the execution profile of an SQL statement.

* Your password box contains the tenant password, if the current tenant is in MySQL mode.

* Your password box contains the password of the sys tenant in the cluster, if the current tenant is in Oracle mode.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>To bind indexes and plans and configure throttling, you must have the <strong>UPDATE</strong> privilege on the current tenant. </p>
  </main>

## Go to the details page of an SQL statement

The procedure of **Method 1** is described as follows:

1. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.src.hook.useMenu.AutonomousService">OceanBase Autonomy Service</UI-TERM>**. On the **<UI-TERM key="ocp-v2.page.Diagnosis.ClusterDetails">Cluster Details</UI-TERM>** page, click the name of the target cluster to go to its **<UI-TERM key="ocp-v2.Detail.Realtime.RealTimeDiagnosis">Real-time Diagnostics</UI-TERM>** page.

2. By default, the **<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.Outline.SqlDiagnosis">SQL Diagnostics</UI-TERM>** tab appears.

3. On the **<UI-TERM key="ocp-v2.page.Diagnosis.SuspiciousSql">Suspicious SQL</UI-TERM>**, **TopSQL**, **SlowSQL**, **ParallelSQL**, **<UI-TERM key="ocp-v2.page.Overview.HighRiskSql">High Risk SQL</UI-TERM>**, or **New SQL** tab, find the target SQL statement.

   You can specify search criteria to find the target SQL statement.

   ![1](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/5824633561/p440539.png)

4. Click the SQL text of the target SQL statement to go to its details page.

   ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/topsql%E4%BF%A1%E6%81%AF.png)

   On the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetail.SqlDetails">SQL Details</UI-TERM>** page, you can view the following details of the SQL statement:

   * In the **<UI-TERM key="ocp-v2.SQLDiagnosis.attributes.slowSqlAttributes.SqlText">SQL Text</UI-TERM>** section, you can view the complete SQL statement. OCP masks sensitive data in the SQL statement. However, if OCP failed to parse the SQL statement, it returns the original SQL statement. You can select **<UI-TERM key="ocp-v2.Component.SQLDetail.IndicatorStructure">Show Schema</UI-TERM>** to show the table creation statement.

   * In the **<UI-TERM key="ocp-v2.Component.SQLDetail.SQLTunning.OptimizationSuggestions">Optimization Suggestions</UI-TERM>** section, you can view the optimization suggestions for the SQL statement. For more information, see **View optimization suggestions**.

   * In the **<UI-TERM key="ocp-v2.Report.SQLTrace.SqlExecutionProfiling">SQL Execution Profile</UI-TERM>** section, you can view the execution details of the SQL statement. For more information, see **View the execution profile of the SQL statement**.

   * On the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.Plan.HistoricalTrends">Previous Tendency</UI-TERM>** tab, you can view the historical trends of the SQL statement. For more information, see **View the historical trends of the SQL statement**.

   * On the **<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.constant.ExecutionPlan">Execution Plans</UI-TERM>** tab, you can view the execution plans of the SQL statement, or bind an execution plan to the statement. For more information, see **View the execution plans of the SQL statement**.

   * On the **<UI-TERM key="ocp-v2.Capacity.Resource.Top.Index">Index</UI-TERM>** tab, you can view the indexes bound to the SQL statement. For more information, see **View and bind indexes**.

   * On the **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.SqlThrottling">SQL Throttling</UI-TERM>** tab, you can view or set throttling for the SQL statement. For more information, see **Set throttling for the SQL statement**.

   * You can view the binding records of the SQL statement in **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ViewBindingRecordsInThe">View Binding Records in Last 30 Days</UI-TERM>** on the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ExecutionPlan">Execution Plans</UI-TERM>**, **<UI-TERM key="ocp-v2.Capacity.Resource.Top.Index">Index</UI-TERM>**, and **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.SqlThrottling">SQL Throttling</UI-TERM>** tabs.

     In the binding records, you can view the status of a bound execution plan, or click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.Unbind">Unbind</UI-TERM>** to unbind the plan from the SQL statement. You can click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.BindPlan">Bind Plan</UI-TERM>** to bind the plan to the SQL statement again.

## View optimization suggestions

If the SQL diagnostics feature identifies a change in the execution plan or performance of the SQL statement or identifies an excessively long response time of the SQL statement, you can view the problems and solutions in the **<UI-TERM key="ocp-v2.Component.SQLDetail.SQLTunning.OptimizationSuggestions">Optimization Suggestions</UI-TERM>** section. This section provides index recommendation, historical plan recommendation, and CPU capacity scale-out recommendation. You can also view the plan hash and diagnostic details, and bind execution plans.

* Index recommendation is provided based on the following algorithm:

  * The equality query columns are arranged in the front and combined in any order.

  * If range queries are performed, the range query column with the best selectivity is arranged after the equality query columns.

  * If no range query is performed, the sorting column is arranged after the equality query columns when the sorting elimination condition is met.

  * Other columns in the predicate are arranged after the index. In this case, the index is a half-width index.

  * Other columns in the SELECT statement are arranged after the index to construct a covering index.

  * If the covering index contains eight or fewer columns, the covering index is recommended. Otherwise, the half-width index is recommended.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>Table joins are not supported. </p>
  </main>
  
  The relevant parameters are described as follows:

  * `ocp.perf.sql.index-advisor-cpu-time-threshold`: the threshold of the average CPU time of SQL statements for index recommendation. When the average CPU time of SQL statements is greater than this value, index recommendation is provided.

  * `ocp.perf.sql.index-advisor-elapsed-time-threshold`: the threshold of the average response time of SQL statements for index recommendation. When the average response time of SQL statements is greater than this value, index recommendation is provided.

* Execution plans for the same type of SQL statements executed in the last 7 days are analyzed. The execution plan whose average CPU time is 80% lower than that of others is recommended. A local plan is preferentially recommended. When a local plan is unavailable, a distributed plan is recommended.

* If the CPU utilization of the tenant is greater than 60%, the system recommends that you scale out the CPU capacity for the tenant.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>You can view the diagnostic details of only suspicious SQL statements. </p>
  </main>

### View the details of an execution plan

Click **<UI-TERM key="ocp-v2.Component.SQLDetail.SQLTunning.ViewPlanHash">View Plan Hash</UI-TERM>**. In the dialog box that appears, you can view the details of the execution plan, including the basic information, execution steps, and server execution plans.
  
## Bind an execution plan

Click **<UI-TERM key="ocp-v2.Alarm.Event.Detail.FixedExecutionPlan">Bind Execution Plan</UI-TERM>**. In the dialog box that appears, click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.RecordTable.Binding">Bind</UI-TERM>**. Then, refresh the page and click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ViewBindingRecordsInThe">View Binding Records in Last 30 Days</UI-TERM>** to confirm that the execution plan is bound.

![5](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/5824633561/p440541.png)
  
## View diagnostic details

Click **<UI-TERM key="ocp-v2.Component.SQLDetail.SQLTunning.ViewDiagnosticDetails">View Diagnostic Details</UI-TERM>** to view the diagnostic details of a suspicious SQL statement.
  
## View the execution profile of the SQL statement

The **<UI-TERM key="ocp-v2.Report.SQLTrace.SqlExecutionProfiling">SQL Execution Profile</UI-TERM>** section displays the operator-level execution details of the SQL statement, including the trace ID, degree of parallelism, request time, response time, and operations.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>You can view the execution profiles of only parallel SQL statements. </p>
  </main>

### View details on the Trace Details page

Click a trace ID to go to the **<UI-TERM key="ocp-v2.Trace.TraceDetailDrawer.LinkDetails">Trace Details</UI-TERM>** page and view the execution profile, which displays the basic information of the trace, schema table, schema index, OBServer node details, and operator execution details.

* Click **<UI-TERM key="ocp-v2.ParallelSQL.TraceDetail.DownloadTheExecutionProfileReport">Download Execution Profile Report</UI-TERM>** in the upper-right corner of the page to export the trace information as an HTML file.
* Click the triangular icon next to the trace ID to switch to another trace.
* On the **<UI-TERM key="ocp-v2.TraceDetail.TraceContent.SchemaTable">Schema Table</UI-TERM>** tab, click the table creation statement to view the details of the statement.
* On the **<UI-TERM key="ocp-v2.TraceDetail.TraceContent.SchemaIndex">Schema Index</UI-TERM>** tab, bind or unbind indexes.

### Download the execution profile report

In the **<UI-TERM key="ocp-v2.Component.SQLDetail.ParallelSQLTraceTable.SqlExecutionProfiling">SQL Execution Profile</UI-TERM>** section, click **<UI-TERM key="ocp-v2.Component.SQLDetail.ParallelSQLTraceTable.DownloadTheExecutionProfileReport">Download Execution Profile Report</UI-TERM>** in the **<UI-TERM key="ocp-v2.Host.Detail.OCPAgent.Operation">Actions</UI-TERM>** column of the target trace to export the trace information as an HTML file.

## View the historical trends of the SQL statement

On the **<UI-TERM key="ocp-v2.ParallelSQL.TraceDetail.SqlDetails">SQL Details</UI-TERM>** page, click the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.Plan.HistoricalTrends">Previous Tendency</UI-TERM>** tab.

You can view the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.RunSqlStatements">SQL Statement Execution</UI-TERM>** and **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.SqlPlanGenerationTime">SQL Plan Generation Time</UI-TERM>** charts on this tab. If you modify the statistical period in the figure, both charts will be updated based on the new period.

* SQL Statement Execution chart

  By default, this chart displays **<UI-TERM key="ocp-v2.ComparisonSqlDrawer.DetailedTable.AverageResponseTime">Average Response Time</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.CpuTime">CPU Time</UI-TERM>**, and **<UI-TERM key="ocp-v2.SQLDiagnosis.attributes.slowSqlAttributes.ExecutionTime">Execution Time</UI-TERM>**. You can select more metrics to display in **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SampleStatisticCard.IndicatorManagement">Metric Management</UI-TERM>** of the figure.

  ![7](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/5824633561/p440543.png)
  
* SQL Plan Generation Time chart

  This chart indicates the generation of a new plan. The time used to generate the plan is represented by the y-axis.

  ![8](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/5824633561/p440544.png)
  
## View the execution plans of the SQL statement

On the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetail.SqlDetails">SQL Details</UI-TERM>** page, click the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ExecutionPlan">Execution Plans</UI-TERM>** tab. On this tab, you can perform the following operations:

* Set the range and time window to query in **<UI-TERM key="ocp-v2.component.RangeTimeDropdown.CustomTime">Custom Time</UI-TERM>**.

* Click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ViewBindingRecordsInThe">View Binding Records in Last 30 Days</UI-TERM>** to view the execution plan binding records of the SQL statement in the last 30 days.

* Click the value in the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.Plan.PlanHash">Plan Hash</UI-TERM>** column to view the details of the execution plan, including basic information, execution steps, and execution records on different OBServer nodes.

* Click **<UI-TERM key="ocp-v2.Component.SQLDetail.SQLTunning.Bind">Bind</UI-TERM>** to bind the execution plan to the SQL statement.

![9](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/5824633561/p440549.png)

## View and bind indexes

On the **<UI-TERM key="ocp-v2.ParallelSQL.TraceDetail.SqlDetails">SQL Details</UI-TERM>** page, click the **<UI-TERM key="ocp-v2.Capacity.Resource.Top.Index">Index</UI-TERM>** tab. On this tab, you can perform the following operations:

![10](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/5824633561/p440550.png)

* View the list of indexes bound to the SQL statement.

  You can filter the indexes by index status and type. You can also click **<UI-TERM key="ocp-v2.Component.SQLDetail.SQLTunning.Bind">Bind</UI-TERM>** to bind an index to the SQL statement. You can create indexes by using a command-line tool or in OceanBase Developer Center (ODC).
  
* Click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ViewBindingRecordsInThe">View Binding Records in Last 30 Days</UI-TERM>** to view the index binding records of the SQL statement in the last 30 days.

  In the binding records, you can view the status of a bound index, or click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.Unbind">Unbind</UI-TERM>** to unbind the index from the SQL statement. You can click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.BindAnIndex">Bind Index</UI-TERM>** to bind the index to the SQL statement again.

  ![11](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/5824633561/p440551.png)
  
## Set throttling for the SQL statement

On the **<UI-TERM key="ocp-v2.ParallelSQL.TraceDetail.SqlDetails">SQL Details</UI-TERM>** page, click the **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.SqlThrottling">SQL Throttling</UI-TERM>** tab. On this tab, you can perform the following operations:

* Check whether the current SQL statement is throttled.

  The following figure shows that the SQL statement is not throttled.

  ![12](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/5824633561/p440554.png)
  
* Set throttling for the current SQL statement.

  ![13](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/5824633561/p440555.png)

  1. As shown in the preceding figure, enable throttling and specify the throttling strategy.

     * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLLimit.MaximumConcurrency">Maximum Concurrency</UI-TERM>**: The value range is [0,+∞), and 0 indicates that throttling is disabled.

     * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.RateLimitingKeyword">Throttling Keywords</UI-TERM>**: Click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLLimit.Set">Settings</UI-TERM>**. In the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLLimit.SetRateLimitingKeywords">Set Throttling Keywords</UI-TERM>** dialog box, specify the throttling keywords in section ① in the figure.

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p>If no keywords are specified, the entire SQL statement is throttled. </p>
      </main>

     * If the throttling keywords failed to take effect, you can view the causes in section ② in the figure.

       ![14](https://help-static-aliyun-doc.aliyuncs.com/assets/img/en-US/5824633561/p440556.png)

  2. Click **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLLimit.Update">Update</UI-TERM>**, and then click **<UI-TERM key="ocp-v2.Component.ClusterFilter.Ok">OK</UI-TERM>** in the dialog box that appears.
