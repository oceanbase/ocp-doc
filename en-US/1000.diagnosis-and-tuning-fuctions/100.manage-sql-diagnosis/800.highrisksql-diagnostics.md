# Diagnose high-risk SQL statements

OceanBase Cloud Platform (OCP) can identify SQL statements that may cause risks to system performance, security, and data based on specific rules.

<main id="notice" type='notice'>
    <h4>Applicability</h4>
    <p>This topic applies only to OCP Enterprise Edition. OCP Community Edition does not support this feature. </p>
</main>

The following table describes the types of high-risk SQL statements that can be identified in OCP.

| Operation | Example  |  Risk type  |  Description  |
|------  |    -----      |   ----     |    ----     |
| Column addition or deletion  |    <ul><li> `alter table test drop column id` </li><li>`alter table test add new_id int not null comment 'New id'` </li> </ul>  | Schema change: Columns are added or deleted.    |    -     |
| Table or database deletion      |  <ul><li>`drop table test`  </li><li>`drop database test` </li> </ul>   | A table or database is deleted.    |  - |
| Table truncation  |     `truncate table test`     | A data table is truncated.      |      -   |
| Update without conditions  |   `update test set new_id =1`       | An update without conditions is performed.     |    -     |
| Update with a permanently true condition  |     `update  test set new_id =1 where 1 = 1`     | An update with a permanently true condition is performed.     |     -    |
| Deletion without conditions  |   `delete from test`       | Deletion without conditions is performed.    |   -      |
| Deletion with a permanently true condition  |    `delete  from test where 1=1`      | Deletion with a permanently true condition is performed.    |     -    |
| Too many rows returned  |   `max_return_rows > 50000`       | Too many rows are returned.    | The `max_return_rows` parameter specifies the maximum number of returned rows allowed for an SQL statement. If the number of returned rows exceeds this value, the SQL statement is considered at high risk. You can modify the parameter as needed by referring to topics in the [Manage system parameters](../../1600.system-management-features/500.manage-system-parameter/100.view-system-parameters.md) chapter.     |
|Too many rows affected  |    `max_affected_rows  > 50000`      | Too many rows are affected.   | The `max_affected_rows` parameter specifies the maximum number of affected rows allowed for an SQL statement. If the number of affected rows exceeds this value, the SQL statement is considered at high risk. You can modify the parameter as needed by referring to topics in the [Manage system parameters](../../1600.system-management-features/500.manage-system-parameter/100.view-system-parameters.md) chapter.      |
| Too many partitions involved  |   `max_partition_cnt >2000`       | Too many partitions are involved.     | The `max_partition_cnt` parameter specifies the maximum number of involved partitions allowed in an SQL statement. If the number of partitions exceeds this value, the SQL statement is considered at high risk. You can modify the parameter as needed by referring to topics in the [Manage system parameters](../../1600.system-management-features/500.manage-system-parameter/100.view-system-parameters.md) chapter.      |

## Prerequisites

* Make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Read-only** or **Tenant Read-only** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.src.hook.useMenu.RealTimeDiagnosis">Real-time Diagnostics</UI-TERM>** menu of **<UI-TERM key="ocp-v2.page.Diagnosis.AutonomousService">OceanBase Autonomy Service</UI-TERM>**

* You have enabled parameters in the **<UI-TERM key="ocp-v2.component.OperationConfig.List.SqlDiagnosticCollection">SQL Diagnostics Collection</UI-TERM>** section by referring to [Manage parameters](../../600.cluster-functions/300.manage-a-cluster/1200.manage-om-configuration/200.manage-om-configuration-parameters.md).

## Procedure

1. Log on to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.src.hook.useMenu.AutonomousService">OceanBase Autonomy Service</UI-TERM>**.

3. In the **<UI-TERM key="ocp-v2.page.Diagnosis.ClusterDetails">Cluster Details</UI-TERM>** section, click the name of the cluster that you want to view.

4. The **<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.Outline.SqlDiagnosis">SQL Diagnostics</UI-TERM>** tab of the **<UI-TERM key="ocp-v2.src.hook.useMenu.RealTimeDiagnosis">Real-time Diagnostics</UI-TERM>** page automatically appears.

5. Click the **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.HighRiskSql">High Risk SQL</UI-TERM>** tab.

6. Specify the filter conditions.

     * **<UI-TERM key="ocp-v2.Detail.Analyze.TimeRange">Time Range</UI-TERM>**: You can select **<UI-TERM key="ocp-v2.SQLDiagnosis.Digest.LastMinutes.1">Last 5 Minutes</UI-TERM>**, **<UI-TERM key="ocp-v2.Information.Detail.CreateCollectDrawer.NearlyMinutes">Last 10 Minutes</UI-TERM>**, **<UI-TERM key="ocp-v2.SQLDiagnosis.Digest.LastMinutes.3">Last 20 Minutes</UI-TERM>**, **<UI-TERM key="ocp-v2.component.OCPRangePicker.constant.NearlyMinutes.3">Last 30 Minutes</UI-TERM>**, **<UI-TERM key="ocp-v2.src.component.RangeTimeDropdown.LastHour">Last 1 Hour</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.log.NearlyHours">Last 3 Hours</UI-TERM>**, or **<UI-TERM key="ocp-v2.component.OCPRangePicker.constant.NearlyHour.6">Last 6 Hours</UI-TERM>** from the **<UI-TERM key="ocp-v2.Detail.Analyze.TimeRange">Time Range</UI-TERM>** drop-down list. You can also select **<UI-TERM key="ocp-v2.component.RangeTimeDropdown.CustomTime">Custom Time</UI-TERM>** from the drop-down list and specify the start time and end time as needed. By default, the information of the last 6 hours is displayed.

     * **OBServer**: You can select an OBServer node or all OBServer nodes in the list. If you select an OBServer node, only SQL statements executed on the selected OBServer node are queried.

     * **<UI-TERM key="ocp-v2.SQLDiagnosis.attributes.slowSqlAttributes.InternalSql">Internal SQL</UI-TERM>**: If you select this option, the SQL statements internally initiated in OceanBase Database are displayed in the query result.

     * **<UI-TERM key="ocp-v2.component.alarm.Search.Keywords">Keyword</UI-TERM>**: The SQL statements that contain the specified keyword are displayed in the query result. The keywords filter SQL statements in the same way as the SQL LIKE operator. The entered strings are automatically prefixed and suffixed with a percent sign (%).

     * **Advanced Search**: You can add multiple filter conditions in **Advanced Search**. Click **<UI-TERM key="ocp-v2.Alarm.Rule.New.Add">Add</UI-TERM>**. In the **Add Advanced Conditions** dialog box, you can specify a metric, an operator, and a metric value. The SQL statements that match the specified conditions will be displayed in the query result.

7. Click **<UI-TERM key="ocp-v2.Detail.Parameter.History.Query">Search</UI-TERM>** to list all SQL statements that meet the search criteria. You can perform the following operations:

   * Click **Export High Risk SQL** to export all SQL statements in the query result.

   * View information about high-risk SQL statements.

     1. On the **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.HighRiskSql">High Risk SQL</UI-TERM>** tab, you can view the columns selected. You can copy the SQL text and filter the SQL statements by database.

     2. You can click the SQL text of an SQL statement to go to the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetail.SqlDetails">SQL Details</UI-TERM>** page of the statement, where you can view the following details of the SQL statement:

        * In the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetail.SqlText">SQL Text</UI-TERM>** section, you can view the complete SQL statement.

        * On the **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.Plan.HistoricalTrends">Previous Tendency</UI-TERM>** tab, you can view the historical trends and plan generation time of the SQL statement. For more information, see the **View the historical trends of an SQL statement** section in [View details of an SQL statement](../100.manage-sql-diagnosis/1000.view-sql-details.md).

        * On the **<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.constant.ExecutionPlan">Execution Plans</UI-TERM>** tab, you can view the execution plans of the SQL statement, or bind an execution plan to the statement. For more information, see the **View the execution plans of an SQL statement** section in [View details of an SQL statement](../100.manage-sql-diagnosis/1000.view-sql-details.md).

        * On the **<UI-TERM key="ocp-v2.Capacity.Resource.Top.Index">Index</UI-TERM>** tab, you can view the indexes bound to the SQL statement. For more information, see the **View and bind indexes** section in [View details of an SQL statement](../100.manage-sql-diagnosis/1000.view-sql-details.md).

        * On the **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.SqlThrottling">SQL Throttling</UI-TERM>** tab, you can view or set throttling of the SQL statement. For more information, see the **Set throttling for an SQL statement** section in [View details of an SQL statement](../100.manage-sql-diagnosis/1000.view-sql-details.md).
