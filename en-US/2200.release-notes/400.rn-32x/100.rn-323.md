# OCP V3.2.3

<!--#RNDate#2021-12-27-->

In OceanBase Cloud Platform (OCP) V3.2.3, the following features are introduced: the web UI-based log query feature, parameter template feature, cross-dimensional performance metric analysis, and the ability to configure SQL throttling, plan binding, and query binding history in the SQL diagnostics feature. In addition, the performance report feature has been enhanced to provide more detailed analysis. In addition to multithreshold alerts, the OCP console also supports 10 built-in alerts in this version, which improve the O&M capabilities of OCP for OceanBase Database clusters.

## Version information

* **Version:** V3.2.3

* **Prerequisite:** V3.1.5

* **Version release date:** December 27, 2021

* **Supported upgrade path: ** You can directly upgrade OCP V2.3.x and later to this version. For OCP versions earlier than V2.3.0, first upgrade to OCP V2.3.x and then to this version.

## Supported OceanBase Database versions

OceanBase Cloud V3.2.3 supports the OceanBase Database instances listed in the following table.

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

## New features

* **<UI-TERM key="ocp-v2.Monitor.AddMonitor.PerformanceMonitoring">Performance Monitoring</UI-TERM>** for clusters and tenants supports drilldown analysis for monitoring.

  You can use the drilldown feature to directly drill down to the tenant or OBServer node dimension of the monitored metrics to view the data for the tenant or OBServer node without having to switch through a complex path to the **<UI-TERM key="ocp-v2.page.Monitor.Monitoring">Performance Monitoring</UI-TERM>** page of the tenant or the **<UI-TERM key="ocp-v2.Host.Detail.Surveillance">Monitoring</UI-TERM>** tab of the host.

* The new log query feature enables you to set query conditions on the OCP console to view logs such as those of OBServer nodes, OBProxy, and hosts. You do not need to download logs to perform log queries.

* The SQL Diagnostics feature supports the SQL binding of indexes, execution plans, and SQL throttling, as well as the SQL binding history query.

* Added 10 built-in alert items for end-to-end monitoring and alerting across active sessions, log synchronization latency, and cross-cloud management by OCP. Additionally, alerting now supports multi-threshold configurations to enhance performance and stability in OceanBase clusters.

* You can now create parameter templates. If you need to create multiple tenants or clusters with the same parameters, you can create a parameter template first and apply it when you create a tenant or cluster. This avoids the need to configure the parameters manually when you create a cluster or tenant.

  * For information about how to create a parameter template, see [Cluster Parameter Templates](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000377800).

  * For instructions on how to create a cluster or a tenant, see [Create a cluster](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000378283) and [Create a tenant](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000377507).

## Feature Enhancements

* Optimized performance monitoring features to further refine metrics related to clusters and tenants, providing more detailed performance information. The metrics include:

  * Cluster metrics: **QPS**, **query response time**, **TPS**, and **transaction response time**.

  * Tenant: **Request Waiting Queue** , **TPS** , **Transaction Response Time** .

* Optimized and enhanced the logic for upgrading and restarting OBServer nodes to support shutdown upgrades and restarts. This optimization meets the need for quickly upgrading and restarting OBServer nodes without requiring business continuity.

* Enhance the **<UI-TERM key="ocp-v2.Detail.Report.PerformanceReport">Performance Report</UI-TERM>** feature, adding the ability to display statistics on **<UI-TERM key="ocp-v2.src.component.DeleteUnitSpecModal.Memory">Memory</UI-TERM>**, **RPC**, and **<UI-TERM key="ocp-performance-report.pages.AWR.ParameterConfigurationChanges">Parameter Changes</UI-TERM>**.

## Version usage limitations

### Hardware requirements

OCP-Server can be installed on physical servers or in Docker containers. OCP-Server supports multi-node high availability deployment.

The minimum hardware requirements for OCP-Server nodes are shown in the following table.

| Hardware |                 Requirements                 |
|-----|------------------------------------|
| CPU | <li>X86_64, 8 cores</li><li>ARM aarch 64 architecture, 8 cores</li> |
| Memory  | 16 GB of available memory                         |
| NIC  | 10 GbE NIC                               |

OCP-Agent consumes very few resources and has no special requirements for the hardware resources of the installation node.

### Operating system requirements

The operating system requirements for installing OCP-Server (including OCP-Agent) are shown in the following table.

|    Server type    |    Operating system    |   Supported versions    |

| x86_64      | RHEL       | 7.2 and later |
| x86_64      | CentOS     | 7.2 and later |
| x86_64      | AliOS      | 7.2 and later |
