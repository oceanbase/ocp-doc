## OCP V4.1.0

OceanBase V4.x introduces significant changes to its architecture and product form, along with numerous new features. As the supporting O&M management platform for OceanBase, OCP needs to present these new features to users in a simpler and more user-friendly way, reducing the difficulty of use. Additionally, as a major version update for OCP, this release further optimizes the product experience, adjusts the product architecture, and enhances product capabilities.

### Version information

* **Version:** V4.1.0

* **Previous version:** V4.0.3

* **Release date:** May 26, 2023

* **Supported upgrade path:**

  * Currently, only direct upgrades from OCP V3.2.4 and later versions are supported to the current version.

  * For OCP V2.3.x and later, but before V3.2.4, you must first upgrade to OCP V3.3.4.

  * For OCP versions earlier than V2.3.0, you must first upgrade to OCP V2.3.x, then to OCP V3.3.4.

### Supported OceanBase Database versions

OCP V4.1.0 supports the following OceanBase Database versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

* OceanBase V4.x

### New features

#### OceanBase V4.x

* **Unified management of standalone and distributed environments**

  Enables simultaneous management of OceanBase environments that are **standalone centralized** (only available in OceanBase V4.1 and later) or **distributed clusters**, meeting the needs of users in different scenarios.

  * Supports selecting the **standalone centralized** or **distributed cluster** mode when creating a cluster, and simplifies the deployment process for **standalone centralized** environments.

  * Supports simultaneously creating a business tenant using the maximum available resources of a cluster during **standalone centralized** deployment, enabling immediate business use.

  * Supports online scaling from a **standalone centralized** environment to a **distributed cluster** to meet business growth and higher security requirements.

* **Arbitration service**

  Supports configuring an arbitration service for tenants with 2F or 4F replicas in OceanBase clusters of version V4.1 and later, reducing the arbitration cost for high availability in multi-replica setups.

  * Added the **Arbitration Service Management** feature, enabling capabilities such as deployment, start/stop, deletion, and upgrade of arbitration services.

  * Supports deploying multiple arbitration service instances on a single node to meet the arbitration and high availability requirements of different clusters.

  * Supports adding, replacing, and removing arbitration services in OceanBase clusters of version V4.1 and later.

  * Supports enabling or disabling the arbitration service for tenants with 2F or 4F replicas after an arbitration service has been added to a cluster.

#### Platform features

* **New information architecture**

  * The original first-level entry **Software Packages** has been moved under **System Management** and renamed **Software Package Management**.

  * Added a new first-level entry **Monitoring and Alerts**, moving the original **Alerts** and **Inspection** under **System Management** to this path.

  * The original **Log Service** under **System Management** has been promoted to a first-level entry.

  * The original **Tasks** entry under **System Management** has been moved to the upper-right corner of the **Home** page.

  * The original first-level entry **Diagnostic Center** has been renamed **Autonomous Services**.

  * The original **Historical Events** under **System Management** has been renamed **Operation Audit**.

  * The original **Security** under **System Management** has been renamed **User Management**.

* **Deployment templates**

  For hosts added to OCP, standardized settings can be applied to the database environment.

* **Multi-OSS geographically distributed backup**

  * Local OSS backup in the production cluster, while replicating local backups to an offsite OSS.

  * The backup scheduling, cycle, and retention policies differ between the two OSS locations. 30 days of backups are retained locally, and 7 days are retained offsite.

  * Tenant recovery from an offsite OceanBase cluster can be performed using the offsite OSS.

  * When replicating log backups, log backups are synchronized first, followed by log metadata to meet timeliness requirements for log backups.

### Feature enhancements

* When setting a backup policy, you can now enter a port number in the OSS access domain name.

* Added a check for read/write permissions on the OBProxy log directory during OBProxy cluster deployment.

* The ocp_agent process is automatically restarted after a server reboot.

* SQL diagnostics now support execution comparison across different hosts.

* When creating a cluster, a new Zone Priority configuration switch is added. When this switch is off, the sys tenant's Zone priority follows OceanBase's default behavior: for cluster versions below V4.x, the first Zone has priority; for V4.x and later, it is random priority.

* Optimized the interface speed for the backup storage trend on the Global View overview page.

* Optimized the display on the homepage of the Diagnostics Center.

* Increased the default value for log backup latency alerts.

* Added memory alerts for non-MemStore regions to OCP alert items.

* Supports custom addition of write lock wait failure count and average wait time per lock alert items.

* Added digest authentication for OCP Agent.

* Added an inspection item for `max open files` on OBProxy servers.

* Added a parameter to control the starting OceanBase Database version for enabling cgroup.

* Monitoring query optimization: reduced peak monitoring query pressure through asynchronous queries, optimized query computation link code, and abstracted the storage layer, thereby improving the overall throughput of the monitoring interface.

* Capacity Center now includes **Capacity Risk** and Tenant **Total Capacity Usage Overview**.

### Security improvements

* Sensitive information involved in web page access interface interactions is transmitted encrypted.

* For new OCP deployments, the built-in initial password is removed and replaced with a user-specified password.

* After uploading the software package, a pop-up window displays the SHA-1 value, which requires user confirmation.

### Version usage restrictions

#### Hardware requirements

OCP-Server can be installed on physical servers or run in Docker containers. OCP-Server supports multi-node high-availability deployment.

The minimum hardware requirements for an OCP-Server node are listed in the following table.

| Hardware | Requirements |
| ------- | ------------------------------------ |
| CPU | <li>x86_64, 8-core</li><li>ARM AArch64 architecture, 8-core</li> |
| Memory | Available Memory: 16 GB |
| NIC | 10 Gbit/s NIC |

OCP-Agent consumes very few resources and has no specific hardware requirements for the installation node.
