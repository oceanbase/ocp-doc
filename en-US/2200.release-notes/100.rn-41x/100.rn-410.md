## V4.1.0 BP2

### Version information

* **Version:** V4.1.0 BP2

* **Previous version:** V4.1.0 BP1

* **Version release date:** September 1, 2023

### Bug fixes

* Fixed the issue where the displayed CPU usage of a tenant was 100 times the actual value.

* Fixed the issue where a non-root user might fail to add a host.

* Fixed the issue where the cleanup of useless alert history failed.

* Fixed the issue where the displayed transaction response time in monitoring was 1,000 times the actual value.

* Fixed the issue where some real-time monitoring data was delayed by two minutes before it could be queried.

* Fixed the issue where more than two units could not be selected during scaling.

## V4.1.0 BP1

### Version information

* **Version:** V4.1.0 BP1

* **Previous version:** V4.1.0

* **Version release date:** July 20, 2023

### New features

* Added support for OAuth2 and CAS as two general single sign-on (SSO) authentication and authorization methods.

* Optimized English terms and text within the product, enabling multi-language switching to meet internationalization requirements.

* Optimized the OBAgent startup logic to support automatic cleanup of historical PID files.

* Added support for O&M management of basic scenarios in OceanBase V4.2.0.0 to support POCs.

### Bug fixes

* Fixed a series of issues related to cross-OCP cluster operations when MetaDB uses the `127.1` address.

* Fixed the issue where the topology diagram had no monitoring data.

* Fixed the issue where backup tasks could not be rescheduled after a secondary backup was canceled.

* Fixed the error when importing hosts via the OpenAPI.

* Optimized the issue where host addition failed in specific shell environments.

* Optimized the host addition process to allow successful addition even when ICMP is disabled.

* Optimized fault tolerance in primary-standby database switching scenarios and prohibited some erroneous operations.

* Enhanced compatibility with the openEuler operating system in host management.

## OCP V4.1.0

The architecture and product form of OceanBase V4.x have undergone significant changes, along with the introduction of numerous new features. As the companion O&M management platform for OceanBase, OCP needs to present these new features in a more user-friendly manner to reduce the difficulty of use for users. Additionally, this major version of OCP further optimizes the product experience, adjusts the product architecture, and enhances its capabilities.

### Version information

* **Version:** V4.1.0

* **Previous version:** V4.0.3

* **Version release date:** May 26, 2023

* **Supported upgrade path:**

  * You can directly upgrade OCP V3.2.4 and later to the current version.

  * For OCP V2.3.x and later, V3.2.4 and earlier, you must first upgrade to OCP V3.3.4.

  * For OCP V2.3.0 and earlier, you must first upgrade to OCP V2.3.x and then to OCP V3.3.4.

### Supported OceanBase Database versions

OCP V4.1.0 supports the following OceanBase Database versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

* OceanBase V4.x

### New features

#### OceanBase V4.x

* **Single-node and distributed cluster management**

  You can manage **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** clusters (available only in OceanBase Database V4.1 and later) and **<UI-TERM key="ocp-v2.Cluster.New.DistributedCluster">Distributed Cluster</UI-TERM>** clusters in the same environment, meeting the needs of different scenarios.

  * You can choose **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** or **<UI-TERM key="ocp-v2.Cluster.New.DistributedCluster">Distributed Cluster</UI-TERM>** mode when you create a cluster. The deployment process of **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** clusters is simplified.

  * You can deploy a business tenant using the maximum available resources of a **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** cluster and enable the tenant immediately.

  * You can online scale out a **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** cluster to a **<UI-TERM key="ocp-v2.Cluster.New.DistributedCluster">Distributed Cluster</UI-TERM>** cluster to meet the growing business needs and higher security requirements.

* **<UI-TERM key="ocp-v2.page.Cluster.ArbitrationService">Arbitration Service</UI-TERM>**

  You can configure the arbitration service for 2F or 4F tenants in an OceanBase cluster of V4.1 or later. This reduces the arbitration cost for high availability of multiple replicas.

  * You can deploy, start, stop, delete, and upgrade the arbitration service.

  * You can deploy multiple arbitration service instances on one node to meet the high availability requirements of different clusters.

  * You can add, replace, or remove the arbitration service in an OceanBase cluster of V4.1 or later.

  * You can enable or disable the arbitration service for 2F or 4F tenants in a cluster that has the arbitration service enabled.

  * A new first-level menu **Monitoring and Alerts** is added. The original **<UI-TERM key="ocp-v2.src.constant.auth.Alert">Alerts</UI-TERM>** and **<UI-TERM key="ocp-v2.page.Inspection.Inspection">Inspection</UI-TERM>** submenus under **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** are moved to this menu.

  * The original **<UI-TERM key="ocp-v2.src.hook.useMenu.LogService">Log Service</UI-TERM>** submenu under **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** is promoted to a first-level menu.

  * The original **<UI-TERM key="ocp-v2.src.hook.useMenu.OperationAudit">Operation Audit</UI-TERM>** submenu under **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** is renamed from **<UI-TERM key="ocp-v2.src.constant.auth.Alert">Alerts</UI-TERM>**.

* **Installation templates**

  You can standardize the database environment settings for hosts added to OCP.

* **Multi-region OSS backup**

  * You can back up data to the local OSS of a production cluster and copy the local backup to the OSS in another region.

  * The backup scheduling, backup cycle, and retention strategy are different between the local and remote OSS. The local OSS retains backups for 30 days, and the remote OSS retains backups for 7 days.

  * You can restore a tenant in an OceanBase cluster in another region by using the OSS in that region.

  * When you copy log backups, you can first synchronize the log backups and then synchronize the log metadata to meet the timeliness requirements of log backups.

### Feature enhancements

* When you set a backup strategy, you can enter the port number in the OSS endpoint.

* When you deploy an OBProxy cluster, the system checks whether the OBProxy log directory has read and write permissions.

* After a server restarts, the ocp_agent process automatically starts.

* SQL diagnostics support comparison of execution results on different hosts.

* When you create a cluster, you can enable the Zone priority configuration switch. If this switch is disabled, the zone priority of the sys tenant remains the default behavior of OceanBase Database. Specifically, when the cluster version is earlier than V4.x, the first zone is the first priority. When the cluster version is V4.x or later, the zone priority is random.

* The backup storage trend interface on the overview page of global views is optimized for speed.

* The homepage of the diagnostics center is optimized.

* The default value of the log backup delay alert is increased.

* The OCP alert items are enhanced to include memory alerts for non-memstore zones.

* You can customize the alert items for the number of write lock wait failures and the average lock wait time.

* The OCP Agent supports digest authentication.

* The `max open files` parameter is added to the inspection items for the obproxy server.

* A parameter is added to control the starting OceanBase Database version for enabling cgroups.

* The monitoring query is optimized. By using asynchronous queries, optimizing the computing chain code, and abstracting the storage layer, the peak pressure of monitoring queries is reduced, thereby improving the overall throughput of the monitoring interface.

* The Capacity Center is enhanced with **<UI-TERM key="ocp-v2.Detail.Capacity.CapacityRisk">Capacity Risks</UI-TERM>** and the tenant **<UI-TERM key="ocp-v2.Detail.Capacity.OverviewOfCapacityUsage">Capacity Usage Overview</UI-TERM>**.

### Security enhancements

* Sensitive information involved in interactions with web page access interfaces is encrypted during transmission.

* When you deploy OCP for the first time, you can specify the initial password instead of using the built-in initial password.

* After you upload a software package, a pop-up window displays the SHA1 value, and you need to confirm it.

### Limitations

#### Hardware requirements

OCP-Server can be installed on a physical server or in a Docker container. OCP-Server supports multi-node high-availability deployment.

The minimum hardware requirements for OCP-Server nodes are as follows:

| Hardware  | Requirements                                 |
|-------|------------------------------------|
| CPU   | <li>X86_64, 8 cores</li><li>ARM aarch 64 architecture, 8 cores</li> |
| Memory  | 16 GB of available memory                         |
| NIC  | 10 GbE NIC                               |

OCP-Agent consumes very few resources and does not have special hardware requirements for the installation node.

#### Operating system requirements

The operating system requirements for installing OCP Server (including OCP-Agent) are as follows:

| Server type       | Operating system       | Supported versions      |
|-------------|------------|-----------|
| x86_64      | RHEL       | 7.2 and later |
| x86_64      | CentOS     | 7.2 and later |
| x86_64      | AliOS      | 7.2 and later |
| x86_64      | openSUSE   | 12SP3 and later |
| ARM aarch64 | AliOS      | 7.2 and later |
| ARM aarch64 | NeoKylin       | 7.6       |
| ARM aarch64 | Huawei EulerOS | 2.0 SP8   |
| x86_64 | Debian       |   Debian GNU/Linux 11 (bullseye)    |
| x86_64 | Ubuntu |  Ubuntu 18.04.6 LTS  |

#### Client requirements

General users typically access OCP through a web browser, so the client requirements are as follows:

| Browser     | Minimum version |
|---------|------|
| Chrome  | 81   |
| Firefox | 64   |
| Safari  | 10   |
| Edge    | 13   |

If you need to access OCP from an iOS device, the minimum version is as follows:

| Operating system | Minimum version |
|------|------|
| iOS  | 10   |

For the best user experience, we recommend using a display with a resolution greater than 1440 x 810.
