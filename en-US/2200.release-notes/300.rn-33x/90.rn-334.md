# OCP V3.3.4

<!--#RNDate#2022-10-21-->

OceanBase Cloud Platform (OCP) V3.3.4 introduces new audit events and enhances other features.

## Version information

* **Version:** V3.3.4

* **Previous version:** V3.3.3

* **Version release date:** October 21, 2022

* **Supported upgrade path:** OCP V2.3.x and later versions can be directly upgraded to this version. For OCP versions earlier than V2.3.0, you must first upgrade to V2.3.x before upgrading to this version.

## Supported OceanBase Database versions

OCP V3.3.4 supports the following OceanBase Database versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

## Feature enhancements

* Operation audit: New audit events are added, including stopping a zone, starting a zone, restarting a zone, modifying the deadlock detection switch, deleting a software package, modifying the OceanBase cluster TopSQL switch, triggering an OceanBase cluster major compaction, clearing the failed status of an OceanBase cluster major compaction, and tenant unit operations (scaling up or down).

* In the **<UI-TERM key="ocp-v2.page.Overview.SuspiciousSql">Suspicious SQL</UI-TERM>** section of the diagnostics, a new judgment mode is added. If the PARTITION_CNT is greater than the AffectRows, it is marked as **<UI-TERM key="ocp-v2.page.Diagnosis.SuspiciousSql">Suspicious SQL</UI-TERM>**.

* The backup cluster creation process is optimized. The success flag of primary and backup cluster creation is changed from **add standy command success** to **snapshot access completed**.

* The test alert feature is optimized. Default values for environment variables are added to improve the success rate of test alerts.

* The pre-check logic for the secondary backup path is optimized. It is prohibited to have a directory with the same cluster name under the backup path.

## Fixed issues

OCP V3.3.4 fixes the following issues:

1. Fixed the issue where the unit of the system variable `connect_timeout` was incorrectly written as **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.Microseconds">Microseconds</UI-TERM>** instead of **<UI-TERM key="ocp-v2.Alarm.Rule.Detail.Seconds">Seconds</UI-TERM>**.

2. Fixed the issue where OCP could not be started when the flow control was disabled.

3. Fixed the issue where the host IP address in an alert message was incorrectly described, and the issue where the tenant list was incorrectly described.

4. Fixed the issue where some parameters that cannot be modified were displayed as modifiable in the frontend.

5. Optimized the performance of AWR report generation to reduce the frequency of report generation timeouts when the number of tenants exceeds 100.

6. Optimized internal table query statements to avoid abnormal cluster status display due to business pressure.

7. Optimized the fault tolerance of host maintenance operations.

8. Optimized the Grafana monitoring push logic to avoid data absence.

9. Optimized the NTP delay collection method to improve accuracy under high host load.

## Version limitations

### Hardware requirements

OCP-Server can be installed on a physical server or in a Docker container. OCP-Server supports multi-node high availability deployment.

The minimum hardware requirements for OCP-Server nodes are as follows:

| Hardware  | Requirement                                 |
|-----|------------------------------------|
| CPU | <li>X86_64, 8 cores</li><li>ARM aarch 64 architecture, 8 cores</li> |
| Memory  | 16 GB of available memory                         |
| NIC  | 10 GbE NIC                               |

OCP-Agent consumes very few resources and has no special hardware requirements for the installation node.

### Operating system requirements

The operating system requirements for installing OCP (including OCP-Agent) are as follows:

|    Server type    |    Operating system    |   Supported version    |
|-------------|------------|-----------|
| x86_64      | RHEL       | 7.2 and later |
| x86_64      | CentOS     | 7.2 and later |
| x86_64      | AliOS      | 7.2 and later |
| x86_64      | openSUSE   | 12SP3 and later |
| ARM aarch64 | AliOS      | 7.2 and later |
| ARM aarch64 | NeoKylin       | 7.6       |
| ARM aarch64 | Huawei EulerOS | 2.0 SP8   |

### Client requirements

General users access OCP through a web browser, so the client requirements are as follows:

| Browser     | Minimum version |
|---------|------|
| Chrome  | 81   |
| Firefox | 64   |
| Safari  | 10   |
| Edge    | 13   |

If you need to access OCP from an iOS device, the minimum operating system version is as follows:

| Operating system | Minimum version |
|------|------|
| iOS  | 10   |

For the best user experience, we recommend using a display with a resolution of 1440 x 810 or higher.
