# OCP V3.3.4

#RNDate#2022-10-21

OceanBase Cloud Platform (OCP) of this version has added audit events and optimized the other features.

## Version information

* **Version number**: V3.3.4

* **Previous version**: V3.3.3

* **Release date**: October 21, 2022

* **Supported upgrade path**: OCP V2.3.x and later versions can be directly upgraded to this version. For OCP versions earlier than V2.3.0, first upgrade to V2.3.x and then to this version.

## Supported OceanBase Database versions

OCP V3.3.4 supports OceanBase Database of the following versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

## Feature enhancements

* Added audit events for operation auditing: stop zone, start zone, restart zone, modify deadlock detection switch, delete software package, modify OceanBase cluster Top SQL switch, trigger OceanBase cluster merge, clear OceanBase cluster merge failure state, tenant unit operation (expansion/shrinkage).

* Added a new judgment mode for **<UI-TERM key="ocp-v2.page.Overview.SuspiciousSql">Suspicious SQL</UI-TERM>** in diagnosis. When the value of PARTITION_CNT is greater than that of AffectRows, it is marked as **<UI-TERM key="ocp-v2.page.Diagnosis.SuspiciousSql">Suspicious SQL</UI-TERM>**.

* Optimized the process for creating a standby cluster. The success indicator changed from the original **add standy command success** to **snapshot access completed**.

* Optimized the test alert feature by adding default values for environment variables to improve test alert success rate.

* Optimized the pre-check logic for the backup path to prohibit the existence of directories with the same cluster name.

## Bug fixes

OCP V3.3.4 fixed the following issues:

1. Fixed the issue where the unit of the system variable `connect_timeout` was incorrectly written as **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.Microseconds">Microseconds</UI-TERM>** instead of **<UI-TERM key="ocp-v2.Alarm.Rule.Detail.Seconds">Seconds</UI-TERM>**.

2. Fixed the issue where OCP could not be started when traffic control is disabled.

3. Fixed the issue where the host IP address was incorrectly described in the alert message and the tenant list was incorrectly described.

4. Fixed the issue where certain unmodifiable parameters were displayed as modifiable on the frontend.

5. Optimized the performance of AWR report generation to reduce the frequency of timeout when the number of tenants exceeds 100.

6. Optimized internal table query statements to prevent cluster status from being displayed abnormally due to business pressure.

7. Enhanced the fault tolerance of host operations.

8. Optimized the logic for pushing monitoring data in Grafana to avoid cases where no data is displayed.

9. Optimized the NTP delay collection method for hosts to improve accuracy under high load.

## Version limitations

### Hardware requirements

OCP-Server can be installed on a physical server or in a Docker container and supports a multi-node highly available deployment model.

The minimum hardware requirements for an OCP-Server node are as follows.

| Hardware  | Requirements                                 |
|-----|------------------------------------|
| CPU | <li>X86_64, 8-core</li><li>ARM aarch 64 architecture, 8-core</li> |
| Memory | 16 GB of available memory                         |
| NIC  | 10 Gigabit Ethernet interface                               |

OCP-Agent has minimal resource requirements and does not impose special hardware requirements on the installation node.

### Operating system requirements

The operating systems supported for installing the OCP service end (including OCP-Agent) are as follows:

|    Server type    |    Operating system    |   Supported versions    |
|-------------|------------|-----------|
| x86_64      | RHEL       | 7.2 and later |
| x86_64      | CentOS     | 7.2 and later |
| x86_64      | AliOS      | 7.2 and later |
| x86_64      | openSUSE   | 12SP3 and later |
| ARM aarch64 | AliOS      | 7.2 and later |
| ARM aarch64 | NeoKylin       | 7.6       |
| ARM aarch64 | Huawei EulerOS | 2.0 SP8   |

### Client requirements

| Browser     | Minimum version |
|---------|------|
| Chrome  | 81   |
| Firefox | 64   |
| Safari  | 10   |
| Edge    | 13   |
