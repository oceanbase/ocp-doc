# OCP V3.3.1

<!--#RNDate#2022-05-24-->

OceanBase Cloud Platform (OCP) is upgraded to support more features and improve the details of existing features. The new version of OCP mainly enhances the SQL diagnostic feature and adds the feature of decoupling between primary and standby databases.

## V3.3.1

### Version information

* **Version:** V3.3.1

* **Previous version:** V3.3.0

* **Version release date:** May 24, 2022

* **Supported upgrade path:** OCP V2.3.x and later versions can be directly upgraded to this version. For OCP versions earlier than V2.3.0, you must first upgrade to V2.3.x and then to this version.

### Supported OceanBase Database versions

OCP V3.3.1 supports the following OceanBase Database versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

### New features

* **VPC support**

  * Added the ECS type as a host type. You can select the ECS type as the host type in the host list, when importing a host, or when creating or expanding an OceanBase cluster or an OBProxy cluster.

  * Added network attribute display on the front-end page in scenarios such as host, OceanBase cluster, and OBProxy cluster.

  * Added the ability to filter hosts by network type in OceanBase cluster and OBProxy cluster maintenance scenarios.

* **Multi-condition alert feature**

  * You can configure multiple alert expressions for different monitoring metrics on the CLI. The expressions support the and and or operators.

  * You can display multiple monitoring charts on the details page of an alert for multiple monitoring metrics.

  * When you modify an alert for multiple monitoring metrics on the front end, a prompt is displayed: "Cannot edit."

  * Integrated OAS alerts for seamless integration with OAS.

* OAS data query capability

  * Enhanced the monitoring query feature to better support OAS. You can use the following multi-condition expressions and the round function:

    * = (equivalent to:)

    * !=

    * =\~ (regular expression match)

    * !\~ (non-regular expression match)

  * Added the collection of kern.log logs for log trace.

  * Added several monitoring data collection items, such as io_await and partition_iutil, to meet OAS requirements.

* Internationalization

  The documentation supports both Simplified Chinese and English, and is adapted to different language environments to ensure an internationalization experience.

### Fixed issues

OCP V3.3.1 fixes the following issues:

* Fixed the issue where FullGC occurs under high pressure (20000 QPS).

* Fixed the issue where an error is returned after the sampling strategy is deleted during backup and restore.

* Fixed the issue where an error is returned during the agent upgrade step when OCP is upgraded from V3.2.3 to a later version on ARM architecture.

* Fixed the issue where an error is returned when OCP V3.3.0 is used to upgrade ob2230 to ob3230.

* Fixed the issue where a read-only cluster can modify tenant replicas.

* Fixed the issue where an NTP service is incorrectly alerted in a container environment.

* Fixed the issue where the Primary Zone information of a tenant is not updated.

* Fixed the issue where a tenant cannot be created on ob1479 through OCP.

* Fixed the issue where the Python alert script template is outdated.

* Fixed the issue where the sys tenant has a long-term SlowSQL alert.

* Fixed the issue where the alert jump logic is incorrect.

* Fixed the issue where the sum of response ratios in SQL diagnostics is not 100%.

* Fixed other issues in SQL diagnostics, monitoring, and alerts that occur under specific conditions.

* Fixed some front-end page interaction issues.

### Version limitations

* Hardware requirements

OCP-Server can be installed on a physical server or in a Docker container. OCP-Server supports multi-node high availability deployment.

The following table lists the minimum hardware requirements for OCP-Server nodes.

| Hardware  |                 Requirement                 |
|-----|------------------------------------|
| CPU | <li>X86_64, 8 cores</li><li>ARM aarch 64 architecture, 8 cores</li> |
| Memory  | 16 GB of available memory                         |
| NIC  | 10 GbE NIC                               |

OCP-Agent consumes very little resources and has no special hardware requirements.

* Operating system requirements

The following table lists the operating system requirements for installing OCP (including OCP-Agent).

|    Server type    |    Operating system    |   Supported versions    |
|-------------|------------|-----------|
| x86_64      | RHEL       | 7.2 and later |
| x86_64      | CentOS     | 7.2 and later |
| x86_64      | AliOS      | 7.2 and later |
| x86_64      | openSUSE   | 12SP3 and later |
| ARM aarch64 | AliOS      | 7.2 and later |
| ARM aarch64 | NeoKylin       | 7.6       |
| ARM aarch64 | Huawei EulerOS | 2.0 SP8   |

* Client requirements

General users access OCP through a Web browser. The following table lists the client requirements.

|   Browser   | Minimum version |
|---------|------|
| Chrome  | 81   |
| Firefox | 64   |
| Safari  | 10   |
| Edge    | 13   |

If you want to access OCP through an iOS device, the following table lists the operating system requirements.

| Operating system | Minimum version |
|------|------|
| iOS  | 10   |

For the best user experience, we recommend that you use a display with a resolution greater than 1440 x 810.

## V3.3.1 BP

* **Version release date:** July 8, 2022

* **Supported upgrade path:** OCP V2.3.x and later versions can be directly upgraded to this version. For OCP versions earlier than V2.3.0, you must first upgrade to V2.3.x and then to this version.

* AWR reports display I/O statistics.

### Fixed issues

OCP V3.3.1 BP fixes the following issues:

* Fixed the issue where the SSH latency information is displayed as undefinedms in the host time of cluster health inspection.

* Fixed the issue where an alert is incorrectly triggered when the CPU system usage rate of a server is excessively high.

* Fixed the issue where a large number of SQL IDs on the SQL diagnostics page causes slow queries.

* Fixed the issue where the ocp-obcloud-service module is missing from the OCP V3.3.1 pom file.

* Fixed the issue where the initialization of OBConnector is timed out due to a single-threaded initialization.
