# OCP V3.3.0

<!--#RNDate#2022-04-27-->

OceanBase Cloud Platform (OCP) is upgraded to support more features and optimize the details of other features. The new version mainly enhances the SQL diagnostic feature and adds the capability of decoupling between primary and standby databases.

## Version information

* **Version:** V3.3.0

* **Previous version:** V3.2.3

* **Version release date:** April 27, 2022

* **Supported upgrade path:** You can directly upgrade OCP V2.3.x and later to this version. For OCP V2.3.0 and earlier, you must first upgrade to V2.3.x before upgrading to this version.

## Supported OceanBase Database versions

OCP V3.3.0 supports the following OceanBase Database versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

## New features

### Diagnostics

* Transaction diagnostics

  Long-running and hanging transactions in the call chain can occupy resources for a long time, leading to an unstable system state and affecting the system's ability to provide efficient services. Transaction diagnostics provide monitoring and analysis of transactions, along with **<UI-TERM key="ocp-v2.Transaction.Detail.ExecutionInformation">Execution Information</UI-TERM>** and **<UI-TERM key="ocp-v2.Transaction.Detail.SqlExecutionDetails">Details About Executed SQL Statements</UI-TERM>** to help you understand the transaction model and identify the specific reasons for high time or resource consumption.

  OCP also provides emergency measures for abnormal transactions, allowing you to disable them with a single click to help the system quickly return to a stable state.

  ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/1.png)

* Correlation analysis

  In addition to the new diagnostic dimensions (transaction diagnostics, AP SQL diagnostics, and SQL request analysis), OCP now supports correlation analysis between alerts, monitoring data, transactions, SQL, and traces.

  ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/2.png)
  ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/3.png)
  ![3](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/4.png)
  ![4](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/5.png)
  ![5](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/6.png)

* SQL request analysis

  In addition to SQL diagnostics, OCP now supports SQL request analysis, which analyzes all database request executions from the **Database/SQL** perspective. This includes execution time distribution, SQL type distribution, and execution trends. This helps you gain a comprehensive understanding of SQL execution and quickly detect any anomalies during execution.

  ![6](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/7.png)
  ![7](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/8.png)

* Parallel SQL execution profiling

  OCP enhances SQL diagnostics for OLAP-type SQL. In complex SQL scenarios such as distributed queries, parallel queries, multi-table joins, and AP queries, it helps you identify slow operators or steps in SQL execution, accelerating SQL optimization.

  ![8](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/9.png)

  * Offline parallel SQL execution profiling:

    ![9](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/10.png)

  * Online parallel SQL execution profiling:

    ![10](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/11.png)

* Custom columns

  In SQL diagnostics, you can now define custom columns and apply advanced condition filters.

  ![11](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/12.png)
* SQL optimization suggestions

  SQL diagnostics now have strong anomaly detection capabilities, including the ability to detect SlowSQL and suspicious SQL based on expert experience. It also provides practical emergency measures such as SQL throttling and plan/index binding. However, for the anomalies detected by the system, you need to decide on the appropriate emergency actions. SQL optimization suggestions guide you on how to optimize SQL.

  OCP now supports suggestions such as optimal index creation, historical execution plan recommendations, and tenant CPU expansion recommendations to help you quickly resolve SQL issues.

  ![12](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/13.png)

* Deadlock detection

  Deadlock detection provides detailed information about deadlocks, including the roles of the participants, the execution sequence, and the SQL statements involved. This helps you analyze the root cause of deadlocks and resolve them by analyzing and addressing circular dependencies in real time.

  ![13](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/14.png)

* Emergency measures

  In addition to binding execution plans, OCP now provides emergency measures for individual and batch SQL throttling.

### Primary and standby databases

* Decoupling of primary and standby databases

  You can physically split the primary and standby databases, promoting the standby database to the primary role. This facilitates production environment testing and load testing.

  ![14](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/15.png)

* Read-only mode for the original primary database after failover

  To facilitate data verification and migration, OCP allows you to start the original primary database in read-only mode after a failover. This enables you to compare and correct data between the new primary and original primary databases.

### Alerts

You can now customize alerts and convert simple monitoring metrics into alert information.

### Capacity management

The **<UI-TERM key="ocp-v2.page.Iframe.ResourceManagement">Resource Management</UI-TERM>** page of the cluster now includes a replica view, allowing you to view the distribution of replicas.

![15](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/16.png)

### Backup and restore

You can now perform tenant-level snapshots for backup.

![16](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/17.png)

## Feature enhancements

* Enhanced alerting capabilities, including custom alert metrics and the ability to convert simple monitoring metrics into alert information. You can also configure alerts for slow SQL.

* Enhanced organization management, allowing you to group all resources under a single organization for easier management and identification.

* Enhanced **<UI-TERM key="ocp-v2.Detail.Monitor.PerformanceMonitoring">Performance Monitoring</UI-TERM>** for clusters, now including statistics such as **Block Cache Size**, **<UI-TERM key="ocp-performance-report.pages.AWR.ReportContent.CacheHitRate">Cache Hit Rate</UI-TERM>**, **Cache Request Count**, and **Open Cursors**.

* Enhanced data middleware capabilities by collecting logs from OBServer nodes and OBProxy using ocp-agent and writing them to storage platforms like ES/SLS. This provides comprehensive log query capabilities, laying a solid foundation for further log analysis.

## Fixed issues

OCP V3.3.0 fixes the following issues:

* The issue where agent installation fails in specific scenarios.

* The issue where tenant data may be deleted during rollback or retry during OceanBase upgrade.

* The issue where the OBProxy configuration page displays "The parameter version of OBProxy is inconsistent with that of the cluster. Please refresh the configuration" in specific scenarios.

* The issue where OBProxy processes are continuously restarted in specific scenarios.

* The issue where the host status is displayed incorrectly in specific scenarios.

* The issue where an error is reported during package sorting.

* The issue where the tenant name is displayed incorrectly in the cluster performance report in specific scenarios.

* The issue where a large number of tmp log files are left due to a bug in the logback component.

* The issue where SQL diagnostics cannot query data in specific scenarios.

* The issue where the OCP frontend responds extremely slowly and the CPU usage of the ocp-server container remains high.

## Known issues

| Number |                        Known issue                        |                              Workaround                               |
|----|----------------------------------------------------|-----------------------------------------------------------------|
| 1  | The sys tenant has a long-term SlowSQL alert.                             | This does not affect business operations, so no workaround is needed.                                                   |
| 2  | The alert table lacks indexes, making it impossible to process a large amount of alert history data.                              | We recommend that you upgrade OCP to V3.3.0 or manually update the OCP alert internal table when you deploy OCP V3.3.0 from scratch to improve alert query performance. |
| 3  | In OCP V3.3.0, the SQL diagnostics feature has compatibility issues with low versions of OceanBase (ob1479). | OCP has some compatibility issues with ob1479. We do not recommend that you manage ob1479 clusters.                       |

## Limitations

### Hardware requirements

You can install OCP-Server on a physical server or in a Docker container. OCP-Server supports multi-node high-availability deployment.

The following table describes the minimum hardware requirements for OCP-Server nodes.

| Hardware  |                 Requirements                 |
|-----|------------------------------------|
| CPU | <li>X86_64, 8 cores</li><li>ARM aarch 64 architecture, 8 cores</li> |
| Memory  | 16 GB of available memory                         |
| NIC  | 10 GbE                               |

OCP-Agent consumes very few resources and has no special hardware requirements for the installation node.

### Operating system requirements

The following table describes the operating system requirements for installing OCP Server (including OCP-Agent).

|    Server type    |    Operating system    |   Supported versions    |
|-------------|------------|-----------|
| x86_64      | RHEL       | 7.2 and later |
| x86_64      | CentOS     | 7.2 and later |
| x86_64      | AliOS      | 7.2 and later |
| x86_64      | openSUSE   | 12SP3 and later |
| ARM aarch64 | AliOS      | 7.2 and later |
| ARM aarch64 | NeoKylin       | 7.6       |
| ARM aarch64 | Huawei EulerOS | 2.0 SP8   |
