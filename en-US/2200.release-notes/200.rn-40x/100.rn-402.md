# OCP V4.0.2

<!--#RNDate#2023-02-06-->

OCP V4.0.2 integrates the load balancing feature to help you better leverage the OceanBase distributed cluster capabilities, and achieve balanced connection distribution and automatic failover.

## Version information

* **Version:** V4.0.2

* **Previous version:** V4.0.1

* **Version release date:** February 6, 2023

* **Supported upgrade path:**

    * You can directly upgrade from OCP V3.2.4 and later to the current version.

    * If you use OCP V2.3.x or later but earlier than V3.2.4, you must first upgrade to OCP V3.3.4.

    * If you use OCP V2.3.0 or earlier, you must first upgrade to OCP V2.3.x and then to OCP V3.3.4.

    </main>

## New features

* You can connect an OBProxy cluster to a load balancing service such as OBLB or SLB (available only in Apsara Stack) to enable automatic configuration synchronization and updates.

* You can use a client such as a JDBC client to obtain the configuration of an OBProxy cluster and use the **<UI-TERM key="ocp-v2.Alarm.Rule.AddAlarmMetricModal.Application">Applications</UI-TERM>** dimension to implement load balancing.

* You can manage AccessKeys and SecretKeys. You can choose to use AccessKey authentication to call OCP APIs.

## Feature enhancements

* You can manage an OBProxy cluster to avoid port inconsistencies among OBProxy nodes in the cluster.

* The following built-in alert items are added:

  * `ocp_meta_db_disconnected`: You can detect and generate alerts for disconnections between OCP and MetaDB or MonitorDB.

  * `ocp_http_request_timeout`: You can detect and generate alerts for timeout of OCP API requests.

  * `ocp_http_request_too_many_errors_occur`: You can detect and generate alerts for errors in OCP API requests.

  * `ocp_alarm_detect_timeout`: You can detect and generate alerts for timeout of OCP alert rule detection.

  * `ob_server_stopped`: You can detect and generate alerts for the stop of OceanBase Database services.

* You can export details of an alert rule and an alert template.

* You can add event alerts to an alert template.

* You can specify the `ocp.alarm.event.resend-interval-seconds` parameter to set the alert sending interval. By default, an alert is sent every 60 seconds. You can increase the value of this parameter to reduce the alert sending frequency.

* The alert recovery strategy is optimized as follows:

  * For threshold-based alerts, such as `xxx_count > 1`, an alert is automatically recovered only when the threshold is met again and the alert is not triggered for a period exceeding the alert recovery cycle. If the monitoring data is lost, the alert is not automatically recovered.

  * For non-threshold-based alerts, the alert is automatically recovered after the alert recovery cycle.

* The alert detection logic is optimized as follows:

  * The alert detection cycle is aligned with the data collection cycle. For a monitoring item that is collected every minute, the maximum alert delay is 70 s to 130 s. For a monitoring item that is collected every second, the maximum alert delay is 20 s.

  * You can specify the alert detection cycle. The smaller the detection cycle, the lower the alert delay. The theoretical alert delay is **detection cycle + data collection cycle + 10 s**. For real-time monitoring, you can specify the `ocp.alarm.query.metric-offset-seconds` parameter to adjust the offset.

* The backup logic is optimized. Before a backup is initiated, the system checks whether the cluster is in the upgrading state to avoid backup failures.

* The backup and restore feature is optimized. A progress bar is added to the **<UI-TERM key="ocp-v2.Backup.Restore.RestoreTask">Recovery Tasks</UI-TERM>** page.

* The display of diagnostic results is optimized. When the information scrolls, the key information columns, such as the SQL text and diagnostic results, are fixed.

## Fixed issues

OCP V4.0.2 fixes the following issues:

1. Fixed the issue where the addition of an OBServer node to an OceanBase cluster may fail in some cases.

2. Fixed the issue where an error is displayed on the **<UI-TERM key="ocp-v2.Detail.Monitor.Monitor.Overview">Overview</UI-TERM>** page after a cluster is deleted.

3. Fixed the issue where the **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.TheNumberOfAffectedRowsIsTooLarge">Too many rows are affected.</UI-TERM>** SQL statement is not diagnosed in the **High-Risk SQL** section of the **Diagnosis Center**.

4. Fixed the issue where no data is displayed in **End-to-End Diagnosis**.

5. Fixed the issue where the storage usage of a cluster is incorrectly displayed in the **Diagnosis Center**.

6. Fixed the issue where custom alerts are not triggered after OCP V3.x is upgraded to OCP V4.x.

7. Fixed the issue where the **Host Unavailable** alert cannot be generated when the OCP agent process does not exist.

8. Fixed the issue where some front-end information is not displayed in full.

## Limitations

### Hardware requirements

OCP-Server can be installed on physical servers or in Docker containers. OCP-Server supports multi-node high availability deployment.

The minimum hardware requirements for OCP-Server nodes are as follows:

| Hardware  | Requirements                                 |
|-----|------------------------------------|
| CPU | <li>X86_64, 8 cores</li><li>ARM aarch 64 architecture, 8 cores</li> |
| Memory  | 16 GB available memory                         |
| Network card  | 10 GbE network card                               |

OCP-Agent consumes very few resources and has no special hardware requirements for the installation node.

### Operating system requirements

The operating system requirements for installing OCP-Server (including OCP-Agent) are as follows:

| Server type       | Operating system       | Supported versions      |
|-------------|------------|-----------|
| x86_64      | RHEL       | 7.2 and later |
| x86_64      | CentOS     | 7.2 and later |
| x86_64      | AliOS      | 7.2 and later |
| x86_64      | openSUSE   | 12 SP3 and later |
| ARM aarch64 | AliOS      | 7.2 and later |
| ARM aarch64 | NeoKylin       | 7.6       |
| ARM aarch64 | Huawei EulerOS | 2.0 SP8   |
| x86_64 | Debian       |   Debian GNU/Linux 11 (bullseye)    |
| x86_64 | Ubuntu |  Ubuntu 18.04.6 LTS  |

### Client requirements

General users typically access OCP services through web browsers, so the client requirements are as follows:

| Browser     | Minimum version |
|---------|------|
| Chrome  | 81   |
| Firefox | 64   |
| Safari  | 10   |
| Edge    | 13   |

If you need to access OCP services using an iOS device, the operating system requirements are as follows:

| Operating system | Minimum version |
|------|------|
| iOS  | 10   |

For the best user experience, we recommend using a display with a resolution greater than 1440 x 810.
