# OCP V4.0.3

## V4.0.3 BP2

### Version information

* **Version:** V4.0.3 BP2

* **Previous version:** V4.0.3 BP1

* **Release date:** April 17, 2023

### Bug fixes

* Optimized second-level monitoring performance for more stable performance on low-configured hosts.

* Fixed the issue where resource trend data was inaccurate when OceanBase Database was version V4.1.0.

## V4.0.3

The main goal of OCP V4.0.3 is to integrate with the OBSharding platform and support taking over OBProxy services under OBSharding. You can configure and manage OBSharding-related alerting and log query services on OCP, leveraging OCP's foundational capabilities and further reducing the time cost of repeated configuration.

### Version information

* **Version:** V4.0.3

* **Previous version:** V4.0.2

* **Release date:** March 03, 2023

* **Supported upgrade path:**

    * Currently, only direct upgrades from OCP V3.2.4 and later versions to the current version are supported.

    * For OCP V2.3.x and later, but earlier than V3.2.4, you must first upgrade to OCP V3.3.4.

    * For OCP versions earlier than V2.3.0, you must first upgrade to OCP V2.3.x, then to OCP V3.3.4.

 <h4>Note</h4>
 <p>For OCP with MetaDB version 1479, some table fields may not be upgradable when upgrading to V4.0.3. If you need to upgrade, it is recommended to contact technical support first.</p>
 </main>

### New features

* **Connect to the OBSharding platform**

    <main id="notice" type='notice'>
    <h4>Note</h4>
    <p>Only OBSharding V3.2.6 and later versions are supported, with a matching OAT version of V4.1.0 or later.</p>
    </main>

  * OCP supports creating an OBProxy cluster in OBSharding mode via API calls.

  * In OBSharding mode, an OBProxy cluster can take over OBProxy services under OBSharding.

  * For the features of the OBSharding platform, the following alerts are added based on the original OBProxy alerts:

    * `odp_sql_query_slow`: The number of slow SQL queries exceeds the limit.
    * `odp_sql_execute_failed`: The number of SQL execution failures exceeds the limit.
    * `odp_instance_compress_failed`: OBProxy instance scale-in failed.
    * `odp_instance_expanse_failed`: OBProxy instance scale-out failed.

  * The log service supports querying and downloading logs related to the OBProxy service under OBSharding.

* **Password Box**

    The **Password Box** adds a **Test Credentials** feature, supporting one-click validation of credential effectiveness.

* **Monitoring**

    Distributed-related monitoring metrics are added in **Tenant** > **Performance Monitoring** (supported only for OceanBase V3.2.4-bp1, V4.1, and later versions):

    * A **SQL Execution Time** monitoring chart is added under **Performance and SQL**, including `local`, `remote`, and `distributed` monitoring data.

    * A **Transaction Response Time** monitoring chart is added under **Transactions**, including `local` and `distributed` monitoring data.

### Feature Optimizations

* Optimized permissions for the platform's **<UI-TERM key="ocp-v2.Detail.Monitor.Monitor.Overview">Overview</UI-TERM>** page. Only administrator users can view the platform overview information.

* Removed the OBProxy tab from the **Password Box** as it has no practical usage scenarios.

* Optimized the password update feature. After updating the root user password for a cluster or tenant, the system will proactively update the corresponding credentials in the Password Box.

* Optimized error notifications when a custom installation directory is not supported for individual operating systems during cluster creation.

* Optimized the cluster upgrade feature to support upgrades from OceanBase V4.0 to V4.1.

* The default timeout alert threshold for data backup is adjusted from **7 minutes** to **60 minutes**.

* Adjusted the default configurations for OCP's backup alert items:

  * `base_backup_timeout`: The alert level is adjusted from **<UI-TERM key="ocp-v2.RealtimeMonitor.View3D.ResourceDrawer.Serious">Critical</UI-TERM>** to **<UI-TERM key="ocp-v2.src.constant.alarm.Small">Caution</UI-TERM>**.

  * `backup_storage_capacity_over_threshold`: The alert level is adjusted from **<UI-TERM key="ocp-v2.src.constant.alarm.Serious">Critical</UI-TERM>** to **<UI-TERM key="ocp-v2.RealtimeMonitor.View3D.ResourceDrawer.Warning">Warning</UI-TERM>**.

  * `backup_storage_capacity_timeout_or_interrupted`: The alert level is adjusted from **<UI-TERM key="ocp-v2.src.constant.alarm.Serious">Critical</UI-TERM>** to **<UI-TERM key="ocp-v2.RealtimeMonitor.View3D.ResourceDrawer.Warning">Warning</UI-TERM>**.

* Optimized the alert statistics on the cluster overview page. You can now view cluster-level, tenant-level, OBServer node-level, and log alert statistics for a cluster.

### Bug Fixes

OCP V4.0.3 fixes the following issues:

1. Optimized the cgroup control flow for OceanBase V4.x clusters by adding a control flow switch.

2. Optimized the CPU monitoring calculation method to better comply with relevant standards.

3. Improved SSH compatibility by adding support for OpenSSH 8.8.

4. Fixed an occasional issue where the `active` count exceeded the `all` count for monitored sessions.

5. Fixed an issue where upgrading OCP from V4.0.1 to V4.0.2 might fail due to timeouts when historical data was present.

6. Fixed an issue where OCP continuously triggered alerts upon restart, falsely indicating a large number of hosts were offline.

7. Fixed an issue where changing an existing OCP deployment from non-multi-zone to multi-zone failed.

8. Fixed several other frontend display issues.

### Version Usage Restrictions

#### Hardware Requirements

OCP-Server can be installed on physical servers or run in Docker containers. It supports high-availability deployment across multiple nodes.

The minimum hardware requirements for an OCP-Server node are listed in the following table.

| Hardware | Requirements |
| ----- | ------------------------------------ |
| CPU | <li>x86_64, 8-core</li><li>ARM AArch64 architecture, 8-core</li> |
| Memory | Available Memory: 16 GB |
| NIC | 10 Gbit/s NIC |

OCP-Agent consumes minimal resources and has no specific hardware requirements for the installation node.

#### Operating System Requirements

The operating system requirements for installing the OCP server (including OCP-Agent) are listed in the following table.

| Server Type | Operating System | Supported Versions |
| ------------- | ------------ | ----------- |
| x86_64 | RHEL | 7.2 and later |
| x86_64 | CentOS | 7.2 and later |
| x86_64 | AliOS | 7.2 and later |
| x86_64 | openSUSE | 12 SP3 and later |
| ARM aarch64 | AliOS | 7.2 and later |
| ARM aarch64 | NeoKylin | 7.6 |
| ARM aarch64 | Huawei EulerOS | 2.0 SP8 |
| x86_64 | Debian | Debian GNU/Linux 11 (bullseye) |
| x86_64 | Ubuntu | Ubuntu 18.04.6 LTS |
