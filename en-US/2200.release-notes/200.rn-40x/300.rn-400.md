# OCP V4.0.0

<!--#RNDate#2022-10-08-->

OCP V4.0.0, as a companion product to OceanBase Database V4.0, has been deeply adapted and modified for OceanBase Database V4.0. It also introduces end-to-end tracing capabilities in a distributed environment, providing more comprehensive link tracing and analysis.

## Version information

* **Version:** V4.0.0

* **Previous version:** V3.3.4

* **Version release date:** October 8, 2022

* **Supported upgrade path:** For OCP V2.3.x and later, you can directly upgrade to this version. For OCP V2.3.0 and earlier, you must first upgrade to V2.3.x before upgrading to this version.

## Supported OceanBase Database versions

OCP V4.0.0 supports the following OceanBase Database versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

* OceanBase V4.x

## New features

OCP V4.0.0 introduces the full-link diagnostics feature, which has the following characteristics:

* A new framework is established for full-link tracing in a distributed environment.

* A standard data model of **transaction + SQL tracing** is provided.

* Full-link tracing from the driver to OBProxy and then to the OBServer node is supported.

## Feature adaptation and changes

* For OceanBase V4.0, OCP has adapted the views and management commands for the following features:

  * Cluster management;

  * Tenant and unit management;

  * Resource management;

  * Parameter management;

  * Database management;

  * Database user management;

  * Backup and restore;

  * SQL diagnostics;

  * SQL collection;

  * Monitoring collection;

  * Inspection;

* For OceanBase V4.0, OCP has made the following changes:

  * Tenant merge: When OceanBase is V4.0 or later, cluster-level management merge is changed to tenant-level management merge.

  * Unit management: When OceanBase is V4.0 or later, only tenant-level overall expansion and reduction are supported, and zone-level expansion and reduction are no longer supported.

  * Database management: The Primary Zone parameter for deleting a database is deleted. When OceanBase is V4.0 or later, setting Primary Zone and Locality at the table, database, and table group levels is no longer supported.

  * Replica view: When OceanBase is V4.0 or later, the concept of partition replicas is deleted.

  * Primary and standby databases: When OceanBase is V4.0 or later, the related features for primary and standby databases are temporarily not supported.

  * Tenant backup and tenant snapshot backup: When OceanBase is V4.0 or later, the tenant backup and tenant snapshot backup features are temporarily not supported.

  * Secondary backup: When OceanBase is V4.0 or later, the secondary backup feature is temporarily not supported.

  * Cluster upgrade: When OceanBase is V4.0 or later, the cluster version upgrade feature is temporarily not supported.

## Other information

* cgroup is enabled by default when you create a cluster.

* When you create a unit, you are prompted to confirm the max_iops parameter.

## Fixed issues

OCP V4.0.0 fixes the following issues:

1. Fixed the issue where the log backup scheduling timeout occasionally occurred when the SQL parsing threads filled the thread pool.

2. Fixed the issue where the database name was not displayed on the SQL details page when you entered the page from a non-SQL list page.

3. Fixed the issue where task accumulation and a sharp increase in memory occurred when the execution of ethtools was blocked.

4. Fixed the issue where some tasks failed when you reinstalled the Agent for a large number (more than 100) of servers in parallel.

5. Enhanced the security of password display in OSS backup logs.

6. Fixed the issue where an exception was reported when you created a standby cluster without a server in a zone in multi-cluster mode.

7. Fixed the issue where you could not query the QPS monitoring data before the upgrade after you upgraded from V3.1.x to V3.2.x.

8. Fixed the issue where inaccurate alerts were generated due to unreleased MemTables.

9. Fixed the issue where alerts were not triggered when you subscribed to OBProxy and other application alerts at the same time.

10. Fixed the issue where inaccurate and false alerts were generated for inode usage.

11. Fixed the issue where false alerts were generated for disk read-only status.

12. Fixed the issue where the TCP retransmission rate occasionally exceeded 100%.

13. Removed the invalid and server-based filtering feature from the SQL diagnostics page.

## Version usage limitations

### Hardware requirements

OCP-Server can be installed on a physical server or in a Docker container. OCP-Server supports multi-node high-availability deployment.

The minimum hardware requirements for an OCP-Server node are as follows.

| Hardware  | Requirement                                 |
|-----|------------------------------------|
| CPU | <li>X86_64, 8 cores</li><li>ARM aarch 64 architecture, 8 cores</li> |
| Memory  | 16 GB of available memory                         |
| NIC  | 10 GbE NIC                               |

OCP-Agent consumes very few resources and has no special hardware requirements.

### Operating system requirements

The following table lists the operating system requirements for installing the OCP service end (including OCP-Agent).

| Server type       | Operating system       | Supported version      |
|-------------|------------|-----------|
| x86_64      | RHEL       | 7.2 and later |
| x86_64      | CentOS     | 7.2 and later |
