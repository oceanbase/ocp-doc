# OCP V3.1.2

#RNDate#2021-07-13

OceanBase Cloud Platform (OCP) V3.1.2 introduces the Active Session History (ASH) report, a new feature in the Performance Diagnostics module. This feature provides historical information about active database sessions, aiding users in diagnosing tenant performance. The backup and restore feature now supports secondary backups. Additionally, the visual content for users with different permissions in OCP has been optimized to ensure a more intuitive experience. The system also includes the ability to take over OBProxy, ensuring the completeness of the takeover process. Other features have been optimized and enhanced, with the SQL diagnostics section now offering an export function for easier issue analysis.

## Version information

* **Version:** V3.1.2

* **Previous version:** V3.1.1

* **Version release date:** September 29, 2021

* **Supported upgrade path:** OCP V2.3.x and later versions can be directly upgraded to this version. For OCP versions earlier than V2.3.0, you must first upgrade to V2.3.x and then to this version.

## Supported OceanBase Database versions

OceanBase Cloud V3.1.2 supports the following OceanBase Database versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

## New features

* You can generate and download an active session history report.

  An active session history report is part of the tenant performance diagnostics feature. It samples data from views such as those related to SQL, sessions, wait events, and system statistics to provide historical active session information. For more information, see [Manage an active session history report](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380271).

* You can perform a secondary backup.

  A secondary backup allows you to archive backup files to other locations. The backup files include baseline data and archived logs. Performing a secondary backup reduces the storage pressure on backup files. For more information, see the following topics:
  * [What is a secondary backup?](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380164)

  * [Create a backup strategy](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380317)

* The visibility of different users with different privileges is optimized.

  The entry is hidden for users without the corresponding privileges to simplify the product path visible to users and reduce invalid clicks.

* You can take over an OBProxy cluster.

  This feature improves the takeover process. After you take over an OceanBase cluster, you can also take over the corresponding OBProxy cluster to OCP. For more information, see [Take over an OBProxy cluster](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380261).

* In multi-zone mode, OCP supports GUI-based management.

  In multi-zone mode, you can control the priority of accessing targets within the same zone when OceanBase Database, OCP, or OBProxy is deployed across IDCs or cities. Multi-zone mode reduces the latency of links and the bandwidth costs across IDCs or cities. For more information, see [Overview](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380186).

  OCP supports the following operations in multi-zone mode:
  * View details about each zone, including the IDCs in the zone and the corresponding OCP. For more information, see [View details about zones](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380368).

  * View or modify multi-zone parameters. For more information, see [Manage multi-zone parameters](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380369).

## Feature enhancements

* The SQL diagnostics feature is optimized. You can export TopSQL, suspicious SQL, and SlowSQL.

* The cluster and tenant performance monitoring feature is optimized. You can disable the collection of cluster and tenant performance metrics.

* The memory usage of monitoring data collection is optimized. This ensures the performance of OCP when the number of hosts managed by OCP increases.

## Fixed issues

OceanBase Cloud V3.1.2 fixes the following issues:

* The statistics of remote plans and distributed plans are inaccurate in the SQL diagnostics feature.

* After the ob_host_log_disk_percent_over_threshold alarm is reported, it automatically recovers without continuous reporting if the issue is not resolved.

* The downloaded logs of an OBProxy cluster cannot be decompressed when you download them through OCP.

* After OCP is upgraded, the creation time of a tenant is reset to the time when OCP is upgraded.

* **TopSQL** contains data without SQL text.

* When you modify OBProxy parameters through OCP, some parameters cannot be modified or cannot be modified to values in a specific range.

* When you modify the recyclebin parameter of a tenant to ON through OCP, the modification does not take effect.

* For a partitioned table with two datetime fields, if only one field is used for partitioning, the **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** page's **<UI-TERM key="ocp-v2.Inspection.Item.ConfigRule.Inspection">Inspection</UI-TERM>** feature cannot inspect the table.

* After a primary-standby disaster recovery switch of an OceanBase cluster, the primary-standby relationship no longer exists, but the cluster is still displayed as a primary-standby cluster in the cluster list.

## Limitations

### Hardware requirements

OCP-Server can be installed on a physical server or in a Docker container. OCP-Server supports multi-node high-availability deployment.

The minimum hardware requirements for OCP-Server nodes are as follows:

| Hardware  |                 Requirement                 |
|-----|------------------------------------|
| CPU | <li>X86_64, 8 cores</li><li>ARM aarch 64 architecture, 8 cores</li> |
| Memory  | 16 GB available memory                         |
| NIC  | 10 Gbps NIC                               |

OCP-Agent consumes very little resources and has no special hardware requirements.

### Operating system requirements

The following table lists the operating system requirements for installing OCP-Server (including OCP-Agent).

|    Server type    |    Operating system    |   Supported version    |
|-------------|------------|-----------|
| x86_64      | RHEL       | 7.2 and later |
| x86_64      | CentOS     | 7.2 and later |
| x86_64      | AliOS      | 7.2 and later |

| ARM aarch64 | AliOS      | 7.2 and later |

| ARM aarch64 | Huawei EulerOS | 2.0 SP8   |
