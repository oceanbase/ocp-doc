# OCP V3.1.2

<!--#RNDate#2021-07-13-->

OceanBase Cloud Platform (OCP) V3.1.2 introduces the Active Session History report, a new feature in the Performance Diagnostics module. It provides historical active session information for the database to assist users in tenant performance diagnostics. This version also supports secondary backup in the Backup and Recovery module. Additionally, it optimizes the visual content for users with different permissions in OCP, ensuring what you see is what you get. A new feature allows for the takeover of OBProxy, ensuring the integrity of the takeover link. Furthermore, other features have been optimized and strengthened. The SQL diagnostics section now includes an export function, making it easier for you to download and analyze issues.

## Version information

* **Version:** V3.1.2

* **Previous version:** V3.1.1

* **Release date:** September 29, 2021

* **Supported upgrade path:** You can directly upgrade from OCP V2.3.x and later versions to this version. For versions earlier than OCP V2.3.0, you must first upgrade to V2.3.x and then to this version.

## Supported OceanBase Database versions

OceanBase Cloud Platform V3.1.2 supports the following versions of OceanBase Database:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

## New features

* Supports generating and downloading the Active Session History report.

  As part of the tenant performance diagnostics feature, the Active Session History report samples data from related views such as SQL, sessions, wait events, and system statistics to help users view historical active session information for the database. For more information, see [Manage Active Session History reports](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380271).

* Backup and Recovery supports secondary backup.

  Secondary backup provides the ability to archive backup files to other locations, including baseline data and archived logs. Supporting secondary backup reduces the storage pressure on backup files. If you need to:
  * Learn about secondary backup, see **Secondary backup** in [Overview](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380164).

  * Use secondary backup, see [Create a backup strategy](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380317).

* Optimized the visibility for users with different permissions in OCP.

  Blocked the entry for users without the permission, simplified the product paths visible to users, and reduced unnecessary clicks.

* Supports the takeover of OBProxy.

  This feature improves the takeover process to some extent. After taking over an OceanBase cluster, you can also take over its corresponding OBProxy cluster in OCP. For more information about how to take over OBProxy, see [Take over OBProxy](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380261).

* For multi-zone mode, OCP supports GUI-based management.

  Multi-zone mode is designed for OceanBase, OCP, or OBProxy deployments across data centers or cities, allowing you to control priority access to targets within the current zone. It effectively reduces latency and lowers cross-data-center or cross-city bandwidth costs. For more information about multi-zones, see [Multi-zone overview](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380186).

  OCP management of multi-zones supports:
  * Viewing detailed information about each zone, including the IDCs it contains and the OCP instance corresponding to each zone. For more information, see [View multi-zones](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380368).

  * Viewing or modifying multi-zone parameters. For more information, see [Manage multi-zone parameters](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380369).

## Feature enhancements

* The SQL diagnostics feature has been optimized to include the ability to export TopSQL, suspicious SQL, and SlowSQL.

* The performance monitoring features for clusters and tenants have been optimized to include a prompt when the collection of performance metrics for a cluster or tenant is disabled.

* The memory usage for monitoring collection has been optimized to ensure OCP maintains performance as it manages more hosts.

## Bug fixes

OceanBase Cloud Platform V3.1.2 fixes the following issues:

* In the SQL diagnostics feature, statistics for remote plans and distributed plans were inaccurate.

* The ob_host_log_disk_percent_over_threshold alert would automatically recover after being reported for a period without the issue being resolved, preventing continuous alerts.

* When downloading logs containing the OBProxy type through OCP, the downloaded logs could not be decompressed.

* After upgrading OCP, a tenant's creation time was reset to the time of the OCP upgrade.

* Some entries in **TopSQL** lacked SQL text.

* When modifying OBProxy parameters via OCP, some parameters could not be modified or could not be set to certain value ranges.

* Setting the tenant parameter recyclebin to ON via OCP did not take effect.

* For a partitioned table with two DATETIME fields, if only one field was used for partitioning, this table could not be detected during an inspection in **System Management** > **Inspection**.

* After a primary/standby disaster recovery switchover in an OceanBase cluster, the primary/standby relationship no longer existed, but it was still displayed as such in the cluster list.

## Known issues

| Number | Known issues | Solution |

| 1 | An error "Exception in parsing backup file" occurred during backup and restore. | Set the system parameter ocp.backup_restore-time-pre-check.enabled to false. |
| 2 | After a rollback is performed following a failure to create an OceanBase standby cluster across OCP instances, the rollback succeeds, but the information about the failed-to-create OceanBase standby cluster still appears on the **Clusters** page of OCP. | This does not affect usage and is not being circumvented for now. |
| 3 | Filtering by inspection object on the **Inspection Script** tab of the **System Management \> Inspection** page does not take effect. | Currently, the only inspection object is the cluster. No filtering or avoidance is required for inspection objects. |
| 4 | Physical backup is displayed as completed in the **Data Backup Scheduling History**, but the **Status** on the cluster's **Backup and Restore** page still shows **Waiting for Backup Scheduling**. | This issue only occurs on the first physical backup. Subsequent backups are scheduled normally and do not affect business operations temporarily, so it may not be necessary to avoid it. |
| 5 | On the OBServer node side, the final directory is not created for the storage path of the secondary backup of the OSS type. However, the **Test** step in the secondary backup storage configuration of OCP tests the full path. | The secondary backup storage path for this OCP release is temporarily set to not support the OSS type. |
| 6 | A major compaction is initiated for OceanBase Database V1.4.7x in OCP, but the **Frozen Version** and **Broadcast Version** displayed on the **Compaction Management** page are inconsistent. | The current version is not compatible with OceanBase Database V1.4.7x. Compatibility will be provided in later versions. |
| 7 | During a cross-OCP primary/standby database upgrade, the parent task waits indefinitely until it times out and fails after all subtasks complete successfully. | Retry in the parent task. |
| 8 | The OceanBase primary cluster in OCP is being created. Taking over an OceanBase primary cluster with the same name was not detected during the pre-check. | Before taking over, manually check whether an OceanBase primary cluster with the same name is being created. |

## Version usage restrictions

### Hardware requirements

OCP-Server can be installed on physical servers or run in Docker containers. OCP-Server supports high-availability deployment with multiple nodes.

The following table lists the minimum hardware requirements for an OCP-Server node.

| Hardware | Requirements |
| ----- | ------------------------------------ |
| CPU | <li>x86_64, 8-core</li><li>ARM AArch64 architecture, 8-core</li> |
| Memory | Available Memory: 16 GB |
| NIC | 10 Gbit/s NIC |

OCP-Agent consumes very few resources and has no specific hardware requirements for the installation node.

### Operating system requirements

The following table lists the operating system requirements for installing the OCP server (including OCP-Agent).

| Server Type | Operating System | Supported Versions |
| ------------- | ------------ | ----------- |
| x86_64 | RHEL | 7.2 and later |
| x86_64 | CentOS | 7.2 and later |
| x86_64 | AliOS | 7.2 and later |

| ARM aarch64 | AliOS | 7.2 and later |
| ARM aarch64 | NeoKylin | 7.6 |
