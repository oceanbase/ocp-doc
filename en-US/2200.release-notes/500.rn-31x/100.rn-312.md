# OCP V3.1.2

<!--#RNDate#2021-07-13-->

OceanBase Cloud Platform (OCP) V3.1.2 introduces the Active Session History (ASH) report, a new feature in the Performance Diagnostics module. This feature provides historical active session information for databases, aiding users in tenant performance diagnostics. In this version, backup and restore support secondary backups. The visualization content for users with different permissions in OCP has been optimized to ensure a more intuitive experience. Additionally, the ability to take over OBProxy has been added, ensuring the completeness of the takeover process. Other features have also been optimized and enhanced, with the addition of an export function in the SQL diagnostics section for convenient problem analysis.

## Version information

* **Version:** V3.1.2

* **Previous version:** V3.1.1

* **Version release date:** September 29, 2021

* **Supported upgrade path:** You can directly upgrade OCP V2.3.x and later to this version. To upgrade OCP V2.3.0 or earlier to this version, you must first upgrade it to OCP V2.3.x.

OceanBase Cloud V3.1.2 supports the following OceanBase Database versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

## New features

* You can generate and download an active session history report.

  An active session history report, as part of the tenant performance diagnostics feature, samples data from views such as SQL, session, wait event, and system statistics to help you view the historical active session information of the database. For more information, see [Manage an active session history report](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380271).

* You can perform secondary backup.

  Secondary backup allows you to archive backup files to other locations. The backup files include baseline data and archived logs. By supporting secondary backup, the storage pressure of backup files is reduced. For more information, see the following topics:
  * [Overview of backup and restore](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380164) for more information about **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.SecondaryBackup">Second Backup</UI-TERM>**.

  * [Create a backup strategy](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380317).

* The view of different users with different permissions is optimized.

  The entry is hidden for users without the corresponding permissions. The product path visible to users is simplified, and invalid clicks are reduced.

* You can take over an OBProxy cluster.

  This feature improves the takeover process. After you take over an OceanBase cluster, you can also take over the OBProxy cluster corresponding to the OceanBase cluster to OCP. For more information, see [Take over an OBProxy cluster](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380261).

* In multi-zone mode, OCP supports GUI-based management.

  In multi-zone mode, OCP allows you to control the priority of accessing targets within the same zone when OceanBase Database, OCP, or OBProxy is deployed across IDCs or cities. Multi-zone mode reduces the latency of links and the bandwidth cost across IDCs or cities. For more information, see [Overview of multi-zone mode](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380186).

  OCP supports the following operations in multi-zone mode:
  * View the details of each zone, including the IDCs in each zone and the OCP corresponding to each zone. For more information, see [View multi-zone information](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380368).

  * View or modify multi-zone parameters. For more information, see [Manage multi-zone parameters](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380369).

## Feature enhancements

* The SQL diagnostics feature is optimized. You can export TopSQL, suspicious SQL, and SlowSQL.

* The cluster and tenant performance monitoring features are optimized. You can disable the collection of cluster and tenant performance metrics.

* The memory usage of monitoring data collection is optimized. The performance of OCP is guaranteed even when the number of hosts managed by OCP increases.

## Fixed issues

OceanBase Cloud V3.1.2 fixes the following issues:

* In the SQL diagnostics feature, the statistics of remote and distributed plans are inaccurate.

* After the ob_host_log_disk_percent_over_threshold alert is reported for a period of time, it automatically recovers without being continuously reported when the issue is not resolved.

* When you download logs of the OBProxy type through OCP, the downloaded logs cannot be decompressed.

* After OCP is upgraded, the creation time of a tenant is reset to the upgrade time.

* **TopSQL** contains data without SQL text.

* When you modify OBProxy parameters through OCP, some parameters cannot be modified or cannot be modified to values in certain ranges.

* When you modify the recyclebin parameter of a tenant through OCP to ON, the modification does not take effect.

* For a partitioned table with two datetime fields, only one of the fields is partitioned. The **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** page's **<UI-TERM key="ocp-v2.Inspection.Item.ConfigRule.Inspection">Inspection</UI-TERM>** feature cannot inspect this table.

* After the primary-standby disaster recovery of an OceanBase cluster is switched, the primary-standby relationship no longer exists. However, the cluster list still displays the primary-standby relationship.

## Limitations

### Hardware requirements

OCP-Server can be installed on a physical server or in a Docker container. OCP-Server supports multi-node high availability deployment.

The minimum hardware requirements for OCP-Server nodes are as follows.

| Hardware  |                 Requirement                 |
|-----|------------------------------------|
| CPU | <li>X86_64, 8 cores</li><li>ARM aarch 64 architecture, 8 cores</li> |
| Memory  | 16 GB of available memory                         |
| NIC  | 10 GbE                               |

OCP-Agent consumes very few resources and has no special requirements for the hardware resources of the installation node.

### Operating system requirements

The following table lists the operating system requirements for installing OCP-Server (including OCP-Agent).

|    Server type    |    Operating system    |   Supported versions    |
|-------------|------------|-----------|
| x86_64      | RHEL       | 7.2 and later |
| x86_64      | CentOS     | 7.2 and later |
| x86_64      | AliOS      | 7.2 and later |
