## V4.3.6 BP1

### Version information

* **Version number:** V4.3.6 BP1

* **Previous version:** V4.3.6

### New features

* OceanBase Database Enterprise Edition (standalone edition) supports features such as viewing and importing licenses, as well as prompts and alerts for license expiration and renewal.
* OceanBase Database Enterprise Edition (standalone edition) can be upgraded to a distributed cluster.
* OceanBase Database Enterprise Edition (standalone edition) can be upgraded to a higher database version.

### Product optimization

* If the host operating system kernel version is lower than 5.1.0, the cluster Cgroup configuration is disabled by default.
* If the OBProxy version is lower than V4.3.1, it cannot be hot-upgraded to V4.3.4.
* If no specific alert target is specified, automatic resolution can be disabled to prevent the alert from automatically resolving.
* Restricts O&M operations in standalone scenarios, such as not supporting restarting OBServer or stopping zones.

## V4.3.6

OceanBase Cloud V4.3.6 is released! This update focuses on **Intelligent Operations**, **Security Enhancements**, and **Basic Capability Boosts**, aiming to comprehensively empower enterprise database operations and maintenance.

* **Intelligent Operations Assistant**: OceanBase AI Assistant is newly introduced, integrating large language models with native database capabilities to provide intelligent Q&A services across the OceanBase ecosystem. This enables efficient and accurate resolution of operational issues.
* **Enhanced Security Features**: New features include OceanBase Transparent Data Encryption (TDE) and end-to-end SSL encryption, providing full protection from data storage to transmission, thereby strengthening the security of the database.
* **Network Architecture Adaptation**: Supports IPv6 for full-scenario deployment, enabling full lifecycle management of OceanBase clusters with IPv6 addresses, meeting compliance requirements and supporting network evolution.
* **30+ Feature Optimizations**: Core modules such as performance monitoring, primary/standby management, backup and restore, alert center, and inspection services are deeply optimized, significantly enhancing operational convenience and management efficiency, helping users easily manage database operations.

### New features

#### Basic O&M

* **Cluster management**: Supports Internet Protocol version 6 (IPv6) for comprehensive control of IPv6 addresses within the cluster. Seamlessly adapts to IPv6 network environments to meet strict cybersecurity regulatory requirements in sectors such as government and finance.
  * Supported OceanBase versions: [V4.2.5 BP3 Hotfix3, V4.3.0) and [4.3.5 BP2 Hotfix1, +∞).
  * Supported OBClient versions: [V2.2.9, +∞).
  * Supported OBProxy versions: [V4.3.4, +∞).
* **Cluster management**: Supports Transparent Data Encryption (TDE) for secure data storage. Prevents attackers from accessing sensitive information directly from the storage layer. Supported OceanBase versions: [V4.0.0, +∞).
* **Cluster management**: Supports TCP and RPC-based SSL encryption to prevent data tampering during communication, enhancing system security. Supported OceanBase versions: [V4.0.0, +∞).
* **OBProxy**: Supports TCP and RPC-based SSL encryption to prevent data tampering during communication, enhancing system security. Supported OBProxy versions: [V2.0.0, +∞).
* **Tenant management**: Supports batch locking and unlocking of regular users, improving user O&M efficiency in scenarios such as data migration and import/export.
* **Tenant management**: Supports creating a standby tenant by copying the backup set of the primary tenant, enhancing disaster recovery management.
* **Host management**: Supports management of regions, IDCs, and host types, but currently does not support deleting objects associated with other hosts.

#### Monitoring and alerts

* Supports displaying the maximum (max), average (avg), and current values of monitoring metrics within the specified monitoring time range.
* Supports adding monitoring items such as Commit and Rollback to QPS and response time. Supported OceanBase versions: [V4.2.5 BP3, V4.3.0) and [V4.3.5 BP2, +∞).
* Supports hardware monitoring by querying `/var/log/messages`, enabling users to promptly detect hardware-related issues.

#### Inspection service

Supports inspection of clock source settings for OBServer nodes within the same cluster, preventing abnormal major compactions caused by inconsistent clock source settings.

#### Binlog management

* Supports setting the number of instance replicas when enabling the Binlog service. The Binlog service automatically distributes instance replicas based on the number of Binlog servers in the cluster.
* Supports adding new instance replicas for Binlog instances. A single business tenant can have a maximum of five instance replicas.
* Supports managing standby Binlog instances, including starting, stopping, throttling, restarting, deleting, and switchover operations.
* Supports deleting the primary Binlog instance.
* Prevents accidental operations on the MetaDB of the Binlog service, avoiding service disruptions.

#### Backup and restore

* Supports setting backup attributes for zones, regions, and IDCs, reducing cross-region network traffic in multi-region or multi-IDC deployment scenarios and improving backup speed.
* Supports setting zone priority to Random when restoring tenants.

#### Platform features

* **AI Assistant**: Provides intelligent Q&A services for OceanBase and its related products based on Large Language Models (LLMs), PowerRAG, and an integrated OceanBase knowledge base.
* **O&M Management**: Supports creating and downloading resource information reports for OceanBase clusters, tenants, OBProxy clusters, hosts, Binlog services, and arbitration services in the Report Center. Supports modifying the report retention period using the `ocp.report.center.report.retention.days` parameter.
* **Parameter Templates**: Supports importing and exporting parameter templates in YAML format for OceanBase clusters, tenants, OBProxy clusters, and Binlog services.
* **Cluster Management** > **O&M Configuration**: Adds five new collection metric switches to control whether to collect information such as wait event, cache hit rate, and partition count.

### Feature enhancements

#### Cluster management

* Only clusters in the Stopped, Unavailable, Deprecated, or Migrated state can be directly deleted.
* In scenarios where units are to be migrated, you can precheck the CPU, memory, log disk, and data disk resources to avoid migration issues due to insufficient resources.
* You can enable or disable Cgroups without restarting the cluster. Supported OceanBase versions: [V4.2.5 BP2, V4.3.0) and [V4.3.5, +∞).

#### Tenant management

* The major compaction management feature allows you to view the MEMStore usage rate, MEMStore usage size, CPU usage rate, and memory usage rate of each unit, helping you observe the resource consumption during major compactions.
* The statistics management feature is optimized. The data statistics logic for **Top 10 Changed Tables** is updated. Supported OceanBase versions: [V4.2.5 BP2, V4.3.0) and [V4.3.5, +∞).
* Only a locked primary tenant can be directly deleted. This prevents accidental deletion.
* When you create a user, you can group permissions by type, such as general and administrator, to facilitate the creation of database users.
* You can batch set role permissions in an Oracle tenant.

#### OBProxy management

Only a primary cluster in the Stopped, Unavailable, or Empty state can be directly deleted.

#### Other enhancements

* **Platform feature**: You can set the password validity period and password reuse limit for a user by using the system parameters `ocp.iam.password.validity.period.days` and `ocp.iam.password.reuse.times`, respectively. This ensures user password security.
* **Platform feature**: You can customize the installation directory of ocp_agent by using the system parameter `ocp.agent.home.path.prefix` on Debian 11 and later operating systems.
* **<UI-TERM key="ocp-v2.src.hook.useMenu.AlarmCenter">Alert Center</UI-TERM>**: The details of the monitoring metrics at the time of alert recovery are displayed.
* **<UI-TERM key="ocp-v2.page.Alarm.Alarm">Alert Center</UI-TERM>**: You can click an alert rule on the alert details page to jump to a new page.

### Key features

#### AI assistant (Experimental)

OceanBase AI assistant leverages large language models (LLMs) and PowerRAG, while integrating OceanBase's built-in knowledge base and native vector and full-text indexing capabilities, to create a core intelligent Q&A engine. Based on PowerRAG's multi-round retrieval mechanism, LLMs can accurately access technical documents, best practices, and failure cases from the knowledge base, providing systematic and specialized solutions for key database operations such as system configuration optimization, failure diagnostics, and performance bottleneck analysis.

For large model configuration, OCP allows users to flexibly integrate third-party large models such as Tongyi Qianwen, JiuLong, and DeepSeek, or deploy a self-built large model through the **System Management** > **External Integration** > **AI Models** module. Users can configure LLMs, embedding models, and optional reranking models to quickly activate AI assistant capabilities. Additionally, OCP supports importing enterprise-specific best practices and standard operating procedures (SOPs) to continuously expand the knowledge base's industry adaptability.

#### Secure Sockets Layer (SSL) encryption

In the era of accelerated digital transformation, data transmission security has become a core requirement. OBProxy and OceanBase support SSL encryption, establishing an encrypted communication channel at the transport layer to provide end-to-end protection for network connections, effectively mitigating risks of data theft and tampering, ensuring the confidentiality and integrity of communication processes, and reinforcing the security of data transmission from the ground up.

As the central hub for full-chain operations and maintenance, OCP provides comprehensive management capabilities for the entire certificate lifecycle:

* **Convenient certificate operations**: Supports one-click certificate upload and deletion, simplifying certificate management.
* **Deep security configuration**: Integrates SSL encryption configuration for OBProxy and OceanBase, supporting custom certificate update strategies to ensure the continuous validity of encrypted connections.
* **Multi-format certificate support**: Provides standard format certificates such as p7b/PEM/JKS for business application access, meeting diverse technical stack security requirements.

Through OCP's unified management, users can easily implement secure communication across business applications > OBProxy > OBServer nodes, as well as secure RPC communication between OBServer nodes, ensuring secure data transmission in key areas such as business access, proxy forwarding, and node interactions, building a comprehensive security barrier for stable database operation.

<h4>Notice</h4>

## Limitations on version usage

### Hardware requirements

OCP-Server can be installed on a physical server or a Docker container. OCP-Server supports multi-node high-availability deployment.

The following table describes the minimum hardware requirements for an OCP-Server node.

| Hardware | Requirement |
|-------|------------------------------------|
| CPU  | <li>x86_64 architecture, 8-core processor</li><li>ARM aarch 64 architecture, 8-core processor</li> |
| Memory | 16 GiB available |
| NIC | 10 Gbit/s NIC |

OCP-Agent itself consumes few resources and does not have special requirements on the hardware resources of the installation node.
