# OCP V4.3.6

## V4.3.6 BP1

### Version information

* **Version number:** V4.3.6 BP1

* **Previous version:** V4.3.6

* **Version release date:** August 11, 2025

### New features

* OceanBase Enterprise Edition (standalone) supports license viewing, import, and alerts for license expiration.
* OceanBase Enterprise Edition (standalone) can be upgraded to a distributed cluster.
* OceanBase Enterprise Edition (standalone) can be upgraded to a higher database version.

### Product optimization

* If the host operating system kernel version is lower than 5.1.0, cluster Cgroup configuration is disabled by default.
* If the OBProxy version is lower than V4.3.1, it cannot be hot-upgraded to V4.3.4.
* If an alert does not have a specific alert target, automatic resolution can be disabled to prevent the alert from automatically resolving.
* Restrict O&M operations in standalone mode, such as not supporting restarting OBServer or stopping zones.

## V4.3.6

OCP V4.3.6 is released! This update focuses on **intelligent features**, **security enhancements**, and **core capability upgrades**, aiming to comprehensively empower enterprise database operations and maintenance.

* **Intelligent O&M Assistant**: OceanBase AI Assistant is newly introduced, integrating large language models with native database capabilities to provide intelligent Q&A services across the OceanBase ecosystem. This enables efficient and accurate resolution of operational issues.
* **Enhanced Security Features**: New features include OceanBase Transparent Data Encryption (TDE) and end-to-end SSL encryption, ensuring comprehensive protection from data storage to transmission, strengthening database security.
* **IPv6 Support**: Full IPv6 deployment is supported, enabling full lifecycle management of OceanBase clusters with IPv6 addresses, meeting compliance requirements and supporting network evolution.
* **30+ Feature Optimizations**: Core modules such as performance monitoring, primary/standby management, backup and restore, alert center, and inspection services are deeply optimized, significantly improving operational convenience and management efficiency, helping users easily manage database operations.

### New features

#### Basic O&M

* **Cluster management**: Supports Internet Protocol version 6 (IPv6), allowing you to manage IPv6 addresses within the cluster. Seamless adaptation to IPv6 networks meets the strict cybersecurity regulatory requirements of industries such as government and finance.
  * OceanBase Database supported by this feature is in the range of [V4.2.5 BP3 Hotfix3, V4.3.0) or [4.3.5 BP2 Hotfix1, +∞).
  * OBClient supported by this feature is in the range of [V2.2.9, +∞).
  * OBProxy supported by this feature is in the range of [V4.3.4, +∞).
* **Cluster management**: Supports Transparent Data Encryption (TDE) for data encryption. This prevents attackers from bypassing the database and reading sensitive information from the storage layer, ensuring data security. OceanBase Database supported by this feature is in the range of [V4.0.0, +∞).
* **Cluster management**: Supports TCP and RPC-based SSL encryption. This prevents communication data from being tampered with during transmission, reducing security risks and enhancing system security. OceanBase Database supported by this feature is in the range of [V4.0.0, +∞).
* **OBProxy**: Supports TCP and RPC-based SSL encryption. This prevents communication data from being tampered with during transmission, reducing security risks and enhancing system security. OBProxy supported by this feature is in the range of [V2.0.0, +∞).
* **Tenant management**: Supports batch locking and unlocking of regular users, improving user O&M efficiency in scenarios such as data migration and data import and export.
* **Tenant management**: Supports creating a backup tenant by copying the backup set of the primary tenant, enhancing disaster recovery management solutions.
* **Host management**: Supports management of regions, IDCs, and host types, but does not support deleting objects that have associated hosts.

#### Monitoring and alerts

* Supports displaying the maximum value (max), average value (avg), and current value (current) of monitoring metrics within the monitoring time range.
* Supports adding monitoring items such as Commit and Rollback to QPS and response time. OceanBase Database supported by this feature is in the range of [V4.2.5 BP3, V4.3.0) or [V4.3.5 BP2, +∞).
* Supports monitoring hardware by querying `/var/log/messages`, enabling users to promptly detect hardware-related issues.

#### Inspection service

Supports inspecting the clock source settings of OBServer nodes within the same cluster, preventing abnormal major compactions caused by inconsistent clock source settings.

#### Binlog management

* Supports setting the number of instance replicas when enabling the Binlog service. The Binlog service automatically distributes instance replicas based on the number of Binlog servers in the cluster.
* Binlog instances support adding instance replicas. A single business tenant can have a maximum of five instance replicas.
* Supports managing backup Binlog instances, including starting, stopping, throttling, restarting, deleting, and switchover operations.
* Supports deleting the primary Binlog instance.
* Prevents accidental operations on the MetaDB of the Binlog service by displaying a prompt, avoiding service disruptions.

#### Backup and restore

* Supports setting backup attributes such as Zone, Region, and IDC to reduce cross-region network traffic in multi-region and multi-IDC deployment scenarios, improving backup speed.
* Supports setting the Zone priority to Random when restoring a tenant.

#### Platform features

* **AI assistant**: Provides intelligent Q&A services for OceanBase and its related products based on LLM + PowerRAG + built-in OceanBase knowledge base.
* **O&M management**: Supports creating and downloading resource information reports for OceanBase clusters, tenants, OBProxy clusters, hosts, Binlog services, and arbitration services in the Report Center. Supports modifying the report retention period through the `ocp.report.center.report.retention.days` parameter.
* **Parameter templates**: Supports importing and exporting YAML-formatted parameter templates for OceanBase clusters, tenants, OBProxy clusters, and Binlog services.
* **Cluster management** > **O&M configuration**: Adds five collection metric switches to control whether to collect information such as Waitevent, Cache hit rate, and number of partitions.

### Feature enhancements

#### Cluster management

* Only clusters in the Stopped, Unavailable, Deprecated, or Migrated states can be directly deleted.
* In the scenario of unit migration, you can precheck the CPU, memory, log disk, and data disk resources to avoid migration errors caused by insufficient resources.
* You can enable or disable cgroups without restarting the cluster. The supported OceanBase versions are [V4.2.5 BP2, V4.3.0) and [V4.3.5, +∞).

#### Tenant management

* The major compaction management feature allows you to view the MEMStore usage rate, MEMStore usage size, CPU usage rate, and memory usage rate on a unit-by-unit basis, helping you observe resource consumption during major compactions.
* The statistics management feature is optimized. The data statistics logic for **Top 10 Tables Changed** is updated. The supported OceanBase versions are [V4.2.5 BP2, V4.3.0) and [V4.3.5, +∞).
* You can delete only a locked primary tenant. This prevents accidental deletion.
* When you create a user, you can group permissions by type, such as general and admin, to help you quickly create a database user.
* You can batch set role permissions in an Oracle tenant.

#### OBProxy management

You can directly delete a primary cluster only if it is in the Stopped, Unavailable, or Empty state to avoid accidental deletion.

#### Others

* **Platform features**: You can set the password validity period and password reuse count for a user by using the system parameters `ocp.iam.password.validity.period.days` and `ocp.iam.password.reuse.times`, respectively. This ensures user password security.
* **Platform features**: You can specify the installation directory of ocp_agent by using the system parameter `ocp.agent.home.path.prefix` in Debian 11 and later.
* **<UI-TERM key="ocp-v2.src.hook.useMenu.AlarmCenter">Alert Center</UI-TERM>**: The monitoring metrics data at the time of alert recovery is displayed in the details of alert recovery.
* **<UI-TERM key="ocp-v2.src.hook.useMenu.AlarmCenter">Alert Center</UI-TERM>**: You can click an alert rule on the alert details page to jump to a new page.

### Feature highlights

#### AI assistant (Experimental feature)

OceanBase AI assistant leverages large language models (LLMs) and PowerRAG, while integrating OceanBase's built-in knowledge base and native vector and full-text indexing capabilities, to create a core intelligent Q&A engine. With PowerRAG's multi-round retrieval mechanism, LLMs can precisely access technical documents, best practices, and failure cases from the knowledge base, providing systematic and professional solutions for database operations and maintenance scenarios such as system configuration optimization, failure diagnosis and repair, and performance bottleneck analysis.

In terms of large model configuration, OCP allows users to flexibly integrate third-party large model services such as Tongyi Qianwen, Doupai, and DeepSeek, or deploy a self-built large model, through the **System Management** > **External Integration** > **AI Model** module. Users can configure LLMs, embedded models, and optional reranking models to quickly activate AI assistant capabilities. Additionally, OCP supports importing enterprise-specific best practices and standard operating procedures (SOPs) to enhance the adaptability of the knowledge base across industries.

#### Secure Sockets Layer (SSL) encryption

As data transmission security becomes a top priority in the era of digital transformation, OceanBase Proxy and OceanBase Database offer SSL encryption to establish secure communication channels at the transport layer. This provides end-to-end protection for network connections, effectively mitigating risks of data interception and tampering, ensuring the confidentiality and integrity of communication processes. This forms a solid foundation for secure data transmission.

As the central hub for full-chain operations and maintenance, OCP (OceanBase Cloud Platform) provides comprehensive management capabilities for the entire lifecycle of certificates:

* **Convenient certificate operations**: Supports one-click upload and deletion of certificates, streamlining certificate management.
* **Deep security configuration**: Integrates SSL encryption configuration for OceanBase Proxy and OceanBase Database, allowing users to customize certificate update strategies to ensure the continuous validity of encrypted connections.
* **Support for multiple certificate formats**: Provides standard format certificates such as p7b/PEM/JKS for business applications, meeting diverse technical stack security access requirements.

Through OCP's unified management, users can easily implement secure communication across business applications > OceanBase Proxy > OBServer nodes, as well as secure RPC communication between OBServer nodes. This ensures secure data transmission at critical stages such as business access, proxy forwarding, and node interactions, building a comprehensive security barrier for stable database operation.

### Hardware requirements

OCP-Server can be installed on a physical server or in a Docker container. OCP-Server supports multi-node high availability deployment.

The following table describes the minimum hardware requirements for an OCP-Server node.

| Hardware | Requirement |
|-------|------------------------------------|
| CPU  | <li>x86_64 architecture, 8-core processor</li><li>ARM aarch 64 architecture, 8-core processor</li> |
| Memory | 16 GiB of available memory |
| NIC | 10 Gbit/s NIC |

OCP-Agent itself consumes few resources and does not impose special requirements on the hardware resources of the installation node.
