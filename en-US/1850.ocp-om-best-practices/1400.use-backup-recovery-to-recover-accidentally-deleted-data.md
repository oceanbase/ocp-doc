# Restore lost data by using backup and restore

Backup and restore is a core feature to ensure the high availability of OceanBase Database. It guarantees data security in accidents such as storage media damage and misoperations. In such cases, you can easily restore the lost data.

## Scenarios

* Scenario 1: The source OceanBase cluster managed by OceanBase Cloud Platform (OCP) is online.
* Scenario 2: The source OceanBase cluster is deleted or offline.
* Scenario 3: The destination OceanBase cluster is not managed by OCP.

## Prerequisites

* To initiate a restore task on the **<UI-TERM key="ocp-v2.Backup.BackupStrategy.Edit.BackupAndRestoration">Backup & Recovery</UI-TERM>** page, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** or **Tenant Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **Restore** menu of **<UI-TERM key="ocp-v2.src.util.menu.BackupAndRestoration">Backup & Recovery</UI-TERM>**

* To initiate a restore task on the **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.BackupAndRestoration">Backup & Recovery</UI-TERM>** page of a cluster, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.Backup.BackupStrategy.New.BackupAndRestoration">Backup & Recovery</UI-TERM>** menu of **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>**

* To initiate a restore task on the **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.BackupAndRestoration">Backup & Recovery</UI-TERM>** page of a tenant, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** or **Tenant Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.Detail.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.Backup.BackupStrategy.Edit.BackupAndRestoration">Backup & Recovery</UI-TERM>** menu of **<UI-TERM key="ocp-v2.Detail.Component.DeleteTenantModal.Tenant">Tenants</UI-TERM>**

* An immediate or periodic backup task has been performed to back up data of the source OceanBase cluster.
* The destination OceanBase cluster can access the backup data in the source OceanBase cluster.
* The destination OceanBase cluster has sufficient resources for restoring a standby tenant.

## Considerations

Before the restore, confirm the version of the cluster to which backup data is to be restored. At present, you can restore backup data from one OceanBase cluster to another if the version of the destination cluster is the same as or later than that of the source cluster. You cannot restore backup data from one cluster to another if they have the same major versions, but the minor version of the destination cluster is earlier than that of the source cluster.

For example, you can restore backup data from a cluster of OceanBase Database V4.2.0 only to a cluster of OceanBase Database V4.2.0 or later. In addition, you cannot restore backup data from a cluster of a version earlier than OceanBase Database V4.0 to a cluster of OceanBase Database V4.0 or later.

## Procedure

* **Scenario 1**: Initiate a restore task on the backup and restore page of the global, cluster, or tenant view. For more information, see [Initiate a restore task](../1100.backup-and-restoration-functions/700.initiate-a-recovery-task.md).

* **Scenario 2**: Initiate a restore task on the backup and restore page of the global view. For more information, see [Initiate a restore task](../1100.backup-and-restoration-functions/700.initiate-a-recovery-task.md).

* **Scenario 3**: Initiate a restore task on the CLI. If the cluster is of OceanBase Database V4.0 or earlier, see [Perform full restore](https://www.oceanbase.com/docs/enterprise-oceanbase-database-cn-10000000000946221) for more information. If the cluster is of a version later than OceanBase Database V4.0, see [Perform physical restore](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001103948) for more information.

## FAQ

**What do I do if the resulting source tenant or the resulting restorable window of the source tenant parsed by OCP is empty?**

Contact OCP Technical Support for a solution.

**What do I do to view the restore progress?**

* If the cluster is of OceanBase Database V2.2.77 or later but earlier than V4.0, you can view the restore progress on the GUI of OCP.

  <main id="notice" type='explain'>
  <h4>Note</h4>
  <p>You can view the restore progress only in OCP V4.0.1 or later. </li></ul></p>
  </main>

* If the cluster is of OceanBase Database V4.0 or later, you can view the restore progress on the CLI. For more information, see [View the physical restore progress](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001103946).

**What do I do to cancel a restore task?**

If the cluster is of a version earlier than OceanBase Database V4.0, see [Cancel restore](https://www.oceanbase.com/docs/enterprise-oceanbase-database-cn-10000000000946225) for more information. If the cluster is of OceanBase Database V4.0 or later, see [Cancel physical restore](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001103943) for more information.
