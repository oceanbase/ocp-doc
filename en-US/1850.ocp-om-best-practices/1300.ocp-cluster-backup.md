# Back up an OceanBase cluster

This topic describes how to back up an OceanBase cluster to ensure data security.

## Scenarios

Many scenarios such as data deletion by mistake, software and hardware failures, and natural disasters, can cause data risks. Backing up the data of an OceanBase cluster based on reasonable backup strategies effectively protects data security.

## Prerequisites

* To create a cluster-level or tenant-level backup strategy on the **<UI-TERM key="ocp-v2.Backup.BackupStrategy.Edit.BackupAndRestoration">Backup & Recovery</UI-TERM>** page, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** or **Tenant Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.Backup">Backup</UI-TERM>** menu of **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.BackupAndRestoration">Backup & Recovery</UI-TERM>**

* To create a cluster-level backup strategy on the **<UI-TERM key="ocp-v2.Detail.Backup.BackupAndRestoration">Backup & Recovery</UI-TERM>** page of a cluster, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.Backup.BackupStrategy.New.BackupAndRestoration">Backup & Recovery</UI-TERM>** menu of **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>**

* To create a cluster-level or tenant-level backup strategy on the **<UI-TERM key="ocp-v2.src.constant.compute.BackupAndRestoration">Backup & Recovery</UI-TERM>** page of a tenant, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.Detail.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** or **Tenant Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.BackupAndRestoration">Backup & Recovery</UI-TERM>** menu of **<UI-TERM key="ocp-v2.src.constant.auditEvent.Tenant">Tenants</UI-TERM>**

* OceanBase Database supports Alibaba Cloud Object Storage Service (OSS), Tencent Cloud Object Storage (COS), and Network File System (NFS) as the backup media.

  * For backup to OSS or COS, you need to prepare the backup buckets, backup paths, and the AccessKey ID/AccessKey secret (AK/SK) pair in advance.
  * For backup to NFS, make sure that you have deployed and mounted NFS by using the recommended parameter settings. For more information, see [Deploy NFS](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001103535).

## Considerations

1. For backup to OSS or COS, make sure that the destination OSS or COS bucket is accessible to all OBServer nodes. Among OceanBase Database V4.x series, only versions later than V4.2.1 support backup to COS.
2. For backup to NFS, make sure that all OBServer nodes are mounted to NFS of the same server.

## Procedure

You can create cluster-level backup strategies on the backup and restore page of a cluster, or tenant-level backup strategies on the backup and restore page of a tenant. When you create a backup strategy, you must specify parameters in the following sections: **<UI-TERM key="ocp-v2.Component.BackupStrategyDetail.StorageConfiguration">Storage Configuration</UI-TERM>**, **<UI-TERM key="ocp-v2.Component.BackupStrategyCard.SchedulingConfiguration">Scheduling Configuration</UI-TERM>**, **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.ExpiredBackupCleanupSchedulingConfiguration">Scheduling Configuration Cleanup for Expiring Backups</UI-TERM>**, and **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.AlarmThresholdConfiguration">Configure Alert Threshold</UI-TERM>**. The following example describes how to create a tenant-level backup strategy:

1. On the backup page of a tenant, click **<UI-TERM key="ocp-v2.Backup.BackupStrategy.New.CreateATenantLevelBackupPolicy">Create Tenant-level Backup Strategy</UI-TERM>** to go to the backup details page.

2. In the **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.BackupObjects">Backup Object</UI-TERM>** section, select the tenant that you want to back up from the **<UI-TERM key="ocp-v2.Backup.Component.BackupNowTenantDrawer.BackupTenant">Back Up Tenant</UI-TERM>** drop-down list.

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/430/%E5%A4%87%E4%BB%BD%E5%AF%B9%E8%B1%A11.png)

3. In the **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.StorageConfiguration">Storage Configuration</UI-TERM>** section, specify the backup media and destination information, such as the domain name and AK/SK pair. Then, click **<UI-TERM key="ocp-v2.src.component.ArchiveForm.Test">Test</UI-TERM>** to test the connectivity.

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/430/%E5%AD%98%E5%82%A8%E9%85%8D%E7%BD%AE1.png)

4. In the **<UI-TERM key="ocp-v2.Component.BackupStrategyCard.SchedulingConfiguration">Scheduling Configuration</UI-TERM>** section, specify the backup scheduling cycle and start time as needed. The following figure shows that full backups are performed on Saturday and incremental backups are performed on other days of a week. We recommend that you schedule a backup after a major compaction is completed. For example, if the daily major compaction starts at 2:00 a.m. and takes 2 to 3 hours to complete, you can set the backup start time at 6:00 a.m.

    ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/430/%E8%B0%83%E5%BA%A6%E9%85%8D%E7%BD%AE1.png)

5. In the **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.ExpiredBackupCleanupSchedulingConfiguration">Scheduling Configuration Cleanup for Expiring Backups</UI-TERM>** section, specify the number of days that a backup file is retained. Expired backup files are automatically cleared. By default, this parameter is disabled, which specifies to retain all backup files. Note that a full backup file is required for data restore. Therefore, the latest full backup file that was generated seven days ago is retained. In addition, if only one valid backup is available, this valid backup will not be cleared.

    ![3](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/430/%E6%B8%85%E7%90%86%E8%B0%83%E5%BA%A6%E9%85%8D%E7%BD%AE1.png)

6. In the **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.AlarmThresholdConfiguration">Configure Alert Threshold</UI-TERM>** section, specify the alert thresholds related to backup. When the actual value of a backup parameter exceeds the threshold, an alert is triggered. You can adjust **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.AlarmThresholdForDataBackup">Alert Threshold for Data Backup Timeouts</UI-TERM>** based on the actual duration of a data backup task, **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.LogBackupLatencyAlarmThreshold">Alert Threshold for Log Backup Latency</UI-TERM>** based on the actual log backup delay, and **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.AlertDaysForNoSuccessful">Alert Period for Failed Data Backups</UI-TERM>** based on the backup scheduling cycle.

    ![4](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/430/%E5%91%8A%E8%AD%A6%E9%98%88%E5%80%BC%E9%85%8D%E7%BD%AE.png)

7. Click **<UI-TERM key="ocp-v2.component.ParameterTemplate.AddDrawer.New">Create</UI-TERM>** to save the backup strategy.

If you want to perform a second backup or remote backup, you must enable the second backup feature of a cluster. For more information, see [Create a cluster-level backup strategy](../1100.backup-and-restoration-functions/500.regular-backup/100.manage-cluster-backup-strategy/100.create-a-cluster-backup-strategy.md).

## FAQ

Q: What do I do if the following error message is returned when I click **<UI-TERM key="ocp-v2.src.component.ArchiveForm.Test">Test</UI-TERM>**: `The storage configuration test on {hostIpList: xxx} failed. Make sure that the configuration directory {xxx} is accessible.`?

![5](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/430/%E5%A4%87%E4%BB%BDfaq.png)

A: Check whether the host corresponding to the IP address can access the specified backup storage directory. If you set the storage type to OSS or COS, check whether the AK/SK pair is correct.
