# Add a host

This topic describes how to add a host. Adding a host means to add an on-premises device to the OCP console.

## Prerequisites

You are logged in to the OCP console as a user with the **ADMIN** or **ORG_ADMIN** role.

## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.component.AddChartDrawer.ChartConfigPanel.Host">Hosts</UI-TERM>**.

3. On the **<UI-TERM key="ocp-v2.Host.Detail.Host">Hosts</UI-TERM>** tab, click **<UI-TERM key="ocp-v2.component.HostSelect.AddHost">Add Host</UI-TERM>** in the upper-right corner of the page.

4. Specify the **<UI-TERM key="ocp-v2.src.component.AddHostDrawer.IpAddress">IP Address</UI-TERM>** and **SSH Port** fields. Enter the IPv4 or IPv6 address of the host. You can enter multiple IP addresses separated by commas. The default SSH port number is 22.

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>When the host IP address is an IPv6 address, the following limitations apply: <ul>
   <li>For OceanBase Database, OBClient, and OBProxy: <ul>
   <li>OceanBase Database must be of the [V4.2.5 BP3 Hotfix3, V4.3.0) or [V4.3.5 BP2 Hotfix1, +∞) version. </li>
   <li>OBClient must be of the [V2.2.9, +∞) version. </li>
   <li>OBProxy must be of the [V4.3.4, +∞) version. </li>
   </ul></li></ul>
   <ul><li>Binlog service does not support IPv6 deployment. </li></ul>
   </ul>
   </p>
   </main>

5. Select a host type. If no host type is available, click **<UI-TERM key="ocp-v2.src.component.HostTypeSelect.NewModel">Create Host Specifications</UI-TERM>** to create a host type in OCP.

6. Select an IDC. If no IDC is available, click **<UI-TERM key="ocp-v2.src.component.IdcSelect.NewDataCenter">Create IDC</UI-TERM>** to create an IDC in OCP.

7. Select a host type, and set a host alias for the host. You can also set a connection credential for the host.

   | Parameter  |   Description   |
   |-------|----------|
   | Host Type  |  The type of the host. Valid values: Physical Machine and ECS.  |
   | Credentials  |  Select a credential from the password box. If no credential is available, click **<UI-TERM key="ocp-v2.src.component.CredentialSelect.AddSecrets">Add Credential</UI-TERM>** to create a connection credential for the host.<br><ul><li>Credential Name: must start with a letter and end with a letter or a digit. It can contain letters, digits, and underscores. It must be 2 to 32 characters in length. </li><li>Authorization Type: Valid values: **<UI-TERM key="ocp-v2.src.constant.compute.UsernamePassword">Username/Password</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.compute.SshPrivateKey">SSH Private Key</UI-TERM>**, and **<UI-TERM key="ocp-v2.src.constant.compute.ConfiguredPasswordFree">Password-Free</UI-TERM>**. </li><li>User Type: the type of the user used to connect to the server. Valid values: **<UI-TERM key="ocp-v2.src.constant.compute.RootUser">Root User</UI-TERM>** and **<UI-TERM key="ocp-v2.src.constant.compute.OrdinaryUsers">General User</UI-TERM>**. <ul><li>**<UI-TERM key="ocp-v2.src.constant.compute.RootUser">Root User</UI-TERM>**: an SSH user with root privileges. </li><li>**<UI-TERM key="ocp-v2.src.constant.compute.OrdinaryUsers">General User</UI-TERM>**: a regular user with root privileges. This user must be configured to execute sudo commands without a password. OCP currently supports configuring password-free execution of all commands via sudo. In other words, you can add `username ALL=(ALL) NOPASSWD:ALL` to the `/etc/sudoers` file. </li></ul></li><li>Username: required when the user type is **<UI-TERM key="ocp-v2.src.constant.compute.OrdinaryUsers">General User</UI-TERM>**. Enter the user used to connect to the server. </li><li>Password: required when the authorization type is **<UI-TERM key="ocp-v2.src.constant.compute.UsernamePassword">Username/Password</UI-TERM>**. Enter the password used to connect to the server. </li><li>Private Key: required when the authorization type is **<UI-TERM key="ocp-v2.src.constant.compute.SshPrivateKey">SSH Private Key</UI-TERM>**. Enter the SSH private key for the server. </li><li>OCP Host Private Key File Path: required when the authorization type is **<UI-TERM key="ocp-v2.src.constant.compute.ConfiguredPasswordFree">Password-Free</UI-TERM>**. Enter the path where the host private key file is stored. The default path is `/home/admin/.ssh/id_rsa`. If OCP is deployed using Docker, use the file path inside the Docker container. </li><li>Note: additional information about the credential. </li></ul> |
   | Host Alias  | The alias of the host. This field is optional.   |

8. (Optional) Enter a description for the host.

9. Click **<UI-TERM key="ocp-v2.page.Information.Ok">OK</UI-TERM>**.
