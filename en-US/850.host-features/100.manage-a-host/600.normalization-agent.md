# Check host standardization

As the foundation of data, the performance and stability of the database cluster are of great importance in the production environment. To ensure that the database cluster can achieve the maximum value, it is recommended to standardize the host environment before going online and fix any potential risks.

This topic describes how to check host standardization. For more information about the host check items, see [Host standardization check items](../100.manage-a-host/700.host-standardized-inspection-scope.md).

## Prerequisites

* The user who logs in to the OCP console has the following permissions:

  * The **Host Maintenance** resource permission.
  * The **<UI-TERM key="ocp-v2.component.HostSelect.All">All</UI-TERM>** menu permission for hosts.

* The host is in the **<UI-TERM key="ocp-v2.src.constant.oceanbase.Idle">Idle</UI-TERM>** state.

## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.Service.Component.ServiceModal.Host">Host</UI-TERM>**.

3. On the Hosts page, find the host standardization entry based on the actual business scenario.

   * If the new host is in the **<UI-TERM key="ocp-v2.src.constant.compute.Idle">Idle</UI-TERM>** state and you are aware or have completed host standardization, click **...** in the Actions column and select **<UI-TERM key="ocp-v2.page.Host.HostStandardization">Host Standardization</UI-TERM>**.

   * If the new host is in the **<UI-TERM key="ocp-v2.src.constant.oceanbase.Idle">Idle</UI-TERM>** state and no standardization has been performed, hover the cursor over the ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E7%A9%BA%E9%97%B2%E5%9B%BE%E6%A0%87.png) icon and click **<UI-TERM key="ocp-v2.page.Host.HostStandardization">Host Standardization</UI-TERM>** in the message that appears.

4. In the panel, select the operation type and product type for host standardization. The specific description is as follows:

   | Parameter | Description |
   |--------|-------|
   | Operation | The operation type can be **<UI-TERM key="ocp-v2.page.Host.CheckAndRepairAutomatically">Check & Auto Repair</UI-TERM>** or **<UI-TERM key="ocp-v2.page.Host.CheckOnly">Check Only</UI-TERM>**. <ul><li>Check and Automatically Repair: The system will check the host and automatically repair the risks found during the check.</li><li>Check Only: The system will only check the host and will not automatically repair the risks found during the check.</li></ul> |
   | Product Type | The product type can be **OceanBase** or **OBProxy**. Multiple selections are supported. The system will execute the host standardization check items required for different product types. |

5. After the check is completed, if there are risks on the host, click **<UI-TERM key="ocp-v2.page.Host.ViewInspectionReports">View Check Report</UI-TERM>** to view the detailed check results.

   * For the inspection report generated by selecting **<UI-TERM key="ocp-v2.page.Host.CheckOnly">Check Only</UI-TERM>**, if the report contains risks that can be automatically repaired, click **<UI-TERM key="ocp-v2.page.Host.AutomaticRepair.1">Auto Repair</UI-TERM>**. The system will automatically repair the risks.
   * For risks that cannot be automatically repaired, you need to manually fix them based on the information in the report.
   * After the risks are fixed, click **<UI-TERM key="ocp-v2.Detail.TakeOver.ReCheck">Recheck</UI-TERM>** in the report to initiate another check task.
