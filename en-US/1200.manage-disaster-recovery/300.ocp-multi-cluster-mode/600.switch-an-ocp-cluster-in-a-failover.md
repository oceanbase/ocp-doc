# Failover OCP clusters

This topic describes how to fail over an OCP standby cluster to a primary cluster. When the primary cluster is unreachable, you can fail over the standby cluster to the primary cluster. After the failover operation, the standby cluster becomes the primary cluster, and no longer has any association with the original primary cluster. If you have a multi-cluster deployment, you need to set up a new primary and standby OCP cluster.

<main id="notice" type='notice'>
<h4>Applicability</h4>
<p>This topic applies only to OCP Enterprise Edition. OCP Community Edition does not support this feature. </p>
</main>

## Background information

When the network connection between the primary and standby OCP clusters is interrupted, you can fail over the standby cluster to the primary cluster based on your business requirements. After the failover, the standby cluster becomes the primary cluster for all OCP clusters that can connect to it. For more information about the failover scenarios, see [Overview of multi-cluster mode](../300.ocp-multi-cluster-mode/100.overview-of-multi-cluster-mode.md).

## Prerequisites

* The current user has the **ADMIN** role.
* All OCP standby clusters are running normally.

## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, choose **System Management > OCP Multi-Cluster Mode**.

3. On the **<UI-TERM key="ocp-v2.page.MultiCluster.MasterSlaveDetails">Leader & Follower Details</UI-TERM>** tab, find the **Current OCP Basic Info** section and click **<UI-TERM key="ocp-v2.MultiCluster.Detail.SwitchToPrimaryOcp">Switch to Leader OCP</UI-TERM>**.

   ![1](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/5895772261/p280268.png)

4. Click **<UI-TERM key="ocp-v2.Detail.Component.FailoverDrawer.DisasterRecoverySwitch">Failover</UI-TERM>**.

   ![1](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/5895772261/p280272.png)

5. After the failover is completed, you can view the progress in the **<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">Task Center</UI-TERM>**. For more information, see [Manage tasks](../../1600.system-management-features/600.manage-tasks.md).

## What to do next

After the failover, the new primary cluster list contains the following two scenarios:

1. The original primary OCP cluster becomes a standby cluster with a heartbeat timeout. You need to manually delete the original primary OCP cluster. For more information, see [Delete an OCP cluster](../300.ocp-multi-cluster-mode/700.delete-an-ocp-cluster.md).

2. The original primary OCP cluster recovers after the failover. You need to delete other OCP clusters from the original primary cluster, change its role to FOLLOWER, and then register it to the new primary cluster. For more information, see [Delete an OCP cluster](../300.ocp-multi-cluster-mode/700.delete-an-ocp-cluster.md) and [Register an OCP cluster](../300.ocp-multi-cluster-mode/200.register-an-ocp-cluster.md).
