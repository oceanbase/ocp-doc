# Daily primary/standby tenant switchover

This topic describes how to perform a daily primary/standby tenant switchover. You can choose one of the following methods based on your business requirements.

* Method 1: Perform a daily primary/standby tenant switchover for a specified primary/standby tenant.
* Method 2: Perform a daily primary/standby tenant switchover for all primary/standby tenants in a cluster.

## Method 1: Switch the specified primary tenant to a standby tenant

This method is applicable to scenarios where you need to switch the specified primary tenant to a standby tenant.

### Prerequisites

* The user who logs in to the OCP console has the following permissions:

  * **Cluster Maintenance** or **Tenant Maintenance** resource permissions.
  * The **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">Overview</UI-TERM>** menu permission for the tenant.

* The primary tenant has a standby tenant in the **<UI-TERM key="ocp-v2.src.constant.tenant.NormalOperation">Running</UI-TERM>** state.

### Considerations

* We recommend that you set the same service name for the primary and standby tenants and associate the primary and standby tenants with the same OBProxy cluster. Otherwise, automatic routing cannot be implemented after the primary tenant is switched.
* If the primary tenant is used to store the MetaDB information of the Binlog Service, switching the primary and standby tenants will make the Binlog Service unavailable. Proceed with caution.

### Procedure

1. Log in to the OceanBase Cloud console, click **<UI-TERM key="ocp-v2.src.constant.alarm.Tenant">Tenant</UI-TERM>** in the left-side navigation pane, and go to the **<UI-TERM key="ocp-v2.component.TenantList.TenantList">Tenants</UI-TERM>** page to enter the primary tenant.

2. Click the More icon in the upper-right corner and select **<UI-TERM key="ocp-v2.Detail.Component.SwitchoverModal.DailySwitchover">Switchover</UI-TERM>**.

   ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/431/%E6%97%A5%E5%B8%B8%E5%88%87%E6%8D%A2.png)

3. In the dialog box, view the tenant switch information and click **<UI-TERM key="ocp-v2.Detail.Component.DailyChangeTenantModal.StartSwitching">Start Switch</UI-TERM>**.

    * If the primary tenant has multiple standby tenants, select the standby tenant to be switched to from the **<UI-TERM key="ocp-v2.Component.ChangeTenantView.NewMasterTenant">New Primary Tenants</UI-TERM>** drop-down list. If OCP multi-cluster mode is enabled, the drop-down list also displays standby tenants managed by remote OCP clusters.
    * If the synchronization method of the selected standby tenant is **<UI-TERM key="ocp-v2.src.constant.tenant.ArchiveBased">Archiving-based</UI-TERM>** and the standby tenant is not enabled for archiving, configure the archive address. The following table describes the parameters.

      | Parameter | Description |
      |--------|---------|
      | Storage Type | The storage medium for backup files. Valid values: <ul><li>File: local file storage, usually NFS.</li><li>OSS: Alibaba Cloud Object Storage Service (OSS). This option is supported only in OceanBase Database V2.2.76 and later.</li></ul>|
      | Storage Directory | The storage directory for backup files on the current storage medium.<main id="notice" type='explain'><h4>Note</h4><p>The primary and standby tenants must have read and write permissions for this directory.</p></main>  |
      | Access Domain Name | The domain name of the cloud storage endpoint for backup files. This parameter is displayed only when **<UI-TERM key="ocp-v2.Backup.Service.Detail.StorageType">Storage Type</UI-TERM>** is set to OSS. You can add a port number to the domain name, for example, `oss.ap-shanghai.myqcloud.com:8080`. |
      | Access User | The user for accessing the cloud storage endpoint. This parameter is displayed only when **<UI-TERM key="ocp-v2.src.component.ArchiveForm.StorageType">Storage Type</UI-TERM>** is set to OSS. |
      | Access Key | The user key for accessing the cloud storage endpoint. This parameter is displayed only when **<UI-TERM key="ocp-v2.Component.BackupStrategyDetail.StorageType">Storage Type</UI-TERM>** is set to OSS.    |

   ![11221339](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/431/%E6%97%A5%E5%B8%B8%E5%88%87%E6%8D%A2%E5%AF%B9%E8%AF%9D%E6%A1%86.png)

4. Click the task ID in the dialog box to view the task progress.

## Method 2: Perform daily switchover for all primary and standby tenants in the cluster

This method is suitable for scenarios where you need to ensure business continuity by using standby tenants to support business operations before performing cluster maintenance. You can follow this method to switch all primary tenants in the cluster to standby tenants.

### Prerequisites

* The user logged in to the OceanBase Cloud console has the following permissions:

  * **Cluster Maintenance** or **Tenant Maintenance** resource permissions.
  * **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** menu permission for tenants.

* The cluster has primary tenants, and each primary tenant has available standby tenants.

* The primary and standby tenants belong to an OceanBase cluster that is associated with the same OBProxy cluster. Otherwise, automatic routing cannot be achieved after the switchover.

### Considerations

* It is recommended that the primary and standby tenants have the same service name. Otherwise, automatic routing cannot be achieved after the switchover.
* If the original primary tenant is used to store MetaDB information for the Binlog Service, switching the primary and standby tenants will make the Binlog Service unavailable. Proceed with caution.

### Procedure

1. Log in to the OceanBase Cloud console. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.page.Cluster.Cluster">Cluster</UI-TERM>**. On the **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page, click the name of the target cluster to go to its **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** page.

2. In the upper-right corner, click the More icon and select **<UI-TERM key="ocp-v2.Detail.Overview.TenantDailySwitching">Tenant Switchover</UI-TERM>**.

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/420/%E7%A7%9F%E6%88%B7%E6%97%A5%E5%B8%B8%E5%88%87%E6%8D%A2-%E9%9B%86%E7%BE%A4.png)

3. In the dialog box that appears, select the tenants to be switched and click **<UI-TERM key="ocp-v2.Detail.Component.SwitchoverModal.DailySwitchover">Switchover</UI-TERM>**.

    * If the primary tenant has multiple standby tenants, select the standby tenant to be switched to the primary tenant from the **<UI-TERM key="ocp-v2.Component.ChangeTenantView.NewMasterTenant">New Primary Tenants</UI-TERM>** drop-down list. If the OCP multi-cluster mode is enabled, the drop-down list also includes standby tenants managed by remote OCP clusters.

      Before performing the daily switchover, the system checks whether the primary and standby tenants meet the following conditions. If the check fails, the tenants cannot be selected for the daily switchover:

      * The primary and standby tenants are both in the **<UI-TERM key="ocp-v2.src.constant.tenant.NormalOperation">Running</UI-TERM>** state.
      * The clusters to which the primary and standby tenants belong are both in the **Running** state and have the same version.
      * The synchronization delay of the standby tenant does not exceed the threshold. The default threshold is 5000 ms. You can modify the `ocp.standby.tenant.delay.threshold` parameter in **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** > **<UI-TERM key="ocp-v2.src.util.menu.SystemParameters">System Parameters</UI-TERM>** to change the threshold.

    * If the synchronization method of the selected standby tenant is **<UI-TERM key="ocp-v2.src.constant.tenant.ArchiveBased">Archiving-based</UI-TERM>** and the tenant has not enabled archiving, configure the archive address. The parameter description is as follows:

      | Parameter | Description |
      |--------|---------|
      | Storage Type  | The storage medium for backup files. Valid values: <ul><li>File: Local file storage, usually NFS.</li><li>OSS: Alibaba Cloud OSS object storage. Only OceanBase Database V2.2.76 and later versions support this option.</li></ul>|
      | Storage Directory        | The storage directory for backup files on the current medium.  <main id="notice" type='explain'><h4>Note</h4><p>The primary and standby tenants must have read and write permissions for this directory.</p></main>  |
      | Access Domain        | This parameter is displayed when **<UI-TERM key="ocp-v2.src.component.ArchiveForm.StorageType">Storage Type</UI-TERM>** is set to OSS. Enter the domain name of the cloud storage endpoint for backup files. You can add a port number to the domain name, for example, `oss.ap-shanghai.myqcloud.com:8080`. |
      | Access User        | This parameter is displayed when **<UI-TERM key="ocp-v2.Backup.Service.Detail.StorageType">Storage Type</UI-TERM>** is set to OSS. Enter the user for accessing the Alibaba Cloud storage endpoint. |
      | Access Key        | This parameter is displayed when **<UI-TERM key="ocp-v2.Component.BackupStrategyDetail.StorageType">Storage Type</UI-TERM>** is set to OSS. Enter the user key for accessing the Alibaba Cloud storage endpoint.    |

      ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/430/%E7%A7%9F%E6%88%B7%E6%97%A5%E5%B8%B8%E5%88%87%E6%8D%A2.png)

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>This operation may cause excessive business pressure on the cluster to which the new primary tenant belongs. Proceed with caution.</p>
    </main>

4. Click the task ID in the dialog box to view the task progress.
