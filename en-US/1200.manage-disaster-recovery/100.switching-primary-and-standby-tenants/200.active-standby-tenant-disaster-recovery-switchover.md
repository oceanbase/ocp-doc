# Failover

When a primary tenant becomes unavailable, you can perform a failover in the OceanBase Cloud Platform (OCP) console to switch a standby tenant of this primary tenant to the PRIMARY role. After the failover, the original standby tenant becomes an independent primary tenant that supports read and write services, and is no longer associated with the original primary tenant.

This topic describes the failover procedure. You can choose either of the following failover methods based on the business needs:

* Method 1: Perform a failover for a specified standby tenant.
* Method 2: Perform a failover for all standby tenants in a cluster.

## Method 1: Perform a failover for a specified standby tenant

You can switch a specified standby tenant to the PRIMARY role.

### Prerequisites

* Make sure that you have the following permissions:
  * **<UI-TERM key="ocp-v2.Auth.Role.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** or **Tenant Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.Detail.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">Overview</UI-TERM>** menu of **<UI-TERM key="ocp-v2.Tenant.New.Tenant">Tenants</UI-TERM>**

* The current tenant is a standby tenant in the **<UI-TERM key="ocp-v2.page.Overview.Content.NormalOperation">Running</UI-TERM>** state.

* The primary tenant of the current standby tenant is unavailable.

### Procedure

1. Log on to the OCP console. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.Tenant.New.Tenant">Tenants</UI-TERM>**. In the tenant list, find the target standby tenant and click its name to go to its basic information page.

2. On the page that appears, click the **<UI-TERM key="ocp-v2.Cluster.Component.MachineResource.SeeMore">More</UI-TERM>** icon in the upper-right corner and select **<UI-TERM key="ocp-v2.MultiCluster.Detail.DisasterRecoverySwitch">Failover</UI-TERM>** from the menu.

3. In the dialog box that appears, click **<UI-TERM key="ocp-v2.MultiCluster.Detail.FailoverModal.DisasterRecoverySwitch">Failover</UI-TERM>**. Then, the system performs a tenant precheck and submits the task.

   If the precheck or task submission fails, you can view the cause of the failure in the dialog box that appears and perform troubleshooting accordingly.

4. After the task is submitted, click the task ID in the dialog box to view the task progress.

## Method 2: Perform a failover for all standby tenants in a cluster.

You can switch all standby tenants in a cluster to the PRIMARY role.

### Prerequisites

* Make sure that you have the following permissions:
  * **<UI-TERM key="ocp-v2.Auth.Role.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** or **Tenant Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** menu of **<UI-TERM key="ocp-v2.Compaction.DetailV4.CompactionTenantListMyDrawer.Tenant">Tenants</UI-TERM>**

* You have created standby tenants in the current cluster.

### Procedure

1. Log on to the OCP console. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>**. On the **<UI-TERM key="ocp-v2.page.Binlog.ClusterList">Cluster List</UI-TERM>** page, go to the **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** page of the target cluster.

2. On the page that appears, click the **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.ViewMore">More</UI-TERM>** icon in the upper-right corner and select **<UI-TERM key="ocp-v2.Detail.Overview.TenantDisasterRecoverySwitchover">Tenant Failover</UI-TERM>** from the menu.

3. In the dialog box that appears, select the tenants for the failover and click **<UI-TERM key="ocp-v2.MultiCluster.Detail.DisasterRecoverySwitch">Failover</UI-TERM>**.

   Before you perform a failover, the system checks the primary and standby tenants against the following conditions. If the check fails, you cannot perform a switchover for the selected tenants.

      * The primary tenant and the standby tenants belong to different clusters.
      * The standby tenants are in the Running state and their primary tenants are unavailable.
      * The cluster of the standby tenants is in the **<UI-TERM key="ocp-v2.src.constant.compute.NormalOperation">Running</UI-TERM>** state.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>A failover will revoke the primary/standby relationship between the specified primary and standby tenants and forcibly switch the specified standby tenant to an independent tenant that supports read and write services. This operation is irreversible. Proceed with caution. </p>
    </main>

4. Click the task ID in the dialog box to view the task progress.
