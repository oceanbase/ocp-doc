# Disaster recovery switchover between primary and standby tenants

When the primary tenant is unavailable, OCP supports disaster recovery switchover to switch the standby tenant to the primary tenant. After the disaster recovery switchover is completed, the original standby tenant becomes an independent, readable and writable primary tenant and is no longer associated with the original primary tenant.

This topic describes how to perform disaster recovery switchover between primary and standby tenants. You can choose one of the following methods based on your business requirements.

* Method 1: Perform disaster recovery switchover between a specified primary and standby tenant.
* Method 2: Perform disaster recovery switchover between all primary and standby tenants in a cluster.

## Method 1: Perform disaster recovery switchover between a specified primary and standby tenant

This method is applicable when you want to switch a specified standby tenant to the primary tenant.

### Prerequisites

* The user who logs in to OCP has the following permissions:

  * **Cluster Maintenance** or **Tenant Maintenance** resource permissions.
  * **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">Overview</UI-TERM>** menu permission for the tenant.

* The current tenant is a standby tenant in the **<UI-TERM key="ocp-v2.src.constant.compute.NormalOperation">Running</UI-TERM>** state.

* The primary tenant of the current tenant is unavailable.

### Procedure

1. Log in to the OceanBase Cloud console. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.component.MonitorSearch.Tenant">Tenant</UI-TERM>**. On the **<UI-TERM key="ocp-v2.page.Tenant.TenantList">Tenants</UI-TERM>** page, click the name of the standby tenant.

2. In the upper-right corner of the page that appears, click More and select **<UI-TERM key="ocp-v2.Detail.Component.FailoverStandbyTenantModal.DisasterRecoverySwitchover">Failover</UI-TERM>**.

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/431/%E5%AE%B9%E7%81%BE%E5%88%87%E6%8D%A2.png)

3. In the dialog box that appears, click **<UI-TERM key="ocp-v2.MultiCluster.Detail.FailoverModal.DisasterRecoverySwitch">Failover</UI-TERM>**. The system will perform a tenant precheck and submit the task.

   If the precheck fails or the task submission fails, you can check the failure reason in the dialog box and troubleshoot accordingly.

   ![11221346](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/431/%E5%AE%B9%E7%81%BE%E5%88%87%E6%8D%A2%E5%AF%B9%E8%AF%9D%E6%A1%86.png)

4. After the task is submitted, click the task ID in the dialog box to view the task progress.

## Method 2: Perform disaster recovery switchover between all primary and standby tenants in a cluster

This method is applicable when you want to switch all standby tenants in a cluster to the primary tenants.

### Prerequisites

* The user who logs in to OCP has the following permissions:

  * **Cluster Maintenance** or **Tenant Maintenance** resource permissions.
  * **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">Overview</UI-TERM>** menu permission for the tenant.

* The current cluster has created standby tenants.

### Procedure

1. Log in to the OceanBase Cloud console. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.component.ParameterTemplate.Cluster">Cluster</UI-TERM>**. On the **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** page, click the name of the cluster where the standby tenant resides to go to the **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** page.

2. In the upper-right corner of the page that appears, click More and select **<UI-TERM key="ocp-v2.Detail.Overview.TenantDisasterRecoverySwitchover">Tenant Failover</UI-TERM>**.

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/420/%E7%A7%9F%E6%88%B7%E5%AE%B9%E7%81%BE%E5%88%87%E6%8D%A2-%E9%9B%86%E7%BE%A4.png)

3. In the dialog box that appears, select the tenants that you want to switch and click **<UI-TERM key="ocp-v2.MultiCluster.Detail.DisasterRecoverySwitch">Failover</UI-TERM>**.

   Before the disaster recovery switchover, the system will check whether the primary and standby tenants meet the following conditions. If the check fails, you cannot select the tenant for disaster recovery switchover:

      * The primary and standby tenants are in different clusters.
      * The standby tenant is in the **Normal** state, and the primary tenant is unavailable.
      * The cluster where the standby tenant resides is in the **Running** state.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>Disaster recovery switchover will break the primary-standby relationship between the tenants and forcibly convert the specified tenant to a readable and writable tenant. This operation cannot be undone. Proceed with caution.</p>
    </main>

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/440/12171444.png)

4. Click the task ID in the dialog box to view the task progress.
