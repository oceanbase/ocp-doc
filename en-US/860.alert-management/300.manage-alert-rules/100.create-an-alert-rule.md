# Create an alert rule

OceanBase Cloud Platform (OCP) provides built-in alert rules to meet the monitoring requirements of your business. You can also customize alert rules by referring to this topic. Compared with [creating an alert template](../400.manage-alert-templates/100.create-an-alert-template.md), creating an alert rule allows you to more flexibly specify alert objects for each rule.

For more information about the built-in alert rules, see [Alert Reference](../../1900.reference-guide/100.alarm-reference/100.alert-reference-overview.md).

## Prerequisites

Make sure that you have the following permissions:

* **<UI-TERM key="ocp-v2.Auth.Role.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance**, **Tenant Maintenance**, **OBProxy Maintenance**, **Arbitration Service Maintenance**, **Binlog Service Maintenance**, or **Host Maintenance** permission
* **<UI-TERM key="ocp-v2.Auth.Role.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.component.MonitorSearch.All">All</UI-TERM>** menu of the **<UI-TERM key="ocp-v2.page.Alarm.Alarm">Alert Center</UI-TERM>**

## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.page.Alarm.Alarm">Alert Center</UI-TERM>**.

3. On the **<UI-TERM key="ocp-v2.Alarm.Rule.Detail.AlertRules">Alert Rules</UI-TERM>** tab, click **<UI-TERM key="ocp-v2.Alarm.Rule.CreateAlertRule">Create Alert Rule</UI-TERM>**.

4. On the **Create Alert Rule** page, specify the following parameters for the alert rule.

### Step 1: Specify basic information

1. Specify **<UI-TERM key="ocp-v2.Alarm.Rule.New.AlertRuleName">Alert Rule Name</UI-TERM>**.

   Third-party applications identify and connect to alert rules in OCP through their names specified by **<UI-TERM key="ocp-v2.Alarm.Rule.Detail.AlertRuleName">Alert Rule Name</UI-TERM>**. An alert rule name can contain only letters, digits, and underscores (_). We recommend that you observe the following rules when you name alerts:

   * Prefix names of alerts related to OceanBase clusters with `ob_cluster_`.
   * Prefix names of alerts related to OceanBase Database tenants with `ob_tenant_`.
   * Prefix names of alerts related to OBServer nodes with `ob_host_`.
   * Prefix names of alerts related to OCP servers with `host_`.
   * Prefix names of alerts related to OCP services with `ocp_service_`.
   * Prefix names of alerts related to OBProxy clusters with `obproxy_cluster_`.
   * Prefix names of alerts related to OBProxy servers with `obproxy_host_`.

2. Specify **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.Description">Description</UI-TERM>**, which briefly describes the purpose of the alert rule.

3. Specify **<UI-TERM key="ocp-v2.Alarm.Event.AlarmClassification">Alert Type</UI-TERM>**, which specifies the existing alert group to which the alert rule belongs.

4. Specify whether to **<UI-TERM key="ocp-v2.Alarm.Rule.New.EnableAlerts">Enable Alerting</UI-TERM>**. You can disable system built-in alert rules and custom alert rules that are temporarily not used.

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/430/alert-basic-settings.png)

### Step 2: Specify the alert rule

The configuration of the alert rule depends on the type of application. You can configure different operation rules based on your business requirements. The system reports alerts of different levels based on the configured operation rules.

The following describes how to create an alert rule that does not involve logs and how to create an alert rule that involves logs.

#### Create an alert rule that does not involve logs

1. Specify the alert object.

   | Parameter | Description |
   |--------|---------|
   | Application | The alert source. Valid values: OceanBase, OBProxy, OCP, OMS, OBLB, OBDNS, and Binlog.  |
   | Object Type | The object type of the alert rule. The options vary with the setting of **<UI-TERM key="ocp-v2.Alarm.Subscriptions.Application">Application</UI-TERM>**.  |
   | Alert Object | The object that uses the alert rule. The options vary with the setting of **<UI-TERM key="ocp-v2.Alarm.Rule.Detail.AlertObjectType">Object Type</UI-TERM>**.  When you select **<UI-TERM key="ocp-v2.component.HostSelect.All">All</UI-TERM>**, existing objects and objects added in the future that are of the current alert object type will be included. You can select **<UI-TERM key="ocp-v2.alarm.FormListWithExclude.ObproxyClusterWithExclude.ExcludeObjects">Excluded Objects</UI-TERM>** on the right to exclude objects that do not need to use the alert rule.  |

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/430/rule-configuration.png)

2. Specify the alert rule.

   * **Single metric**

      Configure a single operation rule for alert reporting. The threshold and level in a rule cannot overlap with those in another rule. You can configure at most five rules.

      | Parameter | Description |
      |--------|---------|
      | Metrics | Select a metric from the **<UI-TERM key="ocp-v2.component.alarm.RuleDetail.Metric">Metrics</UI-TERM>** drop-down list. For more information about metrics, see the corresponding topics in [Alert Reference](../../1900.reference-guide/100.alarm-reference/100.alert-reference-overview.md). </br>You can click **<UI-TERM key="ocp-v2.Alarm.Rule.New.AddMetric">Add Metric</UI-TERM>** in the **<UI-TERM key="ocp-v2.component.alarm.RuleDetail.Metric">Metrics</UI-TERM>** drop-down list to add a custom alert metric. For more information, see [Optional monitoring metrics for custom alerts](../1000.monitoring-metrics-for-customizable-alarm.md).  |
      | Operator | The operation rule symbol for the metric.  |
      | Threshold | The alert threshold for the metric.  |
      | Duration (seconds) | The alert duration. The value 0 indicates that an alert is immediately triggered if the specified operation rule is met.  |
      | Alert Level | The alert level.  |

      ![Image 98](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E5%91%8A%E8%AD%A6%E5%8D%95%E6%8C%87%E6%A0%87.png)

   * **Multiple metrics**

      Multiple metrics are suitable for complex alert scenarios. You can configure multi-level **AND** or **OR** metric relationships for an alert rule.

      | Parameter | Description |
      |--------|---------|
      | Metric Relationship | Select an operation mode for multiple metrics. Options include **AND** and **OR**. **AND** indicates that all conditions must be met. **OR** indicates that any one of the conditions is met.  |
      | Metrics | Select a metric from the **<UI-TERM key="ocp-v2.Alarm.Template.Detail.Indicators">Metrics</UI-TERM>** drop-down list. For more information about metrics, see the corresponding topics in [Alert Reference](../../1900.reference-guide/100.alarm-reference/100.alert-reference-overview.md). </br>You can click **<UI-TERM key="ocp-v2.Alarm.Rule.New.AddMetric">Add Metric</UI-TERM>** in the **<UI-TERM key="ocp-v2.Alarm.Template.Detail.Indicators">Metrics</UI-TERM>** drop-down list to add a custom alert metric. For more information, see [Optional monitoring metrics for custom alerts](../1000.monitoring-metrics-for-customizable-alarm.md).  |
      | Add Rule | Add one or more rules for the metric. The system performs an operation on the rules based on the selected metric relationship.  |
      | Add Rule Group | Add a rule group and configure a metric relationship for multiple metrics in the rule group. A rule group is a collection of operations for multiple metrics.  |
      | Duration (seconds) | The alert duration. The value 0 indicates that an alert is immediately triggered if the specified operation rule is met.  |
      | Alert Level | The alert level.  |

      In the following figure, multiple metrics are configured. A critical alert is triggered when the resource metrics of a server meet one of the following conditions for 2 minutes:

      * The memory usage exceeds 95%.
      * The Network Time Protocol (NTP) clock offset exceeds 100 ms.
      * The CPU utilization exceeds 95%, and the average value of load1_per_cpu exceeds 2%.

      ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E5%A4%9A%E8%BF%90%E7%AE%97%E8%A7%84%E5%88%99.png)

3. Specify **<UI-TERM key="ocp-v2.Alarm.Template.Detail.AlarmCycle">Alert Cycle</UI-TERM>**.

   Set the alert detection cycle, whether to automatically clear the alert, and the clearance cycle.

   * **<UI-TERM key="ocp-v2.Alarm.Template.Detail.DetectionCycle">Detection Cycle</UI-TERM>**: the detection cycle for alert metrics. The system checks in each detection cycle whether the alert trigger condition is met. By default, the detection cycle is 60 seconds.
     * Before the alert is reported, the system detects whether the trigger condition is met once every 60 seconds. If yes, the alert is reported.
     * After the alert is reported, the system still checks in each detection cycle whether the trigger condition is met, and reports an alert if yes.

   * **<UI-TERM key="ocp-v2.Alarm.Rule.New.AutomaticElimination">Automatic Clearance</UI-TERM>**: specifies whether to automatically clear the alert. If automatic clearance is disabled, the alert message will be retained in the alert event list. You can confirm the impact scope of the alert and choose whether to manually clear the alert. If automatic clearance is enabled, the system automatically clears the alert based on the elimination cycle.

   * **<UI-TERM key="ocp-v2.Alarm.Template.Detail.EliminationCycle">Elimination Cycle</UI-TERM>**: the duration of a reported alert. It can be configured only when **<UI-TERM key="ocp-v2.Alarm.Rule.New.AutomaticElimination">Automatic Clearance</UI-TERM>** is enabled. The system automatically clears the alert after the specified duration expires. The default clearance cycle is 5 minutes.

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/430/alert-cycle.png)

#### Create an alert rule that involves logs

1. Specify the alert object.

   | Parameter | Description |
   |--------|---------|
   | Application | The alert source. Valid value: **Logs**.  |
   | Object Type | The object type of the alert rule. Valid values: OceanBase Database Logs, OBProxy Logs, and Host Logs.  |
   | OBServer | The object that uses the alert rule. The options vary with the setting of **<UI-TERM key="ocp-v2.Alarm.Rule.Detail.AlertObjectType">Object Type</UI-TERM>**.  When you select **<UI-TERM key="ocp-v2.component.HostSelect.All">All</UI-TERM>**, existing objects and objects added in the future that are of the current alert object type will be included. You can select **<UI-TERM key="ocp-v2.alarm.FormListWithExclude.ObproxyClusterWithExclude.ExcludeObjects">Excluded Objects</UI-TERM>** on the right to exclude objects that do not need to use the alert rule.  |

2. Specify the alert rule.

   | Parameter | Description |
   |--------|---------|
   | Metrics | Select a metric from the **<UI-TERM key="ocp-v2.component.alarm.RuleDetail.Metric">Metrics</UI-TERM>** drop-down list. For more information about metrics, see the corresponding topics in [Alert Reference](../../1900.reference-guide/100.alarm-reference/100.alert-reference-overview.md). </br>You can click **<UI-TERM key="ocp-v2.Alarm.Rule.New.AddMetric">Add Metric</UI-TERM>** in the **<UI-TERM key="ocp-v2.component.alarm.RuleDetail.Metric">Metrics</UI-TERM>** drop-down list to add a custom alert metric. For more information, see [Optional monitoring metrics for custom alerts](../1000.monitoring-metrics-for-customizable-alarm.md).  |
   | Log Level | When **Object Type** is OceanBase Database Logs or OBProxy Logs, you must specify the log level. If the log content reaches the specified log level, an alert is triggered. If no log level is specified for the log type, this parameter is left empty. <ul><li>OceanBase Database Logs: You can select **ERROR**, **WARN**, **INFO**, **WDIAG**, **EDIAG**, and **TRACE**. Multiple log levels can be selected. </li><li>OBProxy Logs: You can select **ERROR**, **WARN**, and **INFO**. Multiple log levels can be selected. </li></ul>  |
   | Keyword | Specify the keyword for log alert. You can specify multiple keywords. If the log content contains any of the specified keywords, an alert is triggered. If this parameter is left empty, an alert is triggered for all log content of the specified log level. <ul><li>**Any Keyword**: If the log content contains any of the specified keywords, an alert is triggered. </li><li>**All Keywords**: If the log content contains all of the specified keywords, an alert is triggered. </li></ul>  |
   | Duration (seconds) | The alert duration. The value 0 indicates that an alert is immediately triggered if the specified operation rule is met.  |
   | Alert Level | The alert level, which can be **Stopped**, **Critical**, **Warning**, **Caution**, or **Reminder**.  |
   | Filtering Keyword | Specify the keyword for filtering alerts. You can specify multiple keywords. If the log content contains any of the specified keywords, an alert is not triggered. <ul><li>**Any Keyword**: If the log content contains any of the specified keywords, an alert is not triggered. </li><li>**All Keywords**: If the log content contains all of the specified keywords, an alert is not triggered. </li></ul>  |

   In the following figure, an alert is triggered immediately based on the specified configuration when the log content of the `rootservice_log` log meets any of the following conditions:

   * The log level is **ERROR** or **WARNING**, and the log content contains `observice start\(\) has failure`, `ret=-4393`, `observice init\(\) has failure`, or `observer init\(\) has failure`. The alert level is **Stopped**.
   * The log level is **ERROR**, and the log content contains `ret=-4394`. The alert level is **Critical**.
   * The log level is **WARNING**, and the log content contains `ret=-4165`, `errcode=-4165`, `ret=-41652`, or `errcode=-41652`. The alert level is **Reminder**.

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436-en/alert_rule.png)

3. Specify **<UI-TERM key="ocp-v2.Alarm.Template.Detail.AlarmCycle">Alert Cycle</UI-TERM>**.

   Set the elimination cycle and whether to automatically clear the alert.

   * **<UI-TERM key="ocp-v2.Alarm.Rule.New.AutomaticElimination">Automatic Clearance</UI-TERM>**: specifies whether to automatically clear the alert. If automatic clearance is disabled, the alert message will be retained in the alert event list. You can confirm the impact scope of the alert and choose whether to manually clear the alert. If automatic clearance is enabled, the system automatically clears the alert based on the clearance cycle.

   * **<UI-TERM key="ocp-v2.Alarm.Template.Detail.EliminationCycle">Elimination Cycle</UI-TERM>**: the duration of a reported alert. The system automatically clears the alert after the specified duration expires. The default clearance cycle is 5 minutes.

### Step 4: Specify alert details

   You can reference variables by using `${}`. The alert details template is displayed in the alert event and corresponds to the ${alarm_description} variable. This variable can be referenced in the alert message template.

### Step 5: Submit the task

Click **<UI-TERM key="ocp-v2.Alarm.Channel.New.Submit">Submit</UI-TERM>**.
