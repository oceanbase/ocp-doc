# View alert channel configuration examples

This topic provides you with some common examples of alert channel configurations for your reference.

## DingTalk channel

You can use the Webhook of a DingTalk group bot to send group messages. To configure a DingTalk channel, perform the following two steps:

* Configure a bot for the DingTalk group that receives alerts.
* Configure the DingTalk channel information in OCP.

### Configure a bot for the DingTalk group

1. Log in to DingTalk on a PC and open the DingTalk group that receives alerts.

2. Click **Group Settings** in the upper navigation bar.

3. In the dialog box that appears, click **Smart Group Assistant > Add Bot**.

4. In the **Group Bot** dialog box, click ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E8%AE%BE%E7%BD%AE%E5%9B%BE%E6%A0%871.png) and select the bot to add.

5. Click **<UI-TERM key="ocp-v2.Plan.Component.PlanTemplateTable.Custom">Custom</UI-TERM>** to add the bot. In the **Bot Details** dialog box, click **<UI-TERM key="ocp-v2.alarm.FormListWithExclude.OBServerWithExclude.Add">Add</UI-TERM>**.

6. Set the bot information, including the **Bot Name** and **<UI-TERM key="ocp-v2.Tenant.New.SecuritySettings">Security Settings</UI-TERM>**.

   The security settings include three modes: **Custom Keywords**, **Signature**, and **IP Address Segment**. You can refer to [Configure the security settings of a bot](https://open.dingtalk.com/document/robots/customize-robot-security-settings) to select one of the modes for configuration. Here, **Custom Keywords** is used as an example.

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E6%B7%BB%E5%8A%A0%E6%9C%BA%E5%99%A8%E4%BA%BA1.png)

7. Select **I have read and agree to the 《Custom Bot Service and Disclaimer》** and click **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">Complete</UI-TERM>**.

8. In the **Add Bot** dialog box, copy the generated Webhook address and click **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">Complete</UI-TERM>**.

### Configure the DingTalk channel information

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.src.hook.useMenu.AlarmCenter">Alert Center</UI-TERM>**.

3. Click the **<UI-TERM key="ocp-v2.Alarm.Subscriptions.New.AlarmChannel">Alert Channel</UI-TERM>** tab.

4. On the **Alert Channels** tab, click **<UI-TERM key="ocp-v2.Alarm.Channel.New.CreateAChannel">Create Channel</UI-TERM>**.

5. Configure the **<UI-TERM key="ocp-v2.Detail.Overview.BasicInformation">Basic Information</UI-TERM>** of the channel.

   | Parameter | Description |
   |------|-------|
   | Channel Type | Select **<UI-TERM key="ocp-v2.src.constant.alarm.Dingtalk">DingTalk</UI-TERM>**. |
   | Channel Name | The name of the alert channel. |
   | Webhook Address | The Webhook address generated after you configure a bot for the DingTalk group. This is the address copied in **Step 8** of **Configure a bot for the DingTalk group**. |
   | Signature Key | Optional. The signature key string obtained when you select the **Signature** mode in the security settings of the bot. |
   | Specified User | Optional. The mobile phone number of a DingTalk group member. |
   | Proxy | Optional. The proxy server for sending alert information. The format is `http:ip:port`. ip indicates the IP address of the proxy server, and port indicates the port used to send alerts. If the IP address of the proxy server is xxx.xxx.xxx.xxx and port 80 is used to send alerts, you can configure the proxy as `http:xxx.xxx.xxx.xxx:80`. <main id="notice" type='explain'><h4>Note</h4><p>Only HTTP channels require proxy settings. </p></main>   |

   ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E9%92%89%E9%92%89%E9%80%9A%E9%81%93%E5%9F%BA%E6%9C%AC%E4%BF%A1%E6%81%AF1.png)

6. Click **<UI-TERM key="ocp-v2.Alarm.Channel.New.SendTestMessages">Send Test Message</UI-TERM>** to test whether the alert is sent.

7. If the alert is sent, click **<UI-TERM key="ocp-v2.Detail.Parameter.List.Submitted">Submit</UI-TERM>**.

## Custom script channel

The Custom Script Channel is used to satisfy special alert linkage scenarios. It is generally used in scenarios in which alerts cannot be configured by using HTTP or in which custom alert formats are required. You can customize some logic in the script. For example, you can convert alert times, or add default parameters to third-party alert gateways.

* Basic information: In the Channel Type field, select a custom script. Set the other options based on your requirements.

* Configure the channels:

  * Script content: Reference the template by using a tag in the script. For more information, see [OCP alarm template tags](../900.ocp-alert-template-variables.md).

  * Response check information: This information is used to prevent issues such as the failure to receive alerts or missed alert notifications, caused by the non-standard alert script or API responses that still return a 200 response code even when the message sends fail. The response check information must contain one valid piece of information, which can be an API response code or a response body. OCP checks whether the information is matched. The check is based on regular expressions and JSON key-value pairs. If the field that needs to be checked does not match the API response, OCP determines that the alert notification fails. Then, OCP tries to send the alert notification again. However, if a user has already received the alert notification and the interface response is in failure, the user may receive multiple alert notifications. For details, see the following rules:

    * If the return result is in the JSON format, the Response validation information must also be configured as a JSON string (the default is `{}`), and the values of both must match. The API response must contain all key-value pairs specified in the Response validation information. For example, if the API response is `{"success":"success", "code":0, "timestamp":"2023-09-12T10:00:00+8:00"}`, the Response validation information can be configured as any of the following options: `{"success":"success", "code":0}`, `{"success":"success"}`, or `{"code":0}`.
    * If the return result is not a JSON, the response verification information must be the same as the return result. For example, if the return result of the API is success, the response verification information must be set to `success`. If the API return result is `success:2023-09-12T10:00:00+8:00`, the response verification information must be set to the regular expression `success.*`.
    * Currently, a response is identified as JSON only if it begins and ends with `{}`. If a response contains the same opening and closing characters without being in JSON format, the system may misidentify the response.

* Alert message template:

  ```javascript
  OCP Alert Notice - Single Alert
  - Name: ${alarm_name}
  - Level: ${alarm_level}
  - Alert target: ${alarm_target}
  - Overview: ${alarm_summary}
  - Generation time: ${alarm_active_at}
  - Details: ${alarm_description}
  - OCP link: ${alarm_url}
  ```

* Alert restore message templates:

  ```javascript
  OCP Alert Recovery Notice ${alarm_name}
  - Alarm target: ${alarm_target}
  - Alarm details: ${alarm_description}
  - Resolved: ${alarm_resolved_at}
  ```

* Alarm message aggregation template:

  ```javascript
  OCP Alert Notification-Multiple Alerts
  - Name: ${alarm_name}
  - Level: ${alarm_level}
  - Number of Alarms: ${alarm_count}
  - Group by: ${alarm_group_by}
  - Alarm target: ${alarm_target}
  - Occurrence time: ${alarm_active_at}
  ```

* Script name: The system provides a sample custom script `alarm_send_script_demo.sh` for reference. You can modify this sample script or use **Python script sample** and **Bash script sample** to create a custom script. Make sure that the script file is stored in the `/home/admin` directory of each OCP node.

* Send a test message: When you debug a script, you can use the send test message option to test. By default, the message content is the script variable `${message}`. Make sure that this variable is in the message body. The success logic for custom scripts is situation-specific. Therefore, the system assumes that if the script executes successfully, the message is sent successfully. However, in the browser's developer mode, you can debug based on the _test request's response content.

### Python Script Example

```python
#!/usr/bin/env python
# -*- coding: utf-8 -*-

# Note: The first line of the script must be a shebang line specifying the program to execute. It is supported only for Python and Bash scripts.

import json
import requests
import os
import sys

ACCESS_TOKEN = "Ding Talk Token"

def send_alarm():
    """
    You can obtain alert variables by using os.environ.
    For more information about the variables supported by OCP alerts, see 《OCP Alert Template Variables》.
    """
    message = os.environ['message']
    data = {
        "msgtype": "markdown",
        "markdown": {
            "text": message
        }
    }
    resp = requests.post("https://oapi.dingtalk.com/robot/send?access_token=" + ACCESS_TOKEN, json=data)
    resp.close()
    response = json.loads(resp.text)

    # The return result will be output to the standard error (stderr) or standard output (stdout), which will be used to verify whether the alert is successfully sent. stderr has higher priority.
    if not response['errcode'] == 0:
        sys.stderr.write(resp.text)
    else:
        print(resp.text)

def main():
    """
    The function returns 0 if the send operation is successful.
    If the sending fails, an error message is written to stderr, and the return value is not 0.
    """
    try:
        send_alarm()
        return 0
    except Exception as e:
        sys.stderr.write(str(e))
        return 1

if __name__ == "__main__":
    sys.exit(main())
```

### Bash script example

```bash
#!/usr/bin/env bash

# should contains shebang in first line, only python/bash are supported

# this function defines to how to assembly request by yourself according to your requirements
# this demo shows you how to send alarm to ding ding
function send() {
    # this token is ding ding group token, please apply and assign it to variable token
    token='Ding Talk Token'
    URL="https://oapi.dingtalk.com/robot/send?access_token=$token"

    # if message is json format, use "'"${message}"'" or "${message}", do not wrapper a new json body
    # if message is not json format, use "${message}"
    # do not use '${message}'
    # print the response to stderr or stdout, which will be validated if success, validate stderr firstly.
    curl -s -X POST ${URL} -H 'Content-Type: application/json' -d '{"msgtype":"text","text":{"content":"'"${message}"'"}}'

    return $?
}

# invoke function to
send
```
