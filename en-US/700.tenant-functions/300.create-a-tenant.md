# Create a primary tenant

A tenant is a container for database objects and a container for resources (CPU, memory, I/O, and so on). You can create a primary tenant in a cluster based on your business requirements.

You can create a primary tenant in the following two ways:

* On the overview page of a tenant.

* On the tenant management page of a specified cluster.

This topic describes how to create a primary tenant on the overview page of a tenant.

## Prerequisites

* The current OCP user must have the following permissions:

  * **Cluster Maintenance** resource permission.
  * **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** menu permission for the tenant.

* The cluster where the tenant is to be created must be the primary cluster and in the RUNNING state.

* The tenant name must be unique within the same cluster.

* On a single node, only one tenant can be created by default. If you want to create multiple primary tenants on a single node, you must purchase the corresponding feature license and then [import the license](../600.cluster-functions/300.manage-a-cluster/1400.import-license.md).

* Before you enable arbitration service for a tenant, make sure that the following conditions are met:

  * The cluster to which the tenant belongs has added an arbitration service and the arbitration service is in the **RUNNING** state.

  * The Locality of the tenant to be enabled for arbitration service is 2F (F: full-featured replica) or 4F.

  * The remaining resources on the host where the arbitration service is located meet the resource requirements.

    You can modify the resource requirements based on your actual needs. For more information, see [Modify system parameters](../700.tenant-functions/1600.manage-tenant-parameters/200.modify-a-tenant-parameter.md).

    * `ocp.arbitration.min.remain.disk.size`: the minimum remaining size of the CLOG disk on the arbitration service host when you enable tenant arbitration, in MB. The data format (a,b) indicates the values when the tenant replicas are 2F and 4F, respectively. The default value is [12,24].
    * `ocp.arbitration.max.cpu.used.percentage`: the maximum CPU usage of the arbitration service host when you enable tenant arbitration, in %. The default value is 90.
    * `ocp.arbitration.max.memory.used.percentage`: the maximum memory usage of the arbitration service host when you enable tenant arbitration, in %. The default value is 90.

* If you use an AL 8 or later Linux kernel, make sure that a Python soft link is created on the host where the OBServer is located. The command is as follows: `ln -s /usr/bin/python3 /usr/bin/python`. In some OceanBase versions, Python3 is already supported. If the cluster to which the tenant belongs is of the V4.2.1.10, V4.2.5.1, V4.3.5, or V4.4.x version, you do not need to manually create a Python3 soft link.

* If you use RHEL 8 or later Linux kernel, and the host only supports importing data in Python3 mode:

  * If the deployed OceanBase (el7/el8/al8) RPM package supports both Python3 and Python2 modes, only the following OceanBase versions support importing data in Python3 mode:
    * (V4.2.1.7, V4.2.2)
    * (V4.2.4, V4.2.5.2)
    * (V4.3.2, V4.3.5.2)
  * If the deployed OceanBase (el7/el8/al8) RPM package supports only Python2 mode, the following OceanBase versions cannot be imported. In this case, you need to replace the host with one that supports Python2.
    * [V4.0.0, V4.2.1.7]
    * [V4.2.2, V4.2.4]
    * [V4.3.0, V4.3.2]

## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, choose **<UI-TERM key="ocp-v2.src.constant.monitor.Tenant">Tenant</UI-TERM>**. The **<UI-TERM key="ocp-v2.page.Tenant.TenantList">Tenants</UI-TERM>** page automatically appears.

3. On the **<UI-TERM key="ocp-v2.component.TenantList.TenantList">Tenants</UI-TERM>** page, click **<UI-TERM key="ocp-v2.Detail.Tenant.NewTenant">Create Tenant</UI-TERM>**.

7. Open the **Parameter Configuration** module and configure the tenant parameters.

* If you have configured the load type in **<UI-TERM key="ocp-v2.Tenant.New.BasicSettings">Basic Settings</UI-TERM>**, the system will automatically select the corresponding parameter template.

* You can add startup parameters one by one and configure their values, as shown in ①.

* You can also click **<UI-TERM key="ocp-v2.component.ParameterTemplate.ParameterTemplateDropdown.SelectAParameterTemplate">Select Parameter Template</UI-TERM>** in ② to select a parameter template. The system will automatically fill in the parameters and their configurations from the template. If you have not created a tenant parameter template, you can click **Create Tenant Template** to create one. For more information, see [Manage tenant parameter templates](1700.manage-tenant-parameter-templates.md).

The system provides four built-in templates. Each template contains commonly used parameter settings. You can directly apply these templates for cluster initialization. The following table describes the built-in templates.

| Template | Description |
         |------|----------|
         | COMPLEX_OLTP Default Parameter Template   |  Corresponds to the **Complex OLTP** load type. This template is only applicable to OceanBase Database V4.2.5 and later.   |
         | HTAP Default Parameter Template   |   Corresponds to the **HTAP** load type. This template is only applicable to OceanBase Database V4.2.5 and later. |
         | OLAP Default Parameter Template   |   Corresponds to the **OLAP** load type. This template is only applicable to OceanBase Database V4.3.0 and later.   |
         | EXPRESS_OLTP Default Parameter Template   |  Corresponds to the **Express OLTP** load type. This template is only applicable to OceanBase Database V4.2.5 and later.   |

<main id="notice" type='explain'>

    </main>
