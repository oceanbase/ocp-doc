# Overview

On the specific tenant overview page, you can delete a tenant, add a replica, change the password, lock a tenant, and copy a tenant. You can also view the basic information of the tenant and details of replicas, and modify the zone priorities and allowlist of the tenant.

OCP allows you to create associated primary and standby tenants in different clusters. When a tenant has a primary-standby relationship, note the following items:

* When you change the configurations of a tenant, the changes may affect the synchronization efficiency between the primary and standby tenants and the tenant performance. We recommend that you keep the configurations of the primary and standby tenants consistent.
* When the primary-standby synchronization method is <b>network synchronization</b> and the primary tenant does not enable log archiving, the risk of the primary tenant's redo logs not being promptly synchronized to the standby database and being overwritten exists. We recommend that you enable log archiving for the primary tenant.

## Prerequisites

Make sure that the user who is logged in to the OCP console has the following permissions:

* **Cluster Read-Only** or **Tenant Read-Only** permissions.
* The **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** menu permissions.

## View basic information

You can view the basic information about a tenant, including **<UI-TERM key="ocp-v2.Binlog.New.TenantName">Tenant Name</UI-TERM>**, **<UI-TERM key="ocp-performance-report.ReportTables.BasicInfo.ReplicaSizeInfoTable.TenantId">Tenant ID</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Component.RenameTenantModal.Cluster">Cluster</UI-TERM>**, **OceanBase Version**, **<UI-TERM key="ocp-v2.Detail.Component.OBProxyAndConnectionStringModal.ObproxyConnectionString">OBProxy/Connection String</UI-TERM>**, **<UI-TERM key="ocp-v2.src.hook.useMenu.BinlogService">Binlog Service</UI-TERM>**, **<UI-TERM key="ocp-v2.Host.Detail.Basic.Label">Tag</UI-TERM>**, **<UI-TERM key="ocp-v2.Alarm.Subscriptions.CreationTime">Created At</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Overview.Limits">Limitations</UI-TERM>**, **<UI-TERM key="ocp-v2.Component.LBLoadBalanceConditon.Remarks">Remarks</UI-TERM>**, **<UI-TERM key="ocp-v2.Auth.Org.ResourceConfigDrawer.ArbitrationService">Arbitration Service</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Component.AddDatabaseModal.CharacterSet">Character Set</UI-TERM>**, **Collation**, **<UI-TERM key="ocp-v2.Cluster.New.LoadType">Load Type</UI-TERM>**, **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.DeploymentDistribution">Deployment Distribution</UI-TERM>**, and **<UI-TERM key="ocp-v2.Detail.Overview.LockedState">Lock</UI-TERM>**.

* Click the name of the cluster to which the tenant belongs to go to the cluster overview page. For more information, see [Overview of the cluster details page](../../600.cluster-functions/300.manage-a-cluster/200.overview-of-the-cluster-details-page.md).

* Click the copy icon next to the **<UI-TERM key="ocp-v2.Detail.Capacity.TenantName">Tenant Name</UI-TERM>** field to copy the tenant name.

* Click **<UI-TERM key="ocp-v2.Detail.Report.ViewReports">View</UI-TERM>** next to **<UI-TERM key="ocp-v2.Detail.Component.OBProxyAndConnectionStringModal.ObproxyConnectionString">OBProxy/Connection String</UI-TERM>** to copy the connection string in a dialog box.

  * The connection string is obtained after the tenant's cluster is associated with the OBProxy.

  * The tenant's cluster can be directly associated with the OBProxy. Example:

    ```sql
    obclient -Pxxx.xxx.xxx.xxx0 -u<Username>@<Tenant Name#Cluster Name> -P2883 -p****** -c -A sys
    ```

* Click **<UI-TERM key="ocp-v2.Component.ServiceName.AddServiceName">Add Service Name</UI-TERM>** to add a service name. The service name must start with an English letter and can contain English letters, numbers, and underscores. It must be 2 to 64 characters long. You can also edit or delete the service name from the **<UI-TERM key="ocp-v2.Component.BinlogServerList.Operation">Actions</UI-TERM>** drop-down list. For primary and standby tenants, you can also use **<UI-TERM key="ocp-v2.Component.ServiceName.ServiceNameModal.ChangeTheServiceNameOfTheActiveAnd">Sync Service Names of Primary and Standby Tenants</UI-TERM>**.

  <main id="notice" type='explain'>
  <h4>Note</h4>
  <p>
  <ul>
  <li>To configure a service name for the tenant, the OceanBase and OBProxy versions must meet the following requirements: <ul><li>OceanBase: V4.2.1.9, [V4.2.4.0, V4.3.0.0), [V4.3.3.0, +∞)</li><li>OBProxy: [V4.3.1.0, +∞)</li></ul></li>

  <li>If the tenant has a primary/standby relationship, we recommend that you keep the service names of the primary and standby tenants consistent and associate the OceanBase clusters of the primary and standby tenants with the same OBProxy cluster. This way, your applications can automatically route traffic after the primary/standby tenant switches.</li>
  <li>For more information about service names, see <a href="800.manage-service-name.md">Manage service names</a>.</li>
  </ul>
  </p></main>

* You can enable the Binlog service for the tenant. For more information, see [Manage the Binlog service of a tenant](700.manage-binlog-service-of-a-tenant.md).

* Hover the pointer over the tenant tag to view all the tags of the tenant. You can click the edit icon to manage the tags. For more information, see [Manage tags](../../1600.system-management-features/300.manage-tags/100.tags-overview.md).

* Click **<UI-TERM key="ocp-v2.Detail.Overview.See">View</UI-TERM>** next to the **Limit** field to view the resource usage limit of the tenant under the current specification. When the current value approaches the theoretical maximum, you must upgrade the tenant specification to avoid abnormal database behavior.

  <main id="notice" type='explain'>
  <h4>Note</h4>
  <p>The tenant's cluster must meet the following conditions to view the resource usage limit: <ul><li>For V4.2.x, the version must be V4.2.4 or later. </li><li>For V4.3.x, the version must be V4.3.1 or later. </li></ul>
  </p></main>

* Click the icon next to Remarks to modify the remarks.

* Click the icon next to the arbitration service to enable or disable the arbitration service.

  <main id="notice" type='explain'>
  <h4>Note</h4>
  <p><ul><li>When the tenant's cluster is a standalone edition of OceanBase Database, the arbitration service cannot be configured. </li><li>Before you enable the arbitration service, make sure that the following conditions are met: <ul><li>The arbitration service is added to the tenant's cluster and is in the RUNNING state. </li><li>The tenant's locality is 2F (F: full feature replica) or 4F. </li><li>The remaining resources on the host where the arbitration service is located meet the resource requirements. You can modify the resource requirements in the system parameters. For more information, see <a href="../1600.manage-tenant-parameters/200.modify-a-tenant-parameter.md">Modify a system parameter</a>. <ul><li><code>ocp.arbitration.min.remain.disk.size</code>: the minimum remaining CLOG disk space on the arbitration service host when the tenant arbitration service is enabled. Unit: MB. The data format (a,b) indicates the values for 2F and 4F tenant replicas respectively. Default value: [12,24]. </li><li><code>ocp.arbitration.max.cpu.used.percentage</code>: the maximum CPU usage on the arbitration service host when the tenant arbitration service is enabled. Unit: %. Default value: 90. </li><li><code>ocp.arbitration.max.memory.used.percentage</code>: the maximum memory usage on the arbitration service host when the tenant arbitration service is enabled. Unit: %. Default value: 90. </li></ul></li></ul></li></ul>
  </p></main>

For more information about other management operations on the tenant, see [Delete a tenant](400.delete-a-tenant.md), [Create a replica](../1000.manage-tenant-replica/200.create-a-replica.md), [Change the password of the sys tenant](500.change-the-sysy-tenant-password.md), [Rename a tenant](250.rename-a-tenant.md), [Lock a tenant](300.locked-a-tenant.md), [Replicate a tenant](200.replication-a-tenant.md), [Clone a tenant](350.clone-a-tenant.md), and [Configure end-to-end tracing](600.full-link-diagnostic-configuration-of-tenant.md).

## View details of a replica

View the name of the zone, the type of the replica, the unit specification, and the unit quantity, and edit or delete the replica. For more information, see [Edit a tenant replica in a private zone](../1000.manage-tenant-replica/300.edit-a-replica-of-a-tenant-in-a-private-zone.md) and [Delete a tenant replica in a private zone](../1000.manage-tenant-replica/400.delete-a-replica-of-a-tenant-in-a-private-zone.md).

<h4>Note</h4>
<p><li>When the cluster to which the tenant belongs is earlier than V4.0, the <b>Log Disk (GB)</b> and <b>IOPS</b> fields are not displayed in the <b>Unit Specification</b> section. <li>When the cluster to which the tenant belongs is V4.0 or later, if the <b>Log Disk (GB)</b> and <b>IOPS</b> parameters are not configured in the <a href="../1630.manage-unit-specification.md">Add Unit Specification</a> section, the <b>Log Disk (GB)</b> and <b>IOPS</b> fields are not displayed in the <b>Unit Specification</b> section. </li></p>
</main>
