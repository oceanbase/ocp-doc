# View the topology of the primary/standby relationships of a tenant

OceanBase Cloud Platform (OCP) provides a topology diagram that allows you to view the primary/standby relationships of the current tenant.

## Prerequisites

* To view information such as the primary tenant, archive log information, tenant synchronization status, and standby tenant information in the topology, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.Detail.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Read-only** or **Tenant Read-only** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.Detail.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.src.util.menu.TopologicalGraph">Topology</UI-TERM>** menu of **<UI-TERM key="ocp-v2.Resource.Component.Block.Tenant">Tenants</UI-TERM>**

* To perform O&M operations such as suspending or starting tenant synchronization, make sure that you have the following permissions:

  * **<UI-TERM key="ocp-v2.Auth.Role.Detail.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** or **Tenant Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.AddRole.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.src.util.menu.TopologicalGraph">Topology</UI-TERM>** menu of **<UI-TERM key="ocp-v2.Tenant.New.Tenant">Tenants</UI-TERM>**

## Procedure

1. Log in to the OCP console.
2. Click **<UI-TERM key="ocp-v2.Detail.Component.DeleteTenantModal.Tenant">Tenants</UI-TERM>** in the left-side navigation pane. In the **<UI-TERM key="ocp-v2.Resource.Component.Block.Tenant">Tenants</UI-TERM>** list, select the target tenant to go to its **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** page.
3. On the left side of the page, click the topology to go to the **<UI-TERM key="ocp-v2.Detail.Topo.MasterSlaveRelationshipMapping">Topology of Primary/Standby Tenants</UI-TERM>** tab.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>If the tenant has no primary/standby relationship, you can click <b>Create Standby Tenant</b> to create a standby tenant for the current tenant. </p>
    </main>

    You can click the icons in the upper-right corner of the canvas to resize and refresh the topology.

    The topology consists of four layers:

   * The first layer indicates the primary tenant.

   * The second layer indicates archive logs. This layer is shown only when the archiving-based synchronization mode is used.

   * The third layer indicates the tenant synchronization status.

   * The fourth layer indicates the standby tenant.

    If the tenant has a cascading relationship, which means that the current tenant is a standby tenant and it has a standby tenant, the synchronization status and standby tenant information are displayed in the lower part of the canvas.

### Primary tenant

The primary tenant icon shows the name of the cluster to which the primary tenant belongs and the current status of the primary tenant.

### Archive logs

When the archiving-based mode is used for synchronization between the primary and standby tenants, the topology shows the information about archive logs. You can hover the pointer over the archive logs icon to view the archive path.

### Tenant synchronization status

The tenant synchronization status icon shows whether the synchronization is normal and the log latency. You can hover the pointer over the icon to view synchronization details.

Possible synchronization states are **<UI-TERM key="ocp-v2.src.constant.tenant.NormalSynchronization">Normal Synchronization</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.tenant.LogConflict">Log Conflict</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.tenant.SynchronizationPause">Synchronization Suspended</UI-TERM>**, **Logs are missing**, and **<UI-TERM key="ocp-v2.src.constant.tenant.SynchronizationException">Synchronization Error</UI-TERM>**.

* **<UI-TERM key="ocp-v2.src.constant.tenant.NormalSynchronization">Normal Synchronization</UI-TERM>**: The standby tenant is synchronizing data from the primary tenant normally.
* **<UI-TERM key="ocp-v2.src.constant.tenant.SynchronizationException">Synchronization Error</UI-TERM>**: The OceanBase Database version of the primary tenant is later than that of the standby tenant, the primary tenant has been deleted, the log source cannot be accessed or is unreachable, or other exceptions occur.
* **<UI-TERM key="ocp-v2.src.constant.tenant.LogConflict">Log Conflict</UI-TERM>**: The restored logs conflict with those of the standby tenant. For example, a log in the standby tenant is different from the log with the same log sequence number (LSN) in the log source.
* **<UI-TERM key="ocp-v2.src.constant.tenant.SynchronizationPause">Synchronization Suspended</UI-TERM>**: The synchronization is suspended.
* **Logs are missing**: Logs in the log source are incomplete.

### Standby tenant

The standby tenant icon shows the name of the cluster to which the standby tenant belongs, current status of the standby tenant, and whether the standby tenant is a remote tenant.

Click the **<UI-TERM key="ocp-v2.page.Welcome.SeeMore">More</UI-TERM>** icon on the right to view supported operations. You can click **<UI-TERM key="ocp-v2.Topo.TopoStandbyGraph.PauseSynchronization">Pause Synchronization</UI-TERM>** or **<UI-TERM key="ocp-v2.Topo.TopoStandbyGraph.EnableSynchronization">Enable Synchronization</UI-TERM>** to suspend or start data synchronization between the primary and standby tenants.
