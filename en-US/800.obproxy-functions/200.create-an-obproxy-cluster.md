# Create an OBProxy cluster

You can specify the basic information, deployment mode, and advanced settings to create an OBProxy cluster. You can add OBProxies to the cluster or connect the cluster to an OceanBase cluster.

## Prerequisites

* The current login user in the OCP console is assigned the **ADMIN** or **ORG_ADMIN** role.
* OBProxy of V4.3.0 or later supports the configuration of the RPC port.

## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **OBProxy** to go to the OBProxy page.

3. In the upper-right corner of the page, click **Create OBProxy Cluster** to go to the **Create OBProxy Cluster** page.

4. Configure the **<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step2.BasicInformation">Basic Information</UI-TERM>** section.

   | Parameter  | Description  |
   |------|------|
   | Cluster Name        | You can specify a cluster name as needed. The name must start with an English letter and can contain English letters, numbers, and underscores. |
   | Software Version      | Select an OBProxy version. <ul><li> If the version is available in the list, select it from the list.   </li><li> If not, click **<UI-TERM key="ocp-v2.Detail.Component.OBLBServerSelect.AddOblbService">Add OBLB Service</UI-TERM>** to upload it. </li> </ul><main id="notice" type='explain'><h4>Note</h4><p>Only software packages of V1.8.0 or later are supported. For security reasons, we recommend that you select software packages of V3.1.0 or later. </p></main> |
   | Password of root@proxysys | The root@proxysys account is used to log in to OBProxy and manage its parameters. You must specify the password of this account. You can specify a custom password or generate a random password. The password must meet the following complexity requirements:<ul><li> It must be 8 to 32 characters in length. </li><li> It must contain at least three of the following four types: digits (0-9), uppercase letters (A-Z), lowercase letters (a-z), and special characters. The supported special characters are <code>~!@#%^&*_-+=\|(){}[]:;,.?/</code>.  </li></ul>  |
   | Password of proxyro | When the **<UI-TERM key="ocp-v2.OBProxy.New.SoftwareVersion">Software Version</UI-TERM>** of OBProxy is earlier than V4.0, this section is displayed. The proxyro account is used by OBProxy to access OceanBase clusters. If you do not specify the password, the default password of the proxyro account is used. The password must meet the following complexity requirements:<ul><li> It must be 8 to 32 characters in length. </li><li> It must contain at least three of the following four types: digits (0-9), uppercase letters (A-Z), lowercase letters (a-z), and special characters.  </li><li> The supported special characters are <code>~!@#%^&*_-+=\|(){}[]:;,.?/</code>.  </li></ul>  |
   | Load Balancing Management  | If you enable load balancing management, you can configure OBLB to improve the load balancing capability of the OBProxy cluster. <ul><li>OBLB Service: You can select an OBLB service configured on the host or click **<UI-TERM key="ocp-v2.Detail.Component.OBLBServerSelect.AddOblbService">Add OBLB Service</UI-TERM>** to create an OBLB service in the right-side panel. For more information, see **Create Load Balancing** in [Manage Load Balancing](300.manage-a-obproxy-cluster/300.manage-load-balancing.md). <ul><li>OBLB Service Endpoint: the endpoint of the OBLB service. </li><li>OBLB Service Port: the port of the OBLB service. The default value is 9090. </li><li>Username and Password: the username and password of the OBLB service. These are used for the authentication of the OBLB interface. </li></ul></li><li>VIP: the specific VIP address of OBLB. </li><li>Access Port: the access port of OBLB. The default value is 2883. </li><li>Port Type: the type of the access port. Supported values: RPC and SQL. </li><li>Domain Name Configuration (Optional): the configuration information for pointing to the VIP and port. The platform does not provide a mapping between the VIP and the domain name. You must prepare a domain name resolution service. </li><li>Note (Optional): additional information. </li></ul><main id="notice" type='explain'><h4>Note</h4><p><ul><li>The <b>Load Balancing Management</b> feature is available only in OCP Enterprise Edition. OCP Community Edition does not support this feature. </li><li>The <b>Aliyun SLB</b> feature in the <b>Load Balancing Management</b> section is applicable only in a dedicated cloud environment. Please contact the on-site delivery engineer. </li><li>When OBLB and OBProxy are deployed on the same host, the OBLB access port cannot be the same as the OBProxy SQL port. Otherwise, the application cannot connect to the database. </li></ul></p></main> |
   | Access Endpoint       | This section is displayed when **<UI-TERM key="ocp-v2.OBProxy.New.LoadBalancingManagement">Manage Load Balancer</UI-TERM>** is disabled. It specifies the access endpoint of the OBProxy cluster. This parameter is used only to generate connection strings for tenants and does not affect actual usage. You must configure load balancing yourself. If the access endpoint is a VIP, you must apply for and bind it to the OBProxy server.  |
   | Access Port       | This section is displayed when **<UI-TERM key="ocp-v2.OBProxy.New.LoadBalancingManagement">Manage Load Balancer</UI-TERM>** is disabled. The default value is 2883. You must specify the access port based on the actual port of the VIP.  |
   | Startup Mode       | The startup mode of the OBProxy cluster. Valid values:  <ul><li> ConfigUrl: multi-cluster startup mode. The OBProxy cluster can access multiple OceanBase clusters.   </li><li> RsList: single-cluster startup mode. The OBProxy cluster can only access the OceanBase cluster specified when the OBProxy cluster is created. After the OBProxy cluster is created, you cannot add more OceanBase clusters to it. </li>    </ul>    |
   | Connectable OceanBase Cluster | The OceanBase cluster that the OBProxy cluster can access. You can select only an OceanBase cluster that has the same network as the OBProxy cluster. <ul><li> When **<UI-TERM key="ocp-v2.OBProxy.New.StartupMode">Startup Method</UI-TERM>** is ConfigUrl, this parameter is not required. After the cluster is created, you can add more OceanBase clusters to the OBProxy cluster by using [Add Connectable OceanBase Cluster](300.manage-a-obproxy-cluster/200.add-a-connectable-oceanbase-cluster.md).   </li><li> When **<UI-TERM key="ocp-v2.Detail.TakeOver.StartupMode">Startup Method</UI-TERM>** is RsList, this parameter is required. Select the corresponding cluster from the drop-down list. </li><li> If the password box contains the connection credentials of the proxyro user for the cluster, the proxyro user is selected by default.   </li><li> If the password box does not contain the connection credentials of the proxyro user for the cluster, click **Create Connection** to create the connection credentials for the proxyro user. </li> </ul>   |

5. (Optional) Configure **<UI-TERM key="ocp-v2.OBProxy.New.DeploymentObproxy">Deploy OBProxy</UI-TERM>**.

   If you want to deploy OBProxy when you create the OBProxy cluster, configure the settings in this step. Otherwise, skip this step and deploy OBProxy after the cluster is created by using [Take Over OBProxy](400.manage-a-obproxy-server/200.take-over-an-obproxy.md) or [Add OBProxy](400.manage-a-obproxy-server/100.add-an-obproxy.md).

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>If you skip this step, the OBProxy cluster you create is an empty cluster. In this case, you cannot add an OceanBase cluster to the OBProxy cluster by using [Add Connectable OceanBase Cluster](300.manage-a-obproxy-cluster/200.add-a-connectable-oceanbase-cluster.md). </p>
   </main>

   1. Turn on the switch of **<UI-TERM key="ocp-v2.OBProxy.New.DeploymentObproxy">Deploy OBProxy</UI-TERM>**.

   2. Fill in the deployment information based on the following table.

      | Parameter  |    Description   |
      |---------------|--------------|
      | **<UI-TERM key="ocp-v2.src.component.AddHostDrawer.ComputerRoom">IDC</UI-TERM>**     | The IDC where OBProxy is located. One OBProxy can only be located in one IDC.  |
      | **<UI-TERM key="ocp-v2.Detail.TakeOver.Models">Host Type</UI-TERM>**    | Optional. If you select a host type, the host list is filtered based on the host type.   |
      | **Select OBProxy Host** | The host for deploying OBProxy. You can select multiple hosts. You can also click **<UI-TERM key="ocp-v2.src.component.AddHostDrawer.AddHost">Add Host</UI-TERM>** to add more hosts to the cluster. |

      By default, two hosts are displayed for selection. These two hosts can deploy only two OBProxies.

      * If you want to deploy more OBProxies, click **<UI-TERM key="ocp-v2.Detail.Component.AddOBProxyDrawer.AddObproxy">Add OBProxy</UI-TERM>** to add more hosts.

      * If you want to deploy only one OBProxy, click the delete icon next to the host to delete it.

6. Configure the startup parameters of the OBProxy cluster.

   * You can add startup parameters one by one and configure their values. For more information about OBProxy parameters, see [OBProxy parameters](900.obproxy-parameters-description.md).

   * You can also click **<UI-TERM key="ocp-v2.page.Tenant.ParameterTemplate">Parameter Template</UI-TERM>** to select a parameter template. The system automatically fills in the parameters in the template and the configurations to this section. If no cluster parameter template has been created, you can click **Create OBProxy Parameter Template** to create a parameter template for the OBProxy cluster. For more information, see [Manage OBProxy parameter templates](800.manage-obproxy-parameter-templates.md).

   The system provides two built-in templates that contain common parameters. You can directly apply the templates for the initialization settings of the OBProxy cluster.

   | Template      | Description    |
   |-----------|---------|
   | 4.2.1 Default Parameter Template    | The OBProxy V4.2.1 parameter settings are recommended for production environments.   |
   | Default Parameter Template for Columnar Minor Compactions | The parameter settings are recommended for columnar read-only replicas in production environments. |

7. Turn on **<UI-TERM key="ocp-v2.Component.AddOBServerDrawer.CustomSettings">Custom Settings</UI-TERM>** to configure the cluster port, operating system user, and path.

   |   Configuration   |  Description   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Scan.ReportTable.ZoneInfoTable.SqlPort">SQL Port</UI-TERM>**        | The default value is 2883. You can specify a custom port.  |
   | **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.ExporterPort">Exporter Port Number</UI-TERM>**   | The default value is 2884. You can specify a custom port.     |
   | **<UI-TERM key="ocp-v2.Detail.Component.AddOBProxyDrawer.RpcPort">RPC Port</UI-TERM>**        | This port is supported only for OBProxy V4.3.0.0 and later. The default value is 2885. You can specify a custom port.   |
   | **Operating System User**     | The operating system user for installing and running OBProxy. This parameter cannot be modified. You can change the default configuration by using the `ocp.operation.default.os.user` parameter. For more information, see [Modify system parameters](../1600.system-management-features/500.manage-system-parameter/200.modify-system-parameters.md).  |
   | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.SoftwareInstallationPath">Software Installation Path</UI-TERM>**   | <ul><li> When the **Operating System User** is admin, the **<UI-TERM key="ocp-v2.Detail.Overview.SoftwareInstallationPath">Software Installation Path</UI-TERM>** is `/home/admin/obproxy` by default. You can specify a custom path. </li><li> When the **Operating System User** is not admin, the **<UI-TERM key="ocp-v2.Detail.Overview.SoftwareInstallationPath">Software Installation Path</UI-TERM>** is `/opt/oceanbase/obproxy` by default. You can specify a custom path. </li></ul>  After the configuration is complete, click **<UI-TERM key="ocp-v2.src.component.ArchiveForm.Test">Test</UI-TERM>** to verify whether the path is available. If the path is unavailable, you can troubleshoot the issue based on the test results or change the path to another available path. |

8. Click **<UI-TERM key="ocp-v2.OBProxy.New.Submitted">Submit</UI-TERM>** to start creating the OBProxy cluster.

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>When you install obproxy, the system checks whether the permissions on the installation directory are correct. The system supports recursive checks of the permissions on <code>/home/admin/logs/obproxy</code> and its parent directory for the specified user (admin by default). If the permissions are not correct, an error is reported in the log in the following format: "check directory xxx permission failed, reason: xxx". </p>
   </main>
