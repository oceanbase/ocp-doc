# Create a primary tenant

A tenant is a container for various database objects and also a container for resources such as CPU, memory, and I/O. You can create a primary tenant in a cluster based on your business requirements.

## Prerequisites

* Make sure that the user who logs in to the OCP console has the following permissions:

  * The **Cluster Maintenance** resource permission.
  * The **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** menu permission of the tenant.

* The cluster of the tenant must be the primary cluster and in the Running state.

* The name of the tenant cannot be duplicated in the same cluster.

* When the OceanBase cluster to which the tenant belongs is of the following versions, if you use RHEL 8 or later, make sure that the host where the OBServer node is located has created a soft link for Python when you create the tenant. For more information, run the `ln -s /usr/bin/python3 /usr/bin/python` command.

  * (-∞, V4.2.1.7)
  * [V4.2.2, V4.2.4)
  * [V4.3.0, V4.3.2)

* A standalone cluster supports only one tenant by default. If you want to create multiple primary tenants on a standalone cluster, you must purchase the corresponding feature module and then [import the license](../600.cluster-functions/300.manage-a-cluster/1400.import-license.md) again.

* Before you enable the arbitration service for the tenant, make sure that the following conditions are met:

  * The cluster to which the tenant belongs has added the arbitration service, and the arbitration service is in the **RUNNING** state.

  * The locality of the tenant to which the arbitration service is to be enabled is 2F (F: full-featured replicas) or 4F.

  * The remaining resources on the host where the arbitration service is located meet the resource requirements.

    You can modify the resource requirements based on the actual situation. For more information, see [Modify a system parameter](../700.tenant-functions/1600.manage-tenant-parameters/200.modify-a-tenant-parameter.md).

    * `ocp.arbitration.min.remain.disk.size`: the minimum remaining size of the CLOG disk on the host where the arbitration service is located when the tenant arbitration service is enabled, in MB. The value in the (a,b) format indicates the values for 2F and 4F tenant replicas respectively. Default value: [12,24].
    * `ocp.arbitration.max.cpu.used.percentage`: the maximum CPU usage on the host where the arbitration service is located when the tenant arbitration service is enabled, in %. Default value: 90.
    * `ocp.arbitration.max.memory.used.percentage`: the maximum memory usage on the host where the arbitration service is located when the tenant arbitration service is enabled, in %. Default value: 90.

## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.src.constant.monitor.Tenant">Tenant</UI-TERM>** to go to the **<UI-TERM key="ocp-v2.page.Tenant.TenantList">Tenants</UI-TERM>** page.

3. On the **<UI-TERM key="ocp-v2.component.TenantList.TenantList">Tenants</UI-TERM>** page, click **<UI-TERM key="ocp-v2.Detail.Tenant.NewTenant">Create Tenant</UI-TERM>**.

The default tenant type is the primary tenant.</blockquote> |
   | **<UI-TERM key="ocp-v2.component.CardAbnormalTable.Cluster">Cluster</UI-TERM>**        | Select a cluster to which the tenant belongs.<blockquote>**<UI-TERM key="ocp-v2.page.Settings.Profile.Description">Description</UI-TERM>**</br>When you create a primary tenant on the tenant management page of the specified cluster, the cluster name is automatically filled in.</blockquote> |

6. Configure **<UI-TERM key="ocp-v2.Tenant.New.SecuritySettings">Security Settings</UI-TERM>**.

   * Allow all IP addresses: All IP addresses can access the tenant.
      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>This method has access security risks. Proceed with caution. </p>
      </main>

   * Custom: Specify a list of client IP addresses that allow login to the tenant. Supported formats: IP address, subnet/mask, fuzzy matching, and mixed formats. Example:

     |   Format   |     Example     |
     |--------|-------|
     | IP Address   | xxx.xxx.xxx.1,xxx.xxx.xxx.2    |
     | Subnet/Mask  | xxx.xxx.xxx.1/24     |
     | Fuzzy Matching   | xxx.xxx.xxx.% or xxx.xxx.xxx._   |
     | Mixed formats | xxx.xxx.xxx.1,xxx.xxx.xxx.2,xxx.xxx.xxx.%,xxx.xxx.xxx._,xxx.xxx.xxx.1/24 |
     | Special note   | % indicates that all clients can log in.      |

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>The IP address of OCP and the IP address of the OBProxy it relies on must be included in this list. Otherwise, OCP cannot manage the tenant. </p>
      </main>

7. Go to the **Parameter Configuration** section and configure tenant parameters.

    * The system will use the parameter templates that match the load type you specified in **<UI-TERM key="ocp-v2.Tenant.New.BasicSettings">Basic Settings</UI-TERM>**.

    * You can click the plus sign at the beginning of the list of startup parameters to add parameters one by one and set their values.

    * You can also click **<UI-TERM key="ocp-v2.component.ParameterTemplate.ParameterTemplateDropdown.SelectAParameterTemplate">Select Parameter Template</UI-TERM>** to select a parameter template. Then, the system automatically populates the parameters in the template and the parameters you specified in this section. If no tenant parameter template is created, you can click **Create Tenant Template** to create a parameter template. For more information, see [Manage tenant parameter templates](../700.tenant-functions/1700.manage-tenant-parameter-templates.md).

         The system provides the following four built-in parameter templates. Each template contains commonly used parameters and can be used to initialize the cluster. Information about the built-in parameter templates is described in the following table.

         | Template | Description |
         |------|----------|
         | Default parameters template for the COMPLEX_OLTP load type   |  This template applies only to the **Complex OLTP** load type and OceanBase V4.2.5 and later.   |
         | Default parameters template for the HTAP load type   |   This template applies only to the **HTAP** load type and OceanBase V4.2.5 and later. |
         | Default parameters template for the OLAP load type   |   This template applies only to the **OLAP** load type and OceanBase V4.3.0 and later.   |
         | Default parameters template for the EXPRESS_OLTP load type   |  This template applies only to the **Express OLTP** load type and OceanBase V4.2.5 and later.   |

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>If your tenant mode is MySQL and the template you selected contains parameters supported only by Oracle, you need to delete these parameters after the template is filled in. </p>
    </main>

8. Click **<UI-TERM key="ocp-v2.Cluster.Import.Submitted">Submit</UI-TERM>** to submit the configuration. The system displays a message indicating that the **<UI-TERM key="ocp-v2.Tenant.Result.Success.NewTenantTaskSubmittedSuccessfully">Tenant creation task submitted.</UI-TERM>** task has been submitted. On this page, you can view the basic information of the task.

    * To view the task details, click **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.ViewTaskDetails">View Task Details</UI-TERM>**.
    * You can also click **<UI-TERM key="ocp-v2.Tenant.Result.Success.ReturnToTenantList">Return to Tenants List</UI-TERM>** to return to the tenants page. On the tenants page, you can view the creation status and task details of the new tenant, and delete a tenant that failed to be created.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>The tenant is created when the task status is <strong>Completed</strong> and the status of the tenant is <strong>Running</strong> on the <strong>Tenants</strong> page of the cluster whose status is <strong>Running</strong>. </p>
    </main>
