# Create a tenant

A tenant can be seen as a container for database objects and resources such as CPU, memory, and I/O resources.

This topic describes how to create a primary tenant on the **<UI-TERM key="ocp-v2.Detail.Component.DeleteTenantModal.Tenant">Tenants</UI-TERM>** page.

## Prerequisites

* Make sure that you have the following permissions:
  * **<UI-TERM key="ocp-v2.Auth.Role.Detail.ResourcePermissions">Resource Permissions</UI-TERM>**: **Cluster Maintenance** permission
  * **<UI-TERM key="ocp-v2.Auth.Role.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** menu of **<UI-TERM key="ocp-v2.src.util.menu.Tenant">Tenants</UI-TERM>**

* The cluster where you want to create a tenant is the running primary cluster.

* (Optional) You have created a parameter template by referring to [Manage tenant parameter templates](../700.tenant-functions/1700.manage-tenant-parameter-templates.md).

  If you need to create multiple tenants with the same parameter configuration, you can use a parameter template to avoid repeatedly configuring the same parameters.
  
* The following conditions are met before you enable the arbitration service for a tenant:

  * The arbitration service is added for the cluster to which the tenant belongs, and the service is in the **RUNNING** state.

  * The locality of the tenant includes two or four full-featured replicas.

  * The resources available on the server hosting the arbitration service meet the resource requirements.

    You can modify the resource requirements by using the following system parameters based on your business requirements. For more information, see [Modify system parameters](../700.tenant-functions/1600.manage-tenant-parameters/200.modify-a-tenant-parameter.md).

    * `ocp.arbitration.min.remain.disk.size`: the minimum size in MB of the clog disk on the arbitration service host required when the arbitration service is enabled for the tenant. The parameter value is in the (a,b) format, indicating the minimum clog disk sizes required when the tenant has two and four full-featured replicas, respectively. Default value: [12,24].
    * `ocp.arbitration.max.cpu.used.percentage`: the maximum CPU utilization in percentage (%) allowed on the arbitration service host when the arbitration service is enabled for the tenant. Default value: `90`.
    * `ocp.arbitration.max.memory.used.percentage`: the maximum memory usage in percentage (%) allowed on the arbitration service host when the arbitration service is enabled for the tenant. Default value: `90`.

## Procedure

1. Log on to the OCP console.

2. In the left-side navigation pane, select **<UI-TERM key="ocp-v2.Backup.Backup.Data.Tenant">Tenants</UI-TERM>**. The **<UI-TERM key="ocp-v2.Resource.Component.Block.Tenant">Tenants</UI-TERM>** tab automatically appears.

3. On the **<UI-TERM key="ocp-v2.Compaction.DetailV4.CompactionTenantListMyDrawer.Tenant">Tenants</UI-TERM>** page, click **<UI-TERM key="ocp-v2.Tenant.New.NewTenant">Create Tenant</UI-TERM>**.

4. Specify the parameters in the **<UI-TERM key="ocp-v2.Tenant.New.BasicSettings">Basic Settings</UI-TERM>** section. The following table describes the parameters.

   |    **<UI-TERM key="ocp-v2.component.ParameterTemplate.Parameter">Parameter</UI-TERM>**     | **<UI-TERM key="ocp-v2.Alarm.Template.Detail.Description">Description</UI-TERM>** |
   |---------------|---|
   | **<UI-TERM key="ocp-v2.Tenant.New.TenantType">Tenant Type</UI-TERM>**        | Select **<UI-TERM key="ocp-v2.Tenant.New.MasterTenant">Primary Tenant</UI-TERM>**. <blockquote>**<UI-TERM key="ocp-v2.page.Credential.Binlog.Description">Note</UI-TERM>**</br>If the tenant belongs to an OceanBase cluster of a version earlier than V4.2, you cannot select a tenant type. The default value is `Primary Tenant`. </blockquote> |
   | **<UI-TERM key="ocp-v2.component.CardAbnormalTable.Cluster">Cluster</UI-TERM>**        | Select a cluster where the tenant is to be created. <blockquote>**<UI-TERM key="ocp-v2.Detail.Parameter.Description">Note</UI-TERM>**</br>When you create a primary tenant on the **<UI-TERM key="ocp-v2.src.util.menu.TenantManagement">Tenant Management</UI-TERM>** page of a specified cluster, the current cluster is used by default. </blockquote> |
   | **<UI-TERM key="ocp-performance-report.ReportTables.RpcStatInfo.ClogRpcTenantTable.TenantName">Tenant Name</UI-TERM>**       | The tenant name must start with a letter and end with a letter or a digit. It can contain letters, digits, and underscores (_). It must be 2 to 32 characters in length. |
   | **<UI-TERM key="ocp-v2.Tenant.New.AdministratorInitialPassword">Administrator Password</UI-TERM>**   | The password of the tenant administrator account, which can be randomly generated. <ul><li>The administrator account is `root` in MySQL mode.   </li><li>The administrator account is `SYS` in Oracle mode. </li> </ul>The password must meet the following requirements: <ul><li>The password must be 8 to 32 characters in length. It must contain characters of at least three of the following types: digits (0 to 9), uppercase letters (A to Z), lowercase letters (a to z), and special characters. Supported special characters are: <code>~ ! @ # % ^ & * _ - + = \ | ( ) { } [ ] : ; , . ? /</code>. </li> </ul>|
   | **<UI-TERM key="ocp-v2.Tenant.Detail.CharacterSet">Character Set</UI-TERM>**    | <ul><li>In MySQL mode, the supported character sets are binary, utf8mb4, gbk, gb18030, latin1, gb18030_2022, ascii, and tis620. The default character set is utf8mb4.   </li><li>In Oracle mode, the supported character sets are utf8mb4, gbk, and gb18030. The default character set is utf8mb4. </li> </ul>   |
   | **Collation** | The detailed collation corresponding to the specified character set. |
   | **<UI-TERM key="ocp-v2.Component.ServiceName.ServiceName">Service Name</UI-TERM>**       | Optional. This parameter is available when the OceanBase cluster is of a version ranging from V4.2.4 to V4.3.0. The service name is a new database access method provided by OceanBase Database. It can be considered as the alias of the cluster name and tenant name. This way, an application can access the database by using the service name. The service name must start with a letter and can contain letters, digits, and underscores (_). It must be 2 to 64 characters in length. |
   | **<UI-TERM key="ocp-v2.Component.LBLoadBalanceConditon.Remarks">Remarks</UI-TERM>**        | This parameter is optional and allows you to add additional information. |

5. Specify the parameters in the **<UI-TERM key="ocp-v2.Tenant.New.ReplicaSettings">Replica Settings</UI-TERM>** section.

   By default, the system displays configurable zones based on the zone information of the selected cluster. If you do not need to create a replica in a zone, click the **<UI-TERM key="ocp-v2.src.util.component.Delete">Delete</UI-TERM>** icon to delete the zone. The zone information parameters that need to be configured and their descriptions are listed in the following table.

   |    **<UI-TERM key="ocp-performance-report.ReportTables.ParameterStatInfo.ZoneParamInfoTable.Parameter">Parameter</UI-TERM>**     | **<UI-TERM key="ocp-v2.Auth.User.New.Description">Description</UI-TERM>** |
   |----------------|------|
   | **<UI-TERM key="ocp-v2.component.ZoneFormCardList.ReplicaType">Replica Type</UI-TERM>**       | The type of the replica. Valid values: <ul><li>Full-featured Replica</li><li>Read-only Replica   </li><li>Log Replica</li></ul>    Select multiple full-featured replicas to ensure that they are in the majority. <main id="notice" type='explain'><h4>Note</h4><p>In a **standalone centralized** database, only **full-featured replicas** are supported. </p></main>  |
   | **<UI-TERM key="ocp-v2.Detail.Component.ModifyResourcePoolModal.UnitSpecification">Unit Specification</UI-TERM>**    | OCP has a set of built-in unit specifications. You can select the specification that you need from the list of unit specifications or click **<UI-TERM key="ocp-v2.src.component.UnitSpecSelect.NewSpecifications">Add Specification</UI-TERM>** at the bottom of the list to add a custom specification. For more information, see [OCP resource unit specifications](../700.tenant-functions/1660.ocp-resource-unit-specifications.md). <main id="notice" type='notice'><h4>Notice</h4><p><ul><li>We recommend that you set the same specification and number of units for all full-featured replicas. Different specifications or numbers of units can compromise the performance or stability. </li><li>If the OceanBase Database version of the cluster is V4.0.0 or later, take note of the following considerations: <ul><li>You cannot configure less than one CPU core for the tenant. </li><li>By default, the cluster limits the minimum memory size. You can adjust the limit by modifying the <code>__min_full_resource_pool_memory</code> parameter. For more information about how to modify the parameter of an OceanBase cluster of V4.1.0, see <a href="https://en.oceanbase.com/docs/common-oceanbase-database-10000000001375811">Modify cluster parameters</a>. </li></ul></li></li></ul></p></main>   |
   | **<UI-TERM key="ocp-v2.Detail.Component.ModifyResourcePoolModal.UnitQuantity">Units</UI-TERM>**    | The number of resource units in the zone. The number of resource units cannot exceed the number of OBServer nodes in the zone. <ul><li>If the cluster version is OceanBase Database V4.0 or later, you can only set the same number of units for all zones, which is 1 by default. </li><li>If the cluster version is earlier than OceanBase Database V4.0, you can set different numbers of units for different zones. </li><main id="notice" type='explain'><h4>Note</h4><p>In a **standalone centralized** database, the default number of units is **1**, which cannot be modified. </p></main>    |
   | **<UI-TERM key="ocp-v2.Cluster.New.ZonePrioritySorting">Zone Priority Rankings</UI-TERM>** | Specifies whether to define priorities for the zones of the tenant. The priorities affect the priority of the primary zone of the sys tenant. <ul><li>If this parameter is not specified, the zone priorities of the sys tenant are used by default. </li><li>If **<UI-TERM key="ocp-v2.Cluster.New.ZonePrioritySorting">Zone Priority Rankings</UI-TERM>** is enabled with no zone priorities, the random priority is used. </li><li>To configure zone priorities, you can select one or more zones from the list on the left that displays all zones in the current cluster and add the selected zones to the list on the right. By default, the priority of a zone added earlier is higher than that of a zone added later, and the zones added at the same time have the same priority. After you move the zones to the box on the right side, you can also drag them upward or downward to adjust their priority order. A zone takes priority over those beneath it. </li></ul><main id="notice" type='explain'><h4>Note</h4><p>In a **standalone centralized** database, the zone priority rankings are not displayed, and Zone1 has the highest priority by default. </p></main> |

6. Configure the parameters in the **<UI-TERM key="ocp-v2.Tenant.New.SecuritySettings">Security Settings</UI-TERM>** section.

   * **Access from all IP addresses is supported**: This tenant can be accessed by any IP address.
      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>This mode causes access security risks. Proceed with caution. </p>
      </main>

   * **<UI-TERM key="ocp-v2.alarm.ExpressionFormList.MultipleExpressionFormList.Custom">Custom</UI-TERM>**: You can add allowed clients into the allowlist in the formats described in the following table.

     |   Format   |     Example     |
     |--------|-------|
     | IP Address          | xxx.xxx.xxx.1,xxx.xxx.xxx.2    |
     | Subnet/Mask  | xxx.xxx.xxx.1/24     |
     | Fuzzy match   | xxx.xxx.xxx.% or xxx.xxx.xxx. _   |
     | Mixed | xxx.xxx.xxx.1,xxx.xxx.xxx.2,xxx.xxx.xxx.%,xxx.xxx.xxx. _,xxx.xxx.xxx.1/24 |
     | Note   | % indicates that the tenant can be accessed from any client.      |

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>You must add the IP addresses of the OCP and OBProxy servers to the allowlist. Otherwise, you cannot manage the tenant from OCP. </p>
      </main>

7. Enable **<UI-TERM key="ocp-v2.src.component.AddArbitrationDrawer.ParameterSettings">Parameter Settings</UI-TERM>** and configure the tenant parameters.

    * You can click the button in section ① of the following figure to add startup parameters one by one and set their values.

    * You can also click **<UI-TERM key="ocp-v2.component.ParameterTemplate.ParameterTemplateDropdown.SelectAParameterTemplate">Select Parameter Template</UI-TERM>** as shown in section ② of the following figure and select a parameter template. The system will automatically populate parameters in this section by using the template. If no tenant parameter template is available, you can click **Create Tenant Parameter Template** to create one. For more information, see [Manage tenant parameter templates](../700.tenant-functions/1700.manage-tenant-parameter-templates.md).

         The system provides four built-in templates that contain general parameters. You can use a template for cluster configuration. The following table describes the built-in templates.

         | Template | Parameter | Description |
         |------|------|-------|
         | Default parameter template for COMPLEX_OLTP   | `_rowsets_max_rows:4`  | Suitable for workloads such as banking and insurance systems. These workloads often involve complex join operations, complex subqueries, batch processing jobs compiled in PL, long-running transactions, and large transactions. Short-running queries are sometimes executed in parallel. <br>This template applies to OceanBase Database V4.3.0 and later.   |
         | Default parameter template for HTAP   |  `_rowsets_max_rows:32`  | Suitable for hybrid transactional and analytical processing (HTAP) workloads. You can use it to quickly get insights from campaign operation data, fraud detection, and scenario-specific recommendations. <br>This template applies to OceanBase Database V4.3.0 and later. |
         | Default parameter template for OLAP   | `default_table_store_format:column` <br> `ob_query_timeout:604800000000` <br> `ob_sql_work_area_percentage:30` <br> `ob_trx_timeout:604800000000` <br> `parallel_min_scan_time_threshold:10` <br> `_rowsets_max_rows:256`  | Suitable for real-time data warehouse analytics. <br>This template applies to OceanBase Database V4.3.0 and later.   |
         | Default parameter template for EXPRESS_OLTP   | `_rowsets_max_rows:1`  | Suitable for workloads such as trading and core payment systems and high-throughput online applications. Such workloads do not involve restrictions such as foreign keys, stored procedures, long-running or large transactions, complex join operations, or complex subqueries. <br>This template applies to OceanBase Database V4.3.0 and later.   |

    <main id="notice" type='explain'>
    <h4>Note</h4>
    If you are creating a tenant in MySQL mode by using a parameter template that contains parameters that are valid only in Oracle mode, you must manually delete those parameters.
    </main>

8. Click **<UI-TERM key="ocp-v2.Alarm.Rule.New.Submit">Submit</UI-TERM>**.
    The page that appears prompts you that the tenant creation task has been submitted and displays the summary information of the task.

    * To view the task details, click **<UI-TERM key="ocp-v2.page.Result.Success.ViewTaskDetails">View Task Details</UI-TERM>**.
    * To return to the **<UI-TERM key="ocp-v2.Resource.Component.Block.Tenant">Tenants</UI-TERM>** list, click **<UI-TERM key="ocp-v2.Tenant.Result.Success.ReturnToTenantList">Return to Tenants List</UI-TERM>**. In the **<UI-TERM key="ocp-v2.Backup.Backup.Data.Tenant">Tenants</UI-TERM>** list, you can view the status and task details of the new tenant, and delete the tenant if the tenant creation failed.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>When the task status is <strong>Completed</strong>, you can check the status of the new tenant in the <strong>Tenants</strong> list on the <strong>Tenant Management</strong> page. The new tenant is created if its status is <strong>Running</strong>. </p>
    </main>
