# Create a cluster

You can create a distributed primary cluster as needed.

<main id="notice" type='notice'>
<h4>Applicability</h4>
<p>Only the OCP Community Edition allows you to create a primary cluster. </p>
</main>

## Background information

* When the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.DeploymentMode">Deployment Mode</UI-TERM>** of the cluster is set to "Multi-host in Single Zone", only the computing power of OceanBase Database is scaled out, and it does not support multi-replica high availability. This deployment mode applies only to development and test environments.
* If the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.DeploymentMode">Deployment Mode</UI-TERM>** of the cluster is set to an even number of zones, the high availability of data cannot be guaranteed, which poses a data security risk. We recommend that you adjust the configuration to ensure an odd number of zones or enable the arbitration service for the cluster or tenant.

## Prerequisites

* The current login user is the **ADMIN** role or **ORG_ADMIN** role.

* (Optional) If you create a multi-replica OceanBase cluster, you need to have an available OBProxy cluster in the current OCP. To add an OBProxy cluster, see the following links.

  * [Create an OBProxy cluster](../800.obproxy-functions/200.create-an-obproxy-cluster.md)

  * [Take over an OBProxy](../800.obproxy-functions/400.manage-a-obproxy-server/200.take-over-an-obproxy.md)

## Procedure

### Step 1: Go to the Create Cluster page

1. Log in to the OCP console. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.component.alarm.Search.Cluster">Cluster</UI-TERM>** to go to the **<UI-TERM key="ocp-v2.Cluster.Import.Cluster">Cluster</UI-TERM>** page. Find the option to create a cluster based on your business scenario.

   1. If you don't have any clusters that you can manage, the system will prompt you to create a cluster on the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** tab. Click **<UI-TERM key="ocp-v2.page.Cluster.CreateANewCluster">Create Cluster</UI-TERM>** in the prompt.

   2. If you already have clusters that you can manage, click **<UI-TERM key="ocp-v2.page.Cluster.CreateANewCluster">Create Cluster</UI-TERM>** in the upper-right corner of the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** tab.

2. On the **<UI-TERM key="ocp-v2.page.Welcome.CreateACluster">Create Cluster</UI-TERM>** page, select **<UI-TERM key="ocp-v2.Cluster.New.DistributedCluster">Distributed Cluster</UI-TERM>**.

### Step 4: Enable Cgroup

Cgroup is used to isolate CPU resources between tenants within an OceanBase cluster and between tenants within the same cluster. You can choose whether to enable Cgroup based on your actual business requirements to achieve stronger CPU/IOPS isolation. When you create an OceanBase cluster of V4.0 or later, Cgroup is enabled by default.

Enabling Cgroup may result in a performance drop of about 7%. If your business scenario involves a single tenant, a small number of CPU cores (<14), and a need for higher database performance, we recommend that you disable Cgroup. Additionally, if the operating system kernel version on the host is below 4.1.9, tenants cannot be created on the host. In this case, Cgroup is disabled by default and the Cgroup switch is not displayed.

### Step 5: Configure the CPU overselling quota

When different business scenarios have overlapping workloads, OceanBase clusters may experience overload conditions during operation, leading to thread competition for CPU resources among tenants, which can slow down actual business scenarios. To ensure that different tenant workloads can be controlled and interleaved, you can configure CPU resource overselling to improve resource utilization.

In the **<UI-TERM key="ocp-v2.Cluster.New.CpuOversoldSettings">CPU Overallocation Settings</UI-TERM>** section, you can configure the overselling quota using a slider or an input field. The default value is 120%, with a range of 101% to 200%.

<main id="notice" type='explain'>
<h4>Note</h4>
<p><ul><li>Only OceanBase Database 4.0 and later support CPU overselling. With proper configuration, you can fully utilize hardware resources.</li><li>CPU overselling depends on Cgroup. Before configuring the CPU overselling quota, make sure that Cgroup is enabled for the cluster.</li></ul>
</p></main>

### Step 7: Configure users, paths, and ports

In the **<UI-TERM key="ocp-v2.Cluster.New.CustomSettings">Custom Settings</UI-TERM>** section, you can configure cluster-level settings such as the operating system user, paths, and ports. These settings include the operating system user for installing and running OBServer, the software installation path, data disk path, log disk path, SQL port, and RPC port.

1. Configure the operating system user:

   This user is used for installing and running OBServer. It cannot be edited. You can modify this user by adjusting the default value of the `ocp.operation.default.os.user` parameter. Note that changes to this parameter only affect the creation of distributed clusters, [standalone centralized clusters](../600.cluster-functions/200.create-a-cluster/200.create-a-standalone-centralized-cluster.md), [OBProxy clusters](../800.obproxy-functions/200.create-an-obproxy-cluster.md), and [arbitration services](../600.cluster-functions/1350.manage-arbitration-services/200.create-arbitration-services.md). It does not affect the configurations of existing clusters.

2. Configure the paths:

   |   Configuration   |  Description   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.SoftwareInstallationPath">Software Installation Path</UI-TERM>**   | <ul><li>When **Operating System User** is admin, **<UI-TERM key="ocp-v2.Cluster.New.SoftwareInstallationPath">Software Installation Path</UI-TERM>** defaults to `/home/admin/oceanbase`, which can be customized.</li><li>When **Operating System User** is not admin, **<UI-TERM key="ocp-v2.Detail.Overview.SoftwareInstallationPath">Software Installation Path</UI-TERM>** defaults to `/opt/oceanbase/oceanbase`, which can be customized.</li></ul>   |
   | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.DataDiskPath">Data Disk Path</UI-TERM>**       | Defaults to `/data/1`, which can be customized.  |
   | **<UI-TERM key="ocp-v2.Cluster.New.LogDiskPath">Log Disk Path</UI-TERM>**   | Defaults to `/data/log1`, which can be customized. In a production environment, OceanBase Database recommends that the log disk space be at least three times the host memory space. To avoid performance issues, we recommend that you do not mount the data directory and log directory on the same disk. <main id="notice" type='explain'><h4>Note</h4>Starting from OCP 4.3.0 BP1, when you create an OceanBase cluster of the following versions, the slog directory is placed on the log disk and is no longer bound to the data disk. If you set <code>log_disk_size=0</code>, it will be considered as exclusive use for clogs, with the default value of <code>log_disk_percentage</code> being 90%. If the size of the disk where slog and clog are stored is less than 40 GiB, the reserved space for slog will be less than 4 GiB, which may affect the writing of slog. <ul><li>V4.2.4.0 ≤ OceanBase ＜ V4.3.0.0</li><li>OceanBase ≥ V4.3.1.0</li></ul>For more information about slog, see <a href="https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000819002">Installation directory structure of OBServer nodes</a>. </main>      |

3. Configure the ports:

   |   Configuration   |  Description   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Cluster.New.SqlPort">SQL Port</UI-TERM>**        | Defaults to 2881, which can be customized.  |
   | **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.RpcPort">RPC Port</UI-TERM>**   | Defaults to 2882, which can be customized.     |

4. After you configure the parameters, click **<UI-TERM key="ocp-v2.Cluster.New.Test">Test</UI-TERM>** to verify whether the paths and ports are available.

      * If the test succeeds, click **<UI-TERM key="ocp-v2.Alarm.Template.New.Submit">Submit</UI-TERM>**.
      * If the test fails, perform troubleshooting based on the error message.

### Step 8: Verify the configuration information

In the right-side panel, verify that the configuration information is correct and click **<UI-TERM key="ocp-v2.component.FilterDropdown.Determine">OK</UI-TERM>**. After the configuration is submitted, you can view the task progress in **<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">Task Center</UI-TERM>**.
