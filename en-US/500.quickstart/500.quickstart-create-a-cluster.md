# Create a cluster

You can create a distributed primary/standby cluster for management as needed.

<main id="notice" type='notice'>
<h4>Applicability</h4>
<p>OCP Community Edition supports creating only primary clusters. </p>
</main>

## Prerequisites

* The user used to log in to OCP has the **Create Cluster** permission.

* (Optional) If you want to create a multi-replica OceanBase cluster, an OBProxy cluster must exist in OCP. You can follow the steps below to add an OBProxy cluster.

  * [Create an OBProxy cluster](../800.obproxy-functions/200.create-an-obproxy-cluster.md)

  * [Take over an OBProxy cluster](../800.obproxy-functions/400.manage-a-obproxy-server/200.take-over-an-obproxy.md)

* Only a running primary cluster can create a standby cluster. The OceanBase version must be V2.2.50 or later and V4.0.0 or earlier.

## Procedure

1. Log in to the OCP console. Then, find the page to create a cluster based on your business scenario.

   1. If you do not have any manageable clusters, you will be prompted to create a cluster on the **<UI-TERM key="ocp-v2.src.component.TenantLabel.Cluster">Cluster</UI-TERM>** page. In this case, click **<UI-TERM key="ocp-v2.page.Cluster.CreateANewCluster">Create Cluster</UI-TERM>** in the prompt box.

   2. If you already have manageable clusters, click **New Cluster** in the upper-right corner of the **<UI-TERM key="ocp-v2.page.Cluster.Cluster">Cluster</UI-TERM>** page.

2. On the **Create Cluster** page, select **<UI-TERM key="ocp-v2.Cluster.New.DistributedCluster">Distributed Cluster</UI-TERM>**.

3. Set the basic information of the cluster.

   * **Create a primary cluster**

      ![Image 175](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/420/%E5%88%9B%E5%BB%BA%E4%B8%BB%E9%9B%86%E7%BE%A4.png)

      The following table describes the parameters on the page.

     | Parameter  | Description |
     |-----|-------|
     | **<UI-TERM key="ocp-v2.Component.AddZoneDrawer.ClusterType">Cluster Type</UI-TERM>**          | Select **<UI-TERM key="ocp-v2.Cluster.New.MasterCluster">Primary Cluster</UI-TERM>**.  |
     | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.ClusterName">Cluster Name</UI-TERM>**          | Enter the name of the cluster to be managed. The name must start with an English letter and end with an English letter or a number. It can contain English letters, numbers, and underscores, and must be 2 to 32 characters long. |
     | **<UI-TERM key="ocp-v2.Cluster.New.RootSysPassword">Root@sys Password</UI-TERM>**    | The password can be customized or randomly generated. The password must meet the following complexity requirements: <ul><li>It must be 8 to 32 characters long. </li><li>It must contain at least two uppercase letters, two lowercase letters, two digits, and two special characters. </li><li>The special characters are \~!@#%\^\&\*_-+=\`\|(){}\[\]:;',.?/  </li></ul>   |
     | **<UI-TERM key="ocp-v2.Cluster.New.ObVersion">OceanBase version</UI-TERM>**         | You can select an existing OceanBase cluster version from the list or click **<UI-TERM key="ocp-v2.src.component.PackageSelect.AddVersion">Add Version</UI-TERM>** below the list to upload an OceanBase version.  |
     | **Associate with OBProxy Cluster** | If you create a multi-replica OceanBase cluster, we recommend that you enable the **Associate with OBProxy Cluster** option to associate the OceanBase cluster with an OBProxy cluster. After the association, your SQL requests will be accurately forwarded to the corresponding replicas, allowing you to access OceanBase Database as if it were a standalone database. </br>1. By default, the proxyro user is used for association. You do not need to specify the username and password. </br>  2. Select the OBProxy cluster from the drop-down list. If the drop-down list is empty, add an OBProxy cluster as described in the **Prerequisites** section of this topic. <blockquote>**<UI-TERM key="ocp-v2.src.constant.alarm.Small">Caution</UI-TERM>**</br>When the OceanBase version of **<UI-TERM key="ocp-v2.Cluster.New.ObVersion">OceanBase version</UI-TERM>** is V4.0 or later, only OBProxy clusters of V4.0.0 or later can be associated. </blockquote>    |

   * **Create a standby cluster**

      ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/Image%209.png)

      The following table describes the parameters on the page:

     |       Parameter       |                                                                                         Description                                                                                          |
     |----------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
     | **<UI-TERM key="ocp-performance-report.ReportTables.BasicInfo.ClusterInfoTable.ClusterType">Cluster Type</UI-TERM>**       | Select **<UI-TERM key="ocp-v2.component.common.ClusterSelect.StandbyCluster">Standby Cluster</UI-TERM>**.                                                                                                                                                              |
     | **<UI-TERM key="ocp-performance-report.ReportTables.BasicInfo.ClusterInfoTable.MasterCluster">Primary Cluster</UI-TERM>**        | Select the primary cluster. The system will create a standby cluster belonging to the primary cluster.                                                                                                                                                              |
     | **OceanBase Version of Standby Cluster**  | Select the same OceanBase version as that of the primary cluster. <ul><li> If the version is available in the list, select it from the list.   </li><li> Otherwise, click **<UI-TERM key="ocp-v2.src.component.PackageSelect.AddVersion">Add Version</UI-TERM>** below the list to upload it. </li> </ul>   |

4. Set the deployment mode of the cluster.

   By default, three zones are added. If you want to deploy the cluster across more than three zones, click **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.Add">Add</UI-TERM>** to add a zone. If you want to deploy the cluster across fewer than three zones, click the delete icon of the corresponding zone.

   ![10](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E9%83%A8%E7%BD%B2%E6%A8%A1%E5%BC%8F1.png)

   The following table describes the parameters to be set for each zone.

   |   Parameter   |  Description   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Restore.SamplingStrategy.Detail.ZoneName">Zone Name</UI-TERM>**    | You can keep the default value or customize it. The zone name must start with an English letter and support uppercase and lowercase letters, numbers, and underscores. It must be 2 to 32 characters long. When you deploy an OceanBase cluster across multiple zones, the zone that has the same region as the primary zone must be specified as the primary zone.  |
   | **<UI-TERM key="ocp-v2.Component.LBLoadBalanceConditon.DataCenter">IDC</UI-TERM>**     | The data center where the zone is located. A zone can exist in only one data center.  |
   | **<UI-TERM key="ocp-v2.Cluster.New.Models">Host Type</UI-TERM>**    | The model of the servers in the zone. This parameter is optional. If it is selected, the hosts in the following host list will be filtered by the selected model.   |
   | **<UI-TERM key="ocp-v2.Component.AddOBServerDrawer.CpuArchitecture">CPU Architecture</UI-TERM>**    |  When multiple installation packages of different architectures are available for the selected **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.ObVersion">OceanBase version</UI-TERM>**, you need to select the hardware architecture of the host that matches the architecture of the installation package. <blockquote>**<UI-TERM key="ocp-v2.src.constant.alarm.Small">Caution</UI-TERM>**</br><ul><li>The default architecture type is the architecture type of the first installation package. You can switch the architecture type. After the switch, the **<UI-TERM key="ocp-v2.src.component.ModifyTagResourceDrawer.Host">Host</UI-TERM>** list on the page will display hosts of the specified architecture type. </li><li>If different zones are assigned different architectures, the mixed-architecture deployment mode may encounter stability and performance issues. Proceed with caution. </li></blockquote> |
   | **<UI-TERM key="ocp-v2.Component.ZoneList.AddOBServerDrawer.Host">Host</UI-TERM>**  | You can select multiple hosts or add a host.   |
   | **Root Service IP Address**     | You need to select an IP address as the host for Root Service. For a multi-replica OceanBase cluster, you need to specify a Root Service host for each zone.   |
   | **<UI-TERM key="ocp-v2.Tenant.New.ZonePrioritySorting">Zone Priority Rankings</UI-TERM>**  **(This parameter is unavailable when you create a standby cluster.)**  | You can specify the priority for distributing the primary replica of the sys tenant of the cluster. <ul><li>If specified, the zone with the highest priority is considered the primary zone. It can contain only one primary zone. The priority is sorted as follows: </br> 1. Check the left-side list box and select one or more zones. The left-side list box displays all available zones in the current cluster. </br>   2. Click the \> button in the middle. The selected zones will be moved to the **<UI-TERM key="ocp-v2.Detail.Component.ModifyPrimaryZoneDrawer.ZonePrioritySorting">Zone Priority Rankings</UI-TERM>** list. Zones of the same priority have the same color. </br>  3. Repeat steps a and b to add zones of lower priorities. </br>   4. You can drag the zones in the **<UI-TERM key="ocp-v2.Tenant.New.ZonePrioritySorting">Zone Priority Rankings</UI-TERM>** list to change their order. The priority of a zone decreases from top to bottom. </li><li>If this parameter is not specified, the first zone created will have the highest priority. </li></ul>    |
   | **<UI-TERM key="ocp-v2.Component.ArbitrationServerList.AddArbitrationService">Add Arbitration Service</UI-TERM>** |  You can select whether to add an arbitration service for the cluster. You can choose an existing service from the service drop-down list or click **Add Service** to create a new arbitration service for the cluster. For more information, see [Add an arbitration service](../600.cluster-functions/400.manage-arbitration-services/800.add-arbitration-services.md).  <blockquote>**<UI-TERM key="ocp-v2.MultiAzone.Detail.Description">Description</UI-TERM>**</br>Only V4.1.0 and later of the primary cluster support the arbitration service feature. </blockquote>  |

5. Open the **<UI-TERM key="ocp-v2.OBProxy.New.ParameterSettings">Parameter Settings</UI-TERM>** module and configure the cluster parameters.

    * You can add startup parameters and configure their values one by one as shown in Figure ①.

    * Alternatively, you can click **<UI-TERM key="ocp-v2.component.ParameterTemplate.ParameterTemplateDropdown.SelectAParameterTemplate">Select Parameter Template</UI-TERM>** as shown in Figure ② to choose a parameter template. The parameters in the template will be automatically filled with their configurations.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>When OceanBase Database V2.2.77 is used, we recommend that you use the built-in <strong>2.2.77 Version Parameter Template</strong>. This template contains common parameter settings of OceanBase Database V2.2.77. You can apply this template for initial cluster setup. </li>
    <li>If no parameter template is created, you can click <strong>Create Cluster Template</strong> to create a parameter template. For more information, see <a href="../600.cluster-functions/1200.cluster-parameters-template-management.md">Cluster Parameter Template Management</a>. </li>
    </ul>
    </main>

   ![09161737](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E5%8F%82%E6%95%B0%E8%AE%BE%E7%BD%AE1.png)

6. Open **Custom Configuration** and configure the operating system's primary user, paths, and ports.

   * Configure the primary user of the operating system:

      The user who configures and runs OBServer in the operating system. You cannot edit this parameter. For more information, see [Modify system parameters](../1600.system-management-features/300.manage-system-parameter/200.modify-system-parameters.md).

      <main id="notice" type='explain'>
      <h4>Note</h4>After you modify the <code>ocp.operation.default.os.user</code> parameter, the modification will only take effect when you create a distributed cluster, [create an OBProxy cluster](../800.obproxy-functions/200.create-an-obproxy-cluster.md), or [create an arbitration service](../600.cluster-functions/400.manage-arbitration-services/200.creat-arbitration-services.md). It will not affect the configurations of existing clusters.
      </main>

   * Configure the paths:

      |   Parameter   |  Description   |
      |-----|-------|
      | **<UI-TERM key="ocp-v2.Cluster.New.SoftwareInstallationPath">Software Installation Path</UI-TERM>**   | <ul><li> When the value of **OS Primary User** is admin, the default value of **<UI-TERM key="ocp-v2.OBProxy.New.SoftwareInstallationPath">Software Installation Path</UI-TERM>** is `/home/admin/oceanbase`. Custom paths are supported. </li><li>When the value of **OS Primary User** is not admin, the default value of **<UI-TERM key="ocp-v2.OBProxy.New.SoftwareInstallationPath">Software Installation Path</UI-TERM>** is `/opt/oceanbase/oceanbase`. Custom paths are supported. </li></ul>   |
      | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.DataDiskPath">Data Disk Path</UI-TERM>**       | The default value is `/data/1`. Custom paths are supported.  |
      | **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.ExporterPort">Exporter Port Number</UI-TERM>**   | The default value is `/data/log1`. Custom paths are supported.     |

      After the configurations are completed, click **<UI-TERM key="ocp-v2.Settings.Credential.Cluster.Test">Test</UI-TERM>** to verify whether the paths are available. If not, you can troubleshoot the issues based on the test results or modify the paths to other available paths.

      ![11](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E9%85%8D%E7%BD%AE%E8%B7%AF%E5%BE%841.png)

   * Configure the ports:

      |   Parameter   |  Description   |
      |-----|-------|
      | **<UI-TERM key="ocp-v2.Detail.TakeOver.SqlPort">SQL Port Number</UI-TERM>**        | The default value is 2881. Custom ports are supported.  |
      | **<UI-TERM key="ocp-v2.Detail.Component.AddOBProxyDrawer.ExporterPort">Exporter Port Number</UI-TERM>**   | The default value is 2882. Custom ports are supported.     |

      After the configurations are completed, click **<UI-TERM key="ocp-v2.OBProxy.New.Test">Test</UI-TERM>** to verify whether the ports are available. If the ports are occupied, you need to configure other available ports.

      ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E7%AB%AF%E5%8F%A3%E9%85%8D%E7%BD%AE1.png)

7. After the verification, click **<UI-TERM key="ocp-v2.Binlog.New.Submit">Submit</UI-TERM>** .

8. In the **<UI-TERM key="ocp-v2.Cluster.New.ConfirmSubmissionInformation">Confirm Information</UI-TERM>** dialog box, click **<UI-TERM key="ocp-v2.MultiCluster.Detail.SwitchoverModal.Determine">OK</UI-TERM>** to submit the information.

   You can view the task execution progress in the **System Management > Tasks** page.
