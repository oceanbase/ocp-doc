# Add hosts

Before you create a cluster, you need to add the hosts to OCP. To create a 1-1-1 cluster, add four hosts. One host is used for each zone, and one host is used for deploying an OBProxy.

## Prerequisites

The logged-in user has the **ADMIN** or **ORG_ADMIN** role.

## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.component.AddChartDrawer.ChartConfigPanel.Host">Hosts</UI-TERM>**.

3. On the **<UI-TERM key="ocp-v2.src.constant.monitor.Host">Hosts</UI-TERM>** tab, click **<UI-TERM key="ocp-v2.component.HostSelect.AddHost">Add Host</UI-TERM>** in the upper-right corner.

4. Specify the **<UI-TERM key="ocp-v2.src.component.AddHostDrawer.IpAddress">IP Address</UI-TERM>** and **SSH Port**. Enter the IPv4 or IPv6 address of the host. You can add multiple IP addresses, separated by commas. The default SSH port number is 22.

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>When the host IP address is an IPv6 address, the following limitations apply: <ul>
   <li>When deploying OceanBase Database, OBClient, and OBProxy: <ul>
   <li>The OceanBase Database version must be in the range of [V4.2.5 BP3 Hotfix3, V4.3.0) or [V4.3.5 BP2 Hotfix1, +∞). </li>
   <li>The OBClient version must be in the range of [V2.2.9, +∞). </li>
   <li>The OBProxy version must be in the range of [V4.3.4, +∞). </li>
   </ul></li></ul>
   <ul><li>The Binlog service does not support IPv6 deployment. </li></ul>
   </ul>
   </p>
   </main>

5. Select a host type. If no corresponding host type is available, click **<UI-TERM key="ocp-v2.src.component.HostTypeSelect.NewModel">Create Host Specifications</UI-TERM>** to add a host type in OCP.

6. Select an IDC. If no corresponding IDC is available, click **<UI-TERM key="ocp-v2.src.component.IdcSelect.NewDataCenter">Create IDC</UI-TERM>** to add an IDC in OCP.

7. Select a host type, and set the connection credentials and host alias for the host.

   | Parameter  |   Description   |
   |-------|----------|
   | Host Type  |  The type of the host to be added. Valid values: Physical Machine and ECS.  |
   | Credentials  |  Select credentials from the password box. If no corresponding credentials are available, click **<UI-TERM key="ocp-v2.src.component.CredentialSelect.AddSecrets">Add Credential</UI-TERM>** to create new connection credentials for the host.<br><ul><li>Credential Name: must start with a letter and end with a letter or a digit. It can contain letters, digits, and underscores. It must be 2 to 32 characters in length. </li><li>Authorization Type: Valid values: **<UI-TERM key="ocp-v2.src.constant.compute.UsernamePassword">Username/Password</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.compute.SshPrivateKey">SSH Private Key</UI-TERM>**, and **<UI-TERM key="ocp-v2.src.constant.compute.ConfiguredPasswordFree">Password-Free</UI-TERM>**. </li><li>User Type: the type of the user to connect to the server. Valid values: **<UI-TERM key="ocp-v2.src.constant.compute.RootUser">Root User</UI-TERM>** and **<UI-TERM key="ocp-v2.src.constant.compute.OrdinaryUsers">General User</UI-TERM>**. <ul><li>**<UI-TERM key="ocp-v2.src.constant.compute.RootUser">Root User</UI-TERM>**: an SSH user with root privileges. </li><li>**<UI-TERM key="ocp-v2.src.constant.compute.OrdinaryUsers">General User</UI-TERM>**: a regular user with root privileges. This user must be configured to execute sudo commands without a password. OCP currently supports configuring password-free execution of all commands via sudo. In other words, add `username ALL=(ALL) NOPASSWD:ALL` to the `/etc/sudoers` file. </li></ul></li><li>Username: required when the user type is **<UI-TERM key="ocp-v2.src.constant.compute.OrdinaryUsers">General User</UI-TERM>**. Enter the user name for connecting to the server. </li><li>Password: required when the authorization type is **<UI-TERM key="ocp-v2.src.constant.compute.UsernamePassword">Username/Password</UI-TERM>**. Enter the password for connecting to the server. </li><li>Private Key: required when the authorization type is **<UI-TERM key="ocp-v2.src.constant.compute.SshPrivateKey">SSH Private Key</UI-TERM>**. Add an SSH credential for the server. </li><li>OCP Private Key File Path: required when the authorization type is **<UI-TERM key="ocp-v2.src.constant.compute.ConfiguredPasswordFree">Password-Free</UI-TERM>**. Enter the path where the host private key file is stored. The default path is `/home/admin/.ssh/id_rsa`. If OCP is deployed by using Docker, use the file path in the Docker container. </li><li>Note: additional information about the credentials. </li></ul> |
   | Host Alias  | Optional. Enter an alias for the host.   |

8. (Optional) Enter a description for the host.

9. Click **<UI-TERM key="ocp-v2.page.Information.Ok">OK</UI-TERM>**.
