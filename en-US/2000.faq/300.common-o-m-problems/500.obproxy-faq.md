# FAQ about OBProxy

This topic describes common issues in the management of OBProxy.

## Feature support

**Q5: Can OCP take over an OBProxy cluster created by other methods?**

A: No. We recommend that you delete the cluster and then reinstall it.

## Use of OBProxy

**Q1: OCP cannot access MetaDB.**

A: If OBProxy has no traffic for 24 hours, the resources of the cluster are deleted, which prevents OBProxy from connecting to MetaDB. This issue is fixed in V1.8.6.

**Q2: You can directly connect to OceanBase Database, but cannot connect to OceanBase Database through OBProxy. Therefore, the `wait cluster accessible` step fails when you create a cluster. Why cannot OBProxy connect to OceanBase Database?**

A: A Squid proxy server is configured on the host. We recommend that you disable the proxy server.

**Q3: When you create a connection on the OBProxy tab of the password box, no content is displayed in the OBProxy drop-down list.**

A: If no OBProxy cluster is created in OCP, the drop-down list is empty. We recommend that you create an OBProxy cluster first.

**Q4: In multi-cluster mode of OCP, you create an OBProxy cluster in a standby OCP cluster and associate it with an OceanBase cluster in the primary OCP cluster. When you switch to the primary OCP cluster, you cannot view the associated OBProxy cluster. How do I solve this issue?**

A: You can restart any node in the standby OCP cluster.

## Installation of OBProxy

**Q1: What address do I enter for the access address when I create an OBProxy cluster?**

A: If F5 is deployed externally, enter the F5 address. If F5 is not deployed, enter the internal proxy address of OCP.

**Q2: The installation of OBProxy fails at the `set root@proxysys password` step. How do I solve this issue?**

A: Before deployment, set the **skip_proxy_sys_private_checked** parameter to `true` on the Create OBProxy Cluster page.

**Q3: The installation of OBProxy fails with the error message `Failed to check odp connection DrizzleConnection`. How do I solve this issue?**

A: The client address used to connect to OBProxy must be in a specific network segment. You can set the **skip_proxy_sys_private_check** parameter to `true` to bypass this restriction.

**Q4: I set the skip_proxy_sys_private_checked parameter to `true` when I create an OBProxy cluster. However, the installation fails at the `set root@proxysys password` step. Why?**

A: We recommend that you check whether the disk space is sufficient. If not, release the space and then retry the installation.

**Q5: The task framework scheduling fails during the installation of an OBProxy cluster. That is, the `Set obproxy user...` step fails on one node without any error message. How do I solve this issue?**

A: Change the status of the task in the task_instance table of MetaDB to `FAILED`, and then retry the task.

**Q6: The deployment of OBProxy by using OCP fails, and the log displays the error message `command nc not found`. Why?**

A: We recommend that you standardize the host before you deploy OBProxy. For more information, see [Standardize a host](../../850.host-features/100.manage-a-host/600.normalization-agent.md).

## Deployment and configuration of OBProxy

Q1: OceanBase Database is deployed in multiple regions, and you need to access the read-only zone. How do I deploy and configure OBProxy?

A: OCP allows you to create multiple OBProxy clusters and associate them with the same OceanBase cluster. OBProxy routes requests based on IDC and region information. When you create an OBProxy cluster for accessing the read-only zone, you must specify the `proxy_idc_name` parameter.

For more information, see [Create an OBProxy cluster](../../500.quickstart/800.quickstart-create-an-obproxy-cluster.md).
