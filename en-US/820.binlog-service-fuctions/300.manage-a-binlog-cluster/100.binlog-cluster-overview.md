# View information about a binlog cluster

On the **<UI-TERM key="ocp-v2.Detail.Overview.BinlogClusterOverview">Binlog Cluster Overview</UI-TERM>** page of a binlog cluster, you can view its basic information, instance information, and binlog server information, and perform routine O&M operations on the binlog cluster.

## Prerequisites

To view information on the **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">Overview</UI-TERM>** page of an Binlog cluster, make sure that you have the following permissions:

* **<UI-TERM key="ocp-v2.Auth.Role.ResourcePermissions">Resource Permissions</UI-TERM>**: **Binlog Service Read-only** permission
* **<UI-TERM key="ocp-v2.Auth.Role.AddRole.MenuPermissions">Menu Permissions</UI-TERM>**: Permission on the **<UI-TERM key="ocp-v2.src.hook.useMenu.BinlogClusterOverview">Binlog Cluster Overview</UI-TERM>** menu of the **<UI-TERM key="ocp-v2.page.Binlog.BinlogService">Binlog Service</UI-TERM>**

## Basic information

In the **<UI-TERM key="ocp-v2.Alarm.Event.Detail.BasicInformation">Basic Information</UI-TERM>** section, you can view basic cluster information in the following fields: **<UI-TERM key="ocp-v2.Binlog.Component.AddBinlogNodeModal.BinlogClusterNameTest">Binlog Cluster Name</UI-TERM>**, **<UI-TERM key="ocp-v2.Component.BinlogInstanceList.Status">Status</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Overview.VersionNumber">Version No.</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Overview.CdcVersion">CDC Version</UI-TERM>**, **<UI-TERM key="ocp-v2.Alarm.Channel.CreationTime">Created At</UI-TERM>**, **<UI-TERM key="ocp-performance-report.ReportTables.ParameterStatInfo.ClusterParamInfoTable.ModificationTime">Modified At</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Overview.MetadbInformation">MetaDB Information</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Overview.SoftwareInstallationDirectory">Software Installation Directory</UI-TERM>**, and **Binlog File Generation Directory**.

| Column          | Description  |
|---------------|--------|
| Binlog Cluster Name | The name of the binlog cluster.  |
| Status          | The current status of the binlog cluster. Valid values: **<UI-TERM key="ocp-v2.src.constant.tenant.NormalOperation">Running</UI-TERM>**, **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.IndexTable.Creating">Creating</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.binlog.OM">In Operation Maintenance</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.binlog.Deleting">Deleting</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.binlog.Starting">Starting</UI-TERM>**, **<UI-TERM key="ocp-v2.Host.Detail.OCPAgent.Restarting">Restarting</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.oceanbase.Stop">Stopping</UI-TERM>**, and **<UI-TERM key="ocp-v2.src.constant.oceanbase.Stopped">Stopped</UI-TERM>**.  |
| Version No.        | The version number of the binlog cluster.   |
| CDC Version      | The OceanBase CDC version number of the binlog cluster.    |
| Created At      | The time when the binlog cluster was created.   |
| Modified At      | The time when the binlog cluster was last modified.   |
| MetaDB Information   | The information about the MetaDB of the binlog cluster. You can click **<UI-TERM key="ocp-v2.Detail.Backup.See">View</UI-TERM>** to view the MetaDB information.   |
| Software Installation Directory  | The installation path of the binlog service, which is the path specified when the binlog cluster was created. For more information, see [Create a binlog cluster](../200.create-a-binlog-cluster.md).   |
| Binlog File Generation Directory   | The storage path of binlog data. Default value: `software installation path/run`  |

## View the binlog instance list

In the **<UI-TERM key="ocp-v2.Component.BinlogInstanceList.BinlogInstanceList">Binlog Instance List</UI-TERM>** section, you can view information about all instances in the binlog cluster in the following columns: **<UI-TERM key="ocp-v2.Component.BinlogInstanceList.BinlogInstanceName">Binlog Instance Name</UI-TERM>**, **<UI-TERM key="ocp-v2.Component.BinlogInstanceList.BusinessTenant">Business Tenant</UI-TERM>**, **<UI-TERM key="ocp-v2.Component.BinlogInstanceList.NodeIp">Node IP</UI-TERM>**, **Conversion Delay**, **<UI-TERM key="ocp-v2.Component.BinlogInstanceList.ConvertRps">Convert RPS</UI-TERM>**, **<UI-TERM key="ocp-v2.Component.BinlogInstanceList.SubscriptionLinks">Subscription Links</UI-TERM>**, and **<UI-TERM key="ocp-v2.Component.ZoneList.State">Status</UI-TERM>**. You can also click the **<UI-TERM key="ocp-v2.Detail.Overview.Stop">Stop</UI-TERM>**, **<UI-TERM key="ocp-v2.src.constant.oceanbase.Start">Start</UI-TERM>**, or **<UI-TERM key="ocp-v2.page.Host.Restart">Restart</UI-TERM>** option in the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.Operation">Actions</UI-TERM>** column of a binlog instance to operate the binlog instance. For more information, see [Manage binlog instances](500.manage-binlog-instance/100.binlog-instance-overview.md).

## View the binlog server list

In the **Binlog Server List** section, you can view information about binlog servers in the following columns: **IP**, **<UI-TERM key="ocp-v2.Component.BinlogServerList.Hostname">Host Name</UI-TERM>**, **<UI-TERM key="ocp-v2.Component.BinlogServerList.ResourceLevel">Resource Level</UI-TERM>**, **<UI-TERM key="ocp-v2.page.Host.HostType">Host Category</UI-TERM>**, **<UI-TERM key="ocp-v2.OBProxy.New.ModelOptional">Host Type</UI-TERM>**, **<UI-TERM key="ocp-v2.Component.ZoneList.AddOBServerDrawer.Model">Model</UI-TERM>**, **<UI-TERM key="ocp-v2.src.component.AddHostDrawer.ComputerRoom">IDC</UI-TERM>**, **<UI-TERM key="ocp-v2.Component.BackupStrategyDetail.Region">Region</UI-TERM>**, and **<UI-TERM key="ocp-v2.Backup.SecondaryBackup.Log.State">Status</UI-TERM>**. You can also click the **<UI-TERM key="ocp-v2.page.Host.Stop">Stop</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Backup.Start">Start</UI-TERM>**, or **<UI-TERM key="ocp-v2.src.constant.compute.Delete">Delete</UI-TERM>** option in the **<UI-TERM key="ocp-v2.Alarm.Rule.Operation">Actions</UI-TERM>** column of a binlog server to operate the binlog server. For more information, see [Manage binlog servers](600.manage-binlog-server/100.add-a-binlog-server.md).

## Perform cluster management operations

You can perform other cluster management operations on the **<UI-TERM key="ocp-v2.Detail.Overview.BinlogClusterOverview">Binlog Cluster Overview</UI-TERM>** page. For more information, see [Add a binlog node](600.manage-binlog-server/100.add-a-binlog-server.md), [Start and stop a binlog cluster](200.stop-and-start-a-binlog-cluster.md), [Restart a binlog cluster](300.restart-a-binlog-cluster.md), and [Delete a binlog cluster](400.delete-a-binlog-cluster.md).

You can perform routine O&M operations on a cluster by using the options provided in the left-side navigation pane. For more information, see [Manage binlog cluster parameters](../400.manage-binlog-cluster-parameters.md).

## Switch between binlog clusters

To view the information about another binlog cluster, click the name of the cluster in the upper-left corner of the **<UI-TERM key="ocp-v2.Detail.Overview.BinlogClusterOverview">Binlog Cluster Overview</UI-TERM>** page to switch to its overview page.
