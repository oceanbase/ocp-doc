# Create a binlog cluster

A binlog cluster is an external service that comprises one or more binlog servers. When the binlog service is started for a tenant in a binlog cluster with multiple binlog servers, a binlog server is selected based on the load balancing logic. When any binlog server fails, a functioning binlog server in the cluster will take over its services.

You can create a binlog cluster based on your business needs.

## Prerequisites

You have logged in to the OceanBase Cloud Platform (OCP) console and been assigned the **ADMIN** or **ORG_ADMIN** role.

## Procedure

1. Log on to the OCP console. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.page.Binlog.BinlogService">Binlog Service</UI-TERM>**.

2. On the **<UI-TERM key="ocp-v2.page.Binlog.ClusterList">Cluster List</UI-TERM>** page, click **<UI-TERM key="ocp-v2.Component.BinlogService.BinlogServiceConfigModal.CreateABinlogCluster">Create Binlog Cluster</UI-TERM>** in the upper-right corner.

3. On the **<UI-TERM key="ocp-v2.Component.BinlogService.BinlogServiceConfigModal.CreateABinlogCluster">Create Binlog Cluster</UI-TERM>** page, configure the basic information of the cluster.

     | Parameter | Description |
     |-----|-------|
     | **<UI-TERM key="ocp-v2.Binlog.Component.AddBinlogNodeModal.BinlogClusterNameTest">Binlog Cluster Name</UI-TERM>**          | Enter a name for the binlog cluster. The name must start with a letter and end with a letter or a digit. It can contain letters, digits, and underscores (_). It must be 2 to 32 characters in length. |
     | **<UI-TERM key="ocp-v2.Binlog.New.SoftwareVersion">Software Version</UI-TERM>**       | The software version of the binlog cluster. If the required software package is unavailable in the list, you can click **<UI-TERM key="ocp-v2.src.component.PackageUploadModal.UploadSoftwarePackage">Upload Package</UI-TERM>** below the list to upload one.  |
     | **<UI-TERM key="ocp-v2.Cluster.Import.Address">Access Address</UI-TERM>**          | The access address of the binlog cluster, which is used for request forwarding and load balancing during the communication between OBProxy and the binlog cluster.   |
     | **<UI-TERM key="ocp-v2.Binlog.New.AccessPort">Access Port</UI-TERM>** | The access port of the binlog cluster, which is **2983** by default. You can change the access port.   |

4. Specify the information of the MetaDB.

   You need to specify the information about a MySQL tenant for storing the metadata of the binlog service. We recommend that you do not use a business cluster as the MetaDB.

     | Parameter | Description |
     |-----|-------|
     | **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.ClusterName">Cluster Name</UI-TERM>**    | Select an existing OceanBase cluster as the MetaDB for the binlog service. |
     | **<UI-TERM key="ocp-v2.Detail.Resource.Trend.TenantName">Tenant Name</UI-TERM>**        | Select a MySQL tenant from the cluster.   |
     | **<UI-TERM key="ocp-v2.Detail.Overview.DatabaseUsername">Database Username</UI-TERM>**        | Select a user in the MySQL tenant.  |
     | **<UI-TERM key="ocp-v2.Detail.Overview.DatabaseName">Database Name</UI-TERM>**          | The name of the MetaDB, which is `binlog_database` by default. You can change the name.   |

5. Deploy the binlog cluster.

   Each binlog cluster comprises multiple binlog servers. The following table describes the parameters to be specified for each binlog server.

   |   Parameter   | Description   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Cluster.New.ComputerRoom">IDC</UI-TERM>**     | Select the IDC to which the binlog server belongs. A binlog server can belong to only one IDC.  |
   | **<UI-TERM key="ocp-v2.Component.ZoneList.AddOBServerDrawer.Model">Model</UI-TERM>**       | Optional. If you select a model, the host list is filtered based on the model.   |
   | **<UI-TERM key="ocp-v2.Detail.TakeOver.Host">Host</UI-TERM>**  | You can select or add hosts.   |

6. You can add and configure startup parameters one by one in the **<UI-TERM key="ocp-v2.Component.AddOBServerDrawer.ParameterSettings">Parameter Settings</UI-TERM>** section.

7. You can specify a custom software installation path in the **<UI-TERM key="ocp-v2.Component.AddOBServerDrawer.CustomSettings">Custom Settings</UI-TERM>** section. The default path is `/home/admin/binlogservice`. You can change the path.

8. Click **<UI-TERM key="ocp-v2.Oracle.Component.RoleSelect.Submitted">Submit</UI-TERM>**.

9. After a cluster creation task is submitted, you can view the task progress in **<UI-TERM key="ocp-v2.src.hook.useMenuOptions.TaskCenter">Task Center</UI-TERM>**.

## Cluster list

After the cluster is created, you can view the cluster information in the following columns on the **<UI-TERM key="ocp-v2.page.Binlog.ClusterList">Cluster List</UI-TERM>** page: **<UI-TERM key="ocp-v2.Detail.Overview.BinlogClusterName">Binlog Cluster Name</UI-TERM>**, **<UI-TERM key="ocp-v2.page.Binlog.Status">Status</UI-TERM>**, **<UI-TERM key="ocp-v2.Resource.Component.Block.AllocatedCpu">Allocated CPU</UI-TERM>**, **<UI-TERM key="ocp-v2.Cluster.Component.WaterLevel.AllocatedMemory">Allocated Memory</UI-TERM>**, **<UI-TERM key="ocp-v2.Cluster.Component.WaterLevel.DiskUsed">Data Disk Used</UI-TERM>**, **<UI-TERM key="ocp-v2.Binlog.Component.UpgradeBinlogModal.VersionNumber">Version No.</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Database.Created">Created At</UI-TERM>**, and **<UI-TERM key="ocp-v2.page.MultiCluster.Parameter.ModificationTime">Modified At</UI-TERM>**.

* You can click the name of the cluster to go to its **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** page. For more information, see [View information about a binlog cluster](300.manage-a-binlog-cluster/100.binlog-cluster-overview.md).
* You can filter the binlog clusters by status.
