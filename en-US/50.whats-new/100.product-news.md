# Product updates

## OCP V4.4.0 BP3

* Added the ability to analyze materialized views. For periodically refreshed materialized views, a new GUI page is provided to display the refresh status analysis, including refresh time and delay.
* Optimized the logic for configuring Cgroups to ensure their stable operation and enhanced alerting capabilities in case of exceptions.
* Added support for adaptive compaction state control (`_enable_adaptive_compaction`) during cluster upgrades. This feature is automatically disabled during the upgrade and re-enabled afterward.

## OCP V4.4.0 BP2

* Supports alerts for materialized views.
* Supports configuring the timeout period for subtasks of the OCP task engine.

## OCP V4.4.0

The OCP V4.4.0 version was officially released! This upgrade focuses on intelligent operations, security reinforcement, and comprehensive monitoring capabilities, providing all-round support for enterprise database O&M management.

* **Real-time monitoring**

  In modules such as monitoring and alarm, disaster recovery management, backup and restore, and emergency plan management, we have made in-depth optimizations, significantly improving the convenience and usability of operations, helping you easily handle database operations.

### Key Features Interpretation

#### Real-time monitoring

To address the complexity of end-to-end performance monitoring and fault location in a distributed database environment, OCP innovatively introduced an end-to-end real-time monitoring solution. This solution establishes a monitoring system covering the OBProxy, OceanBase cluster, tenants, servers, and Units. With its three core capabilities, this solution enhances the overall O&M experience.

* **3D topology visualization**: A dynamic 3D engine is adopted to visually display the logical relationships and physical deployment of OBProxy to the cluster, cluster to the host, and tenant to OBServer. You can drill down the hierarchical architecture from the global view to the individual unit. The resource distribution and the dependency relationship are clearly visible, making the operating status of the distributed architecture transparent.

* **Monitor multi-dimensional indicators and accurately identify performance changes**：Integrate 10+ key performance metrics, such as QPS, TPS, RT, number of connections, and CPU/memory usage. Compare the current performance to historical trends to precisely locate performance changes. The system supports viewing related alerts and navigating to the alert center directly in the topology diagram for one-click root-cause tracing. This enhances the efficiency of fault detection.

* **Dual-mode data display for comprehensive operations and maintenance scenarios**: A structured tabular data view is provided, complemented by graphical and digital information to meet the needs of both managers for global situational awareness and technicians for in-depth analysis, effectively reducing the cognitive and management complexity of distributed systems.

Through the full-chain real-time monitoring solution, users can better manage and optimize system performance, thereby improving system stability and reliability in daily operations, troubleshooting, and dashboard displays.

#### Key Management Service transparent data encryption

The Transparent Data Encryption (TDE) feature of OceanBase Database is a powerful data protection solution designed to ensure the security of data stored on disk. It employs a transparent encryption mechanism, where data is automatically encrypted during the write process to storage devices and automatically decrypted when read. This transparent process effectively prevents unauthorized access by hackers or malicious users from sensitive data stored in data files, database backups, or disk storage.

OceanBase Database supports tablespace-level Transparent Data Encryption (TDE). The smallest encryption unit is a table in a user-defined encrypted tablespace. A tablespace is a set of tables and is an concept designed to support the compatibility with Oracle databases. Each tablespace is encrypted with an encryption algorithm and a data key. Each tenant has a primary key. The primary key is used to encrypt the data key of the tablespace to prevent unauthorized decryption. Usually, the primary key is stored in a dedicated Keystore.

KMS supports a series of key management features, including key generation, storage, backup, recovery, and destruction. Through KMS, you can conveniently manage access to digital assets and ensure that only authorized users can access specific data resources. Additionally, KMS helps prevent security risks such as key loss and forgetting.

To implement key management uniformly, OCP acts as a proxy for KMS services, providing a unified key management service and interface that abstracts away the differences between various cloud vendors' KMS services. Users only need to provide the access domain name, AccessKey (AK), Secret Key (SK), and main key ID of Alibaba Cloud or Tencent Cloud to easily enable the KMS transparent data encryption (TDE) feature for a tenant.

### New feature

#### Basic Operations Management

1. **Cluster management**: When you upgrade the cluster, the system automatically prompts you that the dynamic partitioning feature is enabled. This avoids DDL operations being disabled during the upgrade, which can affect or disrupt the business. Supported OceanBase versions: [V4.2.5 BP2, +∞).
2. **Cluster management**: OceanBase stops relevant operations upon detecting that the host does not support the AVX instruction set during installation, deployment, or upgrades to avoid potential compatibility issues. OceanBase versions V4.2.5 through V4.2.5 BP2 and 4.3.5 through 4.3.5 BP4 are supported.
3. **Cluster Management**: Displays primary/standby, major compaction, and backup information at the tenant level for easy reference to the cluster status.
4. **Tenant management**: When creating a MySQL tenant, you can set the `ob_compatibility_control` variable. OceanBase Database supports this feature in the following versions: [V4.2.3, V4.3.0) and [V4.3.2, V4.3.5 BP3).
5. **Tenant Management**: Custom tenant connection strings are supported, making it easy for users to access databases through different domains.
6. **Tenant management**: You can grant the `Create routine` permission to a user in a MySQL tenant. The OceanBase Database version must be within [V4.2.2, V4.3.0) or [V4.3.1, +∞).

#### Monitoring and alarm

1. Supports the synchronization status alert (SYNCHRONIZATION_STATUS) of primary/standby OceanBase clusters in the V2.x and V3.x versions.
2. Added 8 new tenant-level monitoring metrics: MemStore Read Lock Request Success Rate, MemStore Write Lock Request Success Rate, RPC Request Success Rate, GTS Requests, Transaction Rollback Ratio, Fuse Row Cache Hit Ratio, Schema Cache Hit Ratio, and Temporary Page Cache Hit Ratio.
3. Two new cluster-level metrics, RPC Network Latency and RPC Delivery Failure during the sampling period, are added.
4. It can be displayed to show the maximum, average, and current values of the monitored metric in the specified time range for the ODP service cluster.

#### Disaster recovery management

1. A primary tenant can serve as the source in an active-standby scenario, or it can be switched to another standby tenant as the new source for data synchronization. This feature allows users to perform disaster recovery drills across different regions.
2. Instandby replication mode of an archive-based primary-standby deployment, you can use the `ocp.standby.tenant.restore.advance.seconds` parameter to specify the point in time for point-in-time restore of the standby tenant. The default value is the current time minus 60 seconds.
3. The tenant overview page supports showing the primary/standby tenant relationships.

#### Preplan management

1. When two tenants are configured in active/standby mode and the service names are set to be the same for both tenants, the system supports automatically switching the read traffic from the standby tenant to the primary tenant when a service anomaly occurs in the standby tenant.
2. The OBD process (OBM) can automatically restart after a crash, and the process restarts only once within 30 minutes.

#### Manage Binlog

You can set a Clog starting point by using a Binlog instance. This way, you can subscribe to required Clogs at the downstream.

#### Restore a backup

1. You can enable or disable the dynamic partitioning feature based on your business requirements during a full restore to prevent data loss. The feature is supported in OceanBase Database V4.3.5 BP2 and later.
2. Supports quick tenant recovery: The recovered tenants are in read-only mode and do not support compaction or data backup. The supported OceanBase versions are [V4.3.3, +∞).
3. A tenant marked as locked is skipped by default during backup at the cluster level if you configure a backup strategy at the cluster level.
4. Enables you to configure advanced options for object storage compatible with the S3 protocol:
   * delete_mode=delete (default)/tagging. Supported OceanBase Database versions: [V4.2.3.0, V4.2.5.0), [V4.3.0, +∞).
   * checksum_type=md5 (default)/crc32. Supported OceanBase Database versions: [V4.2.1.6, V4.2.2.0), [V4.2.3.0, +∞).
   * addressing_model=virtual_hosted_style (default) / path_style, supported OceanBase versions are [V4.2.1.9, V4.2.2.0), [V4.2.5.1, V4.3.0.0), and [V4.3.5.0, +∞).

### Product optimization

#### Cluster management

1. The Resource tab now provides a visual display of the remaining CPU, memory, log disk, and data disk space, helping users to monitor resource usage in real time and improve O&M efficiency.
2. If there is only one OBServer node in a zone of a cluster and the node has replicas, you cannot reinstall the OBServer node.

#### Tenant management

You can search for tenant specifications by unit specification name to improve query efficiency when there are many tenant specifications.

#### Host management

You can view the standardization report of a host in the Actions column of the host list.

#### Backup and restore

1. The sys tenant, as a system management tenant, does not support the backup and restore feature. The backup and restore page for the sys tenant has been removed to avoid user confusion and misoperations. Supported OceanBase Database versions: [V4.0, +∞).
2. When you restore a tenant, you can choose to view the task progress in the Task Center or continue the operation on the restore page.

#### Others

1. In scenarios where a large model is not configured, the AI assistant provides basic conversation capabilities and supports document search.
2. The display length limit for tags on the details pages of clusters, tenants, OBProxies, and hosts has been removed.
3. The Operation Audit feature now supports displaying the client IP address used to access the database.

### Changes in behavior

1. Due to changes in the behavior of Tencent Cloud COS, database log backup may become abnormal. We recommend that you use the S3 protocol instead of the COS protocol. Supported OceanBase Database versions: [V4.2.1.9, V4.2.2), [V4.2.5.0, V4.3.0), and [V4.3.3.0, V4.4.0). OceanBase Database V4.4.0 and later versions no longer support the COS protocol.
2. The restriction on exclusive host usage for the Binlog service has been removed, allowing multiple services to share the same host (recommended only for testing environments), effectively reducing deployment and O&M costs.
