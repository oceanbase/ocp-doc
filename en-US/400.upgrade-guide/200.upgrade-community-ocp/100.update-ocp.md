# Use the GUI to upgrade OCP

This topic describes how to use OceanBase Deployer (OBD) to upgrade OCP-CE to the latest version.

## Prerequisites

* Only OCP V4.0.3 and later versions support this upgrade method. For other versions, contact Technical Support.
* Java is installed and configured. Only JDK17 is supported.
* You have obtained the `ocp-all-in-one-4.4.0-YYYYMMDDhhmmss.el7.x86_64.tar.gz` package by referring to [Installation preparation](../../300.deployment-guide/200.deploying-community-ocp/400.installation-preparation.md) and uploaded the package to any directory of the OCP host. Then, run the following command to decompress the package.

   ```bash
   tar zxf ocp-all-in-one-4.4.0-YYYYMMDDhhmmss.el7.x86_64.tar.gz
   ```

## Procedure

### Step 1: Start obd

1. Log in to the node where the OBD control server is located.

2. Run the following command to go to the `bin` directory of the decompressed package and start the deployment program.

    ```bash
    cd ocp-all-in-one/bin && bash install.sh
    ```

3. Run the following command to make the environment variables effective.

    ```bash
    source ~/.oceanbase-all-in-one/bin/env.sh
    ```

4. Run the `obd web upgrade` command. In the returned information, obtain the IP address of the upgrade wizard page.

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/upgrade.png)

### Step 2: Go to the OCP upgrade wizard page

Open a browser and enter the IP address obtained in **Step 1**. Then, click **Start Upgrade**.

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E5%8D%87%E7%BA%A7%E5%90%91%E5%AF%BC.png)

### Step 3: Configure deployment information

1. Specify the name of the OceanBase cluster to be managed.

   The system automatically obtains the names of all clusters managed by OBD. You can select the name of the cluster to be upgraded from the **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.ClusterName">Cluster Name</UI-TERM>** drop-down list.
   If the cluster to be upgraded (such as a cluster deployed by using Docker) is not managed by OBD, you can manually enter the cluster name. After the cluster is upgraded, OBD automatically manages the cluster.

2. Select the version of the product to be upgraded.

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E5%8D%87%E7%BA%A7%E9%85%8D%E7%BD%AE.png)

### Step 4: Verify the connectivity with MetaDB

1. Verify whether the MetaDB connection information is correct and click **<UI-TERM key="ocp-v2.page.Credential.Host.Verification">Verify</UI-TERM>**. The system verifies whether the MetaDB is connected.

   The installation program automatically obtains the MetaDB configuration information based on the OCP of the current host. Check whether the information in the form is consistent with the expected environment to be upgraded. The OCP upgrade program is executed based on the information.

2. Fill in the information about the operating system user and click **<UI-TERM key="ocp-v2.page.Credential.Cluster.Verification">Verify</UI-TERM>** to test the user connectivity.

   |  Parameter   |   Description   |
   |---------|----------|
   |  Username   | The username of the host operating system user. The username must have sudo privileges.    |
   |  User Password | The password of **<UI-TERM key="ocp-v2.Channel.FormComponent.EMailForm.Username">Username</UI-TERM>**. If the host is configured with password-free login, you can ignore this parameter.     |

3. Click **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">Next</UI-TERM>**.

![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E8%BF%9E%E6%8E%A5%E4%BF%A1%E6%81%AF.png)

### Step 5: Perform a precheck

The precheck verifies whether your environment meets the requirements for upgrading OCP.

The system obtains the OCP-related configuration information based on the MetaDB configuration information. To ensure the consistency of the management features, the upgrade program upgrades the platform management service (COP Server) and all host agent services (OCP Agent) managed by it.

1. Confirm whether the upgrade content in **Installation Configuration** and **Upgrade Configuration** meets your expectations. Then, click **<UI-TERM key="ocp-v2.Detail.TakeOver.Precheck">Precheck</UI-TERM>**.

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E5%8D%87%E7%BA%A7%E9%85%8D%E7%BD%AE%E4%BF%A1%E6%81%AF.png)

2. View the check results.

   * If the check passes, click **<UI-TERM key="ocp-v2.Detail.TakeOver.Next">Next</UI-TERM>**.
   * If the check fails, you can fix or ignore the failed items. If you choose to fix, click **<UI-TERM key="ocp-v2.Cluster.Import.ReCheck">Recheck</UI-TERM>** after the fix is completed. The system re-executes the precheck program. If you choose to ignore, click **Ignore All Failed Items**. In this case, the status of the failed items changes to **Ignored** and you can click **<UI-TERM key="ocp-v2.Detail.TakeOver.Next">Next</UI-TERM>**.

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>Ignoring all failed items may cause the upgrade to fail. We recommend that you fix the failed items before proceeding. </p>
   </main>

   ![3](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E5%8D%87%E7%BA%A7%E9%A2%84%E6%A3%80%E6%9F%A5.png)

### Step 6: Upgrade OCP

During the OCP upgrade, you can view the detailed upgrade logs in the **Upgrade Log** module.

* If the OCP upgrade is successful, you can view the OCP login information, including the URL, username, and password, in the **Upgrade Log** module.

* If the OCP upgrade fails, view the log information to obtain the cause of the failure and contact Technical Support. After you locate and fix the installation failure, click **Reupgrade**. The system re-executes the failed upgrade steps.

<main id="notice" type='explain'>
<h4>Note</h4>
<p>The OCP upgrade process may take a long time. Please wait patiently. </p>
</main>

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/ocp%E5%8D%87%E7%BA%A7%E6%88%90%E5%8A%9F.png)

### Step 7 (Optional): Use OBD to take over the original MetaDB cluster

After you use OBD to upgrade OCP, you can use OBD to manage the original MetaDB cluster of OCP. You just need to copy the information about the original MetaDB cluster to the OBD directory. The command is as follows:

```bash
cp -rf ~/.ocp-installer/cluster/<metadb_cluster_name> ~/.obd/cluster/
```

In this command, `metadb_cluster_name` indicates the name of the original MetaDB cluster. You need to replace it with the actual name.
