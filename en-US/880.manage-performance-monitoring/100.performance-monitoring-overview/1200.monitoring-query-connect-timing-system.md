# Monitor query to external time series system

Starting from OCP V4.3.0, the monitor query supports connecting to an existing time series system, such as Prometheus and SLS metricStore, to reduce the pressure on ocp-server for collecting and computing monitoring data and improve the throughput of the query interface. You can quickly use the feature by simply configuring the target address and authentication information.

## Prerequisites

* You have collected Agent monitoring time series data through Agent Remote push or Pushgateway. For more information, see [Monitor query to external time series system](../../2000.faq/400.common-monitoring-problems/400.ocp-agent-data-push-scheme.md).

* The network from the OCP container to the corresponding time series system is connected.

## Connect to Prometheus

The following table describes the Prometheus-related configurations in the `config_properties` table of the `meta` tenant.

| key  |  Built-in  |  Required  |  Effective after restart  |  Description  |
|------|------------|------------|---------------|--------|
|  `ocp.monitor.metric.service.type`  |  Yes  |  Yes  |  Yes   |  The type of the data source for the monitor query. The default value is `LOCAL`, which indicates MonitorDB. You must set this parameter to PROMETHEUS.  |
|  `ocp.monitor.metric.collect.service.type`  |  Yes  |  Yes  |  Yes   |  The type of the data collection. The default value is `LOCAL`, which indicates that data will be written to MonitorDB for gray release. If you do not want to write data to MonitorDB, you must set this parameter to PROMETHEUS.  |
|  `ocp.monitor.query.prometheus.address`  |  No  |  Yes  |  Yes   |  The deployment address of the Prometheus service, for example, `127.0.0.1`. |
|  `ocp.monitor.query.prometheus.port`  |  No  |  Yes  |  Yes  |  The port of the Prometheus service, for example, `9090`.  |
|  `ocp.monitor.query.prometheus.authentication.username`  |  No  |  No  |  Yes  |  The username for HTTP authentication when you request the Prometheus query API. This parameter is optional.  |
|  `ocp.monitor.query.prometheus.authentication.password`  |  No  |  No  |  Yes  |  The password for HTTP authentication when you request the Prometheus query API. This parameter is optional.  |
|  `ocp.monitor.query.prometheus.connect.timeout`  |  No  |  No  |  Yes  |  The socket connection timeout when you request the Prometheus query API, in ms. The default value is 3000 ms.  |
|  `ocp.monitor.query.prometheus.read.timeout`  |  No  |  No  |  Yes  |  The response timeout when you request the Prometheus query API, in ms. The default value is 3000 ms.  |

The above-mentioned non-built-in parameters are not configured in the `config_properties` table. Therefore, you cannot view or set these parameters in the system parameters. You need to insert a record through the following SQL statement when you use the feature for the first time.

For example, the following SQL statement inserts a record for the `ocp.monitor.query.prometheus.address` parameter:

```sql
INSERT INTO `config_properties` (`key`, `value`, `need_restart`, `description`) VALUES ('ocp.monitor.query.prometheus.address1', '127.0.0.1', 1, 'prometheus service deployment address');
```

After all configurations are updated, restart OCP. You can see that the data sources for the white-screen monitoring and alerts in OCP have been replaced with the corresponding Prometheus services.

## Connect to SLS

The following table describes the SLS-related configurations, which are similar to those of Prometheus.

|  key  |  Built-in  |  Required  |  Effective after restart  |  Description  |
|-------|------------|-----------|---------------|----------|
|  `ocp.monitor.metric.service.type`  |  Yes  |  Yes  |  Yes  |  The type of the data source for the monitor query. The default value is `LOCAL`, which indicates MonitorDB. You must set this parameter to SLS.  |
|  `ocp.monitor.metric.collect.service.type`  |  Yes  |  Yes  |  Yes   |  The type of the data collection. The default value is `LOCAL`, which indicates that data will be written to MonitorDB for gray release. If you do not want to write data to MonitorDB, you must set this parameter to SLS.  |
|  `ocp.monitor.query.sls.end-point`  |  No  |  Yes  |  Yes  |  The endpoint of the SLS service.  |
|  `ocp.monitor.query.sls.sls-project` |  No  |  Yes  |  Yes  |  The project space of SLS.  |
|  `ocp.monitor.query.sls.sls-metricstore`  |  No  |  Yes  |  Yes  |  The MetricStore of SLS.  |
|  `ocp.monitor.query.sls.access-key`  |  No  |  Yes  |  Yes  |  The AccessKey ID of SLS.  |
|  `ocp.monitor.query.sls.access-secret`  |  No  |  Yes  |  Yes  |  The AccessKey secret of SLS.  |
|  `ocp.monitor.query.sls.connect.timeout`  |  No  |  No  |  Yes  |  The socket connection timeout when you request the SLS query API, in ms. The default value is 3000 ms.  |
|  `ocp.monitor.query.sls.read.timeout`  |  No  |  No  |  Yes  |  The response timeout when you request the SLS query API, in ms. The default value is 3000 ms.  |

Similar to the Prometheus configurations, the above-mentioned non-built-in parameters are not configured in the `config_properties` table. Therefore, you cannot view or set these parameters in the system parameters. You need to insert a record through the following SQL statement when you use the feature for the first time.

For example, the following SQL statement inserts a record for the `ocp.monitor.query.sls.sls-metricstore` parameter:

```sql
INSERT INTO `config_properties` (`key`, `value`, `need_restart`, `description`) VALUES ('ocp.monitor.query.sls.sls-metricstore', 'ob_metricstore', 1, 'SLS metricStore');
```

After all configurations are updated, restart OCP. You can see that the data sources for the white-screen monitoring and alerts in OCP have been replaced with the corresponding SLS services.
