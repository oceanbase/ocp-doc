# Call an alert API

This topic provides a script example that shows how to integrate with the alert API and test the alert API.

## Call an OCP API

The following script provides an example of calling the "Push an alert event" API.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>Pushing an alert event means sending the alert to OCP for processing. </p>
  </main>

```python
#!/usr/bin/env python
# -*- coding: utf-8 -*-

import base64
import requests
import json

data = {
    "alarmType": "your_alarm_type",
    "labels": {"key":"value"},
    "target":"alarm_target",
}

base64userpass = base64.b64encode('{0}:{1}'.format('username', 'password'))
headers = {
    'Content-Type': 'application/json',
    'Accept': 'application/json',
    "Authorization": "Basic %s" % base64userpass,
}

resp = requests.post(url='http://xxx.xxx.xxx.xxx:8080/api/v2/alarm/alarms', headers=headers, data=json.dumps(data))
jresp = json.loads(resp.text)
print(jresp)
```

## Example of alert forwarding to OCP

After an alert is generated in OCP, the alert message is sent through the alert channel. You can configure a shell script or a Python script as the alert channel. This example describes how to send an alert through the alert channel. The `send_alarm` function retrieves the values of alert-related variables from the environment variables by using os.environ.

The following is a Python script example. For more examples, see [View examples of alert channel configurations](../../../860.alert-management/500.manage-alert-channels/600.examples-of-alert-channel-configuration.md).

```python
#!/usr/bin/env python
# -*- coding: utf-8 -*-

# Note: The first line of the script must be a shebang line that specifies the program to be executed. Only Python and Bash are supported.

import json
import requests
import os
import sys

ACCESS_TOKEN = "Ding Talk Token"

def send_alarm():
    """
    You can retrieve the values of alert-related variables from the environment variables by using os.environ.
    For more information about the supported variables, see 《User Guide/Appendix 4: OCP alert template variables》.
    """
    message = os.environ['message']
    data = {
        "msgtype": "markdown",
        "markdown": {
            "text": message
        }
    }
    resp = requests.post("https://oapi.dingtalk.com/robot/send?access_token=" + ACCESS_TOKEN, json=data)
    resp.close()
    response = json.loads(resp.text)

    # The return value is written to the standard error (stderr) or standard output (stdout) for verification. The verification is performed in the following order: stderr, stdout.
    if not response['errcode'] == 0:
        sys.stderr.write(resp.text)
    else:
        print(resp.text)

def main():
    """
    If the alert is sent, the return value is 0.
    If the alert fails to be sent, the error message is written to stderr, and the return value is not 0.
    """
    try:
        send_alarm()
        return 0
    except Exception as e:
        sys.stderr.write(str(e))
        return 1

if __name__ == "__main__":
    sys.exit(main())
```

## Example of integrating OCP alerts with your alert platform

This topic describes how to integrate OCP alerts with your alert platform.

### Background information

To integrate OCP alerts with your alert platform, you must call the API to query alert events. For more information, see [Query current alerts](200.fetch-actived-alarms.md) or [Query historical alerts](300.fetch-history-alarms.md).

### Scenario 1: View real-time alerts

To view real-time alerts in the system, you can refer to the code example and periodically call the API to query the list of alert events to obtain the objects that are currently being alerted.

#### Code example

```javascript
curl 'http://OCP-IP:8080/api/v2/alarm/alarms?isSubscribedByMe=false&status=Active&page=1&size=10' \
--user username:password \
--compressed \
--insecure
```

In this example, `data.page.totalPages` indicates the total number of pages for real-time alerts. You can view the alerts on a specific page by setting the page number to the desired value. For example, to view the alerts on page 2, set the page number to 2:

```javascript
curl 'http://OCP-IP:8080/api/v2/alarm/alarms?isSubscribedByMe=false&status=Active&page=2&size=10' \
--user username:password \
--compressed \
--insecure
```

Key information:

|     Parameter      |                                                                                                      Description                                                                                                      |
|-------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| alarmType   | The name of the alert rule.                                                                                                                                                                                                       |
| activeAt    | The time when the alert was triggered. This time is in Coordinated Universal Time (UTC). You must convert it to the local time when you use it.                                                                                                                                                                                 |
| updatedAt   | The time when the alert was last updated. This time is in UTC. You must convert it to the local time when you use it.                                                                                                                                                                                 |
| target      | The object of the alert. For example, a tenant in a cluster.                                                                                                                                                                                             |
| description | The description of the alert.                                                                                                                                                                                                      |
| summary     | The summary of the alert.                                                                                                                                                                                                      |
| level       | The level of the alert.                                                                                                                                                                                                        |
| labels      | Other information, such as the cluster name (obregion or ob_cluster in earlier versions), tenant name (tenant_name), and server IP (svr_ip). The labels that end with _1, _2, or _3 are non-standard internationalization content. We recommend that you do not use them because they are not supported in later versions. For more information about the available labels, see [Sample alert channel configurations](../../../860.alert-management/500.manage-alert-channels/600.examples-of-alert-channel-configuration.md). |

### Scenario 2: Integrate with your alert platform

You can refer to the code example in Scenario 1 and periodically call the API to query the list of alert events and update the status of the alert objects (target) that you have received.

The updated information includes:

* The time of the last alert: The duration of the alert can be calculated based on the time when the alert was triggered.

* The status of the alert: If no alerts for a specific target are returned in a batch of requests (a batch consists of multiple page requests to retrieve all alerts), the status of the alert is set to "Recovered".

* You can statistically count the number of alerts at each level in real time based on the alert level.
