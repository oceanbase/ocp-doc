# Query monitoring data

## Feature description

Queries monitoring data for the specified metric. You must specify the query time range and the array of metrics. The query range is specified by tags, and the data is summarized by specified tags. The results are output in time series.

Regardless of the time range you select, the result data scale approaches 1,440 sampling points.

## Call instructions

### Interface constraints

You must authenticate by using OCP application services.

### Request path

`GET /api/v2/monitor/metric`

### Request parameters

**body:**

|     Parameter     |     Type      | Required |            Example value             |       Description        |
|------------|-------------|----|----------------------------|-----------------|
| startTime | Datetime    | Yes  | 2020-02-16T05:32:16+08:00  | The start time of the monitoring data.      |
| endTime   | Datetime    | Yes  | 2020-02-16T07:32:16+08:00  | The end time of the monitoring data.      |
| metrics    | StringArray | Yes  | io_read_time,io_write_time | The array of monitoring metrics.        |
| groupBy    | StringArray | Yes  | app,ob_cluster_name,ob_cluster_id | The summary tags of the monitoring data.      |
| interval   | Integer     | Yes  | 60                         | The time granularity of the monitoring data, in seconds. |
| minStep    | Integer     | No   | 10                         | The minimum sampling interval for monitoring results, in seconds. The default value is 0. |
| maxPoints  | Integer     | No   | 360                        | The maximum number of points in the monitoring results. The default value is 1440.        |
| labels     | StringArray | Yes  | app:ob,ob_cluster_name=foo        | The filter conditions of the monitoring data.      |

### Return result

**Basic data structure**

|     Parameter      |    Type    |          Description           |
|-------------|----------|-----------------------|
| data        | Object   | The request data.                |
| ├─ contents | Array    | The array of monitoring samples. The data structure of the samples varies based on the monitoring metrics queried. For more information, see **Monitoring sample data structure**.      |
| successful  | Boolean  | Specifies whether the request is successful.               |
| timestamp   | Datetime | The timestamp when the server finishes the request.          |
| duration    | Integer  | The time taken by the server to process the request, in milliseconds.       |
| status      | Integer  | The HTTP status code that conforms to the HTTP status specification. |
| traceId     | String   | The Trace ID of the request, which is used to troubleshoot issues.  |
| server      | String   | The address of the server that responds to the request.          |

**Monitoring sample data structure**

|    Parameter     |   Type    |                 Description                 |
|-----------|---------|------------------------------------|
| timestamp | Integer | The sample time, which is the number of seconds since 1970-01-01 00:00:00. |
| Metric A      | Float   | The sample value of the corresponding metric.                           |
| Metric B      | Float   | The sample value of the corresponding metric.                           |

## Example

### Request example

Monitor the data from 2020-11-11 18:30:00.000+08:00 to 2020-11-11 19:00:00.000+08:00; the monitoring metrics are `net_recv` and `net_send`, with a sampling interval of 60 seconds; the metric values are app=ob, ob_cluster_name=ob1, ob_cluster_id=1; the monitoring data is aggregated by the three tags: app, ob_cluster_name, and ob_cluster_id:

```json
/api/v2/monitor/metric?startTime=2020-11-11T18%3A30%3A00.000%2B08%3A00&endTime=2020-11-11T19%3A00%3A00.000%2B08%3A00&interval=60&metrics=net_recv%2Cnet_send&labels=app%3Aob%2Cob_cluster_name%3Aob1%2Cob_cluster_id%3A1&groupBy=app%2Cob_cluster_name%2Cob_cluster_id
```

where:

* app: the source of the monitoring data. Valid values: `host`, `ob`, and `obproxy`, which respectively represent host monitoring, OceanBase monitoring, and OBProxy monitoring.
* ob_cluster_name: the name of the OceanBase cluster being monitored.
* ob_cluster_id: the ID of the OceanBase cluster being monitored.
