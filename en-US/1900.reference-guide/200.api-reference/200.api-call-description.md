# API call instructions

This topic describes how to call the open API of OCP by using HTTP. It also provides an example of how to call the "list clusters" API.

## Request structure

A complete HTTP request consists of **request URI**, **request method**, **request headers**, and **request body**.

## Request URI

The request URI consists of the following components:

```json
{scheme}://{endpoint}/{resource-path}?{query-string}
```

|      Field       |                                       Description                                        |
|---------------|---------------------------------------------------------------------------------|
| scheme        | The transmission protocol. Generally, it is `http` or `https`.                                                   |
| endpoint      | The endpoint of OCP. For example, `xxx.xxx.xxx.xxx:8080`, which is determined by the specific deployment.                                   |
| resource-path | The resource path of the interface. For the resource path of each interface, see the "Request Path" section in the corresponding interface documentation. For example, the resource path of "List clusters" is `/api/v2/ob/clusters`. |
| query-string  | The query parameters. This parameter is optional. It is in the format of `a=10&b=hello` and contains several key-value pairs. The query-string and resource-path are separated by `?`.    |

A complete URI for the **List clusters** request is as follows:

```java
http://xxx.xxx.xxx.xxx:8080/api/v2/ob/clusters
```

## Request method

The HTTP method, which includes: GET, PUT, POST, and DELETE. The request method for each interface is described in detail in the corresponding interface documentation.

For example, the request path for "List clusters" is `GET /api/v2/ob/clusters`. The request method for this interface is therefore "GET".

## Request headers

The request headers contain additional information about the request, such as the language and authentication information.

|       Name        | Required |                              Description                               |                   Example                   |
|-----------------|----|---------------------------------------------------------------|----------------------------------------|
| Content-Type    | Yes  | The type of the message body. OCP uses the application/json type for the message body.                      | application/json                       |
| Accept-Language | No  | The language supported by the client. OCP Open API supports internationalization and returns content in the specified language based on the client's language settings.       | en-US, en, q=0.9 zh-CN |
| Authorization   | Yes  | The authentication information. OCP Open API uses HTTP Basic authentication. The username and password are encoded in Base64. | Basic Zm9vOmJhcg==                     |

## Request body

The request body is optional and contains the business data sent to the server. OCP Open API uses the JSON format for the request body.

## Authentication

OCP allows you to use the Access Key and Secret Key (AK/SK) or HTTP Basic authentication to call open APIs.

* HTTP Basic authentication

   To call an open API, you must specify the `Authorization` attribute in the request message header and specify the Base64 encoding of the username and password.

   For example, if the password of the foo user is bar, you must specify the request message header when you call an OCP open API with the foo user:

   ```java
   Authorization: Basic Zm9vOmJhcg==
   ```

   Here, `Zm9vOmJhcg==` is the Base64 encoding of `foo:bar`.

   <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>HTTP Basic authentication may cause the password to be leaked. We recommend that you use the AK/SK authentication mode instead. </p>
   </main>

* AK/SK authentication

   The AK/SK authentication mode prevents the password from being transmitted in plaintext over HTTP. You can also authorize others to log in without sharing the password.

   For more information, see [AK/SK signature generation rules](../200.api-reference/300.ak-sk-sign-roles.md).

## Return structure

The return data of open APIs uses a unified structure (except for some special APIs). The basic return data structure is as follows:

|     Parameter      |    Type    |           Description            |
|-------------|----------|-------------------------|
| data        | Object   | “Scalar data”, “list data”, or “paginated data”. |
| ├─ contents | Array    | ├─  Indicates the relationship with the preceding parameter.       |
| successful  | Boolean  | Indicates whether the request is successful.                  |
| timestamp   | Datetime | The timestamp when the server finishes the request.             |
| duration    | Integer  | The time taken by the server to process the request in milliseconds.          |
| status      | Integer  | An HTTP status code that conforms to the HTTP Status specification.    |
| traceId     | String   | The trace ID of the request, which is used to troubleshoot problems.    |
| server      | String   | The identifier of the server that responds to the request.             |

## Call example

**curl**

You can use the curl tool to call an open API. In the following example, the admin user with the password hello is used to access the OCP application at `xxx.xxx.xxx.xxx` on port `8080` to query the tenant list. Here, `YWRtaW46aGVsbG8=` is the Base64 encoding of `admin:hello`.

```java
curl "http://xxx.xxx.xxx.xxx:8080/api/v2/ob/clusters/1/tenants"  \
  -H "Authorization: Basic YWRtaW46aGVsbG8="
```

curl also supports the use of plaintext passwords.

```java
curl "http://xxx.xxx.xxx.xxx:8080/api/v2/ob/clusters/1/tenants"  \
  --user admin:hello
```

<main id="notice" type='explain'>
<h4>Note</h4>
<p>Using plaintext passwords reduces security. Use this method with caution. </p>
</main>

## Internationalization

OCP open APIs support internationalization. The APIs return content in the language specified by the client. For more information, refer to the documentation of each API, which describes whether the attributes support internationalization.

OCP open APIs use the `Accept-Language` attribute in the request message header to specify the language option.

## Traffic control description

OCP provides traffic control to prevent excessive access. When creating a user, the system administrator can set traffic control policies for OCP users. Traffic control resources include global paths, which contain HTTP requests except for static resources, and fine-grained access control, which allows setting access limits for different resource types in OCP. The traffic control window can be set to 10 seconds, 1 minute, 1 hour, or 1 day.

![1](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/9246790261/p273248.png)

Traffic control can be enabled or disabled using the system parameter `ocp.iam.rate-limit.enabled`. The default value is `true`, which enables traffic control.

When traffic control is enabled, the response headers include:

1. `RateLimit-Limit`: the maximum number of accesses allowed in the current window, for example, "10".

2. `RateLimit-Remaining`: the number of accesses remaining in the current window, for example, "7".

3. `RateLimit-Reset`: the time when the current window resets, for example, "53".

When a user exceeds the access limit for a specific resource interface within a window, the HTTP response code is `429`. The response is as follows:

```json
{
    "duration":0,
    "error":{
        "code":0,
        "message":"Too many requests, you have exceeded the request limit in the current traffic control window"
    },
    "server": "a83ad33525",
    "status":429,
    "successful":false,
    "timestamp":"2020-12-03T09:38:24.194+08:00",
    "traceId":""
}
```
