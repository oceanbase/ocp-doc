# ob_host_net_send_percent_over_threshold The server's network send bandwidth usage exceeds the threshold.

## **Alert description**

This alert is triggered when the network bandwidth usage on the server hosting the OBServer node exceeds the threshold during data transmission.

## Alerting principle

The following table describes the key parameters involved in the alerting monitoring logic.

| Parameter | Description |
|-------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Monitoring metric | ob_host_net_send_percent |
| Data source |<li> bandwidth: The data is collected by using the psutil.net_if_stats() function in the python script and converted into bytes (result × 1024 × 1024).   </li><li> node_network_transmit_bytes_total: The data is collected by using the node_exporter process. You can view the data at `http://localhost: 63000/metrics`.   </li> |
| Metric to be collected | node_network_transmit_bytes_total and bandwidth |
| Monitoring expression | 100 × max(sum(rate(node_network_transmit_bytes_total{@LABELS}[@INTERVAL] ) by (device,@GBLABELS)) by (device,@GBLABELS) / sum(bandwidth{@LABELS}) by (device,@GBLABELS)) by (@GBLABELS) |
| Collection interval | 1 second |

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>The data source of this alert is special. OCP-Agent monitors the network usage of the local host. The data is collected by using the python script and the exporter process. For more information, see the description of <strong>Data source</strong> in the table. </p>
  </main>

The value of the monitoring metric ob_host_net_send_percent indicates the percentage of the network bandwidth occupied by the OBServer node. An alert is triggered when the value exceeds the threshold (80% by default).

## **Impact on the System**

When the network bandwidth is about to be exhausted, the performance of OceanBase Database will be bottlenecked. When the business workload continues to increase, the performance of OceanBase Database will be unable to meet the business needs.

## **Possible Causes**

This is common when the business workload of OceanBase Database increases, such as when the amount of data returned by SQL statements is excessively large.

## **Solution**

Go to the **<UI-TERM key="ocp-v2.src.hook.useMenu.Monitoring">Monitoring</UI-TERM>** page of the host in OCP and view the **Network Throughput** section on the **<UI-TERM key="ocp-v2.Monitor.AddMonitor.AddMonitorDrawer.HostPerformance">Host Performance</UI-TERM>** tab.

Observe the network throughput during the alert period.

![08061601](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/9177829261/p302075.png)

* If the network throughput suddenly spikes, it may be due to a surge in short-term business workload.

  You can wait for the business workload to return to normal and then observe whether the alert is automatically eliminated after 5 minutes.

* If the network throughput curve is gradually rising or the network throughput suddenly spikes and does not decrease, it may be due to normal business expansion.

  Contact the network engineer to increase the network bandwidth of the host.
