# ob_cluster_frozen_version_delta_over_threshold

## Alert description

This alert is triggered when the difference between the version number of the pending major compaction and the version number of the completed major compaction exceeds the threshold.

## Alert principle

The following table describes the key parameters involved in the monitoring logic of this alert.

| Parameter | Value |
|---------|------------|
| Metric | frozen_versions, which indicates the difference between the frozen version and the baseline version of the OceanBase cluster. This alert is triggered when the value of this metric exceeds the threshold.     |
| Metric expression | ```max(ob_zone_stat{name="frozen_version",@LABELS}) by (@GBLABELS) - min(ob_zone_stat{name="last_merged_version",@LABELS}) by (@GBLABELS)```    |
| Collected metric | ob_zone_stat     |
| Metric source  | The metric is collected from internal views. The SQL statement for metric collection is as follows: ```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ zone, name, value, time_to_usec(now()) as current from __all_zone```   |
| Collection cycle  | 5 seconds      |

## Rule information

|    Metric       | Default threshold | Duration | Detection cycle | Elimination cycle |
|-------------------|------|------|------|------|
| frozen_versions   | 1    | 0 seconds  | 10 seconds | 5 minutes |

## Alert information

|   Trigger method   | Alert level | Scope |
|------------|------|--------|
| Metric expression | Critical   | Cluster |

## Alert template

* **Alert overview**

  * Template: \${alarm_target} ${alarm_name}
  * Example: alarm_template_id=0:ob_cluster=obcluster-1 The difference between the frozen version and the baseline version of the OceanBase cluster exceeds the threshold.

* **Alert details**

  * Template: Cluster: \${ob_cluster_name}. Alert: \${alarm_name}. The difference \${value} exceeds ${alarm_threshold}.
  * Example: Cluster: obcluster-1. Alert: The difference between the frozen version and the baseline version of the OceanBase cluster exceeds the threshold. The difference 2.0 exceeds 1.0.

* **Alert recovery**

  * Template: Alert: ${alarm_name}. The difference between the frozen version and the baseline version of the OceanBase cluster: \${value}
  * Example: Alert: The difference between the frozen version and the baseline version of the OceanBase cluster exceeds the threshold. The difference between the frozen version and the baseline version of the OceanBase cluster: 0.5

In the template, ${host} displays the IP address of the host by default. If you set it to display the host name, the IP address is displayed when the host is not managed by OCP.

## Impact on the system

This alert affects the response time of statements. In extreme cases, it may cause excessive memory usage on OBServer nodes, business write stoppage, and full clog log disks.

## Possible causes

This alert is commonly triggered in the following scenarios:

* A major compaction is manually initiated when the OceanBase cluster is automatically performing a major compaction.

* Major compactions are manually initiated consecutively.

* The previous major compaction was not completed due to an exception, and a new major compaction is triggered.

## Solution

1. You can use the following two methods to determine the specific scenario that triggers this alert.

   * View the latest major compaction information in the **Major Compaction Details** section of the **Major Compaction Management** page of the specific cluster.

   * View the major compaction tasks in the **<UI-TERM key="ocp-v2.src.hook.useMenuOptions.TaskCenter">Task Center</UI-TERM>**.

2. Perform the corresponding operations based on the determined scenario.

   * If this alert is triggered because a major compaction is manually initiated, you can ignore it and wait for the major compaction to complete.

     Avoid initiating unnecessary major compactions.

   * If this alert is triggered because of slow or failed major compactions, other alerts such as [ob_cluster_merge_error OB Cluster Major Compaction Error](../200.ob-alert/700.ob_cluster_merge_error.md) and [ob_cluster_merge_timeout OB Cluster Major Compaction Timeout](../200.ob-alert/800.ob_cluster_merge_timeout.md) are also triggered.

     You can resolve these alerts and then perform a major compaction to check whether any alerts are reported.

   * For other abnormal scenarios, proceed to the next step for troubleshooting.

3. Follow the steps in [Troubleshoot major compaction exceptions in an OceanBase cluster](../500.appendix/100.exception-handling-for-oceanbase-cluster-compactio.md) for troubleshooting.

   If you still cannot locate the issue or know how to resolve it, contact OCP technical support.
