# ob_host_disk_readonly

## Alert description

This alert is triggered when the disk of an OceanBase server is read-only.

## Alert principle

The following table describes the key parameters involved in the monitoring logic of this alert.

|  Parameter   |                           Value                           |
|-------|-------------------------------------------------------|
| Metric  | disk_readonly_flag. This metric indicates whether the installation directory, data directory, and log directory of an OBServer node are read-only. A value of `0` indicates that the directories are writable. A value of `1` indicates that the directories are read-only and triggers this alert.       |
| Metric expression | ```max(node_filesystem_readonly{@LABELS}) by (@GBLABELS)``` |
| Collected metric  | node_filesystem_readonly    |
| Metric source  | Collected from node_exporter.  |
| Collection cycle  | 5 seconds   |

OCP-Agent periodically monitors whether the disk is readable based on the **collection cycle**. The result is returned by the **collected metric** node_filesystem_readonly. A value of 1 indicates that the disk is read-only, and a value of 0 indicates that the disk is writable. The value of `is_ob_disk` is set to `"1"` for the disk that contains the installation directory, data directory, and log directory of OceanBase Database.

## Rule information

|      Metric            | Default threshold | Duration | Detection cycle | Elimination cycle |
|----------------------------|------|------|------|------|
| disk_readonly_flag | 1    | 0 seconds  | 10 seconds | 5 minutes |

## Alert information

|   Trigger method   | Alert level | Scope  |
|------------|------|-----|
| Metric expression | Critical   | Host |

## Alert template

* **Alert overview**

  * Template: \${alarm_target} ${alarm_name}
  * Example: alarm_template_id=0:ob_cluster=obcluster-1:host=xxx.xxx.xxx.xxx:mount_point=/home/admin The disk is read-only.

* **Alert details**

  * Template: Cluster: \${ob_cluster_name}, Host: \${host}, Alert: \${alarm_name}. The disk mount point \${mount_point} is read-only.
  * Example: Cluster: obcluster-1, Host: xxx.xxx.xxx.xxx, Alert: The disk is read-only. The disk mount point /dev/loop0 is read-only.

* **Alert recovery**

  * Template: Alert: ${alarm_name}, Is the OBServer disk read-only: \${recover_value}
  * Example: Alert: The disk is read-only. Is the OBServer disk read-only: 0

Here, ${alarm_target} is in the format of ob_cluster=xxxxxxx:svr_ip=xxxxxx.

* ob_cluster specifies the name of the cluster that generated the alert.

* svr_ip specifies the IP address of the OBServer node that generated the alert.

## Impact on the system

* If the log disk and data disk of OceanBase Database are read-only, the OBServer node cannot run normally.

* If the log file disk is read-only, the system cannot output logs normally.

## Possible causes

* The disk is full.

* Permission exceptions caused by the operating system.

* Physical media failures, such as disk failures.

## Solution

* Check whether the disk is full or the disk space is insufficient.

  If the disk space is insufficient, the following alerts are also reported. You can first refer to the solutions in the following topics, and then check whether the alerts in this section are also eliminated.

  * [ob_host_data_disk_percent_over_threshold OB Host Data Directory Disk Usage Exceeds Threshold](../200.ob-alert/3500.ob_host_data_disk_percent_over_threshold.md)

  * [ob_host_log_disk_percent_over_threshold OB Host Log Directory Disk Usage Exceeds Threshold](../200.ob-alert/3600.ob_host_log_disk_percent_over_threshold.md)

  * [ob_host_install_disk_percent_over_threshold OB Host Installation Directory Disk Usage Exceeds Threshold](../200.ob-alert/3700.ob_host_install_disk_percent_over_threshold.md)

* Other reasons.

  The reasons for the operating system disk being read-only are complex and fall under the scope of Linux operations and maintenance. We recommend that you contact a Linux O&M engineer for assistance.

  If you do not have a Linux O&M engineer, you can check the logs about the disk being read-only in the `/var/log/messages` file and search for solutions on [www.baidu.com](https://www.baidu.com/) by pasting the error message.

  ```sql
  # List all read-only disks.
  grep "[[:space:]]ro[[:space:],]" /proc/mounts

  # The following information is returned. The /dev/loop0 disk is read-only.
  tmpfs /sys/fs/cgroup tmpfs ro,nosuid,nodev,noexec,mode=755 0 0
  /dev/loop0 /home/admin iso9660 ro,relatime,nojoliet,check=s,map=n,blocksize=2048 0 0

  # You can also query the reason for the disk being read-only by replacing '/dev/loop0' with 'readonly'.
  grep '/dev/loop0' /var/log/messages -Rn
  ```
