# ob_cluster_exists_index_fail_table OceanBase cluster tables with failed indexes

## Description

This alert monitors whether there are tables with failed index creation in the OceanBase cluster and triggers an alert if such tables exist.

## Principle

The following table lists the key parameters involved in the monitoring logic of this alert.

| Parameter | Value |
|-------|---------|
| Monitoring metric  | ob_cluster_index_fail_count    |
| Source of the metric  | <ul><li>For OceanBase versions earlier than V4.0: ```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) QUERY_TIMEOUT(100000000) */ count(*) as cnt from gv$table where table_type in (5) and index_status in (5, 6, 7)```</li><li>For OceanBase V4.0 and later: ```select /*+ MONITOR_AGENT QUERY_TIMEOUT(100000000) */ count(*) as cnt from CDB_INDEXES where status in ('ERROR','UNUSABLE')```</li></ul>  |
| Metric collection  | index_fail_count    |
| Monitoring expression | sum(ob_index_error_num{@LABELS}) by (@GBLABELS)     |
| Collection interval  | 60 seconds    |

**Monitoring metric ob_cluster_index_fail_count** indicates the number of tables with failed index creation in the OceanBase cluster. An alert is triggered when the value exceeds the threshold (which is 0 by default).

## Rules

|            Monitoring metric             | Default threshold | Duration | Detection interval | Elimination interval |
|-----------------------------|------|------|------|------|
| ob_cluster_index_fail_count | 0    | 0 seconds  | 60 seconds | 5 minutes |

## Alert information

|   Alert trigger method      | Alert level | Scope   |
|---------------------|--------|---------|
| Based on the monitoring metric expression | Critical   | Cluster    |

## Alert template

* **Alert summary**
  * Template: \${alarm_target} ${alarm_name}
  * Example: ob_cluster=obcluster-1 OceanBase cluster has tables with failed index creation

* **Alert details**
  * Template: Cluster: \${ob_cluster_name}, Alert: \${alarm_name}. The number of tables with failed index creation is \${value}.
  * Example: Cluster: obcluster-1, Alert: OceanBase cluster has tables with failed index creation. The number of tables with failed index creation is 1.0.

* **Alert recovery**
  * Template: Alert: ${alarm_name}, Number of tables with failed index creation in OceanBase cluster: \${value}
  * Example: Alert: OceanBase cluster has tables with failed index creation, Number of tables with failed index creation in OceanBase cluster: 0

* Alert details

## Impact on the system

Failed index creation prevents SQL execution from being optimized based on the index, and the execution efficiency cannot be demonstrated.

## Possible causes

Common scenarios where index creation fails include errors during the execution of index creation tasks, but the index cannot be established. Common scenarios include:

* Failed creation of a normal index: caused by cluster status issues.

* Failed creation of a unique index: OceanBase creates indexes asynchronously. If the data does not meet the uniqueness constraints, errors are reported later, requiring DBA and business collaboration to confirm data uniqueness and index requirements.

## Procedure

1. Find the failed index content based on the following method:

   1. Run the following command to find the failed index:

      ```sql
      -- For OceanBase Database of a version earlier than V4.0:
      select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) QUERY_TIMEOUT(100000000) */ count(*) as cnt from gv$table where table_type in (5) and index_status in (5, 6)

      -- For OceanBase Database V4.0 and later:
      select /*+ MONITOR_AGENT QUERY_TIMEOUT(100000000) */ count(*) as cnt from CDB_INDEXES where status in ('ERROR','UNUSABLE')
      ```

      Take the values of index_name (index name) and data_table_id (ID of the table to which the index belongs).

   2. Use the data_table_id (ID of the table to which the index belongs) to find the name of the table to which the failed index belongs.

      ```sql
      -- Note that OceanBase Database V2.x uses __all_virtual_database.

      > SELECT t2.database_name, t1.table_name  from __all_table t1 join __all_database t2 on t1.database_id=t2.database_id where t2.tenant_id=1014 and t1.table_id=1114904790614901;
      +---------------+---------------+
      | database_name | table_name    |
      +---------------+---------------+
      | obsink        | question_dest |
      +---------------+---------------+
      1 row in set (0.05 sec)
      ```

   3. Run the following command to find the failed index:

      ```sql
      # MySQL mode #
      obclient> SHOW INDEX FROM table_name;

      # Oracle mode
      obclient> SELECT * FROM USER_IND_COLUMNS WHERE table_name='table_name';
      ```

2. Confirm that the cluster status is normal.

3. Drop and rebuild the index.

   * To drop an index, see [Drop an index](https://www.oceanbase.com/docs/enterprise/oceanbase-database-cn/V3.2.3/10000000000357129) in the documentation of the corresponding OceanBase Database version.

   * To rebuild an index, see [Create an index](https://www.oceanbase.com/docs/enterprise/oceanbase-database-cn/V3.2.3/10000000000355266) in the documentation of the corresponding OceanBase Database version.
