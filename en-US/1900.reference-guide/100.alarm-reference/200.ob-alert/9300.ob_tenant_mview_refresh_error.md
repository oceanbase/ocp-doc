# ob_tenant_mview_refresh_error

## Alert description

<main id="notice" type='explain'>
<h4>Note</h4>
<li>This alert is only applicable to OceanBase clusters of V4.3.5.0 and later. </li>
<li>When a primary-standby relationship exists between tenants, only the primary tenant can report this alert. </li>
</main>

This alert monitors whether a materialized view in the database of the tenant is refreshed properly. If an error occurs during the refresh, this alert is triggered.

## Alert principle

1. The OCP scheduled task executes the following SQL statements in the sys tenant of each cluster to collect data about the automatic refresh errors of materialized views. The data is stored in the `sql_aggregate_data` table of the OCP MonitorDB. The scheduled task runs every 60 seconds.

    ```sql
    SELECT
          D.tenant_id,
          D.tenant_name,
          A.database_name,
          B.table_name AS mview_name,
          E.start_time,
          E.result
    FROM  oceanbase.__all_virtual_database A,
          oceanbase.__all_virtual_table B,
          oceanbase.__all_virtual_mview C,
          oceanbase.DBA_OB_TENANTS D,
          (SELECT tenant_id,
                  result,
                  start_time,
                  mview_id
            FROM   (SELECT tenant_id,
                          result,
                          start_time,
                          mview_id,
                          Row_number()
                            over(
                              PARTITION BY tenant_id, mview_id
                              ORDER BY start_time DESC) rn
                    FROM   oceanbase.__all_virtual_mview_refresh_stats A)
            WHERE  rn = 1)E
    WHERE  A.tenant_id = B.tenant_id
          AND B.tenant_id = C.tenant_id
          AND C.tenant_id = D.tenant_id
          AND D.tenant_id = E.tenant_id
          AND C.mview_id = E.mview_id
          AND A.database_id = B.database_id
          AND B.table_id = C.mview_id
          AND B.table_type = 7
          AND E.result != 0
          AND D.tenant_type<>'META' AND D.tenant_name IS NOT NULL
          AND D.tenant_role = 'PRIMARY';
    ```

2. The OCP alert detection task identifies whether the alert item is of the SQL_AUDIT type. If it is, the following command is executed to scan the `sql_aggregate_data` table for abnormal data and generate corresponding alerts based on the alert detection rules.

   ```sql
   select * from sql_aggregate_data where tags like '%mview_stat%' order by timestamp desc
   ```

| Metric | Default threshold | Duration | Detection cycle | Time before clearance |
|----------|----------|---------|----------|-----------|

| Trigger method | Alert level | Scope  |
|------|------|--------|

## Alert template

* **Alert overview**

  * Template: ${alarm_target} ${alarm_name}
  * Example: alarm_template_id=0:ob_cluster=test471-11:tenant_name=mysqlTes:database=test:mview_name=test_mv_refresh_retry_mv2 The automatic refresh of the materialized view is abnormal.

* **Alert details**

  * Template: The automatic refresh of the materialized view ${mview_name} in the database ${database} of the tenant ${tenant_name} in the OceanBase cluster ${ob_cluster_name} is abnormal. The result is ${result}, and the refresh time is ${start_time}.
  * Example: The automatic refresh of the materialized view test_mv_refresh_retry_mv2 in the database test of the tenant mysqlTes in the OceanBase cluster test471 is abnormal. The result is -5024, and the refresh time is 2025-11-14T16:13:55.026383+08:00.

## Impact on the system

The materialized view may fail to refresh data.

## Possible causes

Internal system errors.

## Solution

1. In the default configuration, after an error occurs during the refresh of a materialized view, only the trace ID and error code can be obtained. You can execute the following command as the sys tenant to obtain the trace ID and error code:

    ```sql
    SELECT A.database_name, B.table_name AS mview_name, C.last_refresh_trace_id, C.last_refresh_time
    FROM oceanbase.__all_virtual_database A, oceanbase.__all_virtual_table B, oceanbase.__all_virtual_mview C
    WHERE A.tenant_id = B.tenant_id
      AND B.tenant_id = C.tenant_id
      AND A.database_id = B.database_id
      AND B.table_id = C.mview_id
      AND B.table_name = 'mview_name';
    ```

    In the preceding command, `mview_name` must be replaced with the actual name of the materialized view that triggers the alert.

2. Collect error logs from the cluster observer log directory based on the trace ID and refresh time, and contact OCP technical support for troubleshooting.
