# ob_tenant_operation_info

## Alert description

This event is triggered when you perform any tenant-level O&M operation through OCP.

O&M tasks:

* Create a tenant.
* Lock or unlock a tenant.
* Delete a tenant.
* Add a replica.
* Modify a replica (unit specification or number).
* Delete a replica.
* Generate an active session history report.
* Perform an immediate backup.

## Alert principle

None.

## Alert template

* **Alert overview**

  * Template: \${alarm_target} ${operation_result}
  * Example: alarm_template_id=0:ob_cluster=obcluster-1:tenant_name=tenant-1:operation_name=Create network standby tenant SUCCESS

* **Alert details**

  * Template: Cluster: \${ob_cluster_name}, Alert: \${operation_name} \${operation_result}, Operator: ${operator}, Result: \${operation_result}.
  * Example: Cluster: obcluster-1, Alert: Create network standby tenant SUCCESS, Operator: admin, Result: success.

Where:

* ${alarm_target}: the object that generates the alert. The format is ob_cluster=xxxxxxx. ob_cluster indicates the name of the cluster that generates the alert.

* ${operation_name}: the operation performed.

* ${operation_result}: the result of the operation. Valid values: SUCCESS (the operation is successful) and FAILED (the operation fails).

* ${operator}: the name of the user who performed the operation.

## Impact on the system

None.

## Possible causes

This alert is commonly triggered when you perform tenant-level O&M operations through OCP, such as adding or deleting replicas.

## Solution

No action is required if the operation result is SUCCESS. If the operation result is FAILED, perform the corresponding troubleshooting based on the cause of the failure.
