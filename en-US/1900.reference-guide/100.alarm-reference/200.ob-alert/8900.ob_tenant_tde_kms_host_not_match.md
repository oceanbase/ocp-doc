# ob_tenant_tde_kms_host_not_match

## Alert description

This alert checks whether the TDE KMS service address of the tenant matches the current OCP service address. Specifically:

* TDE KMS service address of the tenant: The `kms_host` field value in the `external_kms_info` parameter of the corresponding tenant in the `GV$OB_PARAMETERS` view.
* Current OCP service address: The value of the system parameter `ocp.site.url`.

## Alert principle

| Parameter | Value |
| ---------- | ------------ |
| Metric | ob_tenant_tde_kms_host_match_status. This metric indicates the match status between the OceanBase tenant KMS address and the current OCP address. A value of `0` indicates that the service addresses match; a value of `1` indicates that the service addresses do not match, and the alert is triggered. |
| Metric expression | ```max(ob_tenant_tde_kms_host_match_status{@LABELS}) by (@GBLABELS)``` |
| Collected metric | ob_tenant_tde_kms_host_match_status |
| Data source | OCP-Server periodically queries whether the `kms_host` and `ocp.site.url` values match. If they do not match, an alert is issued. |
| Collection cycle | 5 seconds |

## Rule information

| Metric | Default threshold | Duration | Detection cycle | Elimination cycle |
| ---------- | ----------- | -------- | -------- | -------- |
| ob_tenant_tde_kms_host_match_status    |  1    |  120 seconds    |   60 seconds   |  5 minutes  |

## Alert information

| Alert trigger method | Alert level | Scope |
| ------------ | -------- | ------ |
| Based on the expression of the monitoring metric | Critical | Tenant |

## Alert template

* **Alert overview**

  * Template: ${alarm_target} ${alarm_name}
  * Example: alarm_template_id=0:ob_cluster=xxx:tenant_name=xxx The TDE KMS service address of the tenant does not match the current OCP service address.

* **Alert details**

  * Template: The KMS address of tenant ${tenant_name} in the OceanBase cluster ${ob_cluster_name} does not match the OCP address.
  * Example: The KMS address of tenant xxx in the OceanBase cluster Test does not match the OCP address.

* **Alert recovery**

  * Template: Alert: ${alarm_name}, Does the TDE KMS service address of the tenant match the current OCP service address? \${value}
  * Example: Alert: The TDE KMS service address of the tenant does not match the current OCP service address. The TDE KMS service address of the tenant does not match the current OCP service address: 0

## Impact on the system

The following features are unavailable: adding OBServer nodes, creating standby tenants, and creating encrypted tablespaces.

## Possible causes

* The current OCP service address has changed, and the value of the system parameter `ocp.site.url` does not match the `kms_host` value in the `external_kms_info` parameter of the `GV$OB_PARAMETERS` view before the tenant's TDE encryption.
* The `external_kms_info` information of the tenant was modified in the CLI, causing the `ocp.site.url` value to be inconsistent with the `kms_host` value.
* After the cluster was migrated and taken over, the TDE encryption configuration for the related tenants was not completed in time.
* In the multi-cluster mode of OCP, after the primary and standby tenants were decoupled, the TDE encryption configuration for the new primary tenant was not updated in time.

## Solution

* Method 1: Go to the overview module of the cluster corresponding to the alert, click **<UI-TERM key="ocp-v2.Detail.Overview.ModifyEncryption">Modify Encryption</UI-TERM>** based on the page prompt, and go to **<UI-TERM key="ocp-v2.src.hook.useMenu.SecurityConfiguration">Security Configuration</UI-TERM>** > **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">Transparent Data Encryption</UI-TERM>** to modify the TDE encryption information of the corresponding tenant.
* Method 2: In the cluster to which the tenant belongs, go to **<UI-TERM key="ocp-v2.Detail.Security.SecurityConfiguration">Security Configuration</UI-TERM>** > **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">Transparent Data Encryption</UI-TERM>** to modify the TDE encryption information of the corresponding tenant.
